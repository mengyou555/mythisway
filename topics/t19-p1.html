19.1Learning Roadmap

ภาพรวมเส้นทาง

Linux คือระบบปฏิบัติการที่ Server ส่วนใหญ่ทั่วโลกใช้ ทั้งเว็บไซต์ ระบบธนาคาร Cloud อย่าง AWS, Azure และ Google Cloud ไปจนถึง Container ของ Docker และเครื่องที่ใช้ Train โมเดล AI งานบน Server เกือบทั้งหมดทำผ่าน Command Line คือพิมพ์คำสั่งเป็นตัวอักษร ไม่ได้คลิกเมาส์ หัวข้อนี้จึงเป็นหัวข้อแรกของเส้นทางที่แนะนำ เพราะทุกหัวข้อหลังจากนี้ ทั้ง Git, Python, SQL, Backend และ Cyber Security ต้องเปิด Terminal ทุกวัน

เส้นทางนี้แบ่งเป็น 12 ขั้นใน 3 ระดับ เริ่มจากเปิด Terminal ครั้งแรกและเดินไปมาในระบบไฟล์ ต่อด้วยการจัดการสิทธิ์ ติดตั้งโปรแกรม และต่อคำสั่งหลายตัวเข้าด้วยกันเพื่อวิเคราะห์ Log จบด้วยการเขียน Bash Script ที่รันเองตามเวลาด้วย cron ซึ่งเป็นงานที่ System Administrator และ DevOps Engineer ทำจริงทุกวัน ทุกขั้นฝึกบน Ubuntu 24.04 LTS ใน WSL2 ที่คุณติดตั้งไว้แล้วใน Day 0

เปรียบเทียบ

การเรียน Linux เหมือนการหัดขับรถเกียร์ธรรมดา ช่วงแรกต้องคิดทุกจังหวะว่าจะเหยียบคลัตช์ตอนไหน แต่เมื่อขับทุกวันสักพักมือกับเท้าจะทำเองโดยอัตโนมัติ คำสั่ง Linux ก็เป็นแบบนั้น อย่าพยายามท่องจำทั้งหมดในวันเดียว ให้พิมพ์ใช้จริงทุกวัน แล้วคำสั่งที่ใช้บ่อยจะติดมือเอง

Linux คืออะไร ทำไมเรียนเป็นหัวข้อแรก

ก่อนเริ่มพิมพ์คำสั่ง ให้รู้จักคำศัพท์ 6 คำนี้ก่อน เพราะจะเจอตลอดหลักสูตร และเป็นคำถามสัมภาษณ์งานระดับ Junior ที่พบบ่อย

คำศัพท์ความหมายตัวอย่างที่คุณใช้อยู่
Operating System (OS)ซอฟต์แวร์หลักที่จัดการฮาร์ดแวร์ (CPU, RAM, Disk, Network) และให้โปรแกรมอื่นทำงานบนมันWindows 11 บนเครื่องของคุณ และ Ubuntu 24.04 ใน WSL2
Kernelแกนกลางของ OS ที่คุยกับฮาร์ดแวร์โดยตรง จัดสรร CPU และหน่วยความจำให้แต่ละโปรแกรม คำว่า "Linux" จริงๆ แล้วหมายถึง Kernel ตัวนี้Linux Kernel ที่ Microsoft ปรับแต่งสำหรับ WSL2 ดูเวอร์ชันได้ด้วย uname -r
Shellโปรแกรมที่รับคำสั่งที่เราพิมพ์ แปลความหมาย แล้วสั่ง Kernel ให้ทำงาน และยังเป็นภาษาโปรแกรมสำหรับเขียน Script ได้ด้วยBash 5.2.21 ซึ่งเป็น Shell เริ่มต้นของ Ubuntu 24.04 (อีกตัวที่นิยมคือ Zsh)
Terminalหน้าต่างโปรแกรมที่ใช้พิมพ์คำสั่งส่งให้ Shell และแสดงผลลัพธ์กลับมา Terminal เองไม่ได้แปลคำสั่ง แค่เป็นช่องทางสื่อสารWindows Terminal ที่เปิดแท็บ Ubuntu และ Terminal ใน VS Code
Distribution (Distro)ชุด Linux ที่รวม Kernel, Shell, Package Manager และโปรแกรมพื้นฐานไว้ด้วยกันพร้อมใช้Ubuntu, Debian, Fedora, Red Hat Enterprise Linux (RHEL), Rocky Linux, AlmaLinux, Arch Linux
WSL2Windows Subsystem for Linux รุ่นที่ 2 ซึ่งรัน Linux Kernel จริงใน Virtual Machine ขนาดเล็ก ทำให้ใช้ Linux บน Windows ได้โดยไม่ต้องลง OS ใหม่Ubuntu-24.04 ที่ติดตั้งด้วย wsl --install -d Ubuntu-24.04
เปรียบเทียบ

ให้นึกถึงร้านอาหาร OS คือร้านทั้งร้าน Kernel คือครัวและหัวหน้าเชฟที่คุมเตา วัตถุดิบ และลูกมือ (ฮาร์ดแวร์) Shell คือพนักงานรับออร์เดอร์ที่ฟังสิ่งที่ลูกค้าสั่งแล้วแปลให้ครัวเข้าใจ Terminal คือโต๊ะและเมนูที่ลูกค้าใช้สั่งอาหาร ส่วน Distro คือแบรนด์ร้านที่จัดเมนูและการตกแต่งต่างกัน แต่ใช้ครัวแบบเดียวกัน

เหตุผลที่ Linux เป็นหัวข้อแรกของเส้นทางนี้มีดังนี้

  • Server ส่วนใหญ่ใช้ Linux เมื่อคุณ Deploy เว็บ, API หรือโมเดล AI ขึ้น Cloud เกือบทุกครั้งจะไปรันบน Linux และต้องเข้าไปดูแลผ่าน SSH ซึ่งมีแค่ Command Line
  • เครื่องมือของนักพัฒนาสร้างมาให้ใช้ผ่าน Terminal เช่น Git, Python venv, npm, Docker และ psql ถ้าไม่คล่อง Terminal ทุกหัวข้อหลังจากนี้จะติดขัด
  • งาน Automation ทำได้ง่าย งานซ้ำๆ เช่น สำรองไฟล์ ตรวจพื้นที่ Disk หรือสรุป Log เขียนเป็น Bash Script แค่ไม่กี่บรรทัดแล้วตั้งเวลาให้รันเองได้
  • เป็นพื้นฐานของงานหลายสาย ทั้ง Backend, DevOps, Cloud, Cyber Security และ Network Engineer ต่างใช้ Linux เป็นเครื่องมือหลัก

เรียน Linux บน WSL2 ต่างจาก Server จริงอย่างไร

WSL2 รัน Linux Kernel จริง คำสั่งเกือบทั้งหมดในหัวข้อนี้จึงทำงานเหมือนบน Server แต่มีบางเรื่องที่ต่างกัน ควรรู้ไว้ก่อนเพื่อไม่ให้สับสนตอนผลลัพธ์ไม่ตรงกับบทความบนอินเทอร์เน็ต

เรื่องบน WSL2 (Ubuntu 24.04)บน Linux Server จริงสิ่งที่ต้องทำ
systemdเปิดหรือปิดได้ ควบคุมด้วยไฟล์ /etc/wsl.conf ส่วน [boot] บรรทัด systemd=true ซึ่ง Ubuntu ใน WSL รุ่นใหม่มักเปิดไว้ให้แล้วsystemd เป็น Process หมายเลข 1 (PID 1) เสมอตรวจด้วย ps -p 1 -o comm= ถ้าได้ systemd แปลว่าเปิดอยู่ ถ้าได้ init แปลว่ายังไม่เปิด (สอนใน Step 9)
cron และ Service อื่นทำงานเฉพาะตอนที่ WSL เปิดอยู่ ถ้าปิดหน้าต่าง Terminal ทั้งหมด WSL อาจหยุดทำงานหลังจากนั้นไม่นาน และงานที่ตั้งเวลาไว้จะไม่รันทำงานตลอด 24 ชั่วโมงตอนทดสอบ cron ให้เปิด Ubuntu ทิ้งไว้ และตรวจว่า Service cron ทำงานอยู่ (Step 12)
Networkโหมดเริ่มต้นเป็น NAT คือ WSL มี IP ของตัวเอง (มักขึ้นต้นด้วย 172.) แยกจาก Windows แต่ Windows ยังเปิด http://localhost:พอร์ต เพื่อเข้าถึงโปรแกรมใน WSL ได้มี IP จริงที่เครื่องอื่นในเครือข่ายเข้าถึงได้อย่าตกใจถ้า IP ใน ip a ไม่ตรงกับ IP ของ Windows (Step 10)
ไฟล์ของ Windowsไดรฟ์ C: อยู่ที่ /mnt/c ใช้ได้ แต่ช้ากว่ามากเมื่อทำงานจากฝั่ง Linux และ Permission ที่เห็นจะไม่ตรงกับความจริงไม่มีเก็บงานทั้งหมดไว้ใน ~/projects เสมอ
การปิดเครื่องสั่งปิด WSL จาก PowerShell ด้วย wsl --shutdown ไม่ใช้ shutdown หรือ reboot ใน Ubuntuใช้ sudo reboot หรือ sudo shutdown -h nowหลังแก้ /etc/wsl.conf ต้องรัน wsl --shutdown แล้วเปิด Ubuntu ใหม่
อัปเดต KernelKernel มากับแอป WSL อัปเดตด้วย wsl --update ใน PowerShellอัปเดตผ่าน apt แล้ว Rebootไม่ต้องติดตั้ง Kernel เองใน Ubuntu
หมายเหตุ

ในหัวข้อนี้ บางตัวอย่างของ systemctl, journalctl และ cron จะแสดงผลลัพธ์ตัวอย่างที่สมจริง ค่าอย่างวันที่ PID หมายเลข IP และขนาดไฟล์ในเครื่องของคุณจะต่างออกไปเสมอ ให้ดูที่รูปแบบและคำสำคัญ เช่น active (running) ไม่ต้องให้ตัวเลขตรงกัน

วิธีเรียนหัวข้อนี้ให้ได้ผล

  1. พิมพ์เองทุกคำสั่ง อย่าคัดลอกแล้ววาง การพิมพ์เองทำให้มือจำคำสั่งได้ และได้เจอ Error จากการพิมพ์ผิด ซึ่งเป็นการฝึกอ่าน Error ที่ดีที่สุด
  2. ฝึกในโฟลเดอร์ทดลองเท่านั้น สร้าง ~/projects/linux-lab ไว้ฝึก ไม่ทดลองคำสั่งลบหรือเปลี่ยนสิทธิ์ใน /, /etc หรือ /mnt/c
  3. เรียนวันละนิดแต่ทุกวัน วันละ 1–1.5 ชั่วโมงทุกวัน ได้ผลดีกว่าเรียน 8 ชั่วโมงรวดในวันเดียวแล้วหยุดไปหนึ่งสัปดาห์

  5. อ่าน Error ก่อนค้น Google ข้อความอย่าง No such file or directory หรือ Permission denied บอกสาเหตุอยู่แล้ว ให้อ่านให้จบก่อนทุกครั้ง

  • ความต่างของ Kernel, Shell และ Terminal รวมถึงความหมายของ Distribution และ LTS (Long Term Support) ว่าทำไมหลักสูตรนี้ใช้ Ubuntu 24.04 LTS "noble"
  • WSL2 ทำงานอย่างไร: รัน Linux Kernel จริงใน Virtual Machine ขนาดเล็ก ไฟล์ของ Ubuntu เก็บในดิสก์เสมือนแยกจาก Windows และตรวจว่าอยู่ใน WSL2 ด้วย uname -r ที่ลงท้ายด้วย microsoft-standard-WSL2
  • อ่าน Prompt ให้เป็น: somchai@DESKTOP-K7Q2M4P:~$ คือ ชื่อผู้ใช้ @ ชื่อเครื่อง : โฟลเดอร์ปัจจุบัน และ $ หมายถึงผู้ใช้ทั่วไป ส่วน # หมายถึง root
  • คำสั่งแรก: whoami, hostname, uname -a, lsb_release -a, date, echo, clear และ exit
  • โครงสร้างของคำสั่ง: คำสั่ง [option] [argument] เช่น ls -l /etc ความต่างของ Short option (-a) กับ Long option (--all) และการรวม Option (-la)
  • คีย์ลัดที่ต้องใช้ทุกวัน: Ctrl+C หยุดคำสั่ง, Ctrl+L ล้างจอ, Ctrl+A / Ctrl+E ไปต้นหรือท้ายบรรทัด, Ctrl+R ค้นหาคำสั่งเก่า และลูกศรขึ้นลงเพื่อเรียกคำสั่งก่อนหน้า
  • คัดลอกและวางใน Windows Terminal: เลือกข้อความแล้วกด Ctrl+Shift+C และวางด้วย Ctrl+Shift+V หรือคลิกขวา

STEP 2

ระบบไฟล์และการเดินทางใน Terminal

2 วัน · 3–4 ชม.
หัวข้อย่อย
  • โครงสร้างระบบไฟล์ของ Linux (Filesystem Hierarchy Standard): ทุกอย่างเริ่มที่ / (root directory) ไม่มีไดรฟ์ C: หรือ D: แบบ Windows
  • โฟลเดอร์สำคัญ: /home/somchai (บ้านของผู้ใช้), /root (บ้านของ root), /etc (ไฟล์ตั้งค่า), /var/log (Log), /usr/bin (โปรแกรม), /usr/local (โปรแกรมที่ติดตั้งเอง), /tmp (ไฟล์ชั่วคราว), /opt, /dev และ /proc
  • ไดรฟ์ของ Windows ใน WSL: /mnt/c คือไดรฟ์ C: เช่น /mnt/c/Users/ และการเปิดไฟล์ของ Ubuntu จาก Windows Explorer ผ่าน \\wsl.localhost\Ubuntu-24.04
  • pwd ดูตำแหน่งปัจจุบัน, ls พร้อม Option -l, -a, -h, -t, -R และไฟล์ซ่อนที่ชื่อขึ้นต้นด้วยจุด เช่น .bashrc
  • cd ทุกรูปแบบ: cd หรือ cd ~ กลับบ้าน, cd .. ขึ้นไปหนึ่งชั้น, cd - กลับไปโฟลเดอร์ก่อนหน้า, cd / ไปที่ root
  • Absolute path (เริ่มด้วย / เช่น /home/somchai/projects) กับ Relative path (เริ่มจากตำแหน่งปัจจุบัน เช่น projects/linux-lab หรือ ../notes) และความหมายของ . กับ ..
  • Tab completion (กด Tab หนึ่งครั้งเพื่อเติมชื่อ กดสองครั้งเพื่อดูตัวเลือก), history, !! (รันคำสั่งล่าสุดซ้ำ) และ !หมายเลข
  • Linux แยกตัวพิมพ์เล็กและใหญ่ (Notes กับ notes เป็นคนละโฟลเดอร์) และวิธีจัดการชื่อที่มีช่องว่าง เช่น cd "My Folder" หรือ cd My\ Folder
  • เปิด Windows Explorer ที่โฟลเดอร์ปัจจุบันด้วย explorer.exe . เพื่อดูภาพเดียวกันจากฝั่ง Windows
ทำไมต้องเรียน
ทุกคำสั่งใน Linux ทำงานโดยอ้างอิงตำแหน่งในระบบไฟล์ ถ้าไม่รู้ว่าตัวเองอยู่ตรงไหน หรือแยก Absolute path กับ Relative path ไม่ออก จะเจอ No such file or directory บ่อยมาก และ Script ที่เขียนในอนาคตจะทำงานในเครื่องตัวเองแต่พังเมื่อรันจากโฟลเดอร์อื่น การรู้ว่า Config อยู่ใน /etc และ Log อยู่ใน /var/log ยังเป็นทักษะแรกที่ใช้เมื่อต้องแก้ปัญหาบน Server จริง
ลงมือทำ
  • เดินไปที่ /etc, /var/log, /tmp และ /mnt/c/Users แล้วใช้ ls -la ดูว่ามีอะไรอยู่บ้าง
  • จาก /var/log กลับไป ~/projects/linux-lab ให้ได้ทั้งแบบ Absolute path และ Relative path
  • วาดแผนผังโฟลเดอร์สำคัญ 8 โฟลเดอร์ใต้ / พร้อมหน้าที่ของแต่ละโฟลเดอร์ลงใน Learning Journal

3–4 ชั่วโมง ใช้เวลาส่วนใหญ่กับการเดินไปมาจริงจนคล่องมือ ไม่ใช่การท่องจำชื่อโฟลเดอร์
Checkpoint

ก่อนไปขั้นถัดไป คุณต้องทำสิ่งเหล่านี้ได้: (1) บอกหน้าที่ของ /etc, /var/log, /home, /tmp, /usr/bin และ /mnt/c ได้ (2) ไปจาก /var/log ถึง ~/projects/linux-lab ได้ทั้งแบบ Absolute path และ Relative path โดยไม่พิมพ์ผิด (3) แสดงไฟล์ซ่อนในโฟลเดอร์บ้านและหา .bashrc เจอ (4) ใช้ Tab เติมชื่อโฟลเดอร์และใช้ cd - สลับกลับโฟลเดอร์เดิมได้ (5) เปิด Windows Explorer ที่โฟลเดอร์ปัจจุบันด้วย explorer.exe .

STEP 3

สร้าง คัดลอก ย้าย และลบไฟล์อย่างปลอดภัย

2 วัน · 3–4 ชม.
หัวข้อย่อย
  • สร้างไฟล์และโฟลเดอร์: touch สร้างไฟล์ว่างหรืออัปเดตเวลาของไฟล์, mkdir, mkdir -p สร้างโฟลเดอร์ซ้อนหลายชั้นในคำสั่งเดียว และ rmdir ลบโฟลเดอร์ว่าง
  • คัดลอกด้วย cp: คัดลอกไฟล์, cp -r คัดลอกทั้งโฟลเดอร์, cp -i ถามก่อนเขียนทับ และ cp -v แสดงสิ่งที่ทำ
  • ย้ายและเปลี่ยนชื่อด้วย mv (คำสั่งเดียวทำได้ทั้งสองอย่าง) และ mv -i ป้องกันการเขียนทับไฟล์ที่มีอยู่
  • ลบด้วย rm, rm -i และ rm -r ความเข้าใจว่า Linux ไม่มีถังขยะ ลบแล้วกู้คืนเองไม่ได้ และอันตรายของ rm -rf
  • Wildcards (Globbing): * แทนตัวอักษรกี่ตัวก็ได้, ? แทนหนึ่งตัว, [abc] และ [0-9] แทนตัวอักษรในกลุ่ม และวิธีตรวจผลของ Wildcard ด้วย ls หรือ echo ก่อนใช้กับ rm
  • Brace expansion: mkdir -p lab/{notes,scripts,backup} และ touch day{1..5}.txt ซึ่งต่างจาก Wildcard เพราะสร้างชื่อขึ้นใหม่โดยไม่สนว่ามีไฟล์อยู่หรือไม่
  • ดูข้อมูลไฟล์ด้วย file (ไฟล์ชนิดอะไร) และ stat (ขนาด สิทธิ์ เวลาแก้ไข) และสร้าง Symbolic link ด้วย ln -s
  • หลักตั้งชื่อไฟล์ที่ดี: ใช้ตัวพิมพ์เล็ก ไม่มีช่องว่าง ใช้ - หรือ _ คั่นคำ และใส่วันที่แบบ 2026-10-19 เพื่อให้เรียงลำดับได้ถูกต้อง
ทำไมต้องเรียน
งานประจำวันบน Server คือการจัดการไฟล์ เช่น สำรอง Config ก่อนแก้ ย้าย Log เก่า และลบไฟล์ชั่วคราว ความผิดพลาดที่พบบ่อยที่สุดของมือใหม่คือลบไฟล์ผิดหรือเขียนทับไฟล์สำคัญ เพราะ Linux เชื่อว่าผู้ใช้รู้ว่ากำลังทำอะไรและจะไม่ถามซ้ำ ขั้นนี้จึงเน้นทั้งวิธีใช้และนิสัยที่ปลอดภัย เช่น ตรวจด้วย ls ก่อนลบทุกครั้ง
ลงมือทำ
  • สร้างโครงสร้าง ~/projects/linux-lab/step03/{notes,scripts,backup} ด้วยคำสั่งเดียว
  • สร้างไฟล์ day1.txt ถึง day5.txt และ temp1.tmp ถึง temp3.tmp แล้วฝึกคัดลอก ย้าย และเปลี่ยนชื่อ
  • ลบเฉพาะไฟล์ *.tmp โดยรัน ls *.tmp ตรวจก่อน แล้วจึงรัน rm -i *.tmp
ใช้เวลา
3–4 ชั่วโมง ฝึกในโฟลเดอร์ ~/projects/linux-lab เท่านั้น
ระวัง

ห้ามลองคำสั่ง rm -rf /, rm -rf ~ หรือ sudo rm -rf กับโฟลเดอร์ที่ไม่แน่ใจ และระวัง Script ที่เขียน rm -rf "$DIR/" แล้วตัวแปร DIR ว่าง เพราะจะกลายเป็นการลบ / ทั้งเครื่อง วิธีป้องกันจะสอนใน Step 11 ด้วย set -u และ ${DIR:?}

Checkpoint

ก่อนไปขั้นถัดไป คุณต้องทำสิ่งเหล่านี้ได้: (1) สร้างโฟลเดอร์ notes, scripts และ backup พร้อมกันด้วยคำสั่งเดียว (2) คัดลอกทั้งโฟลเดอร์ notes ไปเป็น notes-backup แล้วเปลี่ยนชื่อไฟล์ในนั้นด้วย mv (3) ลบเฉพาะไฟล์ที่ลงท้ายด้วย .tmp โดยตรวจรายชื่อด้วย ls ก่อน (4) อธิบายได้ว่า day{1..3}.txt กับ day*.txt ต่างกันอย่างไร (5) บอกได้ว่าทำไม rm -r อันตราย และใช้ rm -i เพื่อให้ระบบถามก่อนลบ

STEP 4

2 วัน · 3–4 ชม.
หัวข้อย่อย

  • ดูต้นและท้ายไฟล์: head -n 5, tail -n 20 และ tail -f สำหรับดู Log ที่กำลังเพิ่มบรรทัดแบบสด (หยุดด้วย Ctrl+C)
  • นับด้วย wc: wc -l นับบรรทัด, wc -w นับคำ, wc -c นับไบต์
  • แก้ไขไฟล์ด้วย nano 7.2: เปิดไฟล์ด้วย nano ชื่อไฟล์, บันทึกด้วย Ctrl+O แล้วกด Enter, ออกด้วย Ctrl+X, ค้นหาด้วย Ctrl+W, ตัดบรรทัดด้วย Ctrl+K, วางด้วย Ctrl+U และดูวิธีใช้ด้วย Ctrl+G
  • Vim ขั้นเอาตัวรอด (Vim 9.1): เปิดด้วย vim ชื่อไฟล์, กด i เพื่อพิมพ์, กด Esc เพื่อออกจากโหมดพิมพ์, :w บันทึก, :wq บันทึกแล้วออก, :q! ออกโดยไม่บันทึก และฝึกต่อด้วย vimtutor
  • ตั้งโปรแกรมแก้ไขเริ่มต้นด้วย export EDITOR=nano เพราะคำสั่งอย่าง crontab -e และ git commit จะเปิดโปรแกรมนี้ให้
  • หาความช่วยเหลือในเครื่อง: man ls (ค้นหาใน man ด้วย / ออกด้วย q), หมวดของ man (1 คำสั่งทั่วไป, 5 รูปแบบไฟล์ Config, 8 คำสั่งผู้ดูแลระบบ), ls --help, help cd สำหรับคำสั่งในตัวของ Bash, type, which, whatis และ apropos (หรือ man -k)
  • tldr 0.9.2 ติดตั้งด้วย sudo apt install tldr แสดงตัวอย่างการใช้งานสั้นๆ ครั้งแรกจะดาวน์โหลดข้อมูลจากอินเทอร์เน็ตเอง และอัปเดตภายหลังด้วย tldr --update
  • เปิดไฟล์ใน VS Code จาก Terminal ด้วย code ชื่อไฟล์ สำหรับไฟล์ยาวที่ต้องแก้หลายจุด

3–4 ชั่วโมง ใช้เวลากับ nano มากที่สุด และฝึก Vim แค่พอเปิด แก้ และออกได้
Tip

ถ้าเผลอเปิด Vim แล้วออกไม่ได้ ให้กด Esc หนึ่งครั้ง แล้วพิมพ์ :q! ตามด้วย Enter จะออกโดยไม่บันทึกการแก้ไข

Checkpoint

ก่อนไปขั้นถัดไป คุณต้องทำสิ่งเหล่านี้ได้: (1) เปิดไฟล์ยาวด้วย less ค้นหาคำ และออกได้ (2) แสดง 5 บรรทัดแรกและ 5 บรรทัดสุดท้ายของไฟล์ และนับจำนวนบรรทัดด้วย wc -l (3) ใช้ tail -f ดูไฟล์ที่มีบรรทัดเพิ่มขึ้นแบบสดแล้วหยุดด้วย Ctrl+C (4) สร้าง แก้ไข บันทึก และออกจากไฟล์ด้วย nano ได้โดยไม่ต้องดูโพย (5) เปิดไฟล์ด้วย Vim แก้หนึ่งบรรทัด บันทึกและออกได้ (6) ใช้ man หรือ --help หา Option ที่ไม่เคยรู้จักได้เองโดยไม่ใช้ Google

Intermediate สิทธิ์ ซอฟต์แวร์ และพลังของ Pipe

ระดับนี้คือจุดที่ Linux เริ่มต่างจากการใช้คอมพิวเตอร์ทั่วไป คุณจะเข้าใจว่าทำไมบางคำสั่งขึ้น Permission denied ติดตั้งโปรแกรมได้ด้วยคำสั่งเดียว และต่อคำสั่งเล็กๆ หลายตัวเข้าด้วยกันเพื่อตอบคำถามจากข้อมูลจำนวนมาก เช่น "IP ไหนเข้าเว็บมากที่สุด" โดยไม่ต้องเขียนโปรแกรมเลย

STEP 5

Permissions, Ownership, Users และ sudo

3 วัน · 4–5 ชม.
หัวข้อย่อย
  • อ่านผลของ ls -l ให้ออก: ตัวแรกบอกชนิด (- ไฟล์, d โฟลเดอร์, l Symbolic link) ตามด้วยสิทธิ์ 3 ชุดของ user (เจ้าของ), group และ others แล้วจึงเป็นชื่อเจ้าของ ชื่อกลุ่ม ขนาด และเวลาแก้ไข
  • ความหมายของ r, w, x ที่ต่างกันระหว่างไฟล์กับโฟลเดอร์: สำหรับโฟลเดอร์ x คือสิทธิ์ cd เข้าไป และ w คือสิทธิ์สร้างหรือลบไฟล์ข้างใน
  • chmod แบบตัวเลข (r=4, w=2, x=1 เช่น 755, 644, 700, 600) และแบบสัญลักษณ์ (u+x, g-w, o-r, a+r) รวมถึงความเสี่ยงของ chmod -R และ chmod 777
  • เปลี่ยนเจ้าของด้วย sudo chown somchai:somchai ไฟล์ และเปลี่ยนกลุ่มด้วย chgrp
  • umask กำหนดสิทธิ์เริ่มต้นของไฟล์ใหม่ เช่น umask 0002 ทำให้ไฟล์ใหม่ได้ 664 และ umask 0022 ทำให้ได้ 644 (ตรวจค่าของเครื่องตัวเองด้วยคำสั่ง umask)
  • Users และ Groups: id, groups, ไฟล์ /etc/passwd, /etc/group และ /etc/shadow (อ่านได้เฉพาะ root), sudo adduser, sudo usermod -aG กลุ่ม ผู้ใช้, sudo deluser และ su - ชื่อผู้ใช้
  • sudo กับ root: ทำไมไม่ควรใช้งานเป็น root ตลอดเวลา, กลุ่ม sudo, sudo -l ดูสิทธิ์ของตัวเอง และการแก้ /etc/sudoers ต้องทำผ่าน sudo visudo เท่านั้น
  • Special permissions เบื้องต้น: Sticky bit บน /tmp (เห็นเป็น drwxrwxrwt) และ setuid บน /usr/bin/passwd (เห็นเป็น rwsr-xr-x)
  • ข้อควรรู้ของ WSL: ไฟล์ใน /mnt/c มักแสดงสิทธิ์เป็น rwxrwxrwx ทั้งหมด เพราะเป็นระบบไฟล์ NTFS ของ Windows จึงไม่ควรใช้ฝึกเรื่อง Permission
ทำไมต้องเรียน
Linux ถูกออกแบบให้หลายคนใช้เครื่องเดียวกันได้อย่างปลอดภัย ทุกไฟล์จึงมีเจ้าของและสิทธิ์ Permission denied เป็น Error ที่มือใหม่เจอบ่อยที่สุด ถ้าเข้าใจเรื่องนี้จะแก้ได้ในไม่กี่วินาที แทนที่จะแก้แบบผิดๆ ด้วย sudo หรือ chmod 777 ซึ่งเปิดช่องโหว่ให้ผู้บุกรุก การตั้งสิทธิ์ให้ถูกต้องยังเป็นพื้นฐานของ SSH Key (Step 10) และการ Hardening Server ในหัวข้อ Cyber Security
ลงมือทำ
  • สร้างไฟล์ hello.sh ที่มีบรรทัด echo "Hello Linux" ลองรัน ./hello.sh ให้เจอ Permission denied แล้วแก้ด้วย chmod +x hello.sh
  • สร้างไฟล์ secret.txt แล้วตั้งให้เจ้าของอ่านเขียนได้คนเดียวด้วย chmod 600 ตรวจผลด้วย ls -l
  • สร้างผู้ใช้ทดลอง labuser ด้วย sudo adduser labuser สลับไปเป็นผู้ใช้นั้นด้วย su - labuser ลองอ่านไฟล์ secret.txt ของ somchai ให้เจอ Permission denied แล้วลบผู้ใช้ทดลองด้วย sudo deluser --remove-home labuser
ใช้เวลา
4–5 ชั่วโมง ใช้เวลากับการแปลงสิทธิ์ระหว่างตัวอักษรกับตัวเลขจนคล่อง เพราะจะเจอทั้งสองแบบในงานจริง
Security

อย่าแก้ Permission denied ด้วย chmod 777 หรือใส่ sudo หน้าทุกคำสั่ง ให้ถามก่อนเสมอว่า "ใครควรเข้าถึงไฟล์นี้ได้บ้าง" แล้วให้สิทธิ์น้อยที่สุดที่ทำงานได้ (Principle of Least Privilege) และอย่ารันคำสั่ง sudo ที่คัดลอกมาจากอินเทอร์เน็ตโดยไม่เข้าใจว่ามันทำอะไร

Checkpoint

ก่อนไปขั้นถัดไป คุณต้องทำสิ่งเหล่านี้ได้: (1) แปลง rwxr-x--- เป็นตัวเลข 750 และแปลง 644 กลับเป็นตัวอักษรได้ในใจ (2) ทำให้ Script รันได้ด้วย chmod +x แล้วรันด้วย ./hello.sh (3) ตั้งไฟล์ลับให้เจ้าของอ่านได้คนเดียวด้วย chmod 600 (4) สร้างผู้ใช้ทดลอง เพิ่มเข้ากลุ่มด้วย usermod -aG ตรวจด้วย id แล้วลบผู้ใช้นั้น (5) อธิบายได้ว่าทำไมคำสั่ง cat /etc/shadow ขึ้น Permission denied แต่ sudo cat /etc/shadow อ่านได้

STEP 6

ติดตั้งและจัดการซอฟต์แวร์ด้วย apt

1–2 วัน · 2–3 ชม.
หัวข้อย่อย
  • Package, Repository และ Dependency คืออะไร และแหล่งแพ็กเกจของ Ubuntu 24.04 ที่ตั้งค่าไว้ในไฟล์ /etc/apt/sources.list.d/ubuntu.sources (รูปแบบใหม่ที่เรียกว่า deb822)
  • sudo apt update (ดาวน์โหลดรายการแพ็กเกจล่าสุด) ต่างจาก sudo apt upgrade (อัปเกรดโปรแกรมที่ติดตั้งแล้ว) อย่างไร และทำไมต้องรัน update ก่อนเสมอ
  • ค้นหาและดูรายละเอียด: apt search คำค้น, apt show ชื่อแพ็กเกจ และ apt policy ชื่อแพ็กเกจ (ดูเวอร์ชันที่ติดตั้งและเวอร์ชันที่มีให้ติดตั้ง)
  • ติดตั้งและลบ: sudo apt install -y, sudo apt remove (ลบโปรแกรมแต่เก็บ Config), sudo apt purge (ลบทั้ง Config) และ sudo apt autoremove (ลบ Dependency ที่ไม่มีใครใช้แล้ว)
  • ตรวจของที่ติดตั้ง: apt list --installed, apt list --upgradable, dpkg -l, dpkg -L ชื่อแพ็กเกจ (ไฟล์ทั้งหมดของแพ็กเกจ) และ dpkg -S /usr/bin/tree (ไฟล์นี้มาจากแพ็กเกจไหน)
  • apt กับ apt-get: apt ออกแบบมาให้คนพิมพ์ใช้ แสดงผลอ่านง่ายกว่า ส่วนใน Script ให้ใช้ apt-get เพราะรูปแบบผลลัพธ์คงที่ (ถ้าส่งผลของ apt เข้า Pipe จะเห็นคำเตือน WARNING: apt does not have a stable CLI interface. Use with caution in scripts.)
  • อ่าน Error ที่พบบ่อย: E: Unable to locate package (พิมพ์ชื่อผิดหรือยังไม่ได้ update), Could not open lock file ... Permission denied (ลืม sudo) และ Could not get lock /var/lib/dpkg/lock-frontend (มี apt อีกตัวทำงานอยู่ ให้รอจนเสร็จ)
  • แหล่งซอฟต์แวร์อื่น: Snap, PPA และไฟล์ .deb ความเสี่ยงของการเพิ่มแหล่งที่ไม่น่าเชื่อถือ และเหตุผลที่ Node.js กับ Go ในหลักสูตรนี้ติดตั้งผ่าน nvm และไฟล์ทางการแทน apt (เวอร์ชันใน apt เก่ากว่าที่หลักสูตรใช้)
ทำไมต้องเรียน
บน Linux แทบไม่มีการดาวน์โหลดไฟล์ติดตั้งจากเว็บแล้วกด Next แบบ Windows โปรแกรมเกือบทั้งหมดติดตั้งด้วย Package Manager ซึ่งจัดการ Dependency และอัปเดตความปลอดภัยให้ การอัปเดตแพ็กเกจสม่ำเสมอคือการปิดช่องโหว่ที่สำคัญที่สุดบน Server และ Dockerfile ที่จะเจอในหัวข้อ Backend ก็ใช้ apt-get แบบเดียวกันนี้
ลงมือทำ
  • อัปเดตระบบ แล้วติดตั้งชุดเครื่องมือของหัวข้อนี้ตามคำสั่งด้านล่าง
  • ใช้ dpkg -L tree หาว่าไฟล์โปรแกรม tree ถูกติดตั้งไว้ที่ไหน
  • ติดตั้ง cowsay ลองรัน /usr/games/cowsay "Hello" แล้วลบด้วย sudo apt purge cowsay ตามด้วย sudo apt autoremove
ใช้เวลา
2–3 ชั่วโมง เวลาส่วนหนึ่งเป็นการรอดาวน์โหลด ให้ใช้ช่วงนั้นอ่าน man apt

sudo apt update && sudo apt upgrade -y
# ติดตั้งชุดเครื่องมือที่ใช้ตลอดหัวข้อ Linux
# (ตัวที่มีอยู่แล้วในเครื่อง apt จะแจ้งว่า "is already the newest version" ไม่เป็นไร)
sudo apt install -y tree htop tldr shellcheck cron logrotate bind9-dnsutils zip unzip ncdu
# ตรวจเวอร์ชันของเครื่องมือหลัก
tree --version
htop --version
shellcheck --version | head -n 2

htop 3.3.0

version: 0.9.0
Checkpoint

ก่อนไปขั้นถัดไป คุณต้องทำสิ่งเหล่านี้ได้: (1) อธิบายความต่างของ apt update กับ apt upgrade ได้ (2) ค้นหาแพ็กเกจด้วย apt search ดูรายละเอียดด้วย apt show และติดตั้งได้ (3) ใช้ dpkg -L หาไฟล์ของแพ็กเกจ และ dpkg -S หาว่าไฟล์มาจากแพ็กเกจไหน (4) ลบแพ็กเกจพร้อม Config ด้วย purge และล้าง Dependency ด้วย autoremove (5) แก้ Error Could not open lock file และ Unable to locate package ได้เอง (6) บอกได้ว่าใน Script ควรใช้ apt-get เพราะอะไร

STEP 7

Pipes, Redirection และ Text Processing

1 สัปดาห์ · 6–8 ชม.
หัวข้อย่อย
  • Standard streams 3 ช่อง: stdin (0) ข้อมูลเข้า, stdout (1) ผลลัพธ์ปกติ และ stderr (2) ข้อความ Error
  • Redirection: > เขียนทับไฟล์, >> ต่อท้ายไฟล์, < อ่านจากไฟล์, 2> แยก Error ไปไฟล์, 2>&1 รวม Error เข้ากับผลลัพธ์ปกติ, &> แบบย่อของ Bash และ /dev/null สำหรับทิ้งผลลัพธ์ที่ไม่ต้องการ
  • Pipe | ส่งผลลัพธ์ของคำสั่งหนึ่งเป็นข้อมูลเข้าของคำสั่งถัดไป และ tee / tee -a สำหรับแสดงผลบนจอและบันทึกลงไฟล์พร้อมกัน
  • grep: -i ไม่สนตัวพิมพ์เล็กใหญ่, -n แสดงเลขบรรทัด, -v กลับผล, -c นับ, -r ค้นทั้งโฟลเดอร์, -l แสดงแค่ชื่อไฟล์, -w ตรงทั้งคำ, -o แสดงเฉพาะส่วนที่ตรง และ -E ใช้ Extended Regex
  • Regular Expression พื้นฐาน: ^ ต้นบรรทัด, $ ท้ายบรรทัด, . ตัวอักษรใดก็ได้, *, +, ?, [0-9] และ (a|b) เมื่อใช้ -E
  • เรียง นับ และตัดข้อมูล: sort (-n, -r, -k, -t, -u, -h), uniq (-c, -d ซึ่งต้อง sort ก่อนเสมอ), cut -d ',' -f 2, tr (แปลงตัวพิมพ์, -d ลบตัวอักษร, -s ยุบตัวซ้ำ) และ wc -l
  • sed พื้นฐาน: แทนที่ข้อความด้วย s/เก่า/ใหม่/g, ลบบรรทัดที่ตรงเงื่อนไขด้วย /pattern/d, แสดงบางบรรทัดด้วย -n '2,5p' และแก้ไฟล์จริงด้วย -i.bak (เก็บไฟล์สำรองไว้)
  • awk พื้นฐาน: แสดงคอลัมน์ '{print $1}', กำหนดตัวคั่น -F ',', ข้ามหัวตาราง NR>1, กรองแถว '$4 > 80' และหาผลรวมหรือค่าเฉลี่ยใน END { } โดย awk ใน Ubuntu 24.04 คือ mawk 1.3.4 จึงควรเขียนแบบ POSIX
  • find: -name, -iname, -type f หรือ d, -size +1M, -mtime -7, -exec คำสั่ง {} \; และ -delete (ต้องรันโดยไม่ใส่ -delete เพื่อตรวจรายชื่อก่อนทุกครั้ง) รวมถึง xargs และ find -print0 | xargs -0 สำหรับชื่อไฟล์ที่มีช่องว่าง
ทำไมต้องเรียน
นี่คือพลังที่แท้จริงของ Linux ตามแนวคิดของ Unix ที่ว่า "แต่ละโปรแกรมทำสิ่งเดียวให้ดี แล้วนำมาต่อกัน" คำถามอย่าง "เมื่อวานมีคนพยายาม Login ผิดกี่ครั้ง" หรือ "IP ไหนเรียกหน้า /admin บ่อยที่สุด" ตอบได้ด้วยคำสั่งบรรทัดเดียวในไม่กี่วินาที แม้ไฟล์ Log จะมีหลายล้านบรรทัด ทักษะนี้ใช้ตรงๆ ในงาน SOC Analyst, DevOps และ Data Engineer และยังเป็นพื้นฐานของการเขียน Bash Script ในขั้นต่อไป
ลงมือทำ
  • สร้างไฟล์ตัวอย่าง access.log (Log ของ Web Server 10 บรรทัด) แล้วหา 3 IP ที่เข้ามามากที่สุดด้วย Pipeline ด้านล่าง
  • สร้างไฟล์ members.csv (คอลัมน์ id,name,city,score) แล้วใช้ awk หาคะแนนเฉลี่ย และใช้ cut กับ sort -u หารายชื่อเมืองที่ไม่ซ้ำ
  • รัน find / -name "*.conf" 2>/dev/null | head เพื่อฝึกทิ้ง Error Permission denied จำนวนมากไปที่ /dev/null

  • เพิ่มโปรแกรมของตัวเองเข้า PATH: สร้าง ~/.local/bin (Ubuntu เพิ่มโฟลเดอร์นี้เข้า PATH ให้ผ่าน ~/.profile เมื่อโฟลเดอร์มีอยู่จริงตอน Login ครั้งถัดไป) หรือเพิ่มเองด้วย export PATH="$HOME/.local/bin:$PATH"
  • ไฟล์ตั้งค่าของ Shell: ~/.bashrc (โหลดทุกครั้งที่เปิด Terminal), ~/.profile (โหลดตอน Login), /etc/environment และการโหลดใหม่ด้วย source ~/.bashrc
  • Alias และฟังก์ชัน: alias ll='ls -alF' (Ubuntu มีให้แล้ว), สร้าง Alias ของตัวเองแบบถาวร, unalias และฟังก์ชันสั้นๆ ใน .bashrc เช่น mkcd ที่สร้างโฟลเดอร์แล้ว cd เข้าไปทันที
  • ปรับแต่ง Shell: PS1 (หน้าตา Prompt), HISTSIZE, HISTCONTROL=ignoreboth และ HISTTIMEFORMAT สำหรับบันทึกเวลาของแต่ละคำสั่งใน history
  • WSL Interop: code ., explorer.exe ., notepad.exe, clip.exe (cat file.txt | clip.exe คัดลอกเข้า Clipboard ของ Windows), wslpath -w แปลง Path ของ Linux เป็น Path ของ Windows และการเรียกโปรแกรม .exe ได้จาก Ubuntu เพราะ WSL ต่อ PATH ของ Windows ไว้ท้าย PATH ของ Linux
  • ปัญหาข้ามระบบ: ไฟล์ที่สร้างบน Windows ใช้ขึ้นบรรทัดแบบ CRLF ทำให้ Script ขึ้น Error $'\r': command not found แก้ด้วย sed -i 's/\r$//' ชื่อไฟล์ หรือเลือก LF ที่มุมขวาล่างของ VS Code และเรื่องความเร็วที่ต้องเก็บงานไว้ใน ~ ไม่ใช่ /mnt/c

STEP 9

Processes, Services และ Logs

3 วัน · 4–5 ชม.
หัวข้อย่อย
  • Process คืออะไร, PID และ PPID, ดู Process ทั้งหมดด้วย ps aux และ ps -ef, ค้นหาด้วย pgrep -a ชื่อ และดูแบบสดด้วย top (กด P เรียงตาม CPU, M เรียงตาม Memory, q ออก) และ htop 3.3.0
  • Signals: SIGINT (2, เกิดจาก Ctrl+C), SIGTERM (15, ค่าเริ่มต้นของ kill ขอให้ปิดอย่างเรียบร้อย), SIGKILL (9, บังคับปิดทันที ใช้เป็นทางเลือกสุดท้าย), SIGHUP (1) และ SIGTSTP (เกิดจาก Ctrl+Z) พร้อมคำสั่ง kill, kill -9 และ pkill
  • Job control: รันเบื้องหลังด้วย &, jobs, fg %1, bg %1, พักงานด้วย Ctrl+Z, nohup คำสั่ง & ให้ทำงานต่อหลังปิด Terminal และ tmux 3.4 สำหรับแบ่งหน้าจอและเก็บ Session ไว้
  • ทรัพยากรของเครื่อง: free -h (RAM), uptime และความหมายของ Load average, nproc (จำนวน CPU), ไฟล์ /proc/meminfo, /proc/loadavg และ vmstat 1 5
  • systemd คือโปรแกรมแรกที่เริ่มทำงาน (PID 1) และคุม Service ทั้งหมด ใน WSL ตรวจด้วย ps -p 1 -o comm= ถ้าได้ init ให้เปิดด้วยการเพิ่ม [boot] และ systemd=true ใน /etc/wsl.conf แล้วรัน wsl --shutdown ใน PowerShell
  • systemctl: status, start, stop, restart, reload, enable, disable, is-active, is-enabled, list-units --type=service และ systemctl --failed
  • journalctl: -u ชื่อ service, -f ดูแบบสด, -n 20, --since "1 hour ago", -p err เฉพาะ Error และ -b เฉพาะตั้งแต่เปิดเครื่องครั้งล่าสุด
  • Log ใน /var/log: syslog, auth.log (การ Login และการใช้ sudo), apt/history.log, dpkg.log และ dmesg สำหรับข้อความจาก Kernel (ไฟล์ syslog และ auth.log มีเมื่อติดตั้ง rsyslog ไว้ ถ้าไม่มีให้ใช้ journalctl)
ทำไมต้องเรียน
เมื่อเว็บล่มหรือเครื่องช้า สิ่งแรกที่ต้องตอบได้คือ "ตอนนี้โปรแกรมอะไรกิน CPU หรือ RAM อยู่" และ "Service ล่มเพราะอะไร" คำตอบทั้งสองอยู่ใน htop, systemctl status และ journalctl โปรแกรมของคุณเองในหัวข้อ Backend ก็จะถูกรันเป็น systemd Service บน Server การปิด Process ด้วย SIGTERM ก่อน SIGKILL ยังช่วยป้องกันข้อมูลเสียหาย เพราะให้โปรแกรมได้บันทึกงานก่อนปิด

STEP 10

Networking พื้นฐานและ SSH

3 วัน · 4–5 ชม.
หัวข้อย่อย
  • ความรู้เครือข่ายขั้นต่ำ: IP Address, Port, DNS, Gateway และ localhost (127.0.0.1) ซึ่งจะเรียนละเอียดใน
  • คำสั่งตรวจเครือข่าย: ip a (IP ของเครื่อง), ip route (Default gateway), hostname -I, ping -c 4, curl -I (ดู HTTP Header), curl -o และ wget (ดาวน์โหลดไฟล์)
  • ดู Port ที่เปิดอยู่ด้วย ss -tulpn (ต้องใส่ sudo จึงจะเห็นชื่อโปรแกรมของผู้ใช้อื่น) และถาม DNS ด้วย dig example.com, dig +short และ nslookup จากแพ็กเกจ bind9-dnsutils
  • ไฟล์สำคัญ: /etc/hosts และ /etc/resolv.conf ซึ่งใน WSL ถูกสร้างอัตโนมัติโดย WSL (บรรทัดแรกของไฟล์จะบอกไว้) จึงไม่ควรแก้เองโดยตรง
  • Network ของ WSL2: โหมด NAT เป็นค่าเริ่มต้น WSL มี IP ของตัวเองแยกจาก Windows, ระบบ localhost forwarding ทำให้ Browser บน Windows เปิด http://localhost:8000 ถึงโปรแกรมใน WSL ได้, โหมด mirrored (networkingMode=mirrored ในไฟล์ .wslconfig บน Windows 11) และปัญหา DNS เมื่อใช้ VPN
  • SSH Client และ Server: ssh ผู้ใช้@เครื่อง, ติดตั้ง Server ด้วย sudo apt install openssh-server (OpenSSH 9.6p1) และรู้ว่า Ubuntu 24.04 เปิดรับการเชื่อมต่อผ่าน ssh.socket (socket activation) ตรวจด้วย systemctl status ssh.socket
  • SSH Key: สร้างด้วย ssh-keygen -t ed25519 -C "somchai@wsl", ความต่างของ Private key (~/.ssh/id_ed25519 ห้ามแชร์) กับ Public key (.pub แชร์ได้), Passphrase, ssh-copy-id, ไฟล์ ~/.ssh/authorized_keys, สิทธิ์ 700 สำหรับ ~/.ssh และ 600 สำหรับ Private key และ ssh-agent กับ ssh-add
  • ไฟล์ ~/.ssh/config (Host, HostName, User, Port, IdentityFile) เพื่อพิมพ์ ssh lab แทนคำสั่งยาว และคัดลอกไฟล์ข้ามเครื่องด้วย scp และ rsync -avz (ติดตั้งด้วย sudo apt install rsync ถ้ายังไม่มี)
  • ความปลอดภัยของ SSH บน Server จริง: ปิดการ Login ด้วยรหัสผ่าน (PasswordAuthentication no), ไม่อนุญาตให้ root Login โดยตรง และติดตามการ Login จาก journalctl -u ssh หรือ /var/log/auth.log
ทำไมต้องเรียน
งานทุกอย่างบน Server เริ่มจากการ SSH เข้าไป และการ Push โค้ดขึ้น GitHub ใน ก็ใช้ SSH Key แบบเดียวกัน เมื่อแอปเชื่อมต่อกันไม่ได้ คำสั่งอย่าง ss, curl และ dig คือเครื่องมือแรกที่ใช้หาว่าปัญหาอยู่ที่ Port, DNS หรือตัวโปรแกรม การเข้าใจ Network ของ WSL2 ยังช่วยให้ไม่งงเมื่อเปิดเว็บที่รันใน Ubuntu จาก Browser บน Windows
ลงมือทำ

Bash Scripting ที่เชื่อถือได้

1 สัปดาห์ · 6–8 ชม.
หัวข้อย่อย
  • Shebang #!/usr/bin/env bash, chmod +x, ความต่างของการรันด้วย ./script.sh, bash script.sh และ source script.sh
  • ตัวแปรและ Quoting: ตั้งค่าโดยไม่มีช่องว่างรอบ =, "$var" (แทนค่าตัวแปร) ต่างจาก '$var' (ข้อความตรงตัว), Command substitution $(คำสั่ง), Arithmetic $(( a + b )), ค่าเริ่มต้น ${var:-default} และ Array เบื้องต้น
  • รับข้อมูลเข้า: Argument $0, $1, $#, "$@", shift, getopts สำหรับ Option แบบ -v และ read -r -p "ข้อความ: " ตัวแปร
  • เงื่อนไข: if / elif / else, test และ [ ] เทียบกับ [[ ]] ของ Bash, ตัวทดสอบ -f, -d, -z, -n, -eq, -lt, -gt และ case

  • Function และ Exit code: local, การคืนค่าผ่าน echo เทียบกับ return, $?, exit 0 (สำเร็จ) และ exit 1 (ล้มเหลว), การเชื่อมด้วย && และ || และการส่งข้อความ Error ออกทาง stderr ด้วย >&2
  • Strict mode: set -euo pipefail (-e หยุดเมื่อคำสั่งล้มเหลว, -u หยุดเมื่อใช้ตัวแปรที่ไม่ได้ตั้ง, pipefail ให้ Pipeline ล้มเหลวถ้าคำสั่งใดในนั้นล้มเหลว), trap 'cleanup' EXIT, mktemp และ ${DIR:?} ป้องกันตัวแปรว่าง
  • เครื่องมือคุณภาพ: ShellCheck 0.9.0 (shellcheck script.sh) อ่านรหัสคำเตือนเช่น SC2086 (ลืมใส่ Quote ครอบตัวแปร), Debug ด้วย bash -x script.sh หรือ set -x, Here-document <<'EOF', printf แทน echo และรูปแบบวันที่ date +%F_%H%M%S

งานที่ต้องพิมพ์คำสั่งเดิมซ้ำทุกวัน เช่น สำรองไฟล์ ตรวจพื้นที่ Disk หรือ Deploy เวอร์ชันใหม่ ควรเขียนเป็น Script ครั้งเดียวแล้วใช้ซ้ำได้ตลอด Script ที่ดีต้อง "ล้มให้เห็น" เมื่อมีปัญหา ไม่ทำงานต่อแบบผิดๆ จนลบไฟล์ผิดที่ set -euo pipefail กับ ShellCheck คือสองเครื่องมือที่ทีมมืออาชีพใช้เพื่อให้ Script เชื่อถือได้ และ Bash Script ยังเป็นภาษาที่ใช้ใน CI/CD, Dockerfile และงาน DevOps เกือบทุกที่
ลงมือทำ

  • เขียน backup.sh <โฟลเดอร์> ที่สร้างไฟล์ .tar.gz พร้อมวันที่ไว้ใน ~/backups และลบไฟล์สำรองที่เก่ากว่า 7 ชุด

#!/usr/bin/env bash
# count-lines.sh: นับจำนวนบรรทัดของไฟล์ที่ส่งเข้ามา
set -euo pipefail

usage() {
  # ข้อความวิธีใช้ส่งออกทาง stderr แล้วจบด้วย exit code 2
  echo "วิธีใช้: $(basename "$0") <ไฟล์>" >&2
  exit 2
}

main() {
  # ต้องมี argument 1 ตัวพอดี
  [[ $# -eq 1 ]] || usage
  local file="$1"
  # ตรวจว่าไฟล์มีอยู่จริง ถ้าไม่มีให้จบด้วย exit code 1
  if [[ ! -f "$file" ]]; then
    echo "ไม่พบไฟล์: $file" >&2
    exit 1
  fi
  local lines
  # อ่านไฟล์ผ่าน < เพื่อให้ wc แสดงแค่ตัวเลข
  lines=$(wc -l < "$file")
  echo "$file มี $lines บรรทัด"
}

main "$@"
# เข้าโฟลเดอร์ของขั้นนี้ (สร้างไฟล์ count-lines.sh ไว้ที่นี่ด้วย nano หรือ VS Code)

# กรณีปกติ: ใช้ไฟล์ access.log จาก Step 7

# กรณีไฟล์ไม่มีอยู่
./count-lines.sh nofile.txt; echo "exit code = $?"
# กรณีไม่ใส่ argument
./count-lines.sh; echo "exit code = $?"

exit code = 0

  • Log rotation: ทำไม Log ต้องหมุน (ไม่ให้เต็ม Disk), ไฟล์ Config ใน /etc/logrotate.d/, คำสั่งใน Config ของ logrotate 3.21.0 (daily, rotate 7, compress, delaycompress, missingok, notifempty, dateext) และการรัน logrotate ด้วยสิทธิ์ผู้ใช้ทั่วไปพร้อม State file ของตัวเอง (logrotate -s state.file config) รวมถึงทดสอบด้วย -d (Dry run) และ -f (บังคับหมุน)

Must-know Skills

ถ้าต้องสรุปหัวข้อนี้ให้เหลือทักษะที่ผู้สัมภาษณ์และงานจริงคาดหวังจากคนที่ "ใช้ Linux เป็น" จะได้รายการนี้

  1. เดินทางในระบบไฟล์ด้วย Absolute path และ Relative path เพราะทุกคำสั่งและทุก Script อ้างอิงตำแหน่งไฟล์ ถ้าเข้าใจผิดจะทำงานผิดที่หรือหาไฟล์ไม่เจอ
  2. จัดการไฟล์อย่างปลอดภัยด้วย cp, mv, rm และ Wildcard เพราะ Linux ไม่มีถังขยะ การตรวจก่อนลบและการสำรองก่อนแก้เป็นนิสัยที่ป้องกันความเสียหายร้ายแรงได้
  3. อ่านไฟล์และ Log ด้วย less, tail -f และ grep เพราะการแก้ปัญหาบน Server ทุกครั้งเริ่มจากการอ่าน Log เพื่อหาว่าเกิดอะไรขึ้น
  4. แก้ไขไฟล์ Config ด้วย nano หรือ vim เพราะบน Server ที่เข้าผ่าน SSH ไม่มีโปรแกรมแก้ไขแบบ GUI ให้ใช้
  5. เข้าใจ Permissions, Ownership และ sudo เพราะเป็นสาเหตุอันดับต้นของ Permission denied และการตั้งสิทธิ์ผิดคือช่องโหว่ความปลอดภัยที่พบบ่อย
  6. ติดตั้งและอัปเดตซอฟต์แวร์ด้วย apt เพราะการติดตั้ง Patch ความปลอดภัยสม่ำเสมอคือการป้องกันที่ได้ผลที่สุดของ Server
  7. ต่อคำสั่งด้วย Pipe และ Redirection เพราะทำให้ประมวลผลข้อมูลจำนวนมากได้ในบรรทัดเดียวโดยไม่ต้องเขียนโปรแกรม
  8. ประมวลผลข้อความด้วย grep, sort, uniq, cut, sed และ awk เพราะเป็นเครื่องมือหลักในการสรุปและวิเคราะห์ Log ของงาน DevOps และ Security
  9. จัดการ Environment Variable, PATH และ .bashrc เพราะเครื่องมือพัฒนาเกือบทุกตัวและค่าตั้งค่าของแอปพลิเคชันทำงานผ่านกลไกนี้
  10. ดูแล Process และ Service ด้วย ps, kill, systemctl และ journalctl เพราะต้องรู้ว่าอะไรกำลังทำงาน และกู้ Service ที่ล่มให้กลับมาได้อย่างรวดเร็ว
  11. ใช้ SSH Key และคำสั่งตรวจเครือข่ายพื้นฐาน เพราะ SSH คือประตูเข้า Server และ GitHub และคำสั่งอย่าง ss, curl, dig ช่วยหาจุดที่การเชื่อมต่อมีปัญหา
  12. เขียน Bash Script ที่เชื่อถือได้และตั้งเวลาด้วย cron เพราะงานที่ทำซ้ำควรเป็นอัตโนมัติ และ Script ที่มี set -euo pipefail และผ่าน ShellCheck จะไม่สร้างความเสียหายแบบเงียบๆ
