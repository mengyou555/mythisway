Mini Project: URL Shortener Service

เป้าหมายของโปรเจกต์

สร้าง Service ที่โฟลเดอร์ ~/projects/url-shortener ซึ่งรับ URL ยาว แล้วคืนรหัสสั้น (code) เช่น B45RTwb เมื่อมีคนเปิด http://localhost:3000/B45RTwb Server จะพาไปยัง URL ต้นฉบับ (Redirect) และนับจำนวนคลิกเก็บไว้ในฐานข้อมูล SQLite

หัวใจของโปรเจกต์มี 4 ข้อ

  1. ไม่เชื่อข้อมูลจากภายนอก: ทุก Body, Query และค่าใน .env ผ่าน zod ก่อนใช้ ถ้าผิดจะตอบ 400 หรือหยุดโปรแกรมทันที (Fail Fast)
  2. แยก app ออกจาก server: src/app.js สร้าง Express app โดยไม่ listen ส่วน src/server.js เป็นคนเปิดพอร์ตและปิดอย่างสุภาพ ทำให้ Test เรียก app ตรง ๆ ด้วยฐานข้อมูล ':memory:' ได้
  3. ปลอดภัยตั้งแต่ต้น: Prepared Statement ทุกคำสั่ง SQL, helmet, Rate Limit, จำกัดขนาด Body และไม่ส่ง Stack Trace ให้ Client ตอน Production
  4. พร้อม Deploy: มี Test 24 กรณี, Log แบบ JSON, Graceful Shutdown, Dockerfile ที่รันด้วยผู้ใช้ node และไฟล์ตั้งค่า pm2

ฟีเจอร์ทั้งหมด

  • สร้างลิงก์สั้นแบบสุ่ม 7 ตัวอักษรจาก A-Z a-z 0-9 ด้วย crypto.randomInt และลองใหม่สูงสุด 5 ครั้งถ้า code ชนกัน
  • ตั้งชื่อย่อเองได้ (Custom Alias) ตามรูปแบบ ^[A-Za-z0-9_-]{3,32}$ และห้ามใช้คำสงวน api กับ health
  • Redirect ด้วย 302 เป็นค่าเริ่มต้น หรือ 301 เมื่อสร้างลิงก์แบบ permanent: true
  • นับคลิกและบันทึกเวลาคลิกล่าสุดใน UPDATE คำสั่งเดียว
  • ดูรายการลิงก์แบบแบ่งหน้า (limit 1–100, offset) ดูสถิติของลิงก์เดียว และลบลิงก์
  • Error ทุกแบบตอบเป็น JSON รูปแบบเดียวกัน {"error": "...", "message": "...", "details"?: {...}}
  • อ่านค่าตั้งด้วย node --env-file=.env และตรวจด้วย zod ถ้าผิดจะพิมพ์ Error แล้วออกด้วย Exit Code 1
  • Log ทุก Request เป็น JSON ด้วย pino และ pino-http โดยซ่อน Header authorization และ cookie
  • Graceful Shutdown เมื่อได้รับ SIGINT หรือ SIGTERM และบังคับออกถ้าเกิน 10 วินาที
  • GET /health สำหรับ Docker, Load Balancer และระบบ Monitor

  2. Step 2: ค่าตั้งจาก .env ตรวจด้วย zod (src/config.js)

    ค่าใน process.env เป็น String เสมอ เช่น PORT ได้ '3000' ไม่ใช่ตัวเลข ไฟล์นี้ใช้ z.coerce.number() แปลงเป็นตัวเลข ใส่ค่าเริ่มต้นด้วย .default() และถ้าค่าผิดจะ throw พร้อมข้อความที่ z.prettifyError() จัดให้อ่านง่าย ฟังก์ชันรับ env เป็นพารามิเตอร์ จึงเขียน Test ส่งค่าปลอมเข้าไปได้โดยไม่ต้องแก้ process.env จริง

    import { z } from 'zod';

// Schema ของค่าตั้งทั้งหมด ค่าจาก process.env เป็น string เสมอ จึงใช้ z.coerce แปลงเป็นตัวเลข
const ConfigSchema = z.object({
  NODE_ENV: z.enum(['development', 'production', 'test']).default('development'),
  PORT: z.coerce.number().int().min(1).max(65535).default(3000),
  BASE_URL: z.url({ protocol: /^https?$/ }).default('http://localhost:3000'),
  DB_FILE: z.string().min(1).default('data/links.db'),
  LOG_LEVEL: z
    .enum(['fatal', 'error', 'warn', 'info', 'debug', 'trace', 'silent'])
    .default('info'),
  RATE_LIMIT_MAX: z.coerce.number().int().min(1).max(10000).default(10),
});

// อ่านค่าตั้งจาก env แล้วคืนเป็น object ที่ใช้ง่าย ถ้าค่าผิดจะ throw Error ทันที (Fail Fast)
export function loadConfig(env = process.env) {
  const result = ConfigSchema.safeParse(env);
  if (!result.success) {
    throw new Error(`ค่าตั้งใน .env ไม่ถูกต้อง:\n${z.prettifyError(result.error)}`);
  }
  const c = result.data;
  return {
    nodeEnv: c.NODE_ENV,
    port: c.PORT,
    baseUrl: c.BASE_URL.replace(/\/+$/, ''), // ตัด / ท้าย URL ออก
    dbFile: c.DB_FILE,
    logLevel: c.LOG_LEVEL,
    rateLimitMax: c.RATE_LIMIT_MAX,
  };
}
    บรรทัด / ส่วนความหมาย
    z.enum([...]).default('development')รับได้เฉพาะค่าในรายการ ถ้าไม่ได้ตั้งไว้ใช้ development
    z.coerce.number().int().min(1).max(65535)แปลง String เป็นตัวเลข แล้วตรวจว่าเป็นจำนวนเต็มในช่วงพอร์ตที่ใช้ได้
    z.url({ protocol: /^https?$/ })รูปแบบ zod 4 สำหรับตรวจ URL และจำกัดให้เป็น http หรือ https เท่านั้น
    safeParse(env)ตรวจโดยไม่ throw คืน { success, data } หรือ { success, error }
    z.prettifyError(result.error)แปลง Error ของ zod เป็นข้อความหลายบรรทัดที่บอกว่าฟิลด์ไหนผิด
    replace(/\/+$/, '')ตัด / ท้าย BASE_URL ออก กัน shortUrl กลายเป็น //code

    ลองส่งค่าผิดเพื่อดูว่า Fail Fast ทำงาน (ค่าที่ตั้งใน Shell มีผลเหนือค่าใน .env เพราะ --env-file ไม่เขียนทับตัวแปรที่มีอยู่แล้ว) ขั้นนี้ต้องมีไฟล์ src/server.js จาก Step 7 ก่อน ให้กลับมาลองหลังทำ Step 7 เสร็จ

export function openDb(file = ':memory:') {
  if (file !== ':memory:') {
    // สร้างโฟลเดอร์ data/ ให้ก่อน ไม่อย่างนั้น better-sqlite3 เปิดไฟล์ไม่ได้

  db.pragma('journal_mode = WAL'); // อ่านและเขียนพร้อมกันได้ดีขึ้น

    CREATE TABLE IF NOT EXISTS links (
      id              INTEGER PRIMARY KEY AUTOINCREMENT,
      code            TEXT    NOT NULL UNIQUE,
      url             TEXT    NOT NULL,
      permanent       INTEGER NOT NULL DEFAULT 0 CHECK (permanent IN (0, 1)),
      clicks          INTEGER NOT NULL DEFAULT 0,
      created_at      TEXT    NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%fZ', 'now')),
      last_clicked_at TEXT
    )
  `);
  return db;
}

// รวมคำสั่ง SQL ทั้งหมดไว้ที่เดียว ทุกคำสั่งเป็น Prepared Statement กัน SQL Injection
export function createLinkRepo(db) {
  const insert = db.prepare(
    'INSERT INTO links (code, url, permanent) VALUES (@code, @url, @permanent)',
  );
  const byCode = db.prepare('SELECT * FROM links WHERE code = ?');
  const list = db.prepare('SELECT * FROM links ORDER BY id DESC LIMIT ? OFFSET ?');
  const remove = db.prepare('DELETE FROM links WHERE code = ?');
  // เพิ่มจำนวนคลิกและเวลาคลิกล่าสุดใน UPDATE คำสั่งเดียว แล้วคืน url กลับมาเลย
  const click = db.prepare(`
    UPDATE links
       SET clicks = clicks + 1,
           last_clicked_at = strftime('%Y-%m-%dT%H:%M:%fZ', 'now')
     WHERE code = ?
 RETURNING url, permanent
  `);

  return {
    create({ code, url, permanent }) {
      insert.run({ code, url, permanent: permanent ? 1 : 0 });
      return byCode.get(code);
    },
    findByCode: (code) => byCode.get(code),
    list: (limit, offset) => list.all(limit, offset),
    remove: (code) => remove.run(code).changes, // คืนจำนวนแถวที่ถูกลบ (0 หรือ 1)
    click: (code) => click.get(code), // คืน undefined ถ้าไม่พบ code
  };
}

    import { randomInt } from 'node:crypto';

// ตัวอักษร 62 ตัว: A-Z a-z 0-9
export const ALPHABET = 'ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz0123456789';
// code ที่ห้ามใช้ เพราะชนกับ path ของระบบเอง
export const RESERVED_CODES = new Set(['api', 'health']);
export const CUSTOM_CODE_PATTERN = /^[A-Za-z0-9_-]{3,32}$/;

// สุ่ม code ด้วย crypto.randomInt ซึ่งปลอดภัยกว่า Math.random
export function generateCode(length = 7) {
  let code = '';
  for (let i = 0; i < length; i++) {
    code += ALPHABET[randomInt(ALPHABET.length)];
  }
  return code;
}

export function isReservedCode(code) {
  return RESERVED_CODES.has(String(code).toLowerCase());
}

// ตรวจชื่อย่อที่ผู้ใช้ตั้งเอง: รูปแบบถูกต้องและไม่ใช่คำสงวน
export function isValidCustomCode(code) {
  return typeof code === 'string' && CUSTOM_CODE_PATTERN.test(code) && !isReservedCode(code);
}

    เริ่มจาก Error Handler เพราะทุก Route จะ throw Error ที่ไฟล์นี้กำหนด คลาส HttpError เก็บ Status Code ชื่อ Error และข้อความไว้ด้วยกัน ส่วน errorHandler() เป็นที่เดียวที่แปลง Error ทุกแบบเป็น JSON รูปแบบเดียวกัน

    import { z } from 'zod';

// Error ที่รู้ Status Code และชื่อ error สำหรับตอบ Client
export class HttpError extends Error {
  constructor(status, error, message, details) {
    super(message);
    this.name = 'HttpError';
    this.status = status;
    this.error = error;
    this.details = details;
  }
}

// วางหลังทุก Route: ไม่มี Route ไหนตอบ แปลว่าไม่พบ
export function notFound(req, res, next) {
  next(new HttpError(404, 'NotFound', `ไม่พบเส้นทาง ${req.method} ${req.path}`));
}

// Error-handling Middleware ต้องมี 4 พารามิเตอร์ Express จึงจะรู้ว่าเป็นตัวจัดการ Error
export function errorHandler({ isProduction = false } = {}) {
  return (err, req, res, next) => {
    if (res.headersSent) return next(err); // ส่ง Response ไปแล้ว ให้ Express จัดการต่อ

    if (err instanceof z.ZodError) {
      return res.status(400).json({
        error: 'ValidationError',
        message: 'ข้อมูลไม่ถูกต้อง',
        details: z.flattenError(err).fieldErrors,
      });
    }
    if (err.type === 'entity.too.large') {
      return res.status(413).json({ error: 'PayloadTooLarge', message: 'Body ใหญ่เกิน 10kb' });
    }
    if (err.type === 'entity.parse.failed') {
      return res.status(400).json({ error: 'ValidationError', message: 'JSON ไม่ถูกต้อง' });
    }
    if (err instanceof HttpError) {
      const body = { error: err.error, message: err.message };
      if (err.details) body.details = err.details;
      return res.status(err.status).json(body);
    }

    // Error ที่ไม่ได้คาดไว้: บันทึก Log เต็ม ๆ แต่ไม่ส่ง stack ให้ Client ตอน production
    req.log.error({ err }, 'unhandled error');
    const body = {
      error: 'InternalServerError',
      message: isProduction ? 'เกิดข้อผิดพลาดภายในระบบ' : err.message,
    };
    if (!isProduction) body.stack = err.stack;
    return res.status(500).json(body);
  };
}

    import express from 'express';
import { createLinkSchema, listQuerySchema } from '../schemas.js';
import { generateCode } from '../lib/code.js';
import { HttpError } from '../middleware/error-handler.js';

const MAX_RETRIES = 5;

// แปลงแถวจากฐานข้อมูล (snake_case) เป็น JSON ที่ส่งให้ Client (camelCase)
export function toLinkJson(row, baseUrl) {
  return {
    code: row.code,
    url: row.url,
    shortUrl: `${baseUrl}/${row.code}`,
    permanent: row.permanent === 1,
    clicks: row.clicks,
    createdAt: row.created_at,
    lastClickedAt: row.last_clicked_at,
  };
}

const isUniqueError = (err) => err?.code === 'SQLITE_CONSTRAINT_UNIQUE';

export function linksRouter({ repo, baseUrl, createLimiter }) {
  const router = express.Router();

  // POST /api/links สร้างลิงก์สั้น (มี Rate Limit เฉพาะ Route นี้)
  router.post('/', createLimiter, (req, res) => {
    // parse() จะ throw ZodError ถ้าข้อมูลผิด แล้ว Express 5 ส่งต่อให้ errorHandler เอง
    const input = createLinkSchema.parse(req.body ?? {});
    let row;

    if (input.code) {
      try {
        row = repo.create(input);
      } catch (err) {
        if (isUniqueError(err)) {
          throw new HttpError(409, 'Conflict', `code "${input.code}" ถูกใช้แล้ว`);
        }
        throw err;
      }
    } else {
      // code สุ่มอาจชนกันได้ (โอกาสน้อยมาก) จึงลองใหม่ไม่เกิน 5 ครั้ง
      for (let attempt = 1; !row; attempt++) {
        try {
          row = repo.create({ ...input, code: generateCode() });
        } catch (err) {
          if (!isUniqueError(err) || attempt >= MAX_RETRIES) throw err;
        }
      }
    }

    res.status(201).location(`/api/links/${row.code}`).json(toLinkJson(row, baseUrl));
  });

  // GET /api/links?limit=20&offset=0 รายการลิงก์แบบแบ่งหน้า
  router.get('/', (req, res) => {
    const { limit, offset } = listQuerySchema.parse(req.query);
    const items = repo.list(limit, offset).map((row) => toLinkJson(row, baseUrl));
    res.json({ items, limit, offset });
  });

  // GET /api/links/:code สถิติของลิงก์เดียว
  router.get('/:code', (req, res) => {
    const row = repo.findByCode(req.params.code);
    if (!row) throw new HttpError(404, 'NotFound', `ไม่พบลิงก์ code ${req.params.code}`);
    res.json(toLinkJson(row, baseUrl));
  });

  // DELETE /api/links/:code ลบลิงก์ ตอบ 204 ไม่มี Body
  router.delete('/:code', (req, res) => {
    if (repo.remove(req.params.code) === 0) {
      throw new HttpError(404, 'NotFound', `ไม่พบลิงก์ code ${req.params.code}`);
    }
    res.status(204).end();
  });

  return router;
}

    import express from 'express';
import { HttpError } from '../middleware/error-handler.js';

const CODE_PATTERN = /^[A-Za-z0-9_-]{1,32}$/;

export function redirectRouter({ repo }) {
  const router = express.Router();

  // GET /:code พาไปยัง URL ต้นฉบับ: 301 ถ้าเป็นลิงก์ถาวร ไม่อย่างนั้น 302
  router.get('/:code', (req, res, next) => {
    const { code } = req.params;
    if (!CODE_PATTERN.test(code)) return next(); // รูปแบบผิด ปล่อยให้ 404 handler ตอบ

    const hit = repo.click(code); // นับคลิกและอ่าน url ในคำสั่งเดียว
    if (!hit) throw new HttpError(404, 'NotFound', `ไม่พบลิงก์ code ${code}`);

    res.redirect(hit.permanent === 1 ? 301 : 302, hit.url);
  });

  return router;
}

import helmet from 'helmet';
import { rateLimit } from 'express-rate-limit';
import pino from 'pino';
import { pinoHttp } from 'pino-http';
import { createLinkRepo } from './db.js';
import { linksRouter } from './routes/links.js';
import { redirectRouter } from './routes/redirect.js';
import { notFound, errorHandler } from './middleware/error-handler.js';

// สร้าง app โดยยังไม่ listen เพื่อให้เทสต์ส่ง db ':memory:' และค่าอื่นเข้ามาได้
export function createApp({
  db,
  baseUrl = 'http://localhost:3000',
  rateLimitMax = 10,
  logger = pino({ level: 'silent' }),
  nodeEnv = 'development',
} = {}) {
  if (!db) throw new Error('createApp ต้องการ db');
  const repo = createLinkRepo(db);
  const app = express();

  app.disable('x-powered-by'); // helmet ลบให้อยู่แล้ว แต่ปิดไว้อีกชั้นก็ไม่เสียหาย

  // Log ทุก Request เป็น JSON และซ่อน Header ที่เป็นความลับ
  app.use(
    pinoHttp({
      logger,
      redact: ['req.headers.authorization', 'req.headers.cookie'],
      // เก็บเฉพาะข้อมูลที่ต้องใช้ Log จะได้สั้นและอ่านง่าย
      serializers: {
        req: (req) => ({ id: req.id, method: req.method, url: req.url, headers: req.headers }),
        res: (res) => ({ statusCode: res.statusCode }),
      },
      customLogLevel: (req, res, err) => {
        if (err || res.statusCode >= 500) return 'error';
        if (res.statusCode >= 400) return 'warn';
        return 'info';
      },
    }),
  );
  app.use(helmet()); // ใส่ Security Header มาตรฐาน
  app.use(express.json({ limit: '10kb' })); // Body ใหญ่เกิน 10kb ได้ 413

  app.get('/health', (req, res) => {
    res.json({ status: 'ok', uptime: Math.round(process.uptime()) });
  });

  // จำกัดการสร้างลิงก์: rateLimitMax ครั้งต่อ 60 วินาทีต่อ IP
  const createLimiter = rateLimit({
    windowMs: 60_000,
    limit: rateLimitMax,
    standardHeaders: 'draft-8',
    legacyHeaders: false,
    message: { error: 'TooManyRequests', message: 'สร้างลิงก์ถี่เกินไป กรุณารอ 1 นาที' },
  });

  app.use('/api/links', linksRouter({ repo, baseUrl, createLimiter }));
  app.use(redirectRouter({ repo })); // ต้องอยู่หลัง /api และ /health

  app.use(notFound);
  app.use(errorHandler({ isProduction: nodeEnv === 'production' }));
  return app;
}

  7. Step 7: เปิด Server และ Graceful Shutdown (src/server.js)

    ไฟล์นี้เป็นจุดเริ่มโปรแกรม ทำงาน 4 อย่างตามลำดับ: อ่านค่าตั้ง เปิดฐานข้อมูล เปิดพอร์ต และเตรียมปิดตัวอย่างสุภาพ Graceful Shutdown คือเมื่อได้รับสัญญาณให้หยุด (Ctrl+C ส่ง SIGINT, ส่วน docker stop, pm2 และ systemd ส่ง SIGTERM) Server จะหยุดรับ Request ใหม่ รอ Request ที่ค้างอยู่ให้เสร็จ ปิดฐานข้อมูลให้เรียบร้อย แล้วจึงออก ข้อมูลจึงไม่เสียหายและผู้ใช้ไม่โดนตัดกลางทาง

// 4) Graceful Shutdown: หยุดรับงานใหม่ ปิด DB แล้วค่อยออก
let shuttingDown = false;
function shutdown(signal) {
  if (shuttingDown) return;
  shuttingDown = true;
  logger.info({ signal }, 'shutting down');

  // ถ้าปิดไม่เสร็จใน 10 วินาที ให้บังคับออกด้วย code 1
  const timer = setTimeout(() => {
    logger.error('shutdown timeout, forcing exit');
    process.exit(1);
  }, 10_000);
  timer.unref(); // ไม่ให้ timer นี้รั้ง process ไว้

  server.close((err) => {
    db.close();
    logger.info('server closed');
    process.exit(err ? 1 : 0);
  });
  server.closeIdleConnections(); // ปิด keep-alive connection ที่ว่างอยู่ทันที
}

process.on('SIGINT', () => shutdown('SIGINT'));
process.on('SIGTERM', () => shutdown('SIGTERM'));

## Features

- สร้างลิงก์สั้นแบบสุ่ม 7 ตัวอักษร หรือตั้งชื่อย่อเอง (alias)

- ตรวจ Input ด้วย zod 4 และตอบ Error เป็น JSON รูปแบบเดียวกันทุกที่
- SQLite ผ่าน better-sqlite3 ใช้ Prepared Statement ทุกคำสั่ง
- helmet, Rate Limit ที่ POST /api/links, จำกัดขนาด Body 10kb
- Log แบบ JSON ด้วย pino และซ่อน Header ที่เป็นความลับ
- Graceful Shutdown เมื่อได้รับ SIGINT / SIGTERM
- Test 24 กรณีด้วย node:test + supertest

Interview Questions

คำถาม 5 ข้อนี้ผสมระดับ Junior และ Mid-level ที่พบบ่อยในการสัมภาษณ์ตำแหน่ง Backend Developer และ Full-stack Developer ที่ใช้ Node.js ลองตอบด้วยตัวเองออกเสียงก่อน แล้วค่อยเปิดดูแนวคำตอบ ในห้องสัมภาษณ์จริง ให้อ้างถึงโปรเจกต์ URL Shortener ของคุณเป็นตัวอย่างทุกครั้งที่ทำได้

1. Node.js ทำงานบน Thread เดียว แล้วรับ Request พร้อมกันหลายพันตัวได้อย่างไร และงานแบบไหนไม่เหมาะกับ Node.js (Junior)

แนวคำตอบ: โค้ด JavaScript ของเรารันบน Main Thread เดียวจริง แต่งาน I/O เช่น อ่านไฟล์ คุยกับฐานข้อมูล หรือรอ Network ไม่ได้ทำบน Thread นั้น Node.js ส่งงานเหล่านี้ให้ libuv ซึ่งใช้กลไกของระบบปฏิบัติการ (epoll บน Linux) และ Thread Pool ของตัวเองทำแทน ระหว่างรอ Main Thread ว่างไปรับ Request อื่นได้ เมื่องาน I/O เสร็จ Callback หรือ Promise จะถูกนำกลับมาทำต่อผ่าน Event Loop นี่คือ Non-blocking I/O

จุดสำคัญที่ผู้สัมภาษณ์อยากได้ยิน:

  • Node.js = V8 (รัน JavaScript) + libuv (Event Loop และ Async I/O) + Core Modules
  • เหมาะกับงานที่ส่วนใหญ่เป็นการรอ I/O เช่น REST API, Real-time (WebSocket), API Gateway หรือ BFF และ CLI
  • ไม่เหมาะกับงานคำนวณหนักต่อเนื่อง (เข้ารหัสวิดีโอ คำนวณตัวเลขจำนวนมาก) บน Main Thread เพราะระหว่างคำนวณ Event Loop จะค้าง ทุก Request ต้องรอ ถ้าจำเป็นต้องทำ ให้ย้ายไป worker_threads หรือแยกเป็น Service อื่น

ตัวอย่างสั้น ๆ ที่ใช้อธิบาย: ใน URL Shortener ทุก Request ใช้เวลาเพียงไม่กี่มิลลิวินาที เพราะงานหลักคือคำสั่ง SQL สั้น ๆ Node.js ตัวเดียวจึงรับโหลดได้มาก แต่ถ้าเพิ่มฟีเจอร์ย่อรูปภาพขนาดใหญ่ใน Handler โดยตรง Request อื่นทั้งหมดจะช้าลงทันที

2. Middleware ใน Express คืออะไร ทำไมลำดับของ app.use() ถึงสำคัญ และ Express 5 จัดการ Error จาก async Handler ต่างจาก Express 4 อย่างไร (Junior–Mid)

แนวคำตอบ: Middleware คือฟังก์ชันรูปแบบ (req, res, next) ที่ Request วิ่งผ่านเรียงตามลำดับที่ลงทะเบียนไว้ แต่ละตัวทำได้ 3 อย่าง: แก้ req/res แล้วเรียก next() ให้ตัวถัดไปทำต่อ, ตอบกลับเลยแล้วจบ หรือเรียก next(err) เพื่อข้ามไปยัง Error-handling Middleware ที่มี 4 พารามิเตอร์ (err, req, res, next)

ลำดับสำคัญเพราะ Express ทำงานจากบนลงล่าง ตัวอย่างจากโปรเจกต์: pino-http ต้องอยู่บนสุดเพื่อ Log ทุก Request, express.json() ต้องอยู่ก่อน Route ไม่อย่างนั้น req.body เป็น undefined, Route /:code ต้องอยู่หลัง /health ไม่อย่างนั้นจะจับ /health ไปเป็น code และ 404 Handler กับ Error Handler ต้องอยู่ท้ายสุด

เรื่อง async: ใน Express 4 ถ้า async Handler throw หรือ Promise ถูก reject Express ไม่รู้ ต้องเขียน try/catch แล้วเรียก next(err) เอง หรือใช้ Package เสริม ไม่อย่างนั้น Request ค้างและเกิด Unhandled Rejection ส่วน Express 5 จับ Promise ที่ reject แล้วส่งให้ next(err) อัตโนมัติ โค้ดจึงสั้นลงมาก

// Express 5: Error จาก await ถูกส่งไป Error Handler เอง ไม่ต้อง try/catch
router.get('/:code', async (req, res) => {
  const link = await repo.findByCodeAsync(req.params.code);
  if (!link) throw new HttpError(404, 'NotFound', 'ไม่พบลิงก์');
  res.json(link);
});

คะแนนพิเศษถ้าพูดถึงการเปลี่ยนแปลงอื่นของ Express 5 เช่น Path แบบ '*' ต้องเขียนเป็น '/*splat' และ req.query เป็น Getter ที่แก้ค่าตรง ๆ ไม่ได้

3. มี Endpoint หนึ่งทำงานหนักจน Server ทั้งตัวตอบช้า คุณจะหาสาเหตุและแก้อย่างไร (Mid)

แนวคำตอบ: ผู้สมัครที่ดีจะตอบเป็นขั้นตอน ไม่เดาทันที

  1. ยืนยันอาการ: ดู Log ของ pino ว่า responseTime สูงขึ้นทุก Endpoint หรือเฉพาะตัวเดียว ถ้า Endpoint อื่นที่ปกติเร็วก็ช้าตามไปด้วย แปลว่า Event Loop ถูก Block
  2. วัดผล: ใช้ perf_hooks.monitorEventLoopDelay() ดูความหน่วงของ Event Loop หรือรันด้วย node --inspect แล้วอัด CPU Profile ใน Chrome DevTools ดูว่าฟังก์ชันไหนกิน CPU
  3. แก้ตามสาเหตุ:
    • ใช้ API แบบ Sync ใน Handler เช่น readFileSync หรือ crypto.pbkdf2Sync ให้เปลี่ยนเป็นแบบ Async
    • อ่านไฟล์หรือ Body ขนาดใหญ่ทั้งก้อน ให้เปลี่ยนเป็น Stream ด้วย pipeline()
    • JSON ขนาดใหญ่มาก ให้แบ่งหน้า (Pagination) เหมือน limit/offset ในโปรเจกต์
    • งาน CPU จริง ๆ ให้ย้ายไป worker_threads (หรือ Pool ของ Worker) หรือส่งเข้า Queue ให้ Service อื่นทำแล้วตอบ 202 Accepted
    • Regex ที่เขียนไม่ดีอาจใช้เวลานานมากกับ Input บางแบบ (ReDoS) ให้จำกัดความยาว Input ก่อนตรวจ
  4. ป้องกันซ้ำ: ตั้ง Alert ที่ Event Loop Delay และเพิ่ม Load Test ใน CI

คำตอบที่อ่อนคือ "เพิ่ม Server" อย่างเดียว เพราะถ้า Event Loop ถูก Block ทุก Instance ก็จะค้างแบบเดียวกัน

4. Graceful Shutdown คืออะไร ทำไม Service ที่รันใน Docker หรือ Kubernetes ต้องมี และเขียนอย่างไร (Mid)

แนวคำตอบ: Graceful Shutdown คือการปิดโปรแกรมแบบไม่ทิ้งงานค้าง เมื่อได้รับสัญญาณ SIGTERM (Docker, Kubernetes, systemd และ pm2 ส่งสัญญาณนี้ตอนสั่งหยุดหรือ Deploy เวอร์ชันใหม่) โปรแกรมต้อง:

  1. หยุดรับ Connection ใหม่ด้วย server.close()
  2. รอ Request ที่กำลังทำอยู่ให้เสร็จ และปิด Keep-Alive Connection ที่ว่างด้วย server.closeIdleConnections()
  3. ปิดทรัพยากรอื่น เช่น ฐานข้อมูล Queue และ Flush Log
  4. ออกด้วย Exit Code 0 และตั้ง Timer สำรองที่เรียก .unref() ไว้บังคับออกถ้าปิดไม่เสร็จในเวลาที่กำหนด (ไม่ควรเกินเวลาที่ Docker รอก่อนส่ง SIGKILL ซึ่งค่าเริ่มต้นคือ 10 วินาที ถ้าต้องรอนานกว่านั้นให้ตั้ง docker run --stop-timeout)

ถ้าไม่มี ระหว่าง Deploy ผู้ใช้จะเจอ Connection ถูกตัด และฐานข้อมูลอาจปิดไม่เรียบร้อย อีกจุดที่ต้องพูดถึงคือ Dockerfile ต้องใช้ CMD ["node", "src/server.js"] แบบ Exec Form ให้ Node เป็น PID 1 และได้รับสัญญาณโดยตรง ถ้าใช้ npm start สัญญาณอาจไปไม่ถึง Node และ Container จะถูก SIGKILL หลังหมดเวลา

process.on('SIGTERM', () => {
  // บังคับออกถ้าเกิน 10 วินาที และไม่ให้ timer นี้รั้ง process ไว้
  setTimeout(() => process.exit(1), 10_000).unref();
  server.close(() => {
    db.close();
    process.exit(0);
  });
  server.closeIdleConnections();
});
5. ถ้าให้ออกแบบ URL Shortener ที่รองรับผู้ใช้จำนวนมาก คุณจะเลือก 301 หรือ 302 จะสร้าง code ไม่ให้ซ้ำอย่างไร และจะป้องกันการใช้งานในทางที่ผิดอย่างไร (Mid)

แนวคำตอบ: คำถาม System Design ขนาดเล็กแบบนี้ ผู้สัมภาษณ์ดูว่าคุณชั่งข้อดีข้อเสียได้ ไม่ได้มองหาคำตอบเดียว

  • 301 หรือ 302: 301 ให้เบราว์เซอร์ Cache ได้ ลดโหลดของ Server แต่ทำให้นับคลิกไม่ครบและเปลี่ยนปลายทางภายหลังได้ยาก 302 นับคลิกได้ครบและแก้ปลายทางได้ จึงควรเป็นค่าเริ่มต้นถ้าธุรกิจต้องการสถิติ และให้ 301 เป็นตัวเลือกสำหรับลิงก์ถาวร (แบบเดียวกับโปรเจกต์ของเรา)
  • code ไม่ซ้ำ: สุ่มจากตัวอักษร 62 ตัวด้วย crypto.randomInt ยาว 7 ตัว ได้ประมาณ 3.5 ล้านล้านแบบ ให้ฐานข้อมูลบังคับด้วย UNIQUE แล้วลองใหม่เมื่อชน อีกทางคือแปลงเลข ID ที่เพิ่มขึ้นเรื่อย ๆ เป็นฐาน 62 ไม่มีวันชน แต่เดาลิงก์ถัดไปได้ง่าย ถ้าระบบมีหลาย Server ต้องมีตัวแจก ID กลาง
  • ขยายระบบ: การอ่าน (Redirect) มากกว่าการเขียนหลายเท่า จึงใส่ Cache เช่น Redis หน้าฐานข้อมูล นับคลิกแบบรวมเป็นชุด (Batch) แทนการ UPDATE ทุกคลิก และย้ายจาก SQLite ไป PostgreSQL เมื่อต้องรันหลาย Instance เพราะ SQLite เป็นไฟล์บนเครื่องเดียว
  • ป้องกันการใช้ผิด: Rate Limit ต่อ IP หรือต่อ API Key, รับเฉพาะ http/https, ตรวจ URL กับรายการเว็บอันตราย, ห้ามชื่อย่อที่ชนกับ Path ของระบบ และมีช่องทางแจ้งลิงก์ผิดกฎหมายเพื่อปิดลิงก์

ปิดท้ายด้วยตัวเลขจากโปรเจกต์จริงของคุณ เช่น "ผมเขียน Test 24 กรณีครอบคลุม 201, 301, 302, 400, 404, 409, 413 และ 429" จะทำให้คำตอบน่าเชื่อถือขึ้นมาก

แหล่งเรียนต่อ

เริ่มจากเอกสารทางการก่อนเสมอ เพราะอัปเดตตรงกับเวอร์ชันล่าสุด แล้วค่อยเสริมด้วยคอร์สและแนวปฏิบัติจากชุมชน

  • Node.js Learn – บทเรียนทางการของ Node.js ตั้งแต่การติดตั้ง Event Loop ไปจนถึง Security เหมาะอ่านคู่กับ Part 2 ฟรี
  • Node.js API Documentation – เอกสารอ้างอิงของ Core Module ทุกตัว เช่น fs, http, stream, test และ worker_threads เลือกเวอร์ชันให้ตรงกับเครื่องของคุณ ฟรี
  • Express – เอกสารทางการของ Express รวมคู่มือ Routing, Middleware, Error Handling และหน้าคู่มือย้ายจาก Express 4 ไป 5 ฟรี
  • Zod – เอกสารของ zod 4 อธิบาย Schema ทุกแบบ การจัดรูปแบบ Error และการใช้ร่วมกับ TypeScript ฟรี
  • better-sqlite3 – Repository และเอกสาร API ของ better-sqlite3 เช่น prepare, transaction และ pragma ฟรี
  • Pino – เอกสารของ pino ทั้งการตั้งค่า Level, Redaction, Transport และ pino-http ฟรี
  • npm Docs – คู่มือคำสั่ง npm, package.json, Semver และ npm audit ฟรี
  • Node.js Best Practices – รวมแนวปฏิบัติที่ดีจากชุมชน แบ่งเป็นหมวดโครงสร้างโปรเจกต์ Error Handling, Security, Testing และ Production ฟรี
  • The Odin Project – คอร์ส Full Stack JavaScript ที่มีบทเรียน Node.js และ Express พร้อมโปรเจกต์ให้ทำ ฟรี
  • Linux Foundation Training – แหล่งคอร์สและใบรับรองของ OpenJS Foundation เช่น JSNAD และ JSNSD ซึ่งเคยเปลี่ยนสถานะการเปิดสอบมาแล้ว ตรวจสอบก่อนวางแผนสมัครทุกครั้ง มีค่าใช้จ่าย
