Multiple Choice

เลือกคำตอบที่ถูกที่สุดเพียงข้อเดียว ทุกข้ออ้างอิงฐานข้อมูลร้านค้าตัวอย่าง (shop) ที่มีข้อมูลตั้งต้นครบ คือลูกค้า 8 คน หมวดสินค้า 7 หมวด สินค้า 10 รายการ คำสั่งซื้อ 14 รายการ และรายการสินค้าในคำสั่งซื้อ 22 แถว ถ้าไม่แน่ใจ ให้ลองรัน Query บนเครื่องของคุณเองก่อนเปิดเฉลย

  1. ง่าย

    ต้องการหาลูกค้าที่ไม่ได้ระบุเมือง (ค่า city เป็น NULL) Query ใดให้ผลลัพธ์ถูกต้อง

    1. SELECT name FROM customers WHERE city = NULL;
    2. SELECT name FROM customers WHERE city IS NULL;
    3. SELECT name FROM customers WHERE city = '';
    4. SELECT name FROM customers WHERE city <> NULL;
  2. ง่าย

    ข้อใดอธิบาย Primary Key ของตาราง customers (Column customer_id) ได้ถูกต้องที่สุด

    1. เป็น Column ที่ชี้ไปหา Primary Key ของตารางอื่น เพื่อเชื่อมความสัมพันธ์ระหว่างตาราง
    2. เป็น Column ที่เก็บค่าซ้ำกันได้ แต่ห้ามว่าง และช่วยให้ค้นหาเร็วขึ้นเท่านั้น
    3. เป็นค่าที่ไม่ซ้ำกันและไม่เป็น NULL ใช้ระบุลูกค้าแต่ละคนได้แบบไม่กำกวม
    4. เป็นลำดับของแถวในไฟล์ ถ้าลบลูกค้าคนหนึ่ง เลขของลูกค้าคนอื่นจะเลื่อนขึ้นมาแทนโดยอัตโนมัติ
  3. ง่าย

    ในข้อมูลตั้งต้น ลูกค้าอยู่ Bangkok 2 คน, Chiang Mai 2 คน, Khon Kaen 2 คน, Phuket 1 คน และไม่ระบุเมือง (NULL) 1 คน Query SELECT DISTINCT city FROM customers; จะคืนผลลัพธ์กี่แถว

    1. 4 แถว
    2. 8 แถว
    3. 5 แถว
    4. 7 แถว

    2. SQLite จะแจ้ง Error ว่าต้องมี WHERE ทุกครั้งที่ใช้ UPDATE
    3. เฉพาะแถวแรกของตาราง (Laptop Pro 14) เท่านั้นที่ถูกแก้
    4. ไม่มีแถวไหนถูกแก้ เพราะยังไม่ได้พิมพ์ COMMIT
  6. กลาง

    ต้องการแสดงสถานะคำสั่งซื้อที่มีมากกว่า 2 รายการ แล้วเขียน Query นี้ใน PostgreSQL 16 จะเกิดอะไรขึ้น และควรแก้อย่างไร

    SELECT status, COUNT(*)
FROM orders
WHERE COUNT(*) > 2
GROUP BY status;
    1. รันได้ และได้สถานะ pending, paid, shipped ไม่ต้องแก้อะไร
    2. เกิด ERROR: aggregate functions are not allowed in WHERE ต้องย้ายเงื่อนไขไปไว้ใน HAVING COUNT(*) > 2 หลัง GROUP BY
    3. เกิด Error เพราะต้องเขียน COUNT(status) แทน COUNT(*) เสมอเมื่อมี GROUP BY
    4. รันได้ แต่ได้ 0 แถว เพราะ WHERE ทำงานก่อนจึงยังนับไม่ได้ ต้องเพิ่ม ORDER BY ให้ถูก

    Subquery ในคำสั่งนี้คืนค่า 'Bangkok' (ของลูกค้าเลขที่ 1) และ NULL (ของลูกค้าเลขที่ 7) Query ทั้งก้อนจะได้ผลลัพธ์อย่างไรใน PostgreSQL 16

    SELECT name
FROM customers
WHERE city NOT IN (SELECT city FROM customers WHERE customer_id IN (1, 7));
    1. ได้ 0 แถว เพราะการเทียบ city <> NULL ให้ผลเป็น UNKNOWN ทำให้ NOT IN ไม่เคยเป็น TRUE
    2. ได้ 5 แถว คือลูกค้าทุกคนที่ไม่ได้อยู่ Bangkok ยกเว้น Duangjai Saendee
    3. ได้ 8 แถว เพราะ NULL ในรายการถูกข้ามไปเฉย ๆ
    4. เกิด Error more than one row returned by a subquery used as an expression

SELECT customer_id, name, email

NULL ไม่ใช่ค่า แต่หมายถึง "ไม่ทราบค่า" การเทียบอะไรก็ตามกับ NULL ด้วย = จึงได้ UNKNOWN ไม่ใช่ TRUE แม้แต่ NULL = NULL ก็ได้ UNKNOWN และ WHERE เก็บเฉพาะแถวที่เงื่อนไขเป็น TRUE เท่านั้น ถ้าเขียน WHERE city = NULL จะได้ 0 แถวโดยไม่มี Error เตือน ซึ่งอันตรายกว่า Error เสียอีก วิธีที่ถูกคือใช้ตัวดำเนินการเฉพาะ IS NULL หรือ IS NOT NULL

ข้อ 3

คำตอบ: HAVING

SELECT c.name, COUNT(*) AS order_count
FROM orders o
JOIN customers c ON c.customer_id = o.customer_id
GROUP BY c.customer_id, c.name
HAVING COUNT(*) >= 2
ORDER BY order_count DESC, c.name;

WHERE กรองทีละแถว "ก่อน" จัดกลุ่ม ตอนนั้นยังไม่มีค่า COUNT(*) ให้ใช้ ส่วน HAVING กรอง "หลัง" GROUP BY จึงใช้ Aggregate อย่าง COUNT(*) หรือ SUM() เป็นเงื่อนไขได้ ผลลัพธ์มี 5 คน เพราะ Somchai สั่ง 4 ครั้ง ส่วน Somying, Wichai, Manee และ Piti สั่งคนละ 2 ครั้ง (Manee มีคำสั่งซื้อที่ยกเลิก 1 รายการ แต่โจทย์ให้นับทุกสถานะ) ส่วน Chujai และ Duangjai สั่งคนละครั้งเดียวจึงถูกกรองออก

คำตอบ: ช่องแรก LEFT ช่องที่สอง IS NULL

SELECT c.customer_id, c.name
FROM customers c
LEFT JOIN orders o ON o.customer_id = c.customer_id
WHERE o.order_id IS NULL;

LEFT JOIN เก็บลูกค้าทุกคนจากตารางซ้ายไว้ ถึงจะหาคำสั่งซื้อที่คู่กันไม่เจอก็ตาม ในกรณีนั้น ทุก Column ของตาราง orders ในแถวนั้นจะเป็น NULL การกรอง WHERE o.order_id IS NULL จึงเหลือเฉพาะลูกค้าที่ไม่มีคู่ ซึ่งก็คือคนที่ไม่เคยสั่งซื้อ เทคนิคนี้เรียกว่า Anti Join

ควรตรวจ NULL ที่ Column ซึ่งเป็น Primary Key หรือ NOT NULL ของตารางขวา (เช่น o.order_id) เพราะ Column นี้จะเป็น NULL ได้กรณีเดียวคือหาคู่ไม่เจอ ถ้าเลือก Column ที่ปกติเป็น NULL ได้อยู่แล้ว ผลลัพธ์อาจผิด ถ้าใช้ INNER JOIN แทน ลูกค้าที่ไม่มีคำสั่งซื้อจะหายไปตั้งแต่ขั้น JOIN และได้ 0 แถว

WITH monthly AS (
    SELECT to_char(o.order_date, 'YYYY-MM')  AS month,
           SUM(oi.quantity * oi.unit_price) AS revenue
    FROM orders o
    JOIN order_items oi ON oi.order_id = o.order_id

-- ex_2.sql : สรุปลูกค้าและยอดขายตามหมวดสินค้า สำหรับทีมการตลาด (PostgreSQL 16)

-- ส่วนที่ 1: รายงานลูกค้า เก็บเป็น View ให้ทีมเรียกใช้ซ้ำ
-- CTE order_totals คำนวณยอดของแต่ละคำสั่งซื้อที่ไม่ถูกยกเลิก แล้ว LEFT JOIN กับลูกค้าทุกคน
CREATE OR REPLACE VIEW v_customer_summary AS
WITH order_totals AS (
    SELECT o.order_id,
           o.customer_id,
           o.order_date,
           SUM(oi.quantity * oi.unit_price) AS order_total
    FROM orders o
    JOIN order_items oi ON oi.order_id = o.order_id
    WHERE o.status <> 'cancelled'
    GROUP BY o.order_id, o.customer_id, o.order_date
)
SELECT c.customer_id,
       c.name,
       COALESCE(c.city, 'ไม่ระบุ')          AS city,
       COUNT(t.order_id)                    AS orders,
       COALESCE(SUM(t.order_total), 0)      AS total_spent,
       MAX(t.order_date)                    AS last_order,
       CASE
           WHEN COALESCE(SUM(t.order_total), 0) >= 30000 THEN 'VIP'
           WHEN COUNT(t.order_id) = 0 THEN 'ยังไม่เคยซื้อ'
           ELSE 'ลูกค้าทั่วไป'
       END                                  AS segment
FROM customers c
LEFT JOIN order_totals t ON t.customer_id = c.customer_id
GROUP BY c.customer_id, c.name, c.city;

-- ดูรายงานลูกค้าทั้งหมด เรียงจากยอดซื้อมากไปน้อย
SELECT *
FROM v_customer_summary
ORDER BY total_spent DESC, customer_id;

-- ส่วนที่ 2: ยอดขายตามหมวดสินค้า (ไม่นับคำสั่งซื้อที่ยกเลิก) เฉพาะหมวดที่ขายได้เกิน 5,000 บาท
SELECT cat.name                          AS category,
       COUNT(DISTINCT o.order_id)        AS orders,
       SUM(oi.quantity)                  AS units,
       SUM(oi.quantity * oi.unit_price)  AS revenue
FROM order_items oi
JOIN orders o      ON o.order_id = oi.order_id
JOIN products p    ON p.product_id = oi.product_id
JOIN categories cat ON cat.category_id = p.category_id
WHERE o.status <> 'cancelled'
GROUP BY cat.name
HAVING SUM(oi.quantity * oi.unit_price) > 5000
ORDER BY revenue DESC;

-- ส่วนที่ 3: ใช้ View ตอบคำถามสั้น ๆ 2 ข้อ
SELECT name, city, total_spent
FROM v_customer_summary
WHERE segment = 'VIP'
ORDER BY total_spent DESC;

SELECT segment, COUNT(*) AS customers, SUM(total_spent) AS revenue
FROM v_customer_summary
GROUP BY segment
ORDER BY revenue DESC;

-- ex_3.sql : Top-2 สินค้าต่อหมวดหลัก และแนวโน้มรายเดือน (PostgreSQL 16)

-- ส่วนที่ 1: หาหมวดหลัก (root) ของทุกหมวดด้วย Recursive CTE
WITH RECURSIVE cat_root AS (
    -- Anchor: หมวดบนสุด (ไม่มี parent) เป็น root ของตัวเอง
    SELECT category_id, category_id AS root_id, name AS root_name, 1 AS depth
    FROM categories
    WHERE parent_id IS NULL
    UNION ALL
    -- Recursive: หมวดลูกได้ root เดียวกับหมวดแม่
    SELECT c.category_id, r.root_id, r.root_name, r.depth + 1
    FROM categories c
    JOIN cat_root r ON c.parent_id = r.category_id
    WHERE r.depth < 10                      -- กันวนไม่รู้จบ
),
product_sales AS (
    -- ยอดขายต่อสินค้า ไม่นับคำสั่งซื้อที่ยกเลิก
    SELECT p.product_id, p.name, p.category_id,
           SUM(oi.quantity)                 AS units,
           SUM(oi.quantity * oi.unit_price) AS revenue
    FROM order_items oi
    JOIN orders o   ON o.order_id = oi.order_id
    JOIN products p ON p.product_id = oi.product_id
    WHERE o.status <> 'cancelled'
    GROUP BY p.product_id, p.name, p.category_id
),
ranked AS (
    SELECT r.root_name,
           s.name,
           s.units,
           s.revenue,
           ROW_NUMBER() OVER w                                      AS rn,
           ROUND(100.0 * s.revenue / SUM(s.revenue) OVER (PARTITION BY r.root_name), 1) AS pct_of_root
    FROM product_sales s
    JOIN cat_root r ON r.category_id = s.category_id
    WINDOW w AS (PARTITION BY r.root_name ORDER BY s.revenue DESC, s.name)
)
SELECT root_name, rn, name, units, revenue, pct_of_root
FROM ranked
WHERE rn <= 2                               -- Window Function ใช้ใน WHERE ตรง ๆ ไม่ได้ จึงกรองชั้นนอก
ORDER BY root_name, rn;

-- ส่วนที่ 2: ยอดขายรายเดือน ยอดสะสม และการเติบโตเทียบเดือนก่อน
WITH monthly AS (
    SELECT date_trunc('month', o.order_date)::date AS month,
           SUM(oi.quantity * oi.unit_price)       AS revenue
    FROM orders o
    JOIN order_items oi ON oi.order_id = o.order_id
    WHERE o.status <> 'cancelled'
    GROUP BY 1
)
SELECT to_char(month, 'YYYY-MM')                         AS month,
       revenue,
       SUM(revenue) OVER (ORDER BY month)                AS running_total,
       LAG(revenue) OVER (ORDER BY month)                AS prev_month,
       ROUND(100.0 * (revenue - LAG(revenue) OVER (ORDER BY month))
             / NULLIF(LAG(revenue) OVER (ORDER BY month), 0), 1) AS growth_pct
FROM monthly
ORDER BY month;

"""sales_report.py : รายงานยอดขายตามช่วงวันที่ ใช้ psycopg 3 และ Parameterized Query เท่านั้น"""
import argparse
import os
import sys
from datetime import date

import psycopg
from psycopg.rows import dict_row

# อ่าน Connection String จาก Environment Variable ไม่เขียนรหัสผ่านลงในโค้ด
DATABASE_URL = os.environ.get("DATABASE_URL", "postgresql:///shop")

# ยอดรวมของช่วงเวลา: ทุกค่าที่มาจากผู้ใช้ส่งผ่าน %(ชื่อ)s เท่านั้น
SUMMARY_SQL = """
SELECT COUNT(DISTINCT o.order_id)                          AS orders,
       COALESCE(SUM(oi.quantity * oi.unit_price), 0)       AS revenue
FROM orders o
JOIN customers c    ON c.customer_id = o.customer_id
JOIN order_items oi ON oi.order_id = o.order_id
WHERE o.status <> 'cancelled'
  AND o.order_date BETWEEN %(start)s AND %(end)s
  AND (%(city)s::text IS NULL OR c.city = %(city)s)
"""

# Top-N สินค้าต่อหมวดหลัก: Recursive CTE + ROW_NUMBER()
TOP_SQL = """
WITH RECURSIVE cat_root AS (
    SELECT category_id, name AS root_name, 1 AS depth
    FROM categories
    WHERE parent_id IS NULL
    UNION ALL
    SELECT c.category_id, r.root_name, r.depth + 1
    FROM categories c
    JOIN cat_root r ON c.parent_id = r.category_id
    WHERE r.depth < 10
),
product_sales AS (
    SELECT p.name, p.category_id,
           SUM(oi.quantity)                 AS units,
           SUM(oi.quantity * oi.unit_price) AS revenue
    FROM order_items oi
    JOIN orders o    ON o.order_id = oi.order_id
    JOIN customers c ON c.customer_id = o.customer_id
    JOIN products p  ON p.product_id = oi.product_id
    WHERE o.status <> 'cancelled'
      AND o.order_date BETWEEN %(start)s AND %(end)s
      AND (%(city)s::text IS NULL OR c.city = %(city)s)
    GROUP BY p.name, p.category_id
),
ranked AS (
    SELECT r.root_name, s.name, s.units, s.revenue,
           ROW_NUMBER() OVER (PARTITION BY r.root_name
                              ORDER BY s.revenue DESC, s.name) AS rn
    FROM product_sales s
    JOIN cat_root r ON r.category_id = s.category_id
)
SELECT root_name, rn, name, units, revenue
FROM ranked
WHERE rn <= %(top)s
ORDER BY root_name, rn
"""


def parse_args():
    """อ่านตัวเลือกจาก Command Line และตรวจชนิดข้อมูลตั้งแต่ต้นทาง"""
    parser = argparse.ArgumentParser(description="รายงานยอดขายตามช่วงวันที่")
    parser.add_argument("--start", type=date.fromisoformat, required=True,
                        help="วันเริ่มต้น รูปแบบ YYYY-MM-DD")
    parser.add_argument("--end", type=date.fromisoformat, required=True,
                        help="วันสิ้นสุด (รวมวันนี้ด้วย) รูปแบบ YYYY-MM-DD")
    parser.add_argument("--top", type=int, default=2, choices=range(1, 11),
                        metavar="N", help="จำนวนสินค้าอันดับต้นต่อหมวดหลัก (1-10)")
    parser.add_argument("--city", default=None, help="กรองตามเมืองของลูกค้า (ไม่ใส่ = ทุกเมือง)")
    args = parser.parse_args()
    if args.start > args.end:
        parser.error("--start ต้องไม่อยู่หลัง --end")
    return args


def main():
    args = parse_args()
    params = {"start": args.start, "end": args.end, "city": args.city, "top": args.top}

    try:
        # with ... as conn: สำเร็จแล้ว commit, เกิด Exception แล้ว rollback และปิด Connection ให้เอง
        with psycopg.connect(DATABASE_URL, row_factory=dict_row) as conn:
            summary = conn.execute(SUMMARY_SQL, params).fetchone()
            top_rows = conn.execute(TOP_SQL, params).fetchall()
    except psycopg.OperationalError as exc:
        print(f"เชื่อมต่อฐานข้อมูลไม่ได้: {exc}", file=sys.stderr)
        return 1

    city_label = args.city if args.city else "ทุกเมือง"
    print(f"รายงานยอดขาย {args.start} ถึง {args.end} ({city_label})")
    print("-" * 52)
    orders = summary["orders"]
    revenue = summary["revenue"]
    aov = revenue / orders if orders else 0
    print(f"จำนวนคำสั่งซื้อ : {orders:>12,}")
    print(f"ยอดขายรวม      : {revenue:>12,.2f} บาท")
    print(f"ยอดเฉลี่ยต่อบิล  : {aov:>12,.2f} บาท")
    print("-" * 52)
    if not top_rows:
        print("ไม่มียอดขายในช่วงนี้")
        return 0
    print(f"Top {args.top} สินค้าต่อหมวดหลัก")
    for row in top_rows:
        print(f"  {row['root_name']:<12} #{row['rn']}  {row['name']:<20}"
              f" {row['units']:>3} ชิ้น {row['revenue']:>12,.2f}")
    return 0


if __name__ == "__main__":
    sys.exit(main())

  • Parameterized Query ทุกจุด: สคริปต์ไม่ต่อสตริง SQL เลย ทุกค่าที่มาจากผู้ใช้ (วันที่ เมือง และจำนวนอันดับ) ส่งผ่าน %(ชื่อ)s และ Dict params ตัวเดียวใช้ได้กับทั้งสอง Query Payload Bangkok' OR '1'='1 จึงเป็นแค่ชื่อเมืองแปลก ๆ ที่ไม่มีลูกค้าคนไหนอยู่ และได้ 0 คำสั่งซื้อ
  • ป้องกันหลายชั้น (Defense in Depth): argparse ตรวจชนิดข้อมูลตั้งแต่ต้นทาง (date.fromisoformat, int กับ choices) และตรวจตรรกะ (start ต้องไม่อยู่หลัง end) ข้อมูลผิดรูปแบบจึงไม่ไปถึงฐานข้อมูลเลย และ argparse จบโปรแกรมด้วย Exit Code 2 ให้เอง
