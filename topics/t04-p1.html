4.1Learning Roadmap

ภาพรวมเส้นทาง

JavaScript คือภาษาโปรแกรมเพียงภาษาเดียวที่เว็บเบราว์เซอร์ทุกตัวรันได้โดยตรง ทุกครั้งที่คุณกดปุ่มแล้วหน้าเว็บเปลี่ยนโดยไม่โหลดใหม่ พิมพ์ในช่องค้นหาแล้วมีคำแนะนำขึ้นมา หรือเห็นตัวนับเวลาถอยหลังบนหน้าจอ เบื้องหลังคือ JavaScript ทั้งหมด และตั้งแต่มี Node.js ภาษาเดียวกันนี้ก็ใช้เขียน Server, เครื่องมือ Command Line, ระบบอัตโนมัติ และแอป Desktop ได้ด้วย

คุณเรียน Python มาแล้ว จึงเข้าใจหลักการเขียนโปรแกรม เช่น ตัวแปร เงื่อนไข ลูป ฟังก์ชัน และ List อยู่แล้ว หัวข้อนี้จึงไม่ได้เริ่มจากศูนย์ แต่จะเน้น สิ่งที่ JavaScript ต่างจาก Python และ สิ่งที่มีเฉพาะในโลกของเว็บ คือ HTML, CSS, DOM, Event และการทำงานแบบ Asynchronous เส้นทางนี้แบ่งเป็น 14 ขั้นใน 3 ระดับ ระดับ Beginner สอน HTML และ CSS เท่าที่จำเป็นต่อการเขียน JavaScript กับหน้าเว็บ พร้อมไวยากรณ์พื้นฐานของภาษา ระดับ Intermediate สอนการจัดการข้อมูล Module, npm และการควบคุมหน้าเว็บด้วย DOM และ Event ระดับ Advanced สอน Closure, Class, Asynchronous JavaScript, Event Loop, Debugging และ Testing แล้วจบด้วย Mini Project Interactive Quiz App ที่นำไปใส่ Portfolio ได้

JavaScript คืออะไร ทำงานที่ไหนบ้าง

ก่อนเริ่มเขียนโค้ด ให้รู้จักคำศัพท์ต่อไปนี้ก่อน เพราะจะเจอในเอกสาร ข้อความ Error และคำถามสัมภาษณ์งานตลอดเส้นทาง

คำศัพท์ความหมายตัวอย่างที่จะได้ใช้
JavaScript (JS)ภาษาโปรแกรมที่ Brendan Eich สร้างขึ้นที่บริษัท Netscape ในปี 1995 เพื่อให้หน้าเว็บโต้ตอบกับผู้ใช้ได้ ชื่อคล้าย Java แต่เป็นคนละภาษากันโดยสิ้นเชิงไฟล์ .js ทุกไฟล์ในหัวข้อนี้
ECMAScript (ES)ชื่อทางการของมาตรฐานภาษา JavaScript ดูแลโดยคณะกรรมการ TC39 ของ Ecma International ตั้งแต่ปี 2015 ออกรุ่นใหม่ทุกปี เรียกตามปี เช่น ES2015 (บางคนเรียก ES6) ซึ่งเพิ่ม let, const, Arrow function, Class, Module และ Promiseบทความที่เขียนว่า "ES6+" หรือ "Modern JavaScript" หมายถึงไวยากรณ์ที่หัวข้อนี้สอน ดูรุ่นล่าสุดได้ที่ tc39.es
JavaScript Engineโปรแกรมที่อ่านโค้ด JavaScript แล้วแปลงเป็นคำสั่งที่ CPU ทำงานได้V8 (Chrome, Edge และ Node.js), SpiderMonkey (Firefox), JavaScriptCore (Safari)
Runtimeสภาพแวดล้อมที่ห่อ Engine ไว้ และเพิ่มความสามารถให้โค้ดเข้าถึงโลกภายนอก เช่น หน้าจอ ไฟล์ หรือเครือข่าย ภาษาเดียวกันจึงมีความสามารถต่างกันตาม Runtimeเบราว์เซอร์มี document และ localStorage ส่วน Node.js มี process และโมดูล node:fs สำหรับอ่านเขียนไฟล์
Node.jsRuntime ที่นำ V8 มารันนอกเบราว์เซอร์ ทำให้ใช้ JavaScript เขียน Server, CLI และเครื่องมือพัฒนาได้ หลักสูตรนี้ติดตั้งผ่าน nvm และใช้รุ่น LTS (Long Term Support)คำสั่ง node hello.js และ node --test
DOM (Document Object Model)โครงสร้างข้อมูลแบบต้นไม้ที่เบราว์เซอร์สร้างจาก HTML ให้ JavaScript อ่านและแก้ไขหน้าเว็บได้ DOM เป็นความสามารถของเบราว์เซอร์ ไม่ใช่ส่วนหนึ่งของตัวภาษา Node.js จึงไม่มี documentdocument.querySelector('#score') แล้วเปลี่ยนข้อความที่แสดงคะแนน
Web APIsชุดความสามารถที่เบราว์เซอร์เตรียมไว้ให้ JavaScript เรียกใช้ นอกเหนือจาก DOMfetch, localStorage, setTimeout, setInterval
npmPackage Manager ที่มากับ Node.js ใช้ติดตั้งไลบรารีจาก npm Registry และรันคำสั่งที่กำหนดใน package.json ทำหน้าที่คล้าย pip ของ Pythonnpm init -y, npm install, npm test
เปรียบเทียบ

ให้นึกถึงเครื่องยนต์รถ Engine (V8) คือเครื่องยนต์ที่ทำให้รถวิ่งได้ ส่วน Runtime คือตัวรถทั้งคันที่ประกอบเครื่องยนต์นั้นไว้ เบราว์เซอร์เปรียบเหมือนรถเก๋งที่มีกระจกให้มองเห็นถนน (DOM) ส่วน Node.js เปรียบเหมือนรถบรรทุกที่มีกระบะขนของ (อ่านเขียนไฟล์และเปิด Server) เครื่องยนต์เป็นตัวเดียวกัน แต่รถแต่ละแบบทำงานได้ต่างกัน

เหตุผลที่ควรเรียน JavaScript เป็นภาษาที่สองต่อจาก Python มีดังนี้

  • เป็นภาษาเดียวที่รันในเบราว์เซอร์ได้โดยตรง ถ้าต้องการทำหน้าเว็บที่โต้ตอบกับผู้ใช้ ไม่ว่าจะใช้ Framework ใดในอนาคต เช่น React, Vue หรือ Svelte ทั้งหมดคือ JavaScript
  • ใช้ภาษาเดียวได้ทั้ง Frontend และ Backend ด้วย Node.js ทีมเล็กและ Product Builder จึงสร้างผลิตภัณฑ์ทั้งระบบได้เร็ว
  • เป็นพื้นฐานของหัวข้อถัดไป TypeScript คือ JavaScript ที่เพิ่มระบบ Type ส่วน Node.js คือ JavaScript ฝั่ง Server ถ้าพื้นฐาน JavaScript ไม่แน่น ทั้งสองหัวข้อจะยากมาก
  • จำเป็นต่องานสาย Security และ AI การเข้าใจช่องโหว่อย่าง XSS ต้องอ่าน JavaScript ออก และแอป AI ส่วนใหญ่มีหน้าแชตที่เขียนด้วย JavaScript
  • เห็นผลงานทันที เปิดเบราว์เซอร์ก็เห็นสิ่งที่ตัวเองสร้าง และแชร์ลิงก์ให้คนอื่นดูได้ ซึ่งช่วยสร้าง Portfolio ได้ง่าย

หัวข้อย่อย
  • โครงสร้างของเอกสาร HTML: <!DOCTYPE html>, <html lang="th">, <head> ที่มี <meta charset="UTF-8">, <meta name="viewport"> และ <title> และ <body> ที่เป็นเนื้อหาซึ่งผู้ใช้มองเห็น
  • Element, Tag และ Attribute: Tag เปิดและปิด การซ้อนกัน (Nesting) ที่ต้องปิดในลำดับย้อนกลับ Void element ที่ไม่มี Tag ปิด เช่น <img>, <input>, <br> และการใส่ค่า Attribute ใน Quote
  • แท็กเนื้อหาที่ใช้บ่อย: h1 ถึง h6 (เรียงลำดับหัวข้อ ไม่ข้ามระดับ), p, a href, img src alt, ul/ol/li, strong, em และ button
  • Semantic tags: header, nav, main, section, article, aside และ footer บอกความหมายของแต่ละส่วน ช่วยทั้ง Screen reader, Search engine และคนที่อ่านโค้ด แทนการใช้ div ทุกที่
  • Form: form, label for ที่ผูกกับ id ของ input, ชนิดของ input (text, email, number, password, checkbox, radio), textarea, select/option, Attribute name และความต่างของ button type="submit" กับ type="button"
  • Validation ที่มากับ HTML: required, minlength, maxlength, min, max, pattern และ type="email" ซึ่ง JavaScript ตรวจได้ด้วย checkValidity() และปิดข้อความอัตโนมัติของเบราว์เซอร์ได้ด้วย novalidate
  • id, class และ data-*: จุดเชื่อมระหว่าง HTML กับ CSS และ JavaScript โดย id ต้องไม่ซ้ำในหน้าเดียวกัน ส่วน data-level="3" อ่านได้จาก JavaScript ด้วย element.dataset.level
  • Accessibility (การเข้าถึงได้) ขั้นพื้นฐาน: ใส่ alt ให้รูปทุกรูป ใส่ label ให้ช่องกรอกทุกช่อง ใช้ button สำหรับสิ่งที่กดได้ ใช้งานด้วยคีย์บอร์ดได้ด้วย Tab และกำหนด lang="th" ให้ Screen reader อ่านภาษาไทยถูก

STEP 3

CSS พื้นฐาน: Selector, Box Model, Flexbox และ Responsive

4–5 วัน · 5–7 ชม.
หัวข้อย่อย
  • วิธีใส่ CSS สามแบบ: ไฟล์แยกผ่าน <link rel="stylesheet" href="style.css"> (แนะนำ), แท็ก <style> ในหน้า และ Attribute style บน Element (ควรเลี่ยง) และรูปแบบของ Rule selector { property: value; }
  • Selector ที่ต้องรู้: ชื่อแท็ก (p), Class (.card), Id (#score), ลูกหลาน (main p), ลูกโดยตรง (ul > li), Attribute ([data-level="3"]) และ Pseudo-class (:hover, :focus-visible, :nth-child(2), :checked, :disabled) ทั้งหมดนี้ใช้ซ้ำใน document.querySelector ได้ทันที
  • Cascade, Specificity และ Inheritance: เมื่อหลาย Rule ขัดกัน Id ชนะ Class และ Class ชนะชื่อแท็ก Rule ที่อยู่ทีหลังชนะเมื่อน้ำหนักเท่ากัน จึงควรจัดหน้าตาด้วย Class เป็นหลัก และหลีกเลี่ยง !important
  • Box Model: Content, Padding, Border และ Margin ความต่างของ box-sizing: content-box กับ border-box และ Reset ที่นิยมใช้ *, *::before, *::after { box-sizing: border-box; }
  • การแสดงผลและหน่วย: display แบบ block, inline, inline-block และ none หน่วย px, rem, %, vw, vh สีแบบ Hex และ rgb() และ font-family กับ line-height ที่ทำให้อ่านภาษาไทยสบายตา
  • Flexbox: display: flex, flex-direction, justify-content, align-items, gap, flex-wrap และ flex: 1 รวมถึงการจัดของให้อยู่กึ่งกลางทั้งแนวตั้งและแนวนอน
  • Responsive design: แนวคิด Mobile-first และ Media query @media (min-width: 600px) { ... } ที่ทำงานคู่กับ <meta name="viewport"> จาก Step 2
  • CSS สำหรับคนเขียน JavaScript: Class บอกสถานะ เช่น .is-active, .is-hidden, .is-correct ที่ JavaScript เพิ่มหรือลบ, CSS Custom properties (--color-primary) และ @media (prefers-reduced-motion: reduce) สำหรับผู้ใช้ที่ไม่ต้องการภาพเคลื่อนไหว
  • DevTools: แผง Styles, Computed และแผนภาพ Box Model ในแท็บ Elements และ Device toolbar (Ctrl+Shift+M) สำหรับดูหน้าเว็บในขนาดจอมือถือ
ทำไมต้องเรียน
งานส่วนใหญ่ของ JavaScript บนหน้าเว็บคือการเปลี่ยนหน้าตาตามสถานะ เช่น แสดงคำตอบที่ถูกเป็นสีเขียว หรือซ่อนหน้าคำถามเมื่อทำครบ วิธีที่ถูกต้องคือให้ JavaScript เพิ่มหรือลบ Class แล้วให้ CSS เป็นผู้กำหนดหน้าตา ถ้าไม่เข้าใจ Selector และ Specificity จะแก้ไม่ได้ว่าทำไม Class ที่เพิ่มไปไม่มีผล ถ้าไม่เข้าใจ Box Model และ Flexbox จะเสียเวลามากกับการจัดหน้าที่ไม่ยอมเรียงตามที่ต้องการ
ลงมือทำ

  • ลบบรรทัด gap: 12px; แล้วดูว่าความกว้างของการ์ดเปลี่ยนเป็นเท่าไร และลองเปลี่ยน justify-content เป็นค่าต่างๆ

5–6 วัน · 6–8 ชม.
หัวข้อย่อย
  • let กับ const: ใช้ const เป็นค่าเริ่มต้น และใช้ let เฉพาะเมื่อต้องกำหนดค่าใหม่ ทำไมไม่ใช้ var (Scope แบบฟังก์ชันและ Hoisting ที่ทำให้เกิดบั๊ก) กฎการตั้งชื่อ และรูปแบบ camelCase
  • ชนิดข้อมูล Primitive 7 ชนิด: string, number, bigint, boolean, undefined, null, symbol และชนิด object ตรวจชนิดด้วย typeof และข้อยกเว้นที่ต้องจำคือ typeof null ได้ 'object'
  • ตัวดำเนินการ: คณิตศาสตร์ (+ - * / % **), เพิ่มลดค่า (++, --), กำหนดค่า (+=, -=), เปรียบเทียบ (< > <= >=), ตรรกะ (&&, ||, !) และการใช้วงเล็บกำหนดลำดับการคำนวณ
  • === กับ ==: == แปลงชนิดข้อมูลก่อนเทียบ (Type coercion) ทำให้ '5' == 5, 0 == '' และ null == undefined เป็นจริง จึงใช้ === และ !== เสมอ และ NaN ไม่เท่ากับตัวเอง ต้องตรวจด้วย Number.isNaN()
  • Truthy และ Falsy: ค่าที่เป็นเท็จมีแค่ false, 0, -0, 0n, '', null, undefined และ NaN ค่าอื่นทั้งหมดเป็นจริง รวมถึง '0', 'false', [] และ {}
  • กับดักของตัวเลข: 0.1 + 0.2 ไม่เท่ากับ 0.3 พอดี, toFixed() คืนค่าเป็น String, Number('42px') ได้ NaN แต่ parseInt('42px', 10) ได้ 42 และควรเก็บเงินเป็นหน่วยสตางค์ที่เป็นจำนวนเต็ม
  • String: Quote สามแบบ ('...', "...", `...`), Template literal ที่แทรกค่าด้วย ${} และเขียนหลายบรรทัดได้ และเมธอด length, toUpperCase, trim, includes, startsWith, slice, split, replaceAll, padStart และ at(-1)

// grades.js — เงื่อนไข ลูป และฟังก์ชัน
const students = [
  { name: 'สมชาย', score: 82 },
  { name: 'สมหญิง', score: 91 },
  { name: 'มานี', score: 67 },
  { name: 'ปิติ', score: 45 },
];

// Function declaration: เรียกใช้ก่อนบรรทัดที่ประกาศได้
function toGrade(score) {
  if (score >= 80) {
    return 'A';
  } else if (score >= 70) {
    return 'B';
  } else if (score >= 60) {
    return 'C';
  } else if (score >= 50) {
    return 'D';
  }
  return 'F';
}

// Arrow function พร้อม Default parameter
const formatScore = (score, unit = 'คะแนน') => `${score} ${unit}`;

// Rest parameter รวมอาร์กิวเมนต์ที่เหลือเป็น Array
function average(...scores) {
  let sum = 0;
  for (const s of scores) {
    sum += s;
  }
  return sum / scores.length;
}

// for...of วนทีละคน และใช้ ternary เลือกข้อความ
for (const student of students) {
  const grade = toGrade(student.score);
  const status = grade === 'F' ? 'ต้องสอบซ่อม' : 'ผ่าน';
  console.log(`${student.name}: ${formatScore(student.score)} เกรด ${grade} (${status})`);
}

// switch เหมาะกับการเทียบค่าเดียวกับหลายกรณี
function gradeMessage(grade) {
  switch (grade) {
    case 'A':
      return 'ยอดเยี่ยม';
    case 'B':
    case 'C':
      return 'ดี';
    default:
      return 'สู้ต่อไป';
  }
}

console.log('ค่าเฉลี่ย:', average(82, 91, 67, 45));
console.log('ข้อความเกรด B:', gradeMessage('B'));
console.log('หน่วยแบบกำหนดเอง:', formatScore(9, 'แต้ม'));

// while: นับถอยหลังจนเงื่อนไขเป็นเท็จ
let countdown = 3;
while (countdown > 0) {
  console.log('เริ่มสอบใน', countdown);
  countdown--;
}

// map: แปลงทุกตัวเป็นค่าใหม่ (ได้ Array ใหม่ความยาวเท่าเดิม)

// filter: เลือกเฉพาะตัวที่เงื่อนไขเป็นจริง

console.log('มูลค่าสต็อก:', stockValue, 'บาท');

// find และ some
console.log(products.find((p) => p.id === 'p3').name);
console.log('มีของหมดไหม:', products.some((p) => p.stock === 0));

// กับดักของ sort: ค่าเริ่มต้นเรียงแบบ String และแก้ Array เดิม
const prices = products.map((p) => p.price);
console.log([...prices].sort()); // 9 ไปอยู่ท้ายเพราะ '9' > '6' แบบ String
console.log(prices.toSorted((a, b) => a - b)); // ถูกต้อง และไม่แก้ Array เดิม
console.log('Array เดิม:', prices);

// Destructuring, Spread, Optional chaining และ Nullish coalescing
const { name, price, discount } = products[0];
console.log(name, price, discount ?? 'ไม่มีส่วนลด');

const updated = { ...products[1], stock: 30 }; // คัดลอกแล้วแก้เฉพาะ stock
console.log(updated.stock, products[1].stock);

const order = { customer: { name: 'สมชาย' } };
console.log(order.customer?.address?.city ?? 'ยังไม่กรอกที่อยู่');
console.log(0 || 'ค่าเริ่มต้น', 0 ?? 'ค่าเริ่มต้น'); // || มอง 0 เป็นเท็จ แต่ ?? ไม่

// Object.entries แปลง Object เป็นคู่ [key, value]
const countByCategory = {};
for (const p of products) {
  countByCategory[p.category] = (countByCategory[p.category] ?? 0) + 1;
}
console.log(Object.entries(countByCategory));

// src/price.js — โมดูลคำนวณราคา (Named exports)
export const VAT_PERCENT = 7;

// คืนราคารวม VAT ปัดเป็นทศนิยม 2 ตำแหน่ง
export function withVat(price) {

}

// Default export: 1 ไฟล์มีได้แค่ 1 ตัว
export default function formatBaht(amount) {
  return amount.toLocaleString('th-TH', { style: 'currency', currency: 'THB' });
}

import formatBaht, { withVat, VAT_PERCENT } from './src/price.js';

console.log(`รวม VAT ${VAT_PERCENT}%:`, formatBaht(withVat(price)));

DOM: เลือก แก้ไข และสร้าง Element

5–6 วัน · 6–8 ชม.
หัวข้อย่อย
  • DOM คือต้นไม้ของ Node: document เป็นราก แต่ละ Tag เป็น Element node และข้อความเป็น Text node มีความสัมพันธ์แบบ Parent, Children และ Sibling และแท็บ Elements ใน DevTools แสดง DOM ปัจจุบัน ไม่ใช่ไฟล์ HTML ต้นฉบับ

  • รูปแบบ State แล้ว Render: เก็บข้อมูลจริงไว้ในตัวแปร JavaScript แล้วให้ฟังก์ชัน render() สร้างหน้าจอจากข้อมูลทุกครั้งที่ข้อมูลเปลี่ยน แทนการเก็บข้อมูลไว้ใน DOM ซึ่งเป็นแนวคิดเดียวกับ React
  • เคล็ดลับ DevTools: $0 คือ Element ที่เลือกอยู่ในแท็บ Elements, $('selector') เป็นทางลัดของ querySelector ใน Console และ Break on subtree modifications เพื่อหาว่าโค้ดบรรทัดใดแก้ DOM

STEP 9

Events, Event Delegation และ Forms

5–6 วัน · 7–9 ชม.
หัวข้อย่อย
  • addEventListener(type, handler) และ Event ที่ใช้บ่อย: click, input, change, submit, keydown, focus, blur และ DOMContentLoaded พร้อมเหตุผลที่ไม่ใช้ Attribute onclick="..." ใน HTML
  • Event object: event.target (Element ที่ถูกคลิกจริง) กับ event.currentTarget (Element ที่ผูก Listener ไว้), event.key สำหรับคีย์บอร์ด และ event.preventDefault() เพื่อหยุดพฤติกรรมปกติ เช่น การส่งฟอร์มแล้วโหลดหน้าใหม่
  • Event propagation: Event เดินทางลงจาก document ถึง Element เป้าหมาย (Capturing) แล้วไหลกลับขึ้นไปหา Element แม่ทุกชั้น (Bubbling) และเหตุผลที่ควรเลี่ยง stopPropagation()
  • Event delegation: ผูก Listener ตัวเดียวที่ Element แม่ แล้วใช้ event.target.closest('[data-action]') หาว่าคลิกโดนอะไร ทำงานกับ Element ที่สร้างทีหลังได้ทันที และใช้หน่วยความจำน้อยกว่าการผูกทุกปุ่ม
  • เอา Listener ออก: removeEventListener ที่ต้องส่งฟังก์ชันตัวเดียวกับตอนผูก, Option { once: true } และ AbortController สำหรับเอาออกหลายตัวพร้อมกัน
  • อ่านข้อมูลจากฟอร์ม: ฟัง Event submit ที่ form ไม่ใช่ click ที่ปุ่ม, input.value เป็น String เสมอ, Number() หรือ valueAsNumber, checkbox.checked, new FormData(form) กับ Object.fromEntries และ form.reset()
  • ตรวจความถูกต้อง: Constraint Validation API (checkValidity(), reportValidity(), setCustomValidity(), validity.valueMissing) การแสดงข้อความ Error เองเมื่อใส่ novalidate, Attribute aria-invalid และพื้นที่ aria-live="polite" ที่ Screen reader อ่านข้อความใหม่ให้
  • Accessibility ของการโต้ตอบ: button รองรับ Enter และ Space ให้อัตโนมัติ คีย์ลัดด้วย keydown เช่น กดเลข 1 ถึง 4 เพื่อเลือกคำตอบ และห้ามลบเส้นขอบ Focus โดยไม่มีสิ่งทดแทน

let nextId = 1;

  event.preventDefault(); // หยุดไม่ให้เบราว์เซอร์ส่งฟอร์มและโหลดหน้าใหม่

    input.setAttribute('aria-invalid', 'true');
    console.log('ฟอร์มไม่ผ่าน:', JSON.stringify(input.value));
    return;
  }
  error.textContent = '';
  input.removeAttribute('aria-invalid');

  const li = document.createElement('li');
  li.dataset.id = String(nextId++);
  const text = document.createElement('span');
  text.textContent = title;
  const del = document.createElement('button');
  del.type = 'button';
  del.textContent = 'ลบ';
  del.dataset.action = 'delete';

  list.append(li);
  form.reset();
  console.log('เพิ่มงาน:', title, '| ทั้งหมด', list.children.length, 'งาน');
});

STEP 11

Scope, Closures, Hoisting, this และ Classes

6–7 วัน · 7–10 ชม.
หัวข้อย่อย
  • Scope สามระดับ: Global, Function และ Block (ภายใน { } สำหรับ let และ const) และ Module scope ที่ทำให้ตัวแปรระดับบนสุดของแต่ละไฟล์ไม่รั่วไปไฟล์อื่น รวมถึง Lexical scope คือฟังก์ชันมองเห็นตัวแปรตามตำแหน่งที่ฟังก์ชันถูกเขียน ไม่ใช่ตำแหน่งที่ถูกเรียก
  • Closure: ฟังก์ชันด้านในจำตัวแปรของฟังก์ชันด้านนอกไว้ได้แม้ฟังก์ชันด้านนอกทำงานจบแล้ว ใช้สร้างข้อมูลส่วนตัว (Private state) เช่น ตัวนับ ฟังก์ชันที่สร้างฟังก์ชัน once() และ debounce() สำหรับช่องค้นหา
  • Hoisting: Function declaration ถูกยกขึ้นไปทั้งตัวจึงเรียกก่อนบรรทัดที่ประกาศได้ var ถูกยกขึ้นไปพร้อมค่า undefined ส่วน let, const และ class อยู่ใน Temporal Dead Zone (TDZ) ใช้ก่อนประกาศจะได้ ReferenceError: Cannot access 'x' before initialization
  • กฎของ this: เรียกแบบ obj.method() ได้ obj เรียกเป็นฟังก์ชันเดี่ยวๆ ได้ undefined (ใน Module และ Class ซึ่งเป็น Strict mode) Arrow function ไม่มี this ของตัวเองแต่ใช้ของบริเวณรอบข้าง และกำหนด this เองได้ด้วย call, apply และ bind
  • ปัญหา this หายที่พบบ่อย: ส่ง Method ไปเป็น Callback เช่น button.addEventListener('click', game.next) หรือ setTimeout(player.describe, 1000) และวิธีแก้ด้วย bind หรือ Arrow function ครอบ
  • Class: constructor, Instance field, Method, Getter และ Setter, static, Private field และ Private method ที่ขึ้นต้นด้วย #, การสืบทอดด้วย extends และ super และการตรวจด้วย instanceof
  • Prototype: Class เป็นไวยากรณ์ที่ครอบระบบ Prototype ไว้ Method เก็บอยู่ที่ Prototype ไม่ได้อยู่ในทุก Object ซึ่งอธิบายว่าทำไมทุก Array เรียก map ได้ (เพราะอยู่ใน Array.prototype)
  • Custom Error: class QuizError extends Error ที่ตั้ง this.name เอง เพื่อแยกประเภทของ Error ใน catch และหลักการเลือกระหว่าง Class กับ Object ธรรมดาและฟังก์ชัน รวมถึงหลัก Composition over inheritance
ทำไมต้องเรียน
Closure อยู่เบื้องหลัง Event handler, Callback และ React Hooks ทุกตัว ส่วนปัญหา this หายเป็นบั๊กที่พบบ่อยที่สุดเมื่อใช้ Class กับ Event ทั้งสองเรื่องเป็นคำถามสัมภาษณ์งาน JavaScript ระดับ Mid ที่ถามแทบทุกบริษัท การเข้าใจ Hoisting ช่วยให้อ่านข้อความ ReferenceError และ TypeError แล้วรู้สาเหตุทันที และ Class เป็นรูปแบบที่ใช้มากใน TypeScript, Node.js และไลบรารีจำนวนมาก
ลงมือทำ
  • สร้างตัวอย่างด้านล่าง แล้วทายผลทุกบรรทัดก่อนรัน
  • เขียนฟังก์ชัน once(fn) ที่คืนฟังก์ชันใหม่ซึ่งเรียก fn ได้แค่ครั้งแรกครั้งเดียว และ debounce(fn, ms) ที่เรียก fn เมื่อหยุดเรียกไปแล้ว ms มิลลิวินาที
  • รันโค้ด for (var i = 0; i < 3; i++) { setTimeout(() => console.log(i), 0); } แล้วเปลี่ยน var เป็น let อธิบายว่าทำไมผลต่างกัน
  • เขียนคลาส BankAccount ที่มี Private field #balance เมธอด deposit และ withdraw ที่โยน RangeError เมื่อถอนเกินยอด และ Getter balance

// 3) Class: แม่แบบของ Object ที่มีข้อมูลและพฤติกรรม
class Player {
  #score = 0; // Private field ใช้ได้เฉพาะในคลาส

  constructor(name) {
    this.name = name;
  }

  addPoints(points) {
    if (points <= 0) throw new RangeError('points ต้องมากกว่า 0');
    this.#score += points;
    return this; // คืน this เพื่อเรียกต่อกันเป็นสายได้
  }

  get score() {
    return this.#score;
  }

  static compare(a, b) {
    return b.score - a.score;
  }
}

class TimedPlayer extends Player {
  constructor(name, seconds) {
    super(name); // ต้องเรียก super ก่อนใช้ this ในคลาสลูก
    this.seconds = seconds;
  }

  describe() {
    return `${this.name}: ${this.score} คะแนน ใน ${this.seconds} วินาที`;
  }
}

const a = new TimedPlayer('สมชาย', 42).addPoints(3).addPoints(4);

const ranking = [a, b].sort(Player.compare);
console.log('อันดับ 1:', ranking[0].describe());
console.log('a เป็น Player ไหม:', a instanceof Player);

  • Promise: สถานะ pending, fulfilled และ rejected, then, catch, finally, การต่อสาย (Chaining) ที่แต่ละ then คืน Promise ใหม่ และการสร้าง Promise เองด้วย new Promise((resolve, reject) => ...) เช่น ฟังก์ชัน delay(ms)
  • รวมหลาย Promise: Promise.all (ล้มทั้งหมดถ้าตัวใดตัวหนึ่งล้ม), Promise.allSettled (รอทุกตัวและบอกผลแต่ละตัว), Promise.race และ Promise.any สำหรับโหลดข้อมูลหลายแหล่งพร้อมกัน
  • async / await: ฟังก์ชัน async คืน Promise เสมอ await หยุดรอเฉพาะในฟังก์ชันนั้น ไม่ได้หยุดทั้งโปรแกรม ใช้ try/catch จับ Error ความต่างของ await ทีละตัวในลูป (ทำต่อกัน) กับ await Promise.all(...) (ทำพร้อมกัน) และบั๊กจากการลืม await
  • fetch: GET ข้อมูล JSON ด้วย response.json() ตรวจ response.ok และ response.status เพราะ HTTP 404 และ 500 ไม่ทำให้ Promise ล้ม ส่วนปัญหาเครือข่ายจะได้ TypeError ตั้งเวลาหมดด้วย AbortSignal.timeout(ms) ยกเลิกด้วย AbortController และส่งข้อมูลแบบ POST ด้วย method, headers และ body: JSON.stringify(data)
  • CORS ขั้นพื้นฐาน: เบราว์เซอร์ไม่ยอมให้หน้าเว็บอ่านข้อมูลจาก Origin อื่น ถ้า Server ปลายทางไม่อนุญาต ซึ่งเป็นกลไกความปลอดภัยของเบราว์เซอร์ ไม่ใช่บั๊กของโค้ด และเป็นเหตุผลที่ไฟล์ JSON ของแอปควรอยู่ใน Origin เดียวกับหน้าเว็บ
  • Event Loop: Call stack, Macrotask queue (setTimeout, setInterval, Event ของผู้ใช้, I/O) และ Microtask queue (Callback ของ Promise, ส่วนที่อยู่หลัง await, queueMicrotask) โดยกฎหลักคือ เมื่อ Call stack ว่าง จะทำ Microtask ทั้งหมดจนหมดคิวก่อน แล้วจึงหยิบ Macrotask ถัดไปหนึ่งงาน
  • ตัวจับเวลาในแอปจริง: setInterval และ clearInterval สำหรับนับถอยหลัง ปัญหาเวลาคลาดเคลื่อน (Timer drift) และการคำนวณเวลาที่เหลือจาก Date.now() แทนการลบทีละวินาที รวมถึงการล้างตัวจับเวลาเมื่อจบเกมเพื่อไม่ให้ทำงานซ้อนกัน

// fetch-questions.js — โหลด JSON ด้วย fetch และ async/await พร้อมจัดการ Error
const BASE_URL = 'http://localhost:8000';

// คืน Promise ที่ resolve หลังเวลาผ่านไป ms มิลลิวินาที
const delay = (ms) => new Promise((resolve) => setTimeout(resolve, ms));

async function loadJson(path) {
  // AbortSignal.timeout ยกเลิกคำขอถ้าเกิน 3 วินาที
  const response = await fetch(`${BASE_URL}${path}`, { signal: AbortSignal.timeout(3000) });
  // fetch ไม่ throw เมื่อได้ 404 หรือ 500 ต้องเช็ก response.ok เอง
  if (!response.ok) {
    throw new Error(`โหลด ${path} ไม่สำเร็จ: HTTP ${response.status}`);
  }
  return response.json(); // แปลง Body เป็น Object (คืน Promise เช่นกัน)
}

async function main() {
  try {
    const questions = await loadJson('/data/questions.json');
    console.log(`โหลดคำถามได้ ${questions.length} ข้อ`);
    for (const q of questions) {
      console.log(`ข้อ ${q.id}: ${q.question} -> ${q.choices[q.answer]}`);
    }

    await delay(500);
    console.log('รอ 0.5 วินาทีด้วย Promise แล้ว');

    // Promise.allSettled รอทุกคำขอ แม้บางคำขอจะล้มเหลว
    const results = await Promise.allSettled([
      loadJson('/data/questions.json'),
      loadJson('/data/missing.json'),
    ]);
    for (const r of results) {
      console.log(r.status, r.status === 'fulfilled' ? `${r.value.length} ข้อ` : r.reason.message);
    }
  } catch (err) {
    console.error('เกิดข้อผิดพลาด:', err.message);
  }
}

main();

export function percent(correct, total) {
  if (!Number.isInteger(total) || total <= 0) {
    throw new RangeError('total ต้องเป็นจำนวนเต็มที่มากกว่า 0');
  }
  return Math.round((correct / total) * 100);
}

export function nextHighScore(current, saved) {
  return Math.max(current, saved ?? 0);
}

Must-know Skills

ถ้าต้องสรุปหัวข้อนี้ให้เหลือทักษะที่งานจริงและการสัมภาษณ์งานคาดหวังจากคนที่ "เขียน JavaScript เป็น" จะได้รายการนี้

  1. รันและหาข้อผิดพลาดของ JavaScript ได้ทั้งในเบราว์เซอร์และ Node.js เพราะต้องรู้ว่าโค้ดกำลังรันใน Runtime ใด และอ่าน Error จาก Console หรือ Terminal ได้ทันที
  2. เขียน HTML แบบ Semantic และฟอร์มที่ทุกช่องมี Label เพราะเป็นโครงที่ JavaScript ทำงานด้วย และเป็นพื้นฐานของ Accessibility ที่หลายองค์กรกำหนดเป็นข้อบังคับ
  3. ใช้ CSS Selector, Box Model และ Flexbox จัดหน้าได้ เพราะการเปลี่ยนหน้าตาตามสถานะด้วย Class คืองานประจำของ JavaScript ฝั่งหน้าเว็บ
  4. เข้าใจชนิดข้อมูล Truthy/Falsy และใช้ === เสมอ เพราะการแปลงชนิดข้อมูลอัตโนมัติเป็นต้นเหตุของบั๊กที่พบบ่อยที่สุดใน JavaScript
  5. จัดการข้อมูลด้วย map, filter, reduce และเรียงข้อมูลด้วย sort อย่างถูกต้อง เพราะข้อมูลจาก API เกือบทั้งหมดเป็น Array ของ Object และเป็นหัวข้อที่ถูกทดสอบในการสัมภาษณ์บ่อยที่สุด
  6. ใช้ Destructuring, Spread, ?. และ ?? เพราะเป็นไวยากรณ์ที่พบในโค้ดสมัยใหม่ทุกบรรทัด และช่วยป้องกัน TypeError เมื่อข้อมูลบางส่วนหายไป
  7. แยกโค้ดเป็น ES Modules และใช้ npm อย่างปลอดภัย เพราะโปรเจกต์จริงทุกโปรเจกต์มีหลายไฟล์และพึ่งพาแพ็กเกจ และการติดตั้งแพ็กเกจที่ไม่น่าไว้ใจคือความเสี่ยงด้านความปลอดภัย
  8. สร้างและแก้ไข DOM โดยใช้ textContent กับข้อมูลจากผู้ใช้ เพราะเป็นงานหลักของ JavaScript ฝั่งหน้าเว็บ และการใช้ innerHTML ผิดที่คือช่องโหว่ XSS
  9. จัดการ Event ด้วย Event delegation และตรวจฟอร์มได้ เพราะทุกการโต้ตอบของผู้ใช้ผ่าน Event และ Delegation ทำให้รายการที่เพิ่มลบได้ทำงานถูกต้องโดยใช้ Listener น้อย
  10. ใช้ JSON, localStorage และ try/catch โดยโปรแกรมไม่พังเมื่อข้อมูลเสีย เพราะข้อมูลจากภายนอกเชื่อถือไม่ได้เสมอ และผู้ใช้ไม่ควรเห็นหน้าเว็บว่างเปล่าเพราะข้อมูลรายการเดียวผิดรูปแบบ
  11. อธิบายและใช้ Closure, this และ Class ได้ เพราะเป็นกลไกเบื้องหลัง Event handler และ Framework ทุกตัว และเป็นคำถามสัมภาษณ์ระดับ Mid ที่พบเกือบทุกบริษัท
  12. เขียนโค้ด Asynchronous ด้วย async/await และ fetch และอธิบาย Event Loop ได้ เพราะแอปทุกตัวต้องโหลดข้อมูลจาก Server และต้องเข้าใจลำดับการทำงานเพื่อแก้บั๊กที่เกี่ยวกับเวลา
  13. Debug ด้วย DevTools และเขียน Unit test ด้วย node:test เพราะการหาบั๊กได้เร็วและพิสูจน์ได้ว่าโค้ดทำงานถูกต้องคือสิ่งที่แยกมืออาชีพออกจากมือสมัครเล่น

  1. หัวข้อถัดไปในเส้นทาง เพิ่มระบบ Type ให้โค้ดที่เขียนในหัวข้อนี้ ลองแปลง quiz.js ของ Mini Project เป็น TypeScript เป็นแบบฝึกหัดแรก

  4. สร้างระบบหลังบ้านที่เก็บคะแนนของผู้เล่นทุกคนในฐานข้อมูล แทน localStorage ที่อยู่แค่ในเครื่องเดียว
  5. ใช้ความเข้าใจเรื่อง DOM, innerHTML, localStorage และ CORS ไปศึกษาการโจมตีและป้องกันเว็บแอปอย่างถูกกฎหมายในห้องทดลองของตัวเอง
