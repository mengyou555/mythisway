13.2Core Concept & Quick Guide

ส่วนนี้คือแกนหลักของหัวข้อ Node.js เราจะเรียน 12 แนวคิดเรียงจากง่ายไปยาก เริ่มจากการรันไฟล์ JavaScript ไฟล์แรกนอกเบราว์เซอร์ ไปจนถึงการสร้าง REST API ด้วย Express 5 ที่ตรวจข้อมูลด้วย zod เก็บข้อมูลใน SQLite มีชุดทดสอบ มีระบบป้องกันพื้นฐาน มี Log ที่อ่านได้ และรู้จัก Stream กับ worker_threads สำหรับงานหนัก ทุกแนวคิดมีโค้ดที่รันได้จริง ผลลัพธ์ที่ได้จากการรันจริง และข้อความ Error จริงที่คุณจะเจอเมื่อพิมพ์ผิด

Node.js คืออะไร: V8, libuv, Event Loop และ REPL

คืออะไร ทำไมต้องใช้ และใช้เมื่อไร

Node.js คือ Runtime ที่ทำให้ JavaScript รันนอกเบราว์เซอร์ได้ เช่น รันใน Terminal ของ Ubuntu หรือบน Server จริง Node.js ประกอบด้วย 4 ส่วนหลัก ได้แก่ V8 (เครื่องยนต์ที่แปลง JavaScript เป็น Machine Code ตัวเดียวกับใน Google Chrome), libuv (ไลบรารีภาษา C ที่จัดการงาน I/O เช่น อ่านไฟล์ รับส่งข้อมูลผ่าน Network และ Timer), Core Modules (โมดูลที่มากับ Node เช่น node:fs, node:http, node:crypto) และ npm (ตัวจัดการแพ็กเกจที่มีแพ็กเกจให้เลือกใช้หลายล้านตัว)

หัวใจของ Node คือ Event Loop โค้ด JavaScript ของเรารันบน Thread หลักเพียงเส้นเดียว เมื่อโค้ดสั่งงานที่ต้องรอ เช่น อ่านไฟล์หรือรอคำตอบจาก Database Node จะส่งงานนั้นให้ libuv ไปทำ แล้วกลับมารันโค้ดบรรทัดถัดไปทันทีโดยไม่ยืนรอ เราเรียกแบบนี้ว่า Non-blocking I/O เมื่องานเสร็จ libuv จะนำ Callback กลับมาเข้าคิวให้ Event Loop เรียกทำงานต่อ Server ที่เขียนด้วย Node จึงรับ Request ได้หลายพันรายการพร้อมกันด้วย Thread เดียว

  • Node เหมาะกับ: REST API และ Backend ที่เน้นอ่านเขียน Database และเรียก Service อื่น, งาน Real-time เช่น Chat และ WebSocket, เครื่องมือ CLI, BFF (Backend for Frontend) ที่ทีม Frontend ดูแลเอง และงานที่อยากใช้ภาษาเดียวทั้ง Frontend และ Backend
  • Node ไม่เหมาะกับ: งานคำนวณหนักที่กิน CPU นานๆ เช่น ประมวลผลวิดีโอหรือคำนวณทางวิทยาศาสตร์ เพราะระหว่างคำนวณ Event Loop จะถูกบล็อก Request อื่นต้องรอทั้งหมด ถ้าจำเป็นต้องทำ ให้ย้ายงานไปที่ worker_threads (แนวคิดที่ 12) หรือใช้ภาษาอื่นอย่าง Go หรือ Python
  • ต่างจาก JavaScript ในเบราว์เซอร์: Node ไม่มี window, document และ DOM แต่มี process, Buffer, การเข้าถึงไฟล์และ Network โดยตรง ส่วน globalThis, console, setTimeout, fetch และ URL มีทั้งสองที่

วิธีรันโค้ดใน Node มี 4 แบบที่ควรรู้ ได้แก่ REPL (พิมพ์ node เฉยๆ เพื่อทดลองโค้ดทีละบรรทัด), node ไฟล์.js (รันไฟล์), node -p "นิพจน์" และ node -e "โค้ด" (รันโค้ดสั้นๆ บรรทัดเดียว) และ node --watch ไฟล์.js (รันใหม่อัตโนมัติทุกครั้งที่บันทึกไฟล์)

เปรียบเทียบ

Node.js เหมือนร้านกาแฟที่มีพนักงานรับออเดอร์ (Thread หลัก) แค่คนเดียว แต่มีบาริสต้าหลังร้าน (libuv) หลายคน พนักงานรับออเดอร์ไม่ยืนรอให้กาแฟแก้วแรกเสร็จ เขาส่งใบสั่งเข้าครัวแล้วหันไปรับลูกค้าคนถัดไปทันที เมื่อกาแฟแก้วไหนเสร็จ บาริสต้าจะกดกริ่ง (Callback เข้าคิว) แล้วพนักงานค่อยเรียกชื่อลูกค้ามารับ ร้านนี้รับลูกค้าได้เยอะมาก ตราบใดที่พนักงานรับออเดอร์ไม่ถูกลากไปทำงานที่ใช้เวลานาน เช่น นั่งคิดเลขบัญชีทั้งร้าน (งาน CPU หนัก) เพราะระหว่างนั้นคิวหน้าร้านจะหยุดนิ่งทั้งหมด

Modules: ES Modules กับ CommonJS

คืออะไร ทำไมต้องใช้ และใช้เมื่อไร

Module คือไฟล์ JavaScript หนึ่งไฟล์ที่เลือกได้ว่าจะ "ส่งออก" (export) อะไรให้ไฟล์อื่นใช้ และ "นำเข้า" (import) อะไรจากไฟล์อื่น การแบ่งโค้ดเป็น Module ทำให้แต่ละไฟล์ทำหน้าที่เดียว ตัวแปรในไฟล์หนึ่งไม่รั่วไปชนกับอีกไฟล์ ทดสอบง่าย และนำกลับมาใช้ซ้ำได้ ทุกโปรเจกต์ Node ที่มีมากกว่าหนึ่งไฟล์ต้องใช้ Module

Node มีระบบ Module สองแบบ ซึ่งคุณจะเจอทั้งคู่ในงานจริง

  • ES Modules (ESM) ใช้ import / export เป็นมาตรฐานของภาษา JavaScript ใช้ได้ทั้งในเบราว์เซอร์และ Node เปิดใช้โดยใส่ "type": "module" ใน package.json (ไฟล์ .js ทุกไฟล์เป็น ESM) หรือใช้นามสกุล .mjs โปรเจกต์ใหม่ควรใช้แบบนี้ และเราใช้แบบนี้ตลอดทั้งหัวข้อ
  • CommonJS (CJS) ใช้ require() และ module.exports เป็นระบบดั้งเดิมของ Node ก่อนมี ESM ยังพบในโค้ดเก่าและแพ็กเกจเก่าจำนวนมาก ไฟล์นามสกุล .cjs เป็น CommonJS เสมอ

กฎสำคัญของ ESM ใน Node ที่ต้องจำ: (1) import ไฟล์ของเราเองต้องใส่นามสกุลเต็ม เช่น './lib/math.js' (2) ใน ESM ไม่มี require, __dirname และ __filename ให้ใช้ import.meta.dirname และ import.meta.filename (มีตั้งแต่ Node 20.11) แทน (3) ใช้ await ที่ระดับบนสุดของไฟล์ได้เลย (Top-level await) (4) โหลด Module ตอนรันด้วย import() แบบ Dynamic ได้ (5) import ไฟล์ JSON ต้องบอกชนิดด้วย with { type: 'json' } ส่วนการใช้ร่วมกัน ไฟล์ ESM import ไฟล์ CommonJS ได้ทันที (ได้ค่า module.exports เป็น default export) แต่ถ้าไฟล์ CommonJS ต้องการใช้ ESM ให้ใช้ await import() แทน require()

เปรียบเทียบ

Module เหมือนแผนกต่างๆ ในบริษัท แผนกบัญชี (math.js) ทำงานภายในของตัวเอง แต่เปิด "ช่องบริการ" ไว้บางช่อง (export) แผนกอื่นที่อยากใช้บริการต้องกรอกแบบฟอร์มขอเฉพาะบริการที่ต้องการ (import) ESM กับ CommonJS เหมือนแบบฟอร์มสองรุ่น รุ่นใหม่ (ESM) เป็นแบบมาตรฐานสากลที่ทุกบริษัทใช้ ส่วนรุ่นเก่า (CommonJS) ยังรับอยู่เพราะมีเอกสารเก่าจำนวนมาก เวลาเขียนงานใหม่ เราใช้แบบฟอร์มรุ่นใหม่เสมอ

Best Practice
  • โปรเจกต์ใหม่ทุกตัวตั้ง "type": "module" ตั้งแต่วันแรก และใช้ .cjs เฉพาะไฟล์ที่เครื่องมือภายนอกบังคับว่าต้องเป็น CommonJS เท่านั้น
  • ใช้ Named Export เป็นหลัก เพราะชื่อตรงกันทั้งโปรเจกต์ ค้นหาง่าย และ Editor ช่วย Auto-import ได้แม่นกว่า Default Export
  • ห้ามพึ่งการใช้ require() เพื่อโหลดไฟล์ ESM ในโค้ด CommonJS แม้ Node รุ่นใหม่จะทำได้ในบางกรณี เพราะพฤติกรรมยังต่างกันในแต่ละเวอร์ชัน ให้ใช้ await import() ซึ่งทำงานได้แน่นอนทุกรุ่น
  • สร้าง path ไปยังไฟล์ข้างเคียงจาก import.meta.dirname เสมอ ไม่ใช่จากโฟลเดอร์ที่ผู้ใช้รันคำสั่ง

npm, package.json, Semantic Versioning และ npx

คืออะไร ทำไมต้องใช้ และใช้เมื่อไร

npm (Node Package Manager) คือเครื่องมือที่มากับ Node ใช้ดาวน์โหลดแพ็กเกจที่คนอื่นเขียนไว้จาก npm Registry มาใช้ในโปรเจกต์ และใช้รันคำสั่งที่โปรเจกต์กำหนด ทุกโปรเจกต์มีไฟล์ package.json เป็น "บัตรประจำตัว" ที่บอกชื่อ เวอร์ชัน ชนิด Module (type) สคริปต์ (scripts) แพ็กเกจที่ต้องใช้ตอนรันจริง (dependencies) แพ็กเกจที่ใช้แค่ตอนพัฒนา เช่น เครื่องมือทดสอบ (devDependencies) และเวอร์ชัน Node ที่รองรับ (engines)

เวอร์ชันของแพ็กเกจใช้ระบบ Semantic Versioning (semver) รูปแบบ MAJOR.MINOR.PATCH เช่น 7.8.5 ตัวเลข MAJOR เพิ่มเมื่อมีการเปลี่ยนที่ทำให้โค้ดเดิมพัง MINOR เพิ่มเมื่อมีฟีเจอร์ใหม่ที่ยังใช้กับโค้ดเดิมได้ และ PATCH เพิ่มเมื่อแก้ Bug ใน package.json เราเขียนช่วงเวอร์ชันได้หลายแบบ

  • ^5.3.0 (ค่าเริ่มต้นของ npm install) ยอมรับ 5.x.x ที่ไม่ต่ำกว่า 5.3.0 แต่ไม่ยอมรับ 6.0.0
  • ~5.3.0 ยอมรับเฉพาะ 5.3.x
  • 5.3.0 (ไม่มีสัญลักษณ์) ต้องตรงเป๊ะ เรียกว่า Exact Pin ได้ด้วย npm install --save-exact หรือตั้งค่าถาวรด้วย npm config set save-exact true

ไฟล์ package-lock.json บันทึกเวอร์ชันจริงที่ติดตั้งของทุกแพ็กเกจ รวมถึงแพ็กเกจย่อยที่แพ็กเกจของเราดึงมาอีกทอดหนึ่ง ต้อง Commit ไฟล์นี้เข้า Git เสมอ เพื่อให้ทุกเครื่องได้เวอร์ชันเดียวกัน ส่วนโฟลเดอร์ node_modules ห้าม Commit เพราะใหญ่มากและสร้างใหม่ได้จาก Lock File คำสั่ง npm install ใช้ตอนพัฒนา (อาจอัปเดต Lock File) ส่วน npm ci ใช้บน CI และ Server (ลบ node_modules แล้วติดตั้งตาม Lock File เป๊ะ ไม่แก้ Lock File) สุดท้าย npx ใช้รันโปรแกรมจากแพ็กเกจ ถ้ามีในโปรเจกต์จะใช้ตัวนั้น ถ้าไม่มีจะดาวน์โหลดมารันครั้งเดียว

เปรียบเทียบ

package.json เหมือนสูตรอาหารที่เขียนว่า "ใช้น้ำปลายี่ห้อ A รุ่นปี 5 ขึ้นไป" (^5.3.0) ส่วน package-lock.json เหมือนใบเสร็จที่จดว่าวันนี้ซื้อ "ยี่ห้อ A ล็อต 5.9.1" จริงๆ ถ้าเพื่อนในทีมทำอาหารตามสูตรอย่างเดียว อาจได้น้ำปลาล็อตใหม่ที่รสต่างไป แต่ถ้าทำตามใบเสร็จ (npm ci) จะได้รสเดียวกันทุกครั้ง node_modules คือของในตู้กับข้าว ไม่ต้องส่งตู้ไปให้เพื่อน ส่งแค่สูตรกับใบเสร็จ เพื่อนไปซื้อของเองได้

Core Modules: fs/promises, path, os, crypto และ URL

คืออะไร ทำไมต้องใช้ และใช้เมื่อไร

Core Modules คือโมดูลที่มากับ Node ไม่ต้องติดตั้งเพิ่ม ใช้ทำงานพื้นฐานที่ทุก Backend ต้องทำ ห้าตัวที่ใช้บ่อยที่สุดคือ

  • node:fs/promises อ่าน เขียน สร้าง ลบไฟล์และโฟลเดอร์แบบ Promise เช่น readFile, writeFile, appendFile, mkdir, readdir, stat, rm เราใช้แบบ Promise แทน readFileSync เพราะแบบ Sync บล็อก Event Loop ทั้งโปรแกรมจนกว่าจะอ่านเสร็จ ถ้าเป็น Server ผู้ใช้ทุกคนต้องรอ
  • node:path ต่อและแยก path อย่างถูกต้อง เช่น join, resolve, basename, extname, dirname ไม่ต้องต่อ String ด้วยมือเองแล้วพลาดเรื่อง / ซ้ำหรือหาย
  • node:os ข้อมูลเครื่อง เช่น homedir(), platform(), cpus(), totalmem(), EOL (ตัวขึ้นบรรทัดใหม่ของระบบ)
  • node:crypto สร้าง ID ที่ไม่ซ้ำ (randomUUID) สุ่มตัวเลขแบบปลอดภัย (randomInt) และคำนวณ Hash (createHash('sha256')) ใช้แทน Math.random() ทุกครั้งที่ความสุ่มเกี่ยวกับความปลอดภัย
  • URL และ URLSearchParams (ใช้ได้เลยแบบ Global) แยกส่วนของ URL และอ่านแก้ Query String อย่างถูกต้อง URL ที่ผิดรูปแบบจะโยน TypeError

เวลาอ่านไฟล์ Error ที่ต้องรู้จักคือ err.code ได้แก่ ENOENT (ไม่มีไฟล์หรือโฟลเดอร์), EEXIST (มีอยู่แล้ว), EACCES (ไม่มีสิทธิ์) เราตรวจค่านี้เพื่อตัดสินใจว่าจะจัดการเองหรือโยน Error ต่อ

  • ในโค้ด Server ใช้ node:fs/promises เสมอ ฟังก์ชันแบบ Sync ใช้ได้เฉพาะในสคริปต์สั้นๆ หรือตอนเริ่มโปรแกรมก่อนรับ Request

process, Arguments, Environment Variables และ --env-file

คืออะไร ทำไมต้องใช้ และใช้เมื่อไร

Object process คือช่องทางที่โปรแกรม Node คุยกับระบบปฏิบัติการ ส่วนที่ใช้บ่อยมีดังนี้

  • process.argv Array ของคำที่พิมพ์ในคำสั่ง ตัวที่ 0 คือ path ของ node ตัวที่ 1 คือ path ของสคริปต์ ข้อมูลของผู้ใช้เริ่มที่ตัวที่ 2 จึงมักใช้ process.argv.slice(2)
  • process.env Environment Variables ทั้งหมด ค่าทุกตัวเป็น String หรือ undefined ต้องแปลงเป็นตัวเลขเอง
  • process.cwd() โฟลเดอร์ที่ผู้ใช้รันคำสั่ง และ process.pid หมายเลข Process
  • process.exitCode = 1 ตั้งรหัสออกแล้วปล่อยให้โปรแกรมจบเองอย่างเรียบร้อย ส่วน process.exit(1) หยุดทันที (งานที่ค้างอยู่ เช่น การเขียนไฟล์ อาจไม่เสร็จ) รหัส 0 แปลว่าสำเร็จ ค่าอื่นแปลว่าล้มเหลว ดูได้ด้วย echo $? ใน Bash ซึ่ง CI และสคริปต์อัตโนมัติใช้ค่านี้ตัดสินว่างานผ่านหรือไม่
  • console.log เขียนไปที่ stdout (ผลลัพธ์ปกติ) ส่วน console.error เขียนไปที่ stderr (ข้อความ Error) ผู้ใช้จึงแยกเก็บได้ เช่น node cli.js > out.txt 2> err.txt

การแยก Argument ด้วยมือยุ่งยาก Node มี util.parseArgs ในตัว รองรับ Option แบบ String และ Boolean ชื่อย่อ (-n) ค่าเริ่มต้น และ Positional (คำที่ไม่ใช่ Option) ส่วนค่าตั้งค่าที่ต่างกันในแต่ละเครื่อง เช่น Port, รหัสผ่าน Database, API Key ต้องเก็บใน Environment Variables ไม่ใช่ในโค้ด ตั้งได้สามแบบ: export PORT=4000 (ทั้ง Terminal), PORT=4000 node app.js (เฉพาะคำสั่งนั้น) และไฟล์ .env ที่โหลดด้วย node --env-file=.env (มีในตัวตั้งแต่ Node 20.6 ไม่ต้องใช้แพ็กเกจ dotenv) ไฟล์ .env ห้าม Commit ให้ Commit .env.example ที่มีแค่ชื่อตัวแปรและค่าตัวอย่างแทน และควรตรวจค่าทั้งหมดตอนเริ่มโปรแกรม ถ้าผิดให้หยุดทันที (Fail fast) ดีกว่าไปพังกลางทางตอนมีผู้ใช้จริง

Asynchronous Programming, Event Loop และ Error Handling

คืออะไร ทำไมต้องใช้ และใช้เมื่อไร

งานเกือบทุกอย่างของ Backend คือ "การรอ" เช่น รอ Database รอไฟล์ รอ API ภายนอก Node ให้เราเขียนการรอแบบไม่บล็อกได้สามรูปแบบตามยุค ได้แก่ Callback (ส่งฟังก์ชันไปให้เรียกเมื่อเสร็จ), Promise (Object ที่แทนผลลัพธ์ในอนาคต) และ async/await (เขียน Promise ให้อ่านเหมือนโค้ดบรรทัดต่อบรรทัด) โค้ดใหม่ควรใช้ async/await แต่ต้องเข้าใจสองแบบแรกด้วย เพราะ Core Module หลายตัวและโค้ดเก่ายังใช้อยู่

Event Loop ทำงานเป็นรอบ แต่ละรอบผ่านหลาย Phase ที่มือใหม่ควรรู้สามอัน: timers (เรียก Callback ของ setTimeout/setInterval ที่ถึงเวลา), poll (รับผล I/O เช่น อ่านไฟล์เสร็จ มี Request เข้ามา) และ check (เรียก setImmediate) งานเหล่านี้เรียกว่า Macrotask ส่วน Microtask ได้แก่ process.nextTick และ Promise.then/await จะถูกรันจนหมดคิวทุกครั้งหลังโค้ดชุดหนึ่งจบ ก่อนจะไป Macrotask ถัดไป ภายใน Callback ปกติ nextTick มาก่อน Promise เสมอ

  • ทีละตัว vs พร้อมกัน: ถ้างานไม่ขึ้นต่อกัน อย่า await ทีละบรรทัด ให้เริ่มทุกงานพร้อมกันด้วย Promise.all (ล้มเหลวทันทีถ้ามีงานใดพัง), Promise.allSettled (รอครบทุกงานแล้วรายงานผลแต่ละตัว) หรือ Promise.race (เอางานที่เสร็จก่อน)
  • Timeout: ใช้ AbortSignal.timeout(ms) ยกเลิกงานที่นานเกิน ใช้ได้กับ fetch และ node:timers/promises
  • Error: ครอบ await ด้วย try/catch สร้าง Custom Error ด้วย class ... extends Error และเก็บต้นเหตุด้วย { cause } Promise ที่ Reject แล้วไม่มีใครจับ (Unhandled Rejection) จะทำให้ Node ปิดโปรแกรมด้วยรหัส 1 ตั้งแต่ Node 15 เป็นต้นมา
  • อย่าบล็อก Loop: Loop คำนวณหนักบน Thread หลักทำให้ Timer และ Request อื่นทั้งหมดต้องรอ Server จะดูเหมือนค้าง
เปรียบเทียบ

Event Loop เหมือนพนักงานธนาคารคนเดียวที่มีหลายคิว เมื่อทำรายการของลูกค้าคนหนึ่งเสร็จ เขาจะเคลียร์ "งานด่วนที่ต้องทำต่อทันที" (Microtask) จนหมดก่อน จากนั้นจึงเรียกคิวถัดไปตามลำดับช่อง: ช่องนัดเวลา (timers) ช่องเอกสารที่ส่งกลับมาแล้ว (poll) และช่องด่วนพิเศษ (check) ส่วน Promise.all เหมือนการยื่นเอกสารสามใบให้สามแผนกตรวจพร้อมกัน แทนที่จะรอแผนกแรกตรวจเสร็จแล้วค่อยเดินไปแผนกที่สอง

Best Practice
  • ใช้ async/await เป็นหลัก และใช้ Promise.all เมื่องานไม่ขึ้นต่อกัน งานที่อาจล้มเหลวบางส่วนให้ใช้ Promise.allSettled
  • ทุกการเรียก Service ภายนอกต้องมี Timeout (AbortSignal.timeout) ไม่อย่างนั้น Request ของผู้ใช้อาจค้างไม่มีกำหนด
  • ใช้ process.on('unhandledRejection') และ 'uncaughtException' แค่เพื่อเขียน Log แล้วปิดโปรแกรม (ให้ Process Manager เปิดใหม่) อย่าใช้เพื่อ "กลืน" Error แล้วรันต่อ เพราะโปรแกรมอาจอยู่ในสถานะที่เสียไปแล้ว
  • สร้าง Custom Error สำหรับกรณีทางธุรกิจ (NotFoundError, ValidationError) เพื่อให้ส่วนที่ตอบ HTTP แปลงเป็น Status Code ที่ถูกต้องได้ง่าย

EventEmitter และ HTTP Server ด้วย node:http

คืออะไร ทำไมต้องใช้ และใช้เมื่อไร

EventEmitter (จาก node:events) คือกลไก "ประกาศและรับฟัง" ที่อยู่เบื้องหลังเกือบทุกอย่างใน Node ทั้ง Server, Stream และ Process วัตถุหนึ่ง emit('ชื่อ', ข้อมูล) เพื่อประกาศว่าเกิดเหตุการณ์ และใครก็ได้ที่ on('ชื่อ', ฟังก์ชัน) ไว้จะถูกเรียก เมธอดที่ใช้บ่อยคือ on (ฟังทุกครั้ง), once (ฟังครั้งเดียว), off (เลิกฟัง) และ emit เหตุการณ์ชื่อ 'error' พิเศษ: ถ้า emit แล้วไม่มีผู้ฟัง Node จะ throw Error ทำให้โปรแกรมพัง เราจึงต้องฟัง 'error' เสมอ ใช้ EventEmitter เมื่อส่วนหนึ่งของระบบต้องแจ้งหลายส่วนโดยไม่ต้องรู้จักกัน เช่น เมื่อมีออเดอร์ใหม่ให้แจ้งครัว ส่งอีเมล และเขียน Log

node:http คือโมดูลสร้าง Web Server ระดับล่างสุดที่ Express และ Framework อื่นสร้างทับอยู่ http.createServer((req, res) => ...) รับฟังก์ชันที่ถูกเรียกทุกครั้งที่มี Request เข้ามา (Server เองก็เป็น EventEmitter ที่ emit 'request') เราต้องจัดการเองทั้งหมด ได้แก่

  • อ่าน req.method, req.url (แยกด้วย new URL(req.url, 'http://localhost')) และ req.headers
  • ตอบด้วย res.writeHead(status, headers) หรือ res.statusCode + res.setHeader แล้วจบด้วย res.end(body) ทุกครั้ง
  • อ่าน Body ของ POST เอง เพราะ req เป็น Stream ที่ส่งข้อมูลมาเป็นชิ้น (chunk) ต้องรวมแล้ว JSON.parse และจำกัดขนาดเพื่อกันคนส่งข้อมูลมหาศาลมาถล่ม
  • ตอบ 400 เมื่อ JSON ผิด 404 เมื่อไม่มีเส้นทาง 405 เมื่อ Method ไม่ถูก และฟัง server.on('error') เช่น Port ถูกใช้แล้ว

ในงานจริงเราแทบไม่เขียน Server ด้วย node:http ตรงๆ แต่การเขียนเองครั้งหนึ่งทำให้เข้าใจว่า Express ทำอะไรให้เรา และ Debug ปัญหาระดับ HTTP ได้

เปรียบเทียบ

EventEmitter เหมือนกริ่งในร้านอาหาร เมื่อแคชเชียร์กดกริ่ง "ออเดอร์ใหม่" (emit) ทั้งครัว พนักงานเสิร์ฟ และคนทำบัญชีที่ตั้งใจฟังกริ่งนี้ (on) จะได้ยินพร้อมกัน แคชเชียร์ไม่ต้องเดินไปบอกทีละคน ส่วน node:http เหมือนการเปิดร้านแบบไม่มีระบบอะไรเลย ต้องรับออเดอร์ อ่านใบสั่ง ตรวจว่าเมนูมีจริงไหม และส่งอาหารเองทุกขั้น ถ้าลืมยกอาหารไปให้ (res.end()) ลูกค้าจะนั่งรอไปเรื่อยๆ

// order-events.js : คิวออเดอร์ที่แจ้งเหตุการณ์ด้วย EventEmitter
import { EventEmitter } from 'node:events';

class OrderQueue extends EventEmitter {
  #orders = []; // Private field เก็บออเดอร์

  add(order) {
    if (!order.menu) {
      // event ชื่อ 'error' พิเศษ: ถ้าไม่มีใครฟัง Node จะ throw ทันที
      this.emit('error', new Error('ออเดอร์ต้องมีชื่อเมนู'));
      return;
    }
    this.#orders.push(order);
    this.emit('added', order, this.#orders.length); // ส่งข้อมูลไปให้ผู้ฟังได้หลายค่า
  }
}

ต่อไปสร้าง HTTP Server ที่มี 3 เส้นทาง (GET /health, GET /api/hello, POST /api/echo) และตอบ 404 เป็น JSON สำหรับเส้นทางอื่น

// server.js : HTTP Server ด้วย node:http ล้วนๆ ไม่ใช้ Framework
import http from 'node:http';

const PORT = Number(process.env.PORT ?? 3000);
const MAX_BODY = 1024 * 10; // รับ Body ไม่เกิน 10 KB

// ส่ง JSON พร้อม Status Code และ Header ที่ถูกต้อง
function sendJson(res, status, data) {
  res.writeHead(status, { 'Content-Type': 'application/json; charset=utf-8' });
  res.end(JSON.stringify(data));
}

// อ่าน Body ทีละ chunk แล้วแปลงเป็น JSON
async function readJson(req) {
  let size = 0;
  const chunks = [];
  for await (const chunk of req) {
    size += chunk.length;
    if (size > MAX_BODY) throw Object.assign(new Error('Body ใหญ่เกินไป'), { status: 413 });
    chunks.push(chunk);
  }
  try {
    return JSON.parse(Buffer.concat(chunks).toString('utf8'));
  } catch {
    throw Object.assign(new Error('Body ไม่ใช่ JSON ที่ถูกต้อง'), { status: 400 });
  }
}

const server = http.createServer(async (req, res) => {
  const url = new URL(req.url, `http://${req.headers.host ?? 'localhost'}`);
  console.log(`${req.method} ${url.pathname}`);

  try {
    if (url.pathname === '/health') {
      if (req.method !== 'GET') return sendJson(res, 405, { error: 'MethodNotAllowed' });
      return sendJson(res, 200, { status: 'ok', uptime: Math.round(process.uptime()) });
    }
    if (url.pathname === '/api/hello' && req.method === 'GET') {
      const name = url.searchParams.get('name') ?? 'คนแปลกหน้า';
      return sendJson(res, 200, { message: `สวัสดี ${name}` });
    }
    if (url.pathname === '/api/echo' && req.method === 'POST') {
      const body = await readJson(req);
      return sendJson(res, 200, { youSent: body, receivedAt: new Date().toISOString() });
    }
    sendJson(res, 404, { error: 'NotFound', message: `ไม่พบ ${req.method} ${url.pathname}` });
  } catch (err) {
    sendJson(res, err.status ?? 500, { error: 'BadRequest', message: err.message });
  }
});

server.on('error', (err) => {
  console.error('เปิด Server ไม่สำเร็จ:', err.message);
  process.exitCode = 1;
});
server.listen(PORT, () => console.log(`Server พร้อมที่ http://localhost:${PORT}`));

Express 5: Routing, Middleware และ Error Handling

คืออะไร ทำไมต้องใช้ และใช้เมื่อไร

Express คือ Web Framework ที่นิยมที่สุดของ Node สร้างทับ node:http เพื่อให้เขียน API ได้สั้นและเป็นระบบ เราใช้ Express 5.3.0 ซึ่งเป็นสายหลักปัจจุบัน แนวคิดสำคัญมีสามอย่าง

  • Routing: ผูก Method + Path เข้ากับ Handler เช่น app.get('/api/books/:id', handler) ค่าใน path อ่านจาก req.params ค่าหลัง ? อ่านจาก req.query แยกกลุ่ม Route ไปไว้ในไฟล์ของตัวเองด้วย express.Router()
  • Middleware: ฟังก์ชัน (req, res, next) ที่ Request วิ่งผ่านเป็นสายพานตามลำดับที่ app.use แต่ละตัวทำงานแล้วเลือกได้ว่าจะตอบเลยหรือเรียก next() ส่งต่อ ใช้ทำงานร่วมของทุก Request เช่น แปลง JSON Body (express.json()), เขียน Log, ติด Request ID, ตรวจสิทธิ์
  • Error-handling Middleware: Middleware ที่มี 4 พารามิเตอร์ (err, req, res, next) วางไว้ท้ายสุด รับ Error จากทุก Route แล้วตอบเป็นรูปแบบเดียวกัน เช่น { "error": "NotFound", "message": "..." }

สิ่งที่เปลี่ยนใน Express 5 ที่ต้องรู้: (1) Handler แบบ async ที่ throw หรือ Reject จะถูกส่งไป Error Middleware ให้อัตโนมัติ ไม่ต้องใช้แพ็กเกจ express-async-errors หรือ try/catch + next(err) ทุก Route อีกแล้ว (2) ไวยากรณ์ path เปลี่ยน: wildcard ต้องมีชื่อ เช่น '/*splat' แทน '*' และพารามิเตอร์ที่ไม่บังคับเขียนเป็น '/books{/:id}' (3) req.query เป็น getter อ่านได้แต่กำหนดค่าทับไม่ได้ เรายังแยกไฟล์ app.js (สร้าง App) ออกจาก server.js (เปิด Port) เพื่อให้ชุดทดสอบในแนวคิดที่ 10 นำ App ไปใช้ได้โดยไม่ต้องเปิด Port จริง

เปรียบเทียบ

Express เหมือนอาคารสำนักงานที่มีจุดตรวจเรียงกันตั้งแต่ประตู Middleware คือจุดตรวจแต่ละจุด: รปภ. ติดบัตรผู้มาติดต่อ (Request ID) พนักงานต้อนรับจดเวลาเข้า (Logger) เจ้าหน้าที่เปิดซองเอกสาร (express.json()) แต่ละจุดทำหน้าที่แล้วชี้ทางไปจุดถัดไป (next()) Router คือป้ายบอกชั้นว่าแผนกหนังสืออยู่ชั้นไหน ถ้าหาแผนกไม่เจอจะไปจบที่โต๊ะ "ไม่พบแผนกที่ท่านต้องการ" (404) และถ้าเกิดเรื่องผิดปกติที่ใดก็ตาม เรื่องจะถูกส่งไปที่ฝ่ายแก้ปัญหาฝ่ายเดียว (Error Middleware) ซึ่งตอบผู้มาติดต่อด้วยแบบฟอร์มเดียวกันทุกครั้ง

// src/routes/books.js : Router ของ /api/books (เก็บข้อมูลใน Memory)
import express from 'express';

const router = express.Router();

// ข้อมูลตัวอย่าง (หายเมื่อปิด Server เพราะอยู่ใน Memory)
const books = [
  { id: 1, title: 'Clean Code', author: 'Robert C. Martin', year: 2008, isbn: '9780132350884' },
  { id: 2, title: "You Don't Know JS Yet", author: 'Kyle Simpson', year: 2020, isbn: '9798602477429' },
  { id: 3, title: 'Node.js Design Patterns', author: 'Mario Casciaro', year: 2020, isbn: '9781839214110' },
];
let nextId = 4;

// สร้าง Error ที่มี status เพื่อส่งต่อให้ Error-handling Middleware
function httpError(status, error, message) {
  return Object.assign(new Error(message), { status, error });
}

function findBook(idParam) {
  const book = books.find((b) => b.id === Number(idParam));
  if (!book) throw httpError(404, 'NotFound', `ไม่พบหนังสือ id ${idParam}`);
  return book;
}

// GET /api/books?author=... : รายการทั้งหมด กรองด้วย Query ได้
router.get('/', (req, res) => {
  const { author } = req.query;
  const items = author ? books.filter((b) => b.author.includes(author)) : books;
  res.json({ items, total: items.length });
});

// GET /api/books/:id
router.get('/:id', (req, res) => {
  res.json(findBook(req.params.id)); // throw ใน Handler -> ไป Error Middleware อัตโนมัติ
});

// POST /api/books : สร้างใหม่ ตอบ 201 พร้อม Location
router.post('/', (req, res) => {
  const { title, author, year } = req.body ?? {};
  if (!title || !author) throw httpError(400, 'ValidationError', 'ต้องมี title และ author');
  const book = { id: nextId++, title, author, year: Number(year) || null, isbn: null };
  books.push(book);
  res.status(201).location(`/api/books/${book.id}`).json(book);
});

// PATCH /api/books/:id : แก้บางฟิลด์
router.patch('/:id', (req, res) => {
  const book = findBook(req.params.id);
  for (const key of ['title', 'author', 'year']) {
    if (req.body?.[key] !== undefined) book[key] = req.body[key];
  }
  res.json(book);
});

// DELETE /api/books/:id : ลบแล้วตอบ 204 (ไม่มี Body)
router.delete('/:id', (req, res) => {
  const book = findBook(req.params.id);
  books.splice(books.indexOf(book), 1);
  res.status(204).end();
});

export default router;

Best Practice
  • แยก app.js กับ server.js และแยก Router ตามกลุ่มข้อมูล (routes/books.js, routes/users.js) โปรเจกต์โตแล้วยังหาโค้ดง่าย

import { mkdirSync } from 'node:fs';
import path from 'node:path';

export function openDb(file) {
  if (file !== ':memory:') mkdirSync(path.dirname(file), { recursive: true }); // สร้างโฟลเดอร์ data/ ก่อน
  const db = new Database(file);
  db.pragma('journal_mode = WAL'); // อ่านและเขียนพร้อมกันได้ดีขึ้น
  db.exec(`
    CREATE TABLE IF NOT EXISTS books (
      id         INTEGER PRIMARY KEY AUTOINCREMENT,
      title      TEXT    NOT NULL,
      author     TEXT    NOT NULL,
      year       INTEGER NOT NULL,
      isbn       TEXT    UNIQUE,
      created_at TEXT    NOT NULL DEFAULT (datetime('now'))
    )
  `);
  return db;
}

// รวม Prepared Statement ทั้งหมดไว้ที่เดียว (ป้องกัน SQL Injection)
export function booksRepo(db) {
  const stmt = {
    list: db.prepare('SELECT * FROM books ORDER BY id LIMIT ? OFFSET ?'),
    count: db.prepare('SELECT COUNT(*) AS n FROM books'),
    get: db.prepare('SELECT * FROM books WHERE id = ?'),
    insert: db.prepare('INSERT INTO books (title, author, year, isbn) VALUES (@title, @author, @year, @isbn)'),
    update: db.prepare(`UPDATE books SET title = @title, author = @author, year = @year, isbn = @isbn WHERE id = @id`),
    remove: db.prepare('DELETE FROM books WHERE id = ?'),
  };
  return {
    list: (limit, offset) => ({ items: stmt.list.all(limit, offset), total: stmt.count.get().n }),
    get: (id) => stmt.get.get(id),
    create(data) {
      const info = stmt.insert.run({ isbn: null, ...data });
      return stmt.get.get(info.lastInsertRowid);
    },
    update(id, patch) {
      const current = stmt.get.get(id);
      if (!current) return undefined;
      stmt.update.run({ ...current, ...patch, id });
      return stmt.get.get(id);
    },
    remove: (id) => stmt.remove.run(id).changes > 0,
    // Transaction: เพิ่มหลายเล่มแบบ "สำเร็จทั้งหมดหรือไม่เปลี่ยนเลย"
    seed: db.transaction((rows) => rows.forEach((r) => stmt.insert.run({ isbn: null, ...r }))),
  };
}

// Middleware ตรวจข้อมูล: ผ่านแล้วเก็บค่าที่แปลงแล้วไว้ใน req.valid
function validate(schema, source) {
  return (req, res, next) => {
    const result = schema.safeParse(req[source]);
    if (!result.success) {
      return res.status(400).json({
        error: 'ValidationError',
        message: `ข้อมูลใน ${source} ไม่ถูกต้อง`,
        details: z.flattenError(result.error).fieldErrors,
      });
    }
    req.valid = { ...req.valid, [source]: result.data };
    next();
  };
}

export function createApp({ db }) {
  const books = booksRepo(db);
  const app = express();
  app.disable('x-powered-by');
  app.use(express.json({ limit: '10kb' }));

  const notFound = (res, id) => res.status(404).json({ error: 'NotFound', message: `ไม่พบหนังสือ id ${id}` });

  app.get('/api/books', validate(listQuery, 'query'), (req, res) => {
    const { limit, offset } = req.valid.query;
    res.json({ ...books.list(limit, offset), limit, offset });
  });

  app.get('/api/books/:id', validate(idParams, 'params'), (req, res) => {
    const book = books.get(req.valid.params.id);
    return book ? res.json(book) : notFound(res, req.valid.params.id);
  });

  app.post('/api/books', validate(bookCreate, 'body'), (req, res) => {
    const book = books.create(req.valid.body);
    res.status(201).location(`/api/books/${book.id}`).json(book);
  });

  app.patch('/api/books/:id', validate(idParams, 'params'), validate(bookUpdate, 'body'), (req, res) => {
    const book = books.update(req.valid.params.id, req.valid.body);
    return book ? res.json(book) : notFound(res, req.valid.params.id);
  });

  app.delete('/api/books/:id', validate(idParams, 'params'), (req, res) => {
    return books.remove(req.valid.params.id) ? res.status(204).end() : notFound(res, req.valid.params.id);
  });

  app.use((req, res) => res.status(404).json({ error: 'NotFound', message: `ไม่พบ ${req.method} ${req.originalUrl}` }));

  // แปลง Error ของ SQLite ให้เป็น Status Code ที่มีความหมาย
  app.use((err, req, res, next) => {
    if (err.code === 'SQLITE_CONSTRAINT_UNIQUE') {
      return res.status(409).json({ error: 'Conflict', message: 'ISBN นี้มีอยู่แล้ว' });
    }
    const status = err.status ?? 500;
    if (status >= 500) console.error(err);
    res.status(status).json({ error: status >= 500 ? 'InternalServerError' : 'BadRequest', message: status >= 500 ? 'เกิดข้อผิดพลาดภายในระบบ' : err.message });
  });

  return app;
}

// src/lib/slug.js : แปลงชื่อหนังสือเป็น slug สำหรับใช้ใน URL
export function toSlug(text) {
  if (typeof text !== 'string') throw new TypeError('text ต้องเป็น string');
  return text
    .normalize('NFKD')
    .replace(/[̀-ͯ]/g, '') // ตัดวรรณยุกต์ของอักษรละติน เช่น é -> e
    .toLowerCase()
    .replace(/[^a-z0-9฀-๿]+/g, '-') // อักขระอื่นทั้งหมดกลายเป็น -
    .replace(/^-+|-+$/g, ''); // ตัด - หัวท้าย
}

    assert.equal(res.body.title, 'Clean Code');

  });

      await request(app).post('/api/books').send({ title, author: 'somchai', year: 2026 });
    }
    const res = await request(app).get('/api/books?limit=2&offset=1').expect(200);
    assert.deepEqual(res.body.items.map((b) => b.title), ['B', 'C']);

  });

  });

Best Practice
  • เขียน Test สำหรับทุก Status Code ที่ API ตอบได้ (201, 400, 404, 409, 204, 500) ไม่ใช่แค่กรณีที่สำเร็จ
  • Test ต้องเป็นอิสระต่อกัน รันลำดับไหนก็ได้ผลเดิม ใช้ Dependency Injection (createApp({ db })) เพื่อสลับของจริงเป็นของทดสอบ
  • รัน npm test ใน CI (เช่น GitHub Actions) ทุกครั้งที่ Push และใช้ node --test --watch ระหว่างเขียนโค้ด

  • ใช้ Debugger แทนการโรย console.log ทั่วโค้ด และอย่าลืมลบคำสั่ง debugger; ก่อน Commit

คืออะไร ทำไมต้องใช้ และใช้เมื่อไร

API ที่เปิดสู่อินเทอร์เน็ตจะถูกยิง Request แปลกๆ ทันทีที่ออนไลน์ ทั้งจากบอตสแกนช่องโหว่และจากผู้ใช้ที่ส่งข้อมูลผิดรูปแบบ แนวคิดนี้รวมชั้นป้องกันพื้นฐานที่ API ทุกตัวควรมีก่อนขึ้น Production และระบบ Log ที่ช่วยให้เรารู้ว่าเกิดอะไรขึ้นเมื่อมีปัญหา ภัยหลักที่ต้องรู้จักมีดังนี้

  • Injection ผู้ใช้ส่งข้อความที่กลายเป็นคำสั่ง เช่น SQL Injection ป้องกันด้วย Prepared Statement และการตรวจข้อมูลด้วย zod (แนวคิดที่ 9)
  • Body ขนาดใหญ่เกินไป ส่ง JSON หลายร้อย MB เพื่อให้ Server ใช้ Memory จนล่ม ป้องกันด้วย express.json({ limit: '10kb' }) ซึ่งตอบ 413 Payload Too Large
  • Brute Force และการยิงถี่ เช่น เดารหัสผ่านพันครั้งต่อนาที ป้องกันด้วย Rate Limit จาก express-rate-limit 8.7.1 ซึ่งตอบ 429 Too Many Requests
  • การรั่วไหลของข้อมูลภายใน เช่น ส่ง err.stack หรือชื่อเครื่องฐานข้อมูลกลับไปให้ Client ป้องกันด้วย Error Handler ที่ซ่อนรายละเอียดเมื่อ NODE_ENV=production
  • Header ที่ไม่ปลอดภัย เบราว์เซอร์มีกลไกป้องกันหลายอย่างที่ต้องเปิดด้วย Header เช่น Content-Security-Policy, X-Content-Type-Options: nosniff, Strict-Transport-Security, X-Frame-Options แพ็กเกจ helmet 8.3.0 ใส่ให้ทั้งหมดในบรรทัดเดียว และลบ X-Powered-By: Express ที่บอกผู้โจมตีว่าเราใช้อะไร
  • Dependency ที่มีช่องโหว่ แพ็กเกจที่เราติดตั้งอาจมีช่องโหว่ที่ถูกประกาศภายหลัง ตรวจด้วย npm audit และเปิด Dependabot บน GitHub ให้แจ้งเตือนอัตโนมัติ
  • Secret หลุด เก็บ API Key และรหัสผ่านฐานข้อมูลใน Environment Variable เท่านั้น (แนวคิดที่ 5) และห้ามเขียนลง Log

ส่วน Logging คือการบันทึกเหตุการณ์ของโปรแกรม console.log พอใช้ตอนเรียน แต่ใน Production เราต้องการ Log ที่เครื่องอ่านได้ (JSON), มีระดับความสำคัญ (Level), มีเวลา, ผูกกับ Request แต่ละตัว และปิดบังข้อมูลลับได้ pino 10.4.0 ทำทั้งหมดนี้และเร็วมาก ส่วน pino-http 11.0.0 เป็น Middleware ที่เขียน Log ให้ทุก Request อัตโนมัติ ระดับของ pino เรียงจากน้อยไปมากคือ trace (10), debug (20), info (30), warn (40), error (50), fatal (60) ตอนพัฒนาเราอ่าน Log ง่ายขึ้นด้วย pino-pretty 13.2.0 โดยต่อ Pipe (node src/server.js | npx pino-pretty) ส่วน Production ให้ Log เป็น JSON ตามเดิม เพื่อส่งเข้าระบบรวม Log

API เหมือนธนาคารสาขาหนึ่ง helmet คือป้ายและประตูนิรภัยมาตรฐานที่ทุกสาขาต้องมี Body Limit คือกฎว่าห้ามนำกระเป๋าใหญ่เกินกำหนดเข้ามา Rate Limit คือพนักงานหน้าประตูที่ไม่ให้คนคนเดียวเข้าคิวซ้ำร้อยรอบในหนึ่งนาที Error Handler ที่ซ่อน Stack Trace คือพนักงานที่ตอบลูกค้าว่า "ระบบขัดข้อง" แทนการอ่านรหัสตู้เซฟให้ฟัง ส่วน pino คือกล้องวงจรปิดที่บันทึกทุกเหตุการณ์พร้อมเวลา แต่เบลอหน้าจอตอนลูกค้ากดรหัส ATM (redact)

ไฟล์ที่สองคือ createApp() ที่ซ้อนชั้นป้องกันตามลำดับ helmet → Log → Body Limit → Rate Limit → Route → 404 → Error Handler ลำดับนี้สำคัญ เพราะ Express เรียก Middleware จากบนลงล่าง

// src/app.js — Express app ที่เพิ่มชั้นความปลอดภัยและ Logging
import express from 'express';
import helmet from 'helmet';
import { rateLimit } from 'express-rate-limit';
import { pinoHttp } from 'pino-http';
import { logger } from './logger.js';

export function createApp({ rateLimitMax = 5 } = {}) {
  const app = express();
  const isProd = process.env.NODE_ENV === 'production';

  // 1) helmet ใส่ Security Header มาตรฐาน และลบ X-Powered-By ให้
  app.use(helmet());

  // 2) Log ทุก Request เป็น JSON ระดับ Log ขึ้นกับ Status Code
  app.use(
    pinoHttp({
      logger,
      customLogLevel(req, res, err) {
        if (err || res.statusCode >= 500) return 'error';
        if (res.statusCode >= 400) return 'warn';
        return 'info';
      },
    }),
  );

  // 3) จำกัดขนาด Body ไม่เกิน 10kb ถ้าเกินได้ 413
  app.use(express.json({ limit: '10kb' }));

  // 4) Rate Limit เฉพาะ /api: 5 ครั้งต่อ 60 วินาทีต่อ IP (ค่าเล็กเพื่อสาธิต)
  const apiLimiter = rateLimit({
    windowMs: 60 * 1000,
    limit: rateLimitMax,
    standardHeaders: 'draft-8',
    legacyHeaders: false,
    handler(req, res) {
      res.status(429).json({
        error: 'TooManyRequests',
        message: 'เรียก API บ่อยเกินไป กรุณารอสักครู่แล้วลองใหม่',
      });
    },
  });
  app.use('/api', apiLimiter);

  app.get('/health', (req, res) => {
    res.json({ status: 'ok' });
  });

  app.get('/api/hello', (req, res) => {
    // req.log คือ Logger ที่ผูกกับ Request นี้ (มี req.id ติดไปด้วย)
    req.log.info({ name: 'somchai' }, 'ทักทายผู้ใช้');
    res.json({ message: 'สวัสดี somchai' });
  });

  app.post('/api/login', (req, res) => {
    // ห้าม Log รหัสผ่านตรงๆ redact จะเปลี่ยนเป็น [REDACTED]
    req.log.info({ username: req.body?.username, password: req.body?.password }, 'มีคนพยายามล็อกอิน');
    res.status(401).json({ error: 'Unauthorized', message: 'ชื่อผู้ใช้หรือรหัสผ่านไม่ถูกต้อง' });
  });

  app.get('/api/boom', async () => {
    throw new Error('ฐานข้อมูลเชื่อมต่อไม่ได้ (host=db.internal)');
  });

  app.use((req, res) => {
    res.status(404).json({ error: 'NotFound', message: `ไม่พบเส้นทาง ${req.method} ${req.path}` });
  });

  // Error Handler: ไม่ส่ง Stack Trace ให้ Client เมื่ออยู่ใน Production
  app.use((err, req, res, next) => {
    if (err.type === 'entity.too.large') {
      return res.status(413).json({ error: 'PayloadTooLarge', message: 'Body ใหญ่เกิน 10kb' });
    }
    req.log.error({ err }, 'เกิดข้อผิดพลาดที่ไม่คาดคิด');
    res.status(500).json({
      error: 'InternalServerError',
      message: isProd ? 'เกิดข้อผิดพลาดภายในระบบ' : err.message,
    });
  });

  return app;
}
// src/server.js — เริ่ม Server (แยกจาก app.js เพื่อให้ทดสอบได้)
import { createApp } from './app.js';
import { logger } from './logger.js';

const app = createApp();

app.listen(port, () => {
  logger.info({ port }, 'secure-lab พร้อมที่ http://localhost:' + port);
});

Streams, Backpressure และ worker_threads

คืออะไร ทำไมต้องใช้ และใช้เมื่อไร

จนถึงตอนนี้เราอ่านไฟล์ด้วย readFile ซึ่งโหลดข้อมูลทั้งไฟล์เข้า Memory ในครั้งเดียว วิธีนี้ดีกับไฟล์เล็ก แต่ถ้าไฟล์ Log ขนาด 5 GB หรือมีผู้ใช้ 100 คนดาวน์โหลดไฟล์ 200 MB พร้อมกัน Server จะใช้ Memory มหาศาลจนล่ม Stream แก้ปัญหานี้ด้วยการประมวลผลข้อมูลทีละก้อนเล็กๆ (chunk ปกติ 64 KB สำหรับไฟล์) เหมือนสายพาน Memory ที่ใช้จึงคงที่ไม่ว่าข้อมูลจะใหญ่แค่ไหน และเริ่มส่งผลลัพธ์ได้ทันทีโดยไม่ต้องรอข้อมูลครบ ใน Node.js ของหลายอย่างเป็น Stream อยู่แล้ว เช่น req และ res ของ HTTP Server, process.stdin, process.stdout และ Socket ของเครือข่าย Stream มี 4 ชนิด

  • Readable แหล่งข้อมูลที่อ่านได้ เช่น fs.createReadStream(), req ของ Server
  • Writable ปลายทางที่เขียนได้ เช่น fs.createWriteStream(), res ของ Server
  • Transform รับข้อมูลเข้าแล้วแปลงก่อนส่งออก เช่น zlib.createGzip() หรือตัวกรองที่เราเขียนเอง
  • Duplex อ่านและเขียนได้อิสระต่อกัน เช่น TCP Socket

Backpressure คือแรงดันย้อนกลับเมื่อฝั่งเขียนช้ากว่าฝั่งอ่าน เช่น อ่านไฟล์จาก SSD เร็วมาก แต่ส่งผ่านเน็ตมือถือของ Client ได้ช้า ถ้าไม่ควบคุม ข้อมูลจะกองใน Memory จนล้น กลไกของ Node คือ writable.write() คืนค่า false เมื่อ Buffer ภายในเกิน highWaterMark ผู้เขียนต้องหยุดแล้วรอ Event 'drain' ก่อนเขียนต่อ วิธีที่ง่ายและปลอดภัยที่สุดคือใช้ pipeline() จาก node:stream/promises ซึ่งจัดการ Backpressure ให้ ส่ง Error จากทุกท่อมาที่ catch จุดเดียว และปิด Stream ที่เหลือให้อัตโนมัติ

ส่วน worker_threads แก้ปัญหาอีกแบบ จากแนวคิดที่ 6 เรารู้ว่างานคำนวณหนัก (CPU-bound) บน Main Thread บล็อก Event Loop ทำให้ Server ตอบ Request อื่นไม่ได้ Worker Thread คือ Thread แยกที่มี V8 และ Event Loop ของตัวเอง เราส่งงานหนักไปให้มัน แล้วรับผลกลับด้วยข้อความ (postMessage) ใช้กับงานเช่น ย่อรูป, เข้ารหัส/แฮชจำนวนมาก, คำนวณสถิติ, แปลงไฟล์ ส่วนงาน I/O (อ่านไฟล์, เรียกฐานข้อมูล, เรียก API) ไม่ต้องใช้ Worker เพราะ libuv ทำแบบ Non-blocking ให้อยู่แล้ว

เปรียบเทียบ

readFile เหมือนการขนน้ำทั้งถังใหญ่มาเทใส่แก้วในครั้งเดียว ถ้าถังใหญ่กว่าแก้วน้ำก็ล้น Stream คือการต่อท่อจากถังมาที่ก๊อก ไหลทีละนิดเท่าที่ใช้ Backpressure คือวาล์วที่ปิดเองเมื่อแก้วปลายทางใกล้เต็ม และเปิดอีกครั้งเมื่อแก้วพร่อง ('drain') ส่วน Worker Thread เหมือนร้านอาหารที่มีพนักงานรับออร์เดอร์คนเดียว (Main Thread) ถ้าเขาลงไปทำอาหารจานยากเอง ลูกค้าคนอื่นต้องยืนรอ ร้านจึงจ้างพ่อครัวเพิ่ม (Worker) พนักงานรับออร์เดอร์ส่งใบสั่งไปให้ แล้วกลับมารับลูกค้าต่อได้ทันที

ไฟล์ที่ 1 สร้าง Log จำลอง 200,000 บรรทัด (ประมาณ 15 MB) โดยเขียนผ่าน Writable Stream และเคารพ Backpressure ทุกครั้งที่ write() คืน false

// make-log.js — สร้างไฟล์ access.log 200,000 บรรทัด โดยเคารพ Backpressure
import { createWriteStream } from 'node:fs';
import { once } from 'node:events';
import { finished } from 'node:stream/promises';
import path from 'node:path';

const file = path.join(import.meta.dirname, 'access.log');
const TOTAL = 200_000;
const statuses = [200, 200, 404, 500]; // วนสถานะซ้ำตามลำดับ ผลลัพธ์จึงเหมือนกันทุกครั้ง
const paths = ['/', '/api/books', '/api/books/1', '/login'];

// highWaterMark = ขนาด Buffer ภายในก่อนที่ write() จะเริ่มคืน false (64 KB)
const out = createWriteStream(file, { highWaterMark: 64 * 1024 });
let drainCount = 0;

for (let i = 0; i < TOTAL; i++) {
  const status = statuses[i % statuses.length];
  const line = `127.0.0.1 - somchai [21/Oct/2026:10:00:00 +0700] "GET ${paths[i % paths.length]} HTTP/1.1" ${status} ${100 + (i % 900)}\n`;
  // write() คืน false เมื่อ Buffer เต็ม = สัญญาณ Backpressure
  if (!out.write(line)) {
    drainCount++;
    await once(out, 'drain'); // หยุดรอจนดิสก์เขียนทันแล้วค่อยเขียนต่อ
  }
}
out.end(); // บอกว่าไม่มีข้อมูลเพิ่มแล้ว
await finished(out); // รอจนเขียนลงไฟล์ครบ
console.log(`เขียน ${TOTAL.toLocaleString('en-US')} บรรทัดลง access.log แล้ว`);
console.log(`ต้องรอ 'drain' ทั้งหมด ${drainCount} ครั้ง`);

ไฟล์ที่ 2 อ่าน Log ทีละบรรทัดด้วย readline แล้วนับ Status Code พร้อมวัด Memory

// analyze-log.js — อ่านไฟล์ใหญ่ทีละบรรทัดด้วย readline แล้วนับ Status Code
import { createReadStream } from 'node:fs';
import { createInterface } from 'node:readline';
import path from 'node:path';

const file = path.join(import.meta.dirname, process.argv[2] ?? 'access.log');
const input = createReadStream(file, { encoding: 'utf8' });
const rl = createInterface({ input, crlfDelay: Infinity });

const counts = {};
let lines = 0;
let peakHeap = 0;

try {
  // for await...of อ่านทีละบรรทัด Memory จึงคงที่ไม่ว่าไฟล์ใหญ่แค่ไหน
  for await (const line of rl) {
    lines++;
    // Status อยู่ในช่องที่สองจากท้ายของบรรทัด
    const parts = line.split(' ');
    const status = parts[parts.length - 2];
    counts[status] = (counts[status] ?? 0) + 1;
    if (lines % 20_000 === 0) {
      peakHeap = Math.max(peakHeap, process.memoryUsage().heapUsed);
    }
  }
} catch (err) {
  // Error จาก Stream ต้นทาง (เช่น ไม่พบไฟล์) จะถูกโยนออกมาที่ for await
  console.error(`อ่านไฟล์ไม่ได้: ${err.code} ${err.message}`);
  process.exitCode = 1;
}

if (!process.exitCode) {
  console.log(`อ่านทั้งหมด ${lines.toLocaleString('en-US')} บรรทัด`);
  for (const [status, n] of Object.entries(counts).sort()) {
    console.log(`  ${status}: ${n.toLocaleString('en-US')}`);
  }
  console.log(`Heap ที่ใช้สูงสุดประมาณ ${(peakHeap / 1024 / 1024).toFixed(1)} MB`);
}

ไฟล์ที่ 3 ต่อท่อด้วย pipeline: บีบอัดทั้งไฟล์ และกรองเฉพาะบรรทัด 5xx ผ่าน Transform Stream ที่เขียนเอง แล้วลองต่อท่อจากไฟล์ที่ไม่มีอยู่เพื่อดูการจับ Error

// gzip.js — ต่อ Stream เป็นท่อด้วย pipeline: อ่าน → กรองเฉพาะ 5xx → บีบอัด → เขียน
import { createReadStream, createWriteStream } from 'node:fs';
import { stat } from 'node:fs/promises';
import { Transform } from 'node:stream';
import { pipeline } from 'node:stream/promises';
import { createGzip } from 'node:zlib';
import path from 'node:path';

const dir = import.meta.dirname;
const src = path.join(dir, 'access.log');

// Transform Stream ที่เขียนเอง: รับข้อมูลเป็นก้อน (chunk) แล้วส่งต่อเฉพาะบรรทัดที่ Status 5xx
function onlyServerErrors() {
  let leftover = ''; // เศษบรรทัดที่ถูกตัดกลางก้อน
  return new Transform({
    transform(chunk, encoding, callback) {
      const lines = (leftover + chunk.toString('utf8')).split('\n');
      leftover = lines.pop(); // บรรทัดสุดท้ายอาจยังไม่ครบ เก็บไว้ต่อกับก้อนถัดไป
      const kept = lines.filter((l) => / 5\d\d \d+$/.test(l));
      callback(null, kept.length ? kept.join('\n') + '\n' : '');
    },
    flush(callback) {
      // ข้อมูลหมดแล้ว ตรวจเศษบรรทัดสุดท้าย
      callback(null, / 5\d\d \d+$/.test(leftover) ? leftover + '\n' : '');
    },
  });
}

// 1) บีบอัดทั้งไฟล์
await pipeline(createReadStream(src), createGzip(), createWriteStream(src + '.gz'));
// 2) กรองเฉพาะ 5xx แล้วบีบอัด
const errGz = path.join(dir, 'errors.log.gz');
await pipeline(createReadStream(src), onlyServerErrors(), createGzip(), createWriteStream(errGz));

const kb = async (f) => ((await stat(f)).size / 1024).toFixed(1) + ' KB';
console.log(`access.log      ${await kb(src)}`);
console.log(`access.log.gz   ${await kb(src + '.gz')}`);
console.log(`errors.log.gz   ${await kb(errGz)}`);

// 3) pipeline ส่ง Error จากทุกท่อมาที่ catch จุดเดียว และปิด Stream ที่เหลือให้
try {
  await pipeline(createReadStream(path.join(dir, 'missing.log')), createGzip(), createWriteStream(path.join(dir, 'missing.log.gz')));

}

// log-server.js — ส่งไฟล์ใหญ่เป็น HTTP Response แบบ Stream พร้อมบีบอัด gzip ระหว่างทาง
import http from 'node:http';
import { createReadStream } from 'node:fs';
import { pipeline } from 'node:stream/promises';
import { createGzip } from 'node:zlib';
import path from 'node:path';

const file = path.join(import.meta.dirname, 'access.log');
const port = Number(process.env.PORT ?? 3000);

const server = http.createServer(async (req, res) => {
  if (req.method !== 'GET' || req.url !== '/log') {
    res.writeHead(404, { 'Content-Type': 'application/json; charset=utf-8' });
    return res.end(JSON.stringify({ error: 'NotFound', message: 'ลองเรียก GET /log' }));
  }
  res.writeHead(200, {
    'Content-Type': 'text/plain; charset=utf-8',
    'Content-Encoding': 'gzip',
  });
  try {
    // res เป็น Writable Stream: pipeline จัดการ Backpressure ถ้า Client รับช้า
    await pipeline(createReadStream(file), createGzip(), res);
  } catch (err) {
    // เช่น Client ปิดการเชื่อมต่อกลางทาง (ERR_STREAM_PREMATURE_CLOSE)
    console.error('ส่งไฟล์ไม่สำเร็จ:', err.code);
  }
});

server.listen(port, () => console.log(`log-server พร้อมที่ http://localhost:${port}/log`));

Best Practice
  • ใช้ pipeline จาก node:stream/promises เป็นค่าเริ่มต้นทุกครั้งที่ต่อ Stream และครอบด้วย try/catch
  • ข้อมูลที่ขนาดไม่แน่นอนหรือใหญ่ (ไฟล์ที่ผู้ใช้อัปโหลด, Log, Export CSV, การดาวน์โหลด) ให้ประมวลผลแบบ Stream เสมอ ใช้ readFile เฉพาะไฟล์ที่รู้ว่าเล็ก เช่น Config
  • ถ้าต้องเขียนลง Writable Stream ด้วยลูปเอง ให้ตรวจค่าคืนของ write() และรอ 'drain'
  • ใช้ readline กับ for await...of เมื่อต้องการทีละบรรทัด และใช้ import.meta.dirname หรือ import.meta.url สร้าง Path เสมอ
  • ใช้ Worker เฉพาะงาน CPU-bound ที่วัดแล้วว่าบล็อก Event Loop ในงานจริงใช้ Worker Pool และจำกัดจำนวน Worker ไม่เกินจำนวนคอร์ (os.availableParallelism())
  • ส่งข้อมูลระหว่าง Main กับ Worker เท่าที่จำเป็น เพราะทุกข้อความถูกคัดลอก ข้อมูลใหญ่มากให้พิจารณา Transfer ArrayBuffer หรือ SharedArrayBuffer
