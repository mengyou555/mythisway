6.1Learning Roadmap

ภาพรวมเส้นทาง

Go (หรือที่หลายคนเรียกว่า Golang) เป็นภาษาที่ Google ออกแบบให้ อ่านง่าย คอมไพล์เร็ว และรันเร็ว จุดเด่นที่สุดคือเรื่อง Concurrency คือการทำหลายงานพร้อมกันด้วย Goroutine และ Channel ทำให้ Go ถูกใช้มากในงาน Backend, Cloud, DevOps และเครื่องมือสาย Security กับ Network เครื่องมือดังอย่าง Docker, Kubernetes, Terraform และ Prometheus ก็เขียนด้วย Go

หัวข้อนี้เป็น ภาษาที่สองฝั่ง Backend ต่อจาก Node.js และ Python คุณเข้าใจ HTTP, REST, JSON และฐานข้อมูลมาแล้ว จึงโฟกัสที่ "วิธีคิดแบบ Go" ได้เต็มที่ เส้นทางนี้มี 13 ขั้น ใช้เวลาประมาณ 60–90 ชั่วโมง (รวม Mini Project) ถ้าเรียนสัปดาห์ละ 7–8 ชั่วโมงจะจบในราว 10–12 สัปดาห์

  1. Beginner Step 1 · ติดตั้ง Go 1.27.2, Go Modules และคำสั่ง go
  2. Beginner Step 2 · ตัวแปร, Type, Zero Value, Constant และ Control Flow
  3. Beginner Step 3 · Function, Closure และการจัดการ Error แบบ Go
  4. Beginner Step 4 · Array, Slice, Map และ String
  5. Intermediate Step 5 · Struct, Method และ Pointer
  6. Intermediate Step 6 · Interface, Package และการจัดโครงสร้างโปรเจกต์
  7. Intermediate Step 7 · Generics (Type Parameters และ Constraints)
  8. Intermediate Step 8 · Testing: Table-driven Test, Subtest, Benchmark และ Coverage
  9. Intermediate Step 9 · สร้าง CLI: flag, File I/O, encoding/json และ log/slog
  10. Advanced Step 10 · Goroutine, Channel และ select
  11. Advanced Step 11 · sync, Data Race และ Worker Pool
  12. Advanced Step 12 · context, HTTP Client, Timeout และ Retry
  13. Advanced Step 13 · HTTP Server (Routing แบบ Go 1.22+), httptest, Build และ Cross-compile

STEP 1

สัปดาห์ที่ 1 · 4–5 ชม.
หัวข้อย่อย
  • ตรวจสถาปัตยกรรม CPU ด้วย uname -m (x86_64 ใช้ไฟล์ linux-amd64, aarch64 ใช้ไฟล์ linux-arm64)

STEP 2

ตัวแปร, Type, Zero Value, Constant และ Control Flow

สัปดาห์ที่ 1–2 · 5–7 ชม.
หัวข้อย่อย
  • ประกาศตัวแปร 3 แบบ: var x int, var x = 5 และ x := 5 (แบบสุดท้ายใช้ได้เฉพาะในฟังก์ชัน)
  • Basic Types: int, int64, float64, string, bool, byte, rune และการแปลง Type แบบ Explicit เช่น float64(n)
  • Zero Value: ตัวแปรที่ไม่กำหนดค่าจะได้ 0, "", false หรือ nil เสมอ ไม่มีค่าขยะ
  • Constant และ iota สำหรับสร้างค่าที่เรียงกัน เช่น สถานะ Up/Down/Unknown
  • if แบบมีคำสั่งเริ่มต้น เช่น if v, ok := m[k]; ok { ... }
  • for คือ Loop เดียวของ Go: แบบ 3 ส่วน, แบบเงื่อนไขอย่างเดียว (แทน while), แบบไม่สิ้นสุด และ for i := range 3 (range over int ตั้งแต่ Go 1.22)
  • switch ที่ไม่ต้องใส่ break, switch แบบไม่มีนิพจน์ (ใช้แทน if-else ยาว ๆ) และ fallthrough
  • Error ที่มือใหม่เจอบ่อย: declared and not used และ "os" imported and not used
ทำไมต้องเรียน
Syntax ของ Go มีน้อยแต่เข้มงวด ถ้าเข้าใจ Zero Value จะเขียนโค้ดสั้นลงมาก (ไม่ต้องตั้งค่าเริ่มต้นเอง) และถ้าคุ้นกับ for แบบต่าง ๆ จะอ่านโค้ด Go ของคนอื่นได้ทันที ทุกขั้นที่เหลือใช้เรื่องเหล่านี้ตลอด
ใช้เวลา

Function, Closure และการจัดการ Error แบบ Go

สัปดาห์ที่ 2–3 · 6–7 ชม.
หัวข้อย่อย
  • ประกาศฟังก์ชัน, Parameter ที่ Type เดียวกันเขียนรวมได้ เช่น func add(a, b int) int
  • Multiple Return Values และรูปแบบมาตรฐาน (ผลลัพธ์, error) พร้อมการเช็ค if err != nil

  • defer สำหรับเก็บกวาด เช่น ปิดไฟล์ และลำดับการทำงานแบบ LIFO
  • สร้าง Error: errors.New, fmt.Errorf และการห่อ Error ด้วย %w
  • ตรวจ Error: errors.Is สำหรับ Sentinel Error และ errors.As สำหรับ Custom Error Type
  • panic และ recover: มีไว้สำหรับความผิดพลาดที่ไม่ควรเกิดเท่านั้น ไม่ใช่ใช้แทน Exception
ทำไมต้องเรียน
Go ไม่มี try/catch Error เป็นค่าธรรมดาที่ต้องตรวจเองทุกครั้ง โค้ด Go ในงานจริงจึงเต็มไปด้วย if err != nil การห่อ Error ให้มีบริบท (เช่น "findUser id=2: not found") ทำให้หาสาเหตุปัญหาใน Log ได้เร็ว และผู้สัมภาษณ์งาน Go มักถามเรื่อง errors.Is กับ errors.As
ใช้เวลา

package main

import (
	"errors"
	"fmt"
)

// ErrNotFound คือ sentinel error ที่ผู้เรียกตรวจได้ด้วย errors.Is
var ErrNotFound = errors.New("not found")

// HTTPError คือ custom error type ที่เก็บ status code
type HTTPError struct {
	Code int
}

func (e *HTTPError) Error() string {
	return fmt.Sprintf("http status %d", e.Code)
}

// findUser คืนค่า 2 ค่า: ชื่อผู้ใช้ และ error
func findUser(id int) (string, error) {
	if id == 1 {
		return "somchai", nil
	}
	// %w ห่อ error เดิมไว้ เพื่อให้ errors.Is ยังหาเจอ
	return "", fmt.Errorf("findUser id=%d: %w", id, ErrNotFound)
}

func fetch(code int) error {
	if code >= 400 {
		return fmt.Errorf("fetch: %w", &HTTPError{Code: code})
	}
	return nil
}

// sum เป็น variadic function รับตัวเลขกี่ตัวก็ได้
func sum(nums ...int) int {
	total := 0
	for _, n := range nums {
		total += n
	}
	return total
}

// counter คืน closure ที่จำค่า n ไว้ระหว่างการเรียกแต่ละครั้ง
func counter() func() int {
	n := 0
	return func() int {
		n++
		return n
	}
}

func main() {
	defer fmt.Println("defer: ทำงานเป็นบรรทัดสุดท้ายก่อน main จบ")

	name, err := findUser(1)
	fmt.Println(name, err)

	_, err = findUser(2)
	fmt.Println("error:", err)
	fmt.Println("is ErrNotFound?", errors.Is(err, ErrNotFound))

	err = fetch(503)
	var he *HTTPError
	if errors.As(err, &he) {
		fmt.Println("ได้ HTTPError code =", he.Code)
	}

	fmt.Println("sum =", sum(1, 2, 3, 4))
	next := counter()
	next()
	next()
	fmt.Println("counter =", next())
}

STEP 4

Array, Slice, Map และ String

สัปดาห์ที่ 3 · 5–7 ชม.
หัวข้อย่อย
  • Array (ขนาดคงที่ เช่น [3]int) ต่างจาก Slice (ขนาดเปลี่ยนได้ เช่น []int) อย่างไร
  • Slice มี 3 ส่วน: Pointer ไปยัง Backing Array, len และ cap พร้อม make([]T, len, cap)
  • append และกับดักที่พบบ่อย: Slice ย่อยใช้ Backing Array เดียวกับต้นฉบับ จึงเขียนทับข้อมูลกันได้ แก้ด้วย slices.Clone หรือ copy
  • Package slices: slices.Sort, slices.Contains, slices.Index, slices.Clone
  • Map: สร้างด้วย Literal หรือ make, เช็คการมี Key แบบ comma-ok, ลบด้วย delete และการเขียน nil map แล้ว panic
  • ลำดับการวน Map เป็นแบบสุ่ม ใช้ slices.Sorted(maps.Keys(m)) เมื่ออยากได้ผลที่เรียงลำดับ
  • String เป็น Byte แบบ UTF-8 ที่แก้ไขไม่ได้ ภาษาไทย 1 ตัวใช้ 3 Byte ใช้ utf8.RuneCountInString นับตัวอักษร และ for _, r := range s วนทีละ Rune
  • Package strings และ strconv: strings.Split, strings.TrimSpace, strings.Builder, strconv.Atoi
ทำไมต้องเรียน
Slice และ Map คือโครงสร้างข้อมูลที่ใช้มากที่สุดใน Go บัคแปลก ๆ หลายตัวในงานจริงมาจากการไม่เข้าใจ len/cap และ Backing Array และคำถามสัมภาษณ์งาน Go แทบทุกที่มีเรื่องนี้ การรู้ว่า String เป็น Byte ก็จำเป็นมากเมื่อต้องตัดข้อความภาษาไทย
ใช้เวลา
5–7 ชั่วโมง: Slice และกับดักของ append 2–3 ชม., Map 1–2 ชม., String, Rune, strings และ strconv 2 ชม.
package main

import (
	"fmt"
	"maps"
	"slices"
	"unicode/utf8"
)

func main() {
	// make([]T, len, cap) สร้าง slice ที่จองความจุไว้ล่วงหน้า
	s := make([]int, 0, 3)
	for i := range 5 {
		s = append(s, i)
		fmt.Printf("len=%d cap=%d %v\n", len(s), cap(s), s)
	}

	// กับดัก: slice ย่อยใช้ backing array เดียวกับต้นฉบับ
	a := []int{1, 2, 3, 4}
	b := a[:2]
	b = append(b, 99) // เขียนทับ a[2] เพราะยังมีความจุเหลือ
	fmt.Println("a =", a, "b =", b)

	// ทางแก้: คัดลอกก่อนด้วย slices.Clone
	c := slices.Clone(a[:2])
	c = append(c, 7)
	fmt.Println("a =", a, "c =", c)

	// map และการเช็คว่ามี key หรือไม่ (comma-ok)
	status := map[string]int{"go.dev": 200, "example.com": 200, "bad.test": 0}
	if code, ok := status["go.dev"]; ok {
		fmt.Println("go.dev =", code)
	}
	_, ok := status["missing.test"]
	fmt.Println("missing.test มีไหม:", ok)

	// map ไม่เรียงลำดับ ต้องเรียง key เองถ้าอยากได้ผลคงที่
	for _, k := range slices.Sorted(maps.Keys(status)) {
		fmt.Println(k, status[k])
	}

	// string เก็บเป็น byte (UTF-8) ภาษาไทย 1 ตัวใช้ 3 byte
	word := "สวัสดี"
	fmt.Println("bytes:", len(word), "runes:", utf8.RuneCountInString(word))
}

STEP 5

สัปดาห์ที่ 4 · 4–5 ชม.
หัวข้อย่อย
  • ประกาศ Struct, Struct Literal แบบระบุชื่อฟิลด์ และ Zero Value ของ Struct
  • Visibility: ชื่อที่ขึ้นต้นด้วยตัวพิมพ์ใหญ่ (เช่น Owner) Export ออกนอก Package ได้ ตัวพิมพ์เล็กใช้ได้แค่ใน Package เดียวกัน
  • Pointer: &x เอา Address, *p อ่านค่าที่ชี้อยู่, ค่า nil และ panic: runtime error: invalid memory address or nil pointer dereference
  • Method แบบ Value Receiver กับ Pointer Receiver และกฎว่าเมื่อไรต้องใช้ Pointer Receiver (ต้องแก้ค่า, Struct ใหญ่, มี Mutex อยู่ข้างใน)

  • Struct Embedding (การฝัง Struct) เพื่อนำฟิลด์และเมธอดมาใช้ซ้ำแทน Inheritance
  • Struct Tag เช่น `json:"url"` ที่จะใช้ใน Step 9
  • เมธอด String() string ทำให้ fmt พิมพ์ค่าในรูปแบบที่เรากำหนด
ทำไมต้องเรียน
Go ไม่มี Class แต่ใช้ Struct + Method แทน ข้อมูลทุกอย่างในงาน Backend เช่น User, Order, Request และ Result ของ Health Checker ล้วนเป็น Struct การเลือก Value หรือ Pointer Receiver ผิดเป็นสาเหตุของบัค "แก้ค่าแล้วค่าไม่เปลี่ยน" ที่เจอบ่อยมาก
ใช้เวลา

package main

import "fmt"

// Account เก็บข้อมูลบัญชี ฟิลด์ตัวพิมพ์ใหญ่ = export ได้
type Account struct {
	Owner   string
	Balance int
}

// Deposit ใช้ pointer receiver เพราะต้องแก้ค่าในตัว struct จริง
func (a *Account) Deposit(amount int) {
	a.Balance += amount
}

// DepositCopy ใช้ value receiver จึงแก้แค่สำเนา
func (a Account) DepositCopy(amount int) {
	a.Balance += amount
}

// String ทำให้ fmt พิมพ์ Account ในรูปแบบที่เรากำหนด
func (a Account) String() string {
	return fmt.Sprintf("%s: %d บาท", a.Owner, a.Balance)
}

func main() {
	acc := Account{Owner: "somchai", Balance: 100}
	acc.DepositCopy(50)
	fmt.Println("หลัง DepositCopy:", acc)
	acc.Deposit(50)
	fmt.Println("หลัง Deposit:", acc)

	// pointer: p เก็บ address ของ acc
	p := &acc
	p.Balance = 1000
	fmt.Println("แก้ผ่าน pointer:", acc)

	// pointer ที่ยังไม่ชี้ไปไหนมีค่า nil
	var q *Account
	fmt.Println("q == nil:", q == nil)
}

  • แนวคิด "Accept interfaces, return structs" และ Interface ขนาดเล็ก (1–3 เมธอด) ที่ประกาศฝั่งผู้ใช้

package main

import (
	"fmt"
	"strings"
)

// Checker คือ interface: ใครมีเมธอด Check() error ก็นับว่าเป็น Checker
type Checker interface {
	Name() string
	Check() error
}

// HTTPCheck ไม่ต้องประกาศว่า implements Checker (implicit)
type HTTPCheck struct{ URL string }

func (h HTTPCheck) Name() string { return "http " + h.URL }
func (h HTTPCheck) Check() error {
	if strings.HasSuffix(h.URL, ".invalid") {
		return fmt.Errorf("dns lookup failed")
	}
	return nil
}

// DiskCheck เป็นอีก type หนึ่งที่ใช้แทน Checker ได้เหมือนกัน
type DiskCheck struct{ FreePercent int }

func (d DiskCheck) Name() string { return "disk" }
func (d DiskCheck) Check() error {
	if d.FreePercent < 10 {
		return fmt.Errorf("free space %d%%", d.FreePercent)
	}
	return nil
}

func main() {
	checks := []Checker{
		HTTPCheck{URL: "https://go.dev"},
		HTTPCheck{URL: "https://down.invalid"},
		DiskCheck{FreePercent: 5},
	}
	for _, c := range checks {
		if err := c.Check(); err != nil {
			fmt.Printf("%-26s FAIL (%v)\n", c.Name(), err)
			continue
		}
		fmt.Printf("%-26s OK\n", c.Name())
	}

	// type switch ใช้แยกว่าค่าใน interface เป็น type อะไรจริง ๆ
	for _, c := range checks {
		switch v := c.(type) {
		case HTTPCheck:
			fmt.Println("HTTP ->", v.URL)
		case DiskCheck:
			fmt.Println("Disk ->", v.FreePercent, "%")
		}
	}
}

สัปดาห์ที่ 5 · 3–5 ชม.
หัวข้อย่อย
  • Generic Function: func Max[T cmp.Ordered](values ...T) T และการให้คอมไพเลอร์อนุมาน Type เอง
  • Constraint: any, comparable, cmp.Ordered และการเขียน Constraint เองด้วย Type Set เช่น ~int | ~float64
  • Generic Type: type Stack[T any] struct{ ... } พร้อมเมธอด
  • การคืน Zero Value ของ T ด้วย var zero T
  • Generic ใน Standard Library: Package slices, maps และ cmp
  • เมื่อไรควรใช้ Generics (โครงสร้างข้อมูลและฟังก์ชันที่ทำงานเหมือนกันกับหลาย Type) และเมื่อไรใช้ Interface ดีกว่า (เมื่อพฤติกรรมต่างกัน)
ทำไมต้องเรียน

package main

import (
	"cmp"
	"fmt"
)

// Max ใช้ได้กับทุก type ที่เปรียบเทียบด้วย < ได้ (cmp.Ordered)
func Max[T cmp.Ordered](values ...T) T {
	m := values[0]
	for _, v := range values[1:] {
		if v > m {
			m = v
		}
	}
	return m
}

// Filter เลือกเฉพาะสมาชิกที่ฟังก์ชัน keep ตอบ true
func Filter[T any](items []T, keep func(T) bool) []T {
	var out []T
	for _, it := range items {
		if keep(it) {
			out = append(out, it)
		}
	}
	return out
}

// Stack แบบ generic เก็บข้อมูล type ใดก็ได้
type Stack[T any] struct{ items []T }

func (s *Stack[T]) Push(v T) { s.items = append(s.items, v) }
func (s *Stack[T]) Pop() (T, bool) {
	var zero T
	if len(s.items) == 0 {
		return zero, false
	}
	v := s.items[len(s.items)-1]
	s.items = s.items[:len(s.items)-1]
	return v, true
}

func main() {
	fmt.Println(Max(3, 9, 4))
	fmt.Println(Max("apple", "mango", "banana"))
	fmt.Println(Max(1.5, 0.2))

	ms := []int{120, 45, 900, 30}
	slow := Filter(ms, func(v int) bool { return v > 100 })
	fmt.Println("slow (ms):", slow)

	var st Stack[string]
	st.Push("a")
	st.Push("b")
	v, _ := st.Pop()
	fmt.Println("pop:", v)
}

package main

import (
	"bufio"
	"encoding/json"
	"flag"
	"fmt"
	"log/slog"
	"os"
	"strings"
)

// Target คือข้อมูล 1 รายการที่จะเขียนออกเป็น JSON
type Target struct {
	URL     string `json:"url"`
	Enabled bool   `json:"enabled"`
}

func main() {
	// flag: อ่านค่าจาก command line เช่น -file urls.txt
	file := flag.String("file", "urls.txt", "ไฟล์รายการ URL")
	flag.Parse()

	// logger แบบ structured เขียนไปที่ stderr ไม่ปนกับผลลัพธ์จริง
	logger := slog.New(slog.NewTextHandler(os.Stderr, nil))

	f, err := os.Open(*file)
	if err != nil {
		logger.Error("open file failed", "file", *file, "err", err)
		os.Exit(2) // exit code 2 = ใช้งานผิด/ไฟล์ไม่มี
	}
	defer f.Close()

	var targets []Target
	sc := bufio.NewScanner(f)
	for sc.Scan() {
		line := strings.TrimSpace(sc.Text())
		if line == "" || strings.HasPrefix(line, "#") {
			continue // ข้ามบรรทัดว่างและ comment
		}
		targets = append(targets, Target{URL: line, Enabled: true})
	}
	logger.Info("loaded", "count", len(targets))

	// แปลง struct เป็น JSON แบบจัดย่อหน้า
	out, _ := json.MarshalIndent(targets, "", "  ")
	fmt.Println(string(out))

STEP 10

Goroutine, Channel และ select

สัปดาห์ที่ 7–8 · 5–7 ชม.
หัวข้อย่อย
  • Goroutine คืออะไร: go f() เริ่มงานใหม่ที่ทำพร้อมกัน ใช้หน่วยความจำเริ่มต้นเพียงไม่กี่ KB จึงสร้างได้นับหมื่นตัว
  • Concurrency (จัดการหลายงานสลับกัน) ต่างจาก Parallelism (ทำพร้อมกันจริงบนหลาย CPU Core) อย่างไร และบทบาทของ Go Scheduler
  • Channel: make(chan T), ส่งด้วย ch <- v, รับด้วย v := <-ch และ Channel ทิศทางเดียว <-chan T / chan<- T
  • Unbuffered Channel (ผู้ส่งรอจนกว่าผู้รับพร้อม) กับ Buffered Channel (make(chan T, n) ส่งได้ n ค่าก่อนต้องรอ)
  • ปิด Channel ด้วย close(ch), วนรับด้วย for v := range ch และกฎว่า "ผู้ส่งเป็นคนปิด"
  • select รอหลาย Channel พร้อมกัน, ใช้ร่วมกับ time.After ทำ Timeout และ default สำหรับไม่ต้องรอ
  • Deadlock: fatal error: all goroutines are asleep - deadlock! และ Goroutine Leak (Goroutine ค้างตลอดไปเพราะไม่มีใครรับค่า)
  • รูปแบบพื้นฐาน: Generator, Fan-out/Fan-in และ Pipeline
ทำไมต้องเรียน
นี่คือเหตุผลหลักที่บริษัทเลือก Go งาน Backend และ Network ส่วนใหญ่คือ "รอ" เช่น รอฐานข้อมูล รอเว็บอื่นตอบ การตรวจ 100 URL ทีละตัวอาจใช้เวลาหลายนาที แต่ถ้าใช้ Goroutine ตรวจพร้อมกันจะเสร็จในเวลาใกล้เคียงกับ URL ที่ช้าที่สุดเพียงตัวเดียว
ใช้เวลา
5–7 ชั่วโมง: Goroutine และ Channel 2–3 ชม., select และ Timeout 1–2 ชม., ทดลองทำให้เกิด Deadlock แล้วแก้ 1 ชม., อ่านบทความ "Go Concurrency Patterns: Pipelines" บน go.dev/blog 1 ชม.
package main

import (
	"fmt"
	"time"
)

// worker รับงานจาก jobs แล้วส่งผลกลับทาง results
func worker(id int, jobs <-chan int, results chan<- string) {
	for n := range jobs {
		time.Sleep(10 * time.Millisecond) // จำลองงานที่ใช้เวลา
		results <- fmt.Sprintf("worker %d ทำงาน %d เสร็จ", id, n)
	}
}

func main() {
	// unbuffered channel: ผู้ส่งจะรอจนกว่าผู้รับพร้อม
	done := make(chan string)
	go func() { done <- "goroutine ทักทาย" }()
	fmt.Println(<-done)

	// buffered channel: ส่งได้ 2 ค่าโดยยังไม่มีคนรับ
	buf := make(chan int, 2)
	buf <- 1
	buf <- 2
	fmt.Println("len(buf) =", len(buf), "cap(buf) =", cap(buf))

	jobs := make(chan int, 3)
	results := make(chan string, 3)
	go worker(1, jobs, results)
	for i := 1; i <= 3; i++ {
		jobs <- i
	}
	close(jobs) // บอก worker ว่าไม่มีงานเพิ่มแล้ว
	for range 3 {
		fmt.Println(<-results)
	}

	// select: รอหลาย channel พร้อมกัน พร้อม timeout
	slow := make(chan string)
	go func() {
		time.Sleep(200 * time.Millisecond)
		slow <- "ตอบช้า"
	}()
	select {
	case msg := <-slow:
		fmt.Println(msg)
	case <-time.After(50 * time.Millisecond):
		fmt.Println("timeout หลัง 50ms")
	}
}

STEP 11

sync, Data Race และ Worker Pool

สัปดาห์ที่ 8–9 · 5–7 ชม.
หัวข้อย่อย
  • sync.WaitGroup: รอให้ Goroutine ทุกตัวจบ ใช้ wg.Go(func() { ... }) (Go 1.25+) หรือแบบเดิม wg.Add(1) + defer wg.Done()
  • Data Race คืออะไร: หลาย Goroutine อ่านและเขียนตัวแปรเดียวกันพร้อมกันโดยไม่มีการป้องกัน ผลลัพธ์จึงผิดแบบสุ่ม
  • Race Detector: go run -race และ go test -race (ต้องมี gcc เพราะใช้ cgo ติดตั้งด้วย sudo apt install -y gcc)
  • sync.Mutex และ sync.RWMutex สำหรับป้องกันข้อมูลที่ใช้ร่วมกัน และ sync/atomic สำหรับตัวนับง่าย ๆ เช่น atomic.Int64
  • sync.Once สำหรับงานที่ต้องทำครั้งเดียว เช่น โหลด Config
  • Worker Pool: จำกัดจำนวน Goroutine ที่ทำงานพร้อมกัน (เช่น 3 หรือ 10 ตัว) ด้วย Channel ของงาน + WaitGroup + ปิด Channel ผลลัพธ์เมื่อทุกตัวจบ
  • เก็บผลให้อยู่ในลำดับเดิมโดยส่ง Index ไปพร้อมงาน หรือเรียงผลภายหลัง
  • รู้จัก golang.org/x/sync/errgroup (v0.24.0) สำหรับรอหลายงานพร้อมรับ Error ตัวแรก
ทำไมต้องเรียน
การปล่อย Goroutine ไม่จำกัดจำนวนอาจยิง Request ไปหาเว็บปลายทางหลายพันครั้งพร้อมกัน ซึ่งทั้งเปลืองทรัพยากรและอาจโดนบล็อก Worker Pool คือรูปแบบมาตรฐานในงานจริง และ Data Race เป็นบัคที่หายากที่สุดบัคหนึ่ง ทีม Go จึงรัน go test -race ใน CI เสมอ
ใช้เวลา
5–7 ชั่วโมง: WaitGroup และ Mutex 2 ชม., Race Detector 1 ชม., Worker Pool และการเก็บผลตามลำดับ 2–3 ชม., อ่าน errgroup 1 ชม.

package main

import (
	"fmt"
	"slices"
	"sync"
)

// SafeCounter ใช้ Mutex ป้องกันการเขียน map พร้อมกันจากหลาย goroutine
type SafeCounter struct {
	mu     sync.Mutex
	counts map[string]int
}

func (c *SafeCounter) Inc(key string) {
	c.mu.Lock()
	defer c.mu.Unlock()
	c.counts[key]++
}

func main() {
	urls := []string{"a.test", "b.test", "c.test", "d.test", "e.test", "f.test"}
	jobs := make(chan string)
	results := make(chan string)
	counter := &SafeCounter{counts: map[string]int{}}

	// worker pool: 3 workers ช่วยกันดึงงานจาก channel เดียวกัน
	var wg sync.WaitGroup
	for id := range 3 {
		wg.Go(func() { // wg.Go มีตั้งแต่ Go 1.25
			for u := range jobs {
				counter.Inc("checked")
				results <- fmt.Sprintf("%s by worker-%d", u, id)
			}
		})
	}

	// ส่งงานใน goroutine แยก แล้วปิด channel เมื่อส่งครบ
	go func() {
		for _, u := range urls {
			jobs <- u
		}
		close(jobs)
	}()
	// ปิด results เมื่อ worker ทุกตัวจบ
	go func() {
		wg.Wait()
		close(results)
	}()

	var got []string
	for r := range results {
		got = append(got, r[:6]) // เก็บเฉพาะชื่อ URL เพื่อเรียงผล
	}
	slices.Sort(got)
	fmt.Println(got)
	fmt.Println("checked =", counter.counts["checked"])
}

STEP 12

context, HTTP Client, Timeout และ Retry

สัปดาห์ที่ 9–10 · 4–6 ชม.
หัวข้อย่อย
  • Package context: context.Background(), context.WithTimeout, context.WithCancel และการเรียก defer cancel() ทุกครั้ง
  • ส่ง ctx เป็นพารามิเตอร์ตัวแรกของฟังก์ชันที่ทำ I/O ตามธรรมเนียม func Check(ctx context.Context, url string) Result
  • ตรวจการยกเลิกด้วย <-ctx.Done() ใน select และแยกสาเหตุด้วย errors.Is(err, context.DeadlineExceeded) หรือ context.Canceled
  • http.Client ที่กำหนด Timeout เสมอ (ค่าเริ่มต้นของ http.DefaultClient คือรอไม่จำกัด) และ http.NewRequestWithContext สำหรับ Timeout ราย Request
  • ปิด resp.Body ทุกครั้งด้วย defer resp.Body.Close() เพื่อคืน Connection ให้ระบบใช้ซ้ำ
  • Retry แบบมีขอบเขต: ลองใหม่เฉพาะ Network Error และ Status 5xx, จำกัดจำนวนครั้ง, รอเพิ่มขึ้นทีละขั้น (Backoff) และหยุดทันทีเมื่อ ctx ถูกยกเลิก
  • วัด Latency ด้วย time.Now() และ time.Since(start)
  • จำลอง Server ใน Test ด้วย httptest.NewServer เพื่อไม่ต้องพึ่งอินเทอร์เน็ต
ทำไมต้องเรียน
ระบบที่ไม่มี Timeout คือระบบที่รอค้างได้ตลอดไป ถ้าเว็บปลายทางเดียวไม่ตอบ ทั้งโปรแกรมอาจหยุดนิ่ง context คือวิธีมาตรฐานของ Go ในการส่งสัญญาณ "หยุดได้แล้ว" ข้ามทุกฟังก์ชันและทุก Goroutine Library ทุกตัวในงานจริง เช่น Driver ฐานข้อมูลและ gRPC ก็รับ ctx เป็นพารามิเตอร์แรก
ใช้เวลา
4–6 ชั่วโมง: context 2 ชม., HTTP Client และการปิด Body 1–2 ชม., เขียน Retry พร้อม Backoff และทดสอบกับ httptest 1–2 ชม.

ตัวอย่างนี้สร้าง Server จำลองที่ตอบช้า 300 ms ไว้ในโปรแกรมเลย จึงรันได้โดยไม่ต้องต่ออินเทอร์เน็ต แล้วตั้ง Timeout ของ Request ไว้แค่ 100 ms

package main

import (
	"context"
	"errors"
	"fmt"
	"net/http"
	"net/http/httptest"
	"time"
)

func main() {
	// สร้าง server จำลองในเครื่อง ที่ตอบช้า 300ms
	slow := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		select {
		case <-time.After(300 * time.Millisecond):
			fmt.Fprintln(w, "ok")
		case <-r.Context().Done(): // client ยกเลิกแล้ว ก็หยุดทำงาน
		}
	}))
	defer slow.Close()

	// http.Client ควรกำหนด Timeout เสมอ (ค่าเริ่มต้นคือรอไม่จำกัด)
	client := &http.Client{Timeout: 5 * time.Second}

	// context กำหนดเวลาให้ request นี้แค่ 100ms
	ctx, cancel := context.WithTimeout(context.Background(), 100*time.Millisecond)
	defer cancel()

	req, _ := http.NewRequestWithContext(ctx, http.MethodGet, slow.URL, nil)
	start := time.Now()
	_, err := client.Do(req)
	fmt.Println("error:", err != nil)
	fmt.Println("is DeadlineExceeded:", errors.Is(err, context.DeadlineExceeded))
	fmt.Println("ใช้เวลาน้อยกว่า 200ms:", time.Since(start) < 200*time.Millisecond)
}

เปรียบเทียบ

context เหมือนนาฬิกาจับเวลาที่หัวหน้าทีมยื่นให้ลูกทีมทุกคนก่อนออกไปทำงาน เมื่อนาฬิกาดัง (Timeout) หรือหัวหน้าโทรสั่งยกเลิก (Cancel) ทุกคนที่ถือนาฬิกาเรือนนั้นต้องหยุดงานและกลับมาพร้อมกัน ไม่มีใครค้างอยู่ข้างนอก

Security

เครื่องมือที่ยิง Request ไปหาหลายเว็บพร้อมกันต้องใช้อย่างรับผิดชอบ ทดสอบกับ httptest, 127.0.0.1 หรือ Server ของคุณเองเท่านั้น จำกัดจำนวน Worker และจำนวน Retry เสมอ การยิง Request ถี่ ๆ ใส่ระบบของผู้อื่นโดยไม่ได้รับอนุญาตอาจผิด พ.ร.บ.ว่าด้วยการกระทำความผิดเกี่ยวกับคอมพิวเตอร์ และถูกมองว่าเป็นการโจมตีแบบ DoS

Checkpoint

ก่อนไปขั้นถัดไป คุณต้องทำสิ่งเหล่านี้ได้: เขียนฟังก์ชัน Check(ctx context.Context, client *http.Client, url string) (int, time.Duration, error) ที่คืน Status Code และ Latency พร้อม defer resp.Body.Close(), เพิ่ม Retry สูงสุด 2 ครั้งเมื่อได้ 5xx โดยรอ 100 ms และ 200 ms ระหว่างครั้ง แล้วพิสูจน์ด้วย httptest Server ที่ตอบ 503 สองครั้งก่อนตอบ 200, ใช้ context.WithCancel หยุด Goroutine หลายตัวพร้อมกันได้ และอธิบายได้ว่า Client.Timeout ต่างจาก Timeout ใน ctx อย่างไร

package main

import (
	"encoding/json"
	"log/slog"
	"net/http"
	"os"
	"strconv"
)

// Item คือข้อมูลสินค้าที่ API ส่งออก
type Item struct {
	ID   int    `json:"id"`
	Name string `json:"name"`
}

var items = map[int]Item{1: {1, "keyboard"}, 2: {2, "mouse"}}

func writeJSON(w http.ResponseWriter, status int, v any) {
	w.Header().Set("Content-Type", "application/json")
	w.WriteHeader(status)
	json.NewEncoder(w).Encode(v)
}

func main() {
	mux := http.NewServeMux()
	// routing pattern แบบใหม่ของ Go 1.22+: ระบุ method และ path variable ได้
	mux.HandleFunc("GET /health", func(w http.ResponseWriter, r *http.Request) {
		writeJSON(w, http.StatusOK, map[string]string{"status": "ok"})
	})
	mux.HandleFunc("GET /items/{id}", func(w http.ResponseWriter, r *http.Request) {
		id, err := strconv.Atoi(r.PathValue("id")) // อ่านค่า {id} จาก path
		if err != nil {
			writeJSON(w, http.StatusBadRequest, map[string]string{"error": "id must be a number"})
			return
		}
		item, ok := items[id]
		if !ok {
			writeJSON(w, http.StatusNotFound, map[string]string{"error": "item not found"})
			return
		}
		writeJSON(w, http.StatusOK, item)
	})

	addr := "127.0.0.1:8080"
	slog.Info("server started", "addr", addr)
	if err := http.ListenAndServe(addr, mux); err != nil {
		slog.Error("server stopped", "err", err)
		os.Exit(1)
	}
}

ตำแหน่งทำอะไรระดับทักษะที่ต้องมี
Junior Backend Developer (Go)เขียนและดูแล REST API, เชื่อมฐานข้อมูล, เขียน Test ให้ Service ของทีมJuniornet/http หรือ chi/Gin, JSON, SQL กับ pgx, Table-driven Test, Git
Backend / Microservices Engineerออกแบบ Service ที่รองรับผู้ใช้จำนวนมาก, ทำ Concurrency, Caching และ Message QueueMid–SeniorGoroutine, context, gRPC, PostgreSQL, Redis, Docker, Observability
Platform / DevOps Engineerสร้างเครื่องมือภายในและ CLI สำหรับ Deploy, เขียน Automation และดูแล CI/CDMidGo CLI, Cross-compile, Docker, Kubernetes, GitHub Actions, Linux
Site Reliability Engineer (SRE)ดูแลให้ระบบพร้อมใช้งาน, เขียน Health Check, Exporter และเครื่องมือตรวจสอบระบบMid–SeniorGo, Prometheus, Logging ด้วย slog, Timeout/Retry, Incident Response
Cloud Native / Kubernetes Developerเขียน Operator, Controller และส่วนขยายของ Kubernetes ซึ่งเขียนด้วย Go เป็นหลักSeniorGo ขั้นสูง, Kubernetes API, Interface Design, Concurrency
Security Tooling Engineerสร้างเครื่องมือ Scan, ตรวจ Config และวิเคราะห์ Log สำหรับทีม Security (ในระบบที่ได้รับอนุญาตเท่านั้น)MidGo, HTTP/TLS, Worker Pool, JSON, ความรู้ OWASP และ Network
Network Automation Engineerเขียนโปรแกรมตรวจสถานะและตั้งค่าอุปกรณ์เครือข่ายจำนวนมากพร้อมกันMidGo, Concurrency, SSH/API ของอุปกรณ์, TCP/IP, YAML/JSON

ใบรับรอง (Certification)

  • Go: ไม่มีใบรับรองหลัก ทีม Go และ Google ไม่มีการสอบรับรองทางการสำหรับภาษา Go สิ่งที่ผู้จ้างดูคือ Portfolio บน GitHub ที่มี Test และ README ดี, การมีส่วนร่วมใน Open Source ที่เขียนด้วย Go และผลงานจริง เช่น Mini Project ของหัวข้อนี้
  • GitHub Actions (GH-200) สถานะ Active ช่วยยืนยันทักษะการตั้ง CI ที่รัน go test -race และ Build Binary อัตโนมัติ
  • GitHub Foundations (GH-900) สถานะ Active เหมาะถ้ายังไม่เคยมีใบรับรองด้าน Git/GitHub
  • AWS Certified Developer – Associate สอบรหัส DVA-C02 ได้ถึง 2026-11-30 และเปลี่ยนเป็น DVA-C03 ตั้งแต่ 2026-12-01 เหมาะกับสาย Backend ที่ Deploy Go Service บน AWS
  • LFCS (Linux Foundation Certified System Administrator) สถานะ Active เหมาะกับสาย Platform/SRE ที่รัน Go Service บน Linux
  • ใบรับรองด้าน Kubernetes ของ Linux Foundation (เช่น CKAD) เป็นที่ยอมรับในสาย Cloud Native แต่หลักสูตรนี้ไม่ได้ตรวจสอบรายละเอียดล่าสุด ให้ตรวจสอบเงื่อนไข ราคา และเวอร์ชันข้อสอบที่ training.linuxfoundation.org ก่อนสมัคร
หมายเหตุ

เงินเดือนของตำแหน่งที่ใช้ Go แตกต่างกันมากตามประสบการณ์ ขนาดบริษัท อุตสาหกรรม และเมือง หลักสูตรนี้จึงไม่ระบุตัวเลข วิธีหาข้อมูลจริง: ค้นใน JobsDB และ LinkedIn Jobs ด้วยคำว่า "Golang", "Go Developer" และ "Backend Go" แล้วกรองตามประเทศไทยและระดับประสบการณ์ ดูช่วงเงินเดือนที่ประกาศระบุไว้ อ่านรายงานเงินเดือนประจำปีของบริษัทจัดหางาน และสอบถามจากคนที่ทำงานในตำแหน่งนั้นผ่าน LinkedIn หรือชุมชน Go ในไทย
