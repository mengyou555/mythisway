2.1Learning Roadmap

ภาพรวมเส้นทาง

Vibe Coding คือการสร้างซอฟต์แวร์ด้วยการ "สั่ง" AI เป็นภาษาคน เช่น พิมพ์ว่า "เพิ่มหน้าแสดงสรุปรายจ่ายรายเดือน" แล้วให้ AI Coding Assistant เขียนโค้ด แก้ไฟล์ และรันคำสั่งให้ คุณทำหน้าที่เหมือนหัวหน้างานที่บอกเป้าหมาย ตรวจผลงาน และตัดสินใจว่าจะรับหรือไม่รับโค้ดนั้น ทักษะนี้กลายเป็นเรื่องปกติของนักพัฒนาทุกสายในช่วงปี 2025–2026 เพราะช่วยให้สร้างต้นแบบ (Prototype) ได้ในไม่กี่ชั่วโมงแทนหลายวัน

แต่ความเร็วมีราคา AI เขียนโค้ดที่ ดูถูกต้องแต่ผิด ได้บ่อย ทั้งบั๊กที่กรณีขอบ ช่องโหว่ SQL Injection การฝัง Secret ลงในโค้ด และการแนะนำแพ็กเกจที่ไม่มีอยู่จริง หัวข้อนี้จึงไม่ได้สอนแค่ "สั่งให้ AI เขียน" แต่สอน Workflow ที่มีวินัย คือ เขียน Spec ก่อน แตกงานเป็นก้าวเล็ก ให้ AI วางแผนก่อนลงมือ ให้ AI เขียน Test แล้วคุณรันเอง Commit ทุกครั้งที่ทำงานได้ อ่าน Diff ทีละบรรทัด และตรวจความปลอดภัยด้วยเครื่องมืออัตโนมัติ เป้าหมายคือคุณใช้ AI เร่งงานได้ โดยยังเป็นเจ้าของคุณภาพของโค้ดทุกบรรทัด

หัวข้อนี้วางไว้ลำดับที่ 16 ของเส้นทางที่แนะนำโดยตั้งใจ เพราะตอนนี้คุณผ่าน Linux, Git, Python, Prompt Engineering, SQL, JavaScript, TypeScript, Node.js, API Design, Backend, Go, AI and Data Science, AI Engineer และ AI Agents มาแล้ว คุณจึง อ่านและรีวิวโค้ดที่ AI เขียนได้จริง ซึ่งเป็นเงื่อนไขสำคัญที่สุดของการใช้ AI เขียนโค้ดอย่างปลอดภัย คนที่อ่านโค้ดไม่ออกจะแยกไม่ได้ว่าโค้ดที่ได้มาถูกหรือผิด

เส้นทางนี้แบ่งเป็น 12 ขั้นใน 3 ระดับ ใช้เวลารวมประมาณ 22–30 ชั่วโมง ถ้าเรียนวันละ 1–1.5 ชั่วโมง สัปดาห์ละ 6 วัน จะจบในราว 4 สัปดาห์ ทุกขั้นฝึกบน Ubuntu 24.04 LTS ใน WSL2 ด้วย Python 3.12, Flask 3.1.3, pytest 9.1.1, ruff 0.17.1 และ pip-audit 2.10.1 และจบด้วย Mini Project Personal Finance Web App ที่สร้างร่วมกับ AI พร้อม Spec, Test และบันทึก AI_LOG.md ที่แสดงให้นายจ้างเห็นว่าคุณใช้ AI อย่างมีวิจารณญาณ

  1. Beginner Step 1 · รู้จัก Vibe Coding และสเปกตรัมของเครื่องมือ AI
  2. Beginner Step 2 · เตรียมเครื่อง โปรเจกต์ และกติกาความปลอดภัยก่อนเปิดใช้ AI
  3. Beginner Step 3 · เขียน Spec / Mini PRD ก่อนสั่ง AI
  4. Beginner Step 4 · ทำงานเป็นก้าวเล็ก: Plan → Implement → Verify → Commit และการย้อนกลับด้วย Git
  5. Intermediate Step 5 · Context File (AGENTS.md / CLAUDE.md) และมาตรฐานโค้ดที่เครื่องตรวจได้
  6. Intermediate Step 6 · Test-first Prompting ด้วย pytest
  7. Intermediate Step 7 · อ่านและรีวิว Diff ที่ AI เขียนทีละบรรทัด
  8. Intermediate Step 8 · Debug ร่วมกับ AI อย่างเป็นระบบ
  9. Advanced Step 9 · Refactor ด้วย AI อย่างปลอดภัย
  10. Advanced Step 10 · Security Review โค้ดที่ AI เขียน
  11. Advanced Step 11 · Supply Chain, License และความเป็นส่วนตัวของข้อมูล
  12. Advanced Step 12 · Quality Gate อัตโนมัติ, รู้ว่าเมื่อไรไม่ควร Vibe Code และ Mini Project

เปรียบเทียบ

การใช้ AI เขียนโค้ดเหมือนการจ้างผู้รับเหมาที่ทำงานเร็วมากและไม่เคยบ่นเหนื่อย แต่บางครั้งก็มั่นใจเกินจริง เช่น บอกว่า "เดินสายไฟเสร็จแล้ว" ทั้งที่ยังไม่ได้ต่อสายดิน เจ้าของบ้านที่ดีจะไม่สั่งงานลอยๆ ว่า "สร้างบ้านให้หน่อย" แต่จะมีแบบบ้าน (Spec) แบ่งงานเป็นงวด (ก้าวเล็ก) ตรวจรับงานทุกงวด (Test และ Review) และเก็บหลักฐานทุกงวดไว้ (Git Commit) ถ้างวดไหนพังก็รื้อกลับไปงวดก่อนได้ หัวข้อนี้สอนให้คุณเป็นเจ้าของบ้านแบบนั้น

Vibe Coding คืออะไร และต่างจากการเขียนโค้ดแบบเดิมอย่างไร

คำว่า "vibe coding" ถูกทำให้เป็นที่รู้จักโดย Andrej Karpathy (ผู้ร่วมก่อตั้ง OpenAI และอดีตหัวหน้าทีม AI ของ Tesla) ในโพสต์บน X เมื่อต้นเดือนกุมภาพันธ์ 2025 เขาอธิบายว่าเป็นการเขียนโปรแกรมแบบใหม่ที่ "ปล่อยตัวไปตาม Vibe" พูดหรือพิมพ์บอก AI ว่าต้องการอะไร กดยอมรับทุกการแก้ไขโดยไม่อ่าน Diff เจอ Error ก็คัดลอกไปวางให้ AI แก้ จนแทบ "ลืมไปว่ามีโค้ดอยู่" (forget that the code even exists) และเขาเองก็บอกว่าวิธีนี้เหมาะกับโปรเจกต์ทิ้งขว้างช่วงสุดสัปดาห์ ต่อมาคำนี้แพร่หลายมากจนพจนานุกรม Collins เลือก "vibe coding" เป็นคำแห่งปี 2025

ในทางปฏิบัติ คำว่า Vibe Coding ถูกใช้ในสองความหมาย และคุณต้องแยกให้ออก เพราะใช้ในงานจริงต่างกันมาก

ประเด็นVibe Coding แบบดั้งเดิม (ตามต้นฉบับ)AI-assisted Engineering (แบบที่หัวข้อนี้สอน)
การอ่านโค้ดไม่อ่าน กดยอมรับทุกอย่างอ่าน Diff ทุกบรรทัดก่อนรับ และอธิบายได้ว่าโค้ดทำอะไร
การทดสอบลองคลิกดูว่า "ดูเหมือนใช้ได้"มี Test อัตโนมัติด้วย pytest ที่รันเอง ไม่เชื่อคำว่า "ผ่านแล้ว" จาก AI
การวางแผนสั่งไปเรื่อยๆ ตามอารมณ์มี Spec และแผนทีละก้าว ก่อนเริ่มเขียนโค้ด
การย้อนกลับถ้าพังก็สั่งให้ AI แก้ซ้ำไปเรื่อยๆCommit ทุกครั้งที่ทำงานได้ และย้อนกลับด้วย Git ได้ในไม่กี่วินาที
ความปลอดภัยไม่ได้ตรวจตรวจ Secret, SQL Injection, Input Validation และ Dependency ทุกครั้ง
เหมาะกับของเล่น ต้นแบบที่จะทิ้ง สคริปต์ใช้ครั้งเดียวบนเครื่องตัวเองงานที่มีผู้ใช้จริง โค้ดของทีม งานที่ต้องดูแลต่อ และ Portfolio ที่นายจ้างจะอ่าน

เครื่องมือ AI สำหรับเขียนโค้ดมีหลายระดับ ตั้งแต่แชตธรรมดาไปจนถึง Agent ที่ทำงานเองได้หลายขั้นตอน หน้าตาและชื่อเมนูของเครื่องมือเหล่านี้เปลี่ยนเร็วมาก หลักสูตรนี้จึงอธิบายแบบทั่วไปตาม "ระดับความเป็นอิสระ" และให้คุณดูวิธีติดตั้งจากเอกสารทางการของแต่ละเครื่องมือ

ระดับรูปแบบAI ทำอะไรได้ตัวอย่างเครื่องมือสิ่งที่ต้องระวัง
1Chat Assistantตอบคำถามและเขียนโค้ดในหน้าแชต คุณคัดลอกไปวางเอง AI ไม่เห็นโปรเจกต์ของคุณแอปแชตของผู้ให้บริการ AI เช่น Claude, ChatGPT, GeminiAI ไม่รู้โครงสร้างโปรเจกต์ จึงเดาชื่อไฟล์และเวอร์ชันผิดได้ง่าย และเสี่ยงเผลอวางข้อมูลลับลงในแชต
2Inline Completionเดาและเติมโค้ดต่อจากที่คุณกำลังพิมพ์ใน Editor กด Tab เพื่อรับGitHub Copilot ใน VS Code, ฟีเจอร์ Tab ของ Cursorรับทีละนิดจนเผลอรับโค้ดที่ไม่ได้อ่าน โดยเฉพาะค่าคงที่และ Query
3Chat และ Edit ใน Editorเห็นไฟล์ที่เปิดอยู่ แก้หลายไฟล์พร้อมกัน แล้วแสดง Diff ให้กดยอมรับหรือปฏิเสธหน้าต่างแชตของ Copilot ใน VS Code, CursorDiff ยาวหลายไฟล์ทำให้รีวิวยาก ต้องสั่งให้แก้ทีละเรื่อง
4Agentic Coding Toolอ่านทั้งโปรเจกต์ วางแผน แก้ไฟล์ รันคำสั่งและ Test เอง แล้ววนแก้จนผ่าน โดยขออนุญาตก่อนทำสิ่งที่เสี่ยงClaude Code (ใน Terminal และ Editor), Agent Mode ของ GitHub Copilot, Agent ของ Cursorรันคำสั่งได้จริง จึงต้องตั้งสิทธิ์ให้รัดกุม ห้ามอนุญาตคำสั่งอันตรายแบบอัตโนมัติ และต้องมี Git Checkpoint เสมอ
5Background / Cloud Agentรับงานจาก Issue หรือคำสั่ง ทำงานบนเครื่องใน Cloud แล้วเปิด Pull Request ให้คนรีวิวCoding Agent ของ GitHub Copilot, Claude Code บนเว็บต้องรีวิว Pull Request อย่างเข้มงวดเหมือนโค้ดของคนอื่น และระวังสิทธิ์ที่ให้ Agent เข้าถึง Repository
หมายเหตุ

ราคา แผนฟรี และวิธีติดตั้งของเครื่องมือเหล่านี้เปลี่ยนบ่อย ให้ตรวจที่เอกสารทางการก่อนใช้เสมอ เช่น Claude Code Docs, GitHub Copilot Docs และ Cursor Docs ทุกตัวอย่างในหัวข้อนี้แสดง "โค้ดที่ AI ตอบกลับมา" ไว้ให้แล้ว คุณจึงฝึกตามได้ครบแม้ยังไม่มีบัญชี AI แบบเสียเงิน แค่ใช้แชตฟรีตัวใดก็ได้เพื่อลองส่ง Prompt ของตัวเองเปรียบเทียบ

ไม่ว่าจะใช้เครื่องมือระดับไหน วงจรการทำงานพื้นฐานเหมือนกันเสมอ คือ บอกเป้าหมาย → AI เสนอโค้ด → คุณรันและตรวจ → รับหรือปฏิเสธ → บันทึกด้วย Git ความต่างอยู่ที่ว่า AI ทำขั้นไหนแทนคุณได้บ้าง ยิ่ง AI ทำเองได้มาก คุณยิ่งต้องตั้งรั้ว (Test, Quality Gate, สิทธิ์การรันคำสั่ง) ให้แข็งแรงขึ้น

Prerequisites: ต้องรู้อะไรมาก่อน

หัวข้อนี้ใช้ทักษะจากหัวข้อก่อนหน้าเกือบทั้งหมด สิ่งที่ ต้องมี ก่อนเริ่มคือ

  • เขียน Prompt ที่มีบทบาท เป้าหมาย ข้อจำกัด ตัวอย่าง และรูปแบบผลลัพธ์ชัดเจน เพราะการสั่ง AI เขียนโค้ดคือ Prompt Engineering ในงานเฉพาะทาง
  • ใช้ git status, git diff, git add, git commit, git log, git restore, git switch -c และ Push ขึ้น GitHub ได้คล่อง เพราะ Git คือ "ปุ่ม Undo" ของ Vibe Coding
  • อ่านโค้ดออกอย่างน้อยหนึ่งภาษา คือ (ภาษาหลักของหัวข้อนี้) หรือ ถ้าอ่านโค้ดไม่ออก คุณจะรีวิวสิ่งที่ AI เขียนไม่ได้ และไม่ควรนำโค้ดนั้นไปใช้จริง
  • สร้างโฟลเดอร์ ใช้ venv ตั้ง Environment Variable และอ่าน Error ใน Terminal ได้

สิ่งที่ ช่วยได้มาก และคุณเรียนมาแล้วตามลำดับที่แนะนำ

  • เข้าใจ Query, Parameter และเหตุผลที่ห้ามต่อ String เป็น SQL ซึ่งใช้ตรงๆ ใน Step 10
  • และ ออกแบบ Endpoint, Status Code, Validation และโครงสร้างโปรเจกต์ Backend ซึ่งเป็นสิ่งที่คุณต้องใส่ลงใน Spec
  • และ เข้าใจว่า LLM ทำงานอย่างไร ทำไมจึง "มั่นใจแต่ผิด" ได้ (Hallucination) และ Agent ใช้ Tool อย่างไร ซึ่งช่วยให้ใช้ Agentic Coding Tool ได้อย่างรู้เท่าทัน

def format_minutes(total: int) -> str:
    """แปลงจำนวนนาทีเป็นข้อความ เช่น 95 -> '1 ชม. 35 นาที'"""
    if total < 0:
        raise ValueError("นาทีต้องไม่ติดลบ")
    hours, minutes = divmod(total, 60)
    if hours == 0:
        return f"{minutes} นาที"
    if minutes == 0:
        return f"{hours} ชม."
    return f"{hours} ชม. {minutes} นาที"


if __name__ == "__main__":
    for m in (45, 60, 95):
        print(m, "->", format_minutes(m))
def format_minutes(total: int) -> str:
    """แปลงจำนวนนาทีเป็นข้อความ เช่น 95 -> '1 ชม. 35 นาที'"""
    hours = total / 60
    minutes = total % 60
    return f"{hours} ชม. {minutes} นาที"


if __name__ == "__main__":
    for m in (45, 60, 95):
        print(m, "->", format_minutes(m))

import csv

from duration import format_minutes


def total_minutes(path: str) -> int:
    """รวมนาทีทั้งหมดจากไฟล์ CSV ถ้าพบค่าที่ไม่ใช่ตัวเลขให้แจ้งเลขบรรทัดที่ผิด"""
    total = 0
    with open(path, encoding="utf-8") as f:
        # บรรทัดที่ 1 คือหัวตาราง ข้อมูลจึงเริ่มที่บรรทัดที่ 2
        for line_no, row in enumerate(csv.DictReader(f), start=2):
            value = row["minutes"].strip()
            if not value.isdigit():
                raise ValueError(f"บรรทัด {line_no}: minutes ต้องเป็นจำนวนเต็ม แต่ได้ {value!r}")
            total += int(value)
    return total

import csv

from duration import format_minutes


def parse_minutes(value: str, line_no: int) -> int:
    """แปลงข้อความเป็นนาที ถ้าไม่ใช่จำนวนเต็มให้แจ้งเลขบรรทัดที่ผิด"""
    cleaned = value.strip()
    if not cleaned.isdigit():
        raise ValueError(f"บรรทัด {line_no}: minutes ต้องเป็นจำนวนเต็ม แต่ได้ {cleaned!r}")
    return int(cleaned)


def total_minutes(path: str) -> int:
    """รวมนาทีทั้งหมดจากไฟล์ CSV"""
    with open(path, encoding="utf-8") as f:
        # บรรทัดที่ 1 คือหัวตาราง ข้อมูลจึงเริ่มที่บรรทัดที่ 2
        rows = enumerate(csv.DictReader(f), start=2)
        return sum(parse_minutes(row["minutes"], line_no) for line_no, row in rows)

import json
import sys
import urllib.error
import urllib.request


def check(name: str) -> bool:
    url = f"https://pypi.org/pypi/{name}/json"
    try:
        with urllib.request.urlopen(url, timeout=10) as resp:
            data = json.load(resp)
    except urllib.error.HTTPError as e:
        if e.code == 404:
            print(f"[ไม่พบ] {name}: ไม่มีบน PyPI ห้ามติดตั้ง อาจเป็นชื่อที่ AI แต่งขึ้น")
            return False
        raise
    info = data["info"]
    uploads = [f["upload_time"][:10] for files in data["releases"].values() for f in files]
    license_ = info.get("license_expression") or info.get("license") or "ไม่ระบุ"
    source = (info.get("project_urls") or {}).get("Source", "ไม่ระบุ")
    print(f"[พบ] {info['name']} {info['version']} | ออกครั้งแรก {min(uploads)} | License {license_}")
    print(f"      Source: {source}")
    return True


if __name__ == "__main__":

import subprocess

LINE_TOKEN = "lt-9f8e7d6c5b4a"


def notify(message: str) -> None:
    """ส่งข้อความแจ้งเตือนผ่านคำสั่งในเครื่อง"""
    subprocess.run(f"echo {message}", shell=True, check=True)
# ให้สิทธิ์รัน Hook

เมื่อไรไม่ควร Vibe Code
สถานการณ์ทำไมไม่ควรให้ AI เขียนแทนทางที่เหมาะกว่า
ระบบ Login, การเข้ารหัส, การจัดการรหัสผ่าน และการชำระเงินผิดเพียงเล็กน้อยก็เสียหายรุนแรง และ AI มักเสนอวิธีที่ล้าสมัย เช่น เก็บรหัสผ่านด้วย MD5ใช้ไลบรารีหรือบริการมาตรฐานที่ผ่านการตรวจสอบแล้ว ใช้ AI ช่วยอธิบายเอกสาร และให้ผู้เชี่ยวชาญรีวิว
โค้ดในภาษาหรือ Framework ที่คุณอ่านไม่ออกคุณรีวิวไม่ได้ จึงรับผิดชอบโค้ดนั้นไม่ได้เรียนพื้นฐานก่อน หรือให้คนที่เชี่ยวชาญภาษานั้นรีวิว
งานที่ต้องส่งข้อมูลส่วนบุคคล ข้อมูลลูกค้า หรือโค้ดลับของบริษัทให้เครื่องมือที่ไม่ได้รับอนุญาตข้อมูลออกนอกองค์กร อาจผิดนโยบายบริษัทและ PDPAใช้เครื่องมือที่องค์กรอนุมัติ หรือใช้ข้อมูลจำลองแทนข้อมูลจริง
ช่วงที่กำลังฝึกพื้นฐานของภาษาใหม่AI คิดแทนจนคุณไม่ได้ฝึกการแก้ปัญหาด้วยตัวเองเขียนเองก่อน แล้วใช้ AI อธิบายหรือให้ Hint เมื่อติด
แก้ระบบที่ล่มอยู่ขณะเร่งรีบ และไม่มี TestAI แก้ตามอาการได้เร็ว แต่อาจสร้างปัญหาใหม่ที่หนักกว่าย้อนกลับไปเวอร์ชันที่ทำงานได้ก่อน แล้วค่อยหาสาเหตุอย่างเป็นระบบตาม Step 8
การคำนวณที่ต้องถูกต้องตามกฎหมาย เช่น ภาษี ดอกเบี้ย ค่าจ้างAI อาจใช้สูตรหรืออัตราที่ล้าสมัยโดยไม่บอกเขียน Test จากตัวอย่างในเอกสารทางการก่อน แล้วให้ AI เขียนโค้ดให้ผ่าน Test เหล่านั้น
งานเล็กมากที่พิมพ์เองเร็วกว่าการอธิบายเสียเวลาเขียน Prompt และรีวิวมากกว่าเขียนเองพิมพ์เอง แล้วใช้ Inline Completion ช่วยถ้ามี
Mini Project ของหัวข้อนี้: Personal Finance Web App

เว็บแอปบันทึกรายรับรายจ่ายส่วนตัวขนาดเล็ก ใช้ Flask 3.1.3 + SQLite + HTML (Jinja2 Template) ที่คุณสร้างร่วมกับ AI Coding Assistant ตาม Workflow ทั้ง 12 ขั้น ฟีเจอร์หลักคือ เพิ่มรายการรายรับหรือรายจ่ายพร้อมหมวดหมู่ ดูรายการรายเดือน ดูสรุปยอดรายรับ รายจ่าย และคงเหลือตามหมวด ลบรายการ และ Export เป็น CSV สิ่งที่ต้องส่งมีดังนี้

  • SPEC.md ที่มี Acceptance Criteria ที่ทดสอบได้ และ AGENTS.md กับ CLAUDE.md ที่บอกกติกาของโปรเจกต์
  • Test ด้วย pytest ที่ครอบคลุมการเพิ่ม แสดง สรุป และลบรายการ รวมถึง Security Test สำหรับ SQL Injection และ Input ที่ผิดรูปแบบ
  • scripts/check.sh ที่ผ่านทั้ง 4 ด่าน และ GitHub Actions ที่รันด่านเดียวกัน
  • AI_LOG.md ที่บันทึก Prompt สิ่งที่ AI เสนอ สิ่งที่คุณรับ แก้ หรือปฏิเสธ พร้อมเหตุผลและ Commit ที่เกี่ยวข้อง
  • README.md ที่อธิบายวิธีติดตั้ง วิธีรัน วิธีทดสอบ และสรุปว่าใช้ AI ในส่วนใดของโปรเจกต์

ขั้นตอนเต็ม โครงสร้างโฟลเดอร์ และโค้ดทั้งหมดอยู่ในส่วนที่ 4 ของหัวข้อนี้

Must-know Skills

ทักษะต่อไปนี้คือสิ่งที่แยก "คนที่ใช้ AI เขียนโค้ดได้เร็วและปลอดภัย" ออกจาก "คนที่ได้โค้ดเร็วแต่พังบ่อย" ทุกข้อฝึกไปแล้วใน Step 1–12 ให้ใช้รายการนี้เป็นแบบประเมินตัวเองก่อนสมัครงานหรือก่อนทำ Mini Project

  1. เขียน Spec ที่ทดสอบได้ก่อนสั่ง AI เพราะ SPEC.md ที่มีเป้าหมาย ขอบเขต (Must / Should / Won't) และ Acceptance Criteria เป็นตัวอย่างค่าเข้าและค่าออก ทำให้ AI เดาน้อยลง และทำให้คุณรู้ชัดว่างานเสร็จเมื่อไร
  2. แตกงานเป็นก้าวเล็กแบบ Plan → Implement → Verify → Commit เพราะงานก้อนเล็กรีวิวได้จริงในไม่กี่นาที และถ้า AI ทำพัง คุณเสียงานแค่ก้าวเดียว ไม่ใช่ทั้งวัน
  3. ใช้ Git เป็นจุด Checkpoint และย้อนกลับได้คล่อง (git add -p, git diff, git restore, git reset, git revert) เพราะ AI แก้หลายไฟล์พร้อมกันได้ในไม่กี่วินาที และ Commit ที่ทำงานได้ล่าสุดคือที่ปลอดภัยที่คุณกลับไปได้เสมอ
  4. เขียน Context File (AGENTS.md / CLAUDE.md) ที่สั้น ชัด และตรวจได้ เพราะ AI จำกติกาของโปรเจกต์ข้ามบทสนทนาไม่ได้ ไฟล์นี้บอกคำสั่งรัน Test มาตรฐานโค้ด และสิ่งที่ห้ามทำ ทุกครั้งที่เริ่มงานใหม่
  5. Test-first Prompting ด้วย pytest เพราะการให้ AI เขียน Test จาก Acceptance Criteria ก่อน แล้วคุณรันเองให้เห็นว่า "ล้ม" ก่อน "ผ่าน" คือหลักฐานเดียวที่เชื่อถือได้ว่าโค้ดทำตาม Spec ไม่ใช่แค่ดูเหมือนถูก
  6. อ่านและรีวิว Diff ทีละบรรทัด เพราะบั๊กของ AI มักซ่อนอยู่ในบรรทัดที่ดูธรรมดา เช่น หารด้วยศูนย์เมื่อ List ว่าง Default Argument ที่เป็น List หรือการแก้ไฟล์ Test เพื่อให้ Test ผ่าน และคุณต้องรับผิดชอบทุกบรรทัดที่ Commit
  7. Debug ร่วมกับ AI ด้วยข้อมูลครบ (Error เต็ม ๆ, คำสั่งที่รัน, ไฟล์ที่เกี่ยวข้อง, สิ่งที่คาดหวัง และสิ่งที่ลองแล้ว) เพราะ AI ที่เห็นแค่ข้อความ Error บรรทัดเดียวจะเดาสาเหตุ แต่ AI ที่เห็น Traceback เต็มจะชี้บรรทัดที่ผิดได้
  8. Refactor อย่างปลอดภัยโดยมี Test คุ้มกัน เพราะการให้ AI "ทำให้สะอาดขึ้น" โดยไม่มี Test มักเปลี่ยนพฤติกรรมของโปรแกรมแบบเงียบ ๆ จำนวน Test ที่ผ่านต้องเท่าเดิม และไฟล์ใน tests/ ต้องไม่ถูกแก้
  9. Security Review โค้ดที่ AI เขียน (Secret ที่ฝังในโค้ด, SQL Injection, ไม่ตรวจ Input, shell=True, debug=True) เพราะ AI เรียนจากโค้ดตัวอย่างบนอินเทอร์เน็ตที่มีทั้งดีและไม่ปลอดภัย และมักเลือกทางสั้นที่สุดโดยไม่คิดถึงผู้โจมตี
  10. ตรวจ Supply Chain ก่อนติดตั้งแพ็กเกจ (เช็กว่ามีจริงบน PyPI / npm, ดูอายุ ผู้ดูแล License และรัน pip-audit) เพราะ AI แต่งชื่อแพ็กเกจที่ไม่มีอยู่จริงได้ และผู้ไม่หวังดีจดชื่อเหล่านั้นไว้รอ (Slopsquatting)
  11. ตั้ง Quality Gate อัตโนมัติ (ruff check, ruff format --check, pytest, pip-audit ใน scripts/check.sh, Git Hook และ GitHub Actions) เพราะวินัยที่อาศัยความจำจะหลุดในวันที่รีบ แต่ด่านอัตโนมัติไม่เคยลืม
  12. รักษาความเป็นส่วนตัวของข้อมูลและเคารพ License เพราะการวาง Secret ข้อมูลลูกค้า หรือโค้ดลับของบริษัทลงในเครื่องมือที่ไม่ได้รับอนุญาตอาจผิดนโยบายบริษัทและผิดกฎหมายคุ้มครองข้อมูลส่วนบุคคล (PDPA) ได้ แม้โค้ดจะทำงานถูกก็ตาม
  13. บันทึกการทำงานกับ AI ใน AI_LOG.md เพราะบันทึกว่า Prompt ไหนได้ผล ข้อเสนอไหนรับ แก้ หรือปฏิเสธ และเพราะอะไร ทำให้คุณพัฒนาวิธีสั่งงานได้จริง และใช้เป็นหลักฐานใน Portfolio และการสัมภาษณ์งาน
  14. รู้ว่าเมื่อไรไม่ควร Vibe Code เพราะงานยืนยันตัวตน การเข้ารหัส การชำระเงิน การคำนวณตามกฎหมาย และโค้ดในภาษาที่คุณอ่านไม่ออก ต้องการความเข้าใจลึกที่ AI ให้แทนไม่ได้ การเลือกไม่ใช้ AI ในงานเหล่านี้คือความเป็นมืออาชีพ

เงินเดือนและการหาข้อมูลตลาดงาน

หลักสูตรนี้ ไม่ระบุตัวเลขเงินเดือน เพราะค่าตอบแทนต่างกันมากตามตำแหน่ง ประสบการณ์ ขนาดบริษัท อุตสาหกรรม เมือง และรูปแบบงาน (ประจำ, สัญญาจ้าง, Freelance, Remote ให้บริษัทต่างประเทศ) และตัวเลขเปลี่ยนทุกปี ให้หาข้อมูลเองด้วยวิธีนี้

  1. ค้นหาตำแหน่งในตารางด้านบนบน JobsDB และ LinkedIn Jobs ด้วยคำค้นทั้งภาษาไทยและอังกฤษ เช่น "Python Developer", "Full-stack Developer", "GitHub Copilot", "AI-assisted development"
  2. จดช่วงเงินเดือนจากประกาศที่ระบุตัวเลขอย่างน้อย 10 ประกาศลงตาราง พร้อมระดับประสบการณ์ที่ต้องการ แล้วหาค่ากลาง อย่าเชื่อประกาศเดียว
  3. จดทักษะที่ปรากฏซ้ำบ่อยที่สุด เช่น เครื่องมือ AI ที่ระบุชื่อ, Test, CI หรือ Security แล้วเทียบกับ Must-know Skills ของหัวข้อนี้ เพื่อดูว่าควรเสริมอะไร
  4. ดูรายงานผลสำรวจเงินเดือนประจำปีของบริษัทจัดหางาน และถามคนที่ทำงานตำแหน่งนั้นจริงผ่าน LinkedIn หรือชุมชนนักพัฒนา
