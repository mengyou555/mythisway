สถานการณ์

ร้านอาหารตามสั่งเล็ก ๆ ของสมชายรับออเดอร์ผ่าน LINE แล้วเก็บรายการไว้เป็น Array ของ Object เจ้าของร้านอยากได้สคริปต์ที่รันใน Terminal แล้วพิมพ์ใบเสร็จออกมาสวย ๆ เพื่อคัดลอกส่งให้ลูกค้า ใบเสร็จต้องบอกรายการทีละบรรทัด ยอดรวม ส่วนลด และยอดสุทธิ โดยตัวเลขเงินต้องมีทศนิยม 2 ตำแหน่งเสมอ ร้านมีโปรโมชันว่าถ้ายอดรวมถึง 300 บาท จะลด 10%

โจทย์ที่ 3Advanced

fetchJson ที่ทนทาน: Timeout, Retry และ Unit Test ด้วย node:test

สถานการณ์

แอปแบบทดสอบของบริษัทต้องโหลดไฟล์คำถามจาก Server ภายในองค์กร Server ตัวนี้บางครั้งช้าจนค้าง บางครั้งตอบ 503 Service Unavailable ช่วงสั้น ๆ ตอน Deploy และบางครั้งก็ปิดไปเลย ผู้ใช้บ่นว่าหน้าเว็บค้างโดยไม่มีข้อความอะไร หัวหน้าทีมจึงมอบหมายให้สมชายเขียนฟังก์ชันกลาง fetchJson ที่ทุกส่วนของแอปจะเรียกใช้ โดยมีกติกาดังนี้

  • รอแต่ละครั้งได้ไม่เกิน timeoutMs มิลลิวินาที (ค่าเริ่มต้น 2000) แล้วต้องยกเลิกคำขอ
  • ถ้าเกิด Network Error (ต่อ Server ไม่ได้), หมดเวลา หรือได้ Status 5xx ให้ลองใหม่ได้อีก retries ครั้ง (ค่าเริ่มต้น 2 รวมเป็นสูงสุด 3 ครั้ง) และรอนานขึ้นทีละขั้นระหว่างแต่ละครั้ง
  • ถ้าได้ Status 4xx เช่น 404 ห้ามลองใหม่ เพราะลองกี่ครั้งไฟล์ก็ยังไม่มี และถ้า JSON เสียก็ห้ามลองใหม่เช่นกัน
  • เมื่อลองครบแล้วยังไม่สำเร็จ ต้องโยน Error ที่อ่านเข้าใจได้ และเก็บ Error ต้นเหตุไว้ใน cause
  • ต้องมี Unit Test ที่รันได้โดยไม่ต้องเปิด Server จริง และไม่ต้องรอเวลานาน
สิ่งที่ต้องทำ
  1. สร้างโปรเจกต์ ~/projects/js-lab/challenges/ch3-retry-fetch ที่มี package.json ของตัวเอง ("type": "module" และ "scripts": { "test": "node --test", "demo": "node demo.js" }) และโฟลเดอร์ src, test, data
  2. คัดลอกคำถาม 3 ข้อแรกจาก Part 1 ไปไว้ที่ data/questions.json (ใช้ Schema { id, question, choices, answer })
  3. ใน src/fetch-json.js สร้าง class HttpError extends Error ที่เก็บ status ไว้ และฟังก์ชัน isRetryable(error) ที่ตัดสินว่า Error แบบไหนควรลองใหม่
  4. เขียน export async function fetchJson(url, { retries = 2, timeoutMs = 2000, retryDelayMs = 300, fetchImpl = globalThis.fetch, onRetry = () => {} } = {}) โดยส่ง signal: AbortSignal.timeout(timeoutMs) ให้ทุกคำขอ ตรวจ response.ok และห่อ Error สุดท้ายด้วย new Error(ข้อความ, { cause })
  5. เขียน test/fetch-json.test.js อย่างน้อย 6 Test โดยส่ง fetch ปลอมที่สร้างด้วย mock.fn() เข้าไปทาง fetchImpl ครอบคลุมกรณี: สำเร็จครั้งแรก, 503 แล้วสำเร็จ, 404 ไม่ลองใหม่, Network Error ทุกครั้ง, หมดเวลา และ JSON เสีย พร้อมตรวจจำนวนครั้งที่ fetch ถูกเรียก
  6. เขียน demo.js ที่เรียก fetchJson กับ Server จริง 3 กรณี: ไฟล์มีอยู่, ไฟล์ไม่มี (404) และพอร์ตที่ไม่มี Server เปิด (127.0.0.1:8001)
  7. รัน npm test ให้ผ่านทั้งหมด แล้วเปิด python3 -m http.server 8000 --bind 127.0.0.1 ใน Terminal อีกหน้าต่าง และรัน npm run demo

Hint
  • ใช้ลูป for (let attempt = 1; attempt <= retries + 1; attempt += 1) แล้วครอบเนื้อในด้วย try/catch ใน catch ให้ตัดสิน 3 ทาง: ไม่ควรลองใหม่ให้ throw error ทันที, ลองครบแล้วให้โยน Error ใหม่ที่มี cause, ยังไม่ครบให้รอแล้ววนรอบต่อไป
  • เมื่อต่อ Server ไม่ได้ fetch ของ Node จะ reject ด้วย TypeError: fetch failed และรหัสจริงอยู่ใน error.cause.code เช่น ECONNREFUSED
  • เมื่อ AbortSignal.timeout หมดเวลา คำขอจะ reject ด้วย Error ชื่อ TimeoutError ดังนั้นตรวจ error.name === 'TimeoutError'
  • เขียน return await response.json(); ภายใน try เพื่อให้ Error จากการแปลง JSON วิ่งเข้า catch ของรอบนั้นด้วย
  • สร้าง Response ปลอมใน Test ได้ด้วย new Response(JSON.stringify(data), { status: 200 }) เพราะ Response เป็น Global ใน Node 18 ขึ้นไป
  • fetch ปลอมสำหรับกรณีหมดเวลา ต้องฟัง signal.addEventListener('abort', ...) แล้ว reject ด้วย signal.reason และควรมี setTimeout จำลอง Server ที่ตอบช้า (เช่น 1000ms) ไว้ด้วย เพราะ Timer ภายในของ AbortSignal.timeout ไม่ได้ช่วยให้โปรแกรมรอ ถ้าไม่มี Timer อื่นค้างอยู่ node --test จะจบ Test ก่อนที่ Timeout จะเกิด

คำตอบ: ช่องแรกคือ === ช่องที่สองคือ ==

=== (Strict Equality) เทียบทั้งชนิดข้อมูลและค่า '5' เป็น String แต่ 5 เป็น Number ชนิดต่างกันจึงได้ false ทันที ส่วน == (Loose Equality) จะแปลงชนิดให้ก่อน (Type Coercion) โดยแปลง '5' เป็นตัวเลข 5 แล้วจึงเทียบ จึงได้ true ในงานจริงให้ใช้ === เสมอตามกติกาในแนวคิดที่ 1 เพราะ == ให้ผลที่เดายาก เช่น 0 == '' ก็เป็น true

// เทียบ String '5' กับ Number 5
console.log('5' === 5); // ต้องได้ false เพราะชนิดข้อมูลต่างกัน
console.log('5' == 5); // ต้องได้ true เพราะแปลง '5' เป็นตัวเลขก่อนเทียบ

ข้อ 3

คำตอบ: ?? (Nullish Coalescing)

a ?? b คืน b เฉพาะเมื่อ a เป็น null หรือ undefined เท่านั้น ค่า 0 ไม่ใช่ทั้งสองอย่าง จึงได้ 0 ตามที่ผู้ใช้ตั้งไว้ ถ้าใช้ || จะได้ 16 ซึ่งผิด เพราะ || ดูแค่ว่าค่าทางซ้ายเป็น Falsy หรือไม่ และ 0, '' กับ false ล้วนเป็น Falsy (ทบทวนแนวคิดที่ 5)

const settings = { theme: 'dark', fontSize: 0 };

const size = settings.fontSize ?? 16;
console.log(size); // ต้องได้ 0 ไม่ใช่ 16

// เทียบให้เห็นกับ || ที่ทิ้งค่า 0
console.log(settings.fontSize || 16);

คำตอบ: C ตัวแปร let และ const ถูก Hoist ขึ้นไปต้น Block เหมือนกัน แต่อยู่ในช่วง Temporal Dead Zone (TDZ) ตั้งแต่ต้น Block จนถึงบรรทัดที่ประกาศ การอ่านค่าในช่วงนั้นจึงได้ ReferenceError: Cannot access 'x' before initialization (ข้อความจริงจาก Node) Error นี้ช่วยให้เราเจอบั๊กเร็ว ต่างจาก var ที่คืน undefined แบบเงียบ ๆ (แนวคิดที่ 9)

คำตอบ: C ค่า this ถูกกำหนดตอนเรียกฟังก์ชัน ไม่ใช่ตอนสร้าง เมื่อเรียก counter.increment() ค่า this คือ counter แต่เมื่อดึงเมธอดออกมาเก็บใน fn แล้วเรียก fn() เฉย ๆ จะไม่มี Object หน้าจุด และเพราะ ES Module กับ Class ทำงานใน Strict Mode ค่า this จึงเป็น undefined ผลจากการรันจริงคือ TypeError: Cannot read properties of undefined (reading 'count') วิธีแก้คือ const fn = counter.increment.bind(counter); หรือห่อด้วย Arrow Function () => counter.increment() (แนวคิดที่ 9)

  • A ผิดเพราะ fn ไม่ได้ผูกกับ counter แล้ว การเรียก fn() จึงไม่รู้ว่าต้องเพิ่มค่า count ของ Object ไหน
  • B ผิดเพราะโค้ดไปไม่ถึงขั้นคำนวณ undefined + 1 เนื่องจาก this เองเป็น undefined การอ่าน this.count จึงพังด้วย TypeError ตั้งแต่แรก
  • D ผิดเพราะพฤติกรรมที่ this ชี้ไปที่ Global Object เกิดเฉพาะโค้ดแบบ Sloppy Mode เก่า ใน Module และ Class ซึ่งเป็น Strict Mode เสมอ this จะเป็น undefined
ข้อ 12

คำตอบ: A Event Loop ทำงานตามลำดับนี้: รันโค้ด Synchronous ใน Call Stack ให้หมดก่อน (A และ D) จากนั้นเคลียร์ Microtask Queue ทั้งหมด (Callback ของ Promise.then คือ C) แล้วจึงหยิบ Macrotask ตัวถัดไป (Callback ของ setTimeout คือ B) ผลจากการรันจริงคือ A D C B แม้ setTimeout จะตั้งเวลา 0 และถูกเรียกก่อน Promise.resolve() ก็ตาม (แนวคิดที่ 11)

  • B ผิดเพราะคิดว่าโค้ดทำงานตามลำดับบรรทัดทั้งหมด แต่ setTimeout และ .then แค่ "ลงทะเบียน" Callback ไว้ในคิว ไม่ได้รันทันที
  • C ผิดเพราะสลับลำดับ Microtask กับ Macrotask Microtask (Promise) ต้องถูกเคลียร์ให้หมดก่อนที่ Event Loop จะไปหยิบ Macrotask (setTimeout) เสมอ
  • D ผิดเพราะ Callback ของ Promise ไม่สามารถแทรกระหว่างโค้ด Synchronous ได้ ต้องรอให้ Call Stack ว่างก่อน ดังนั้น D ต้องมาก่อน C

คำตอบ: A fetch reject เฉพาะเมื่อส่งคำขอไม่สำเร็จ (Network Error หรือถูก Abort) เมื่อ Server ตอบกลับมาแล้ว แม้จะเป็น 404 Promise ก็ fulfilled ตามปกติ โค้ดจึงไม่เข้า catch และพิมพ์ ผล: false 404 ผลการทดลองจริงใน Chromium คือ false 404 นอกจากนี้ DevTools จะแสดงบรรทัดสีแดง Failed to load resource: the server responded with a status of 404 (File not found) ซึ่งเป็นข้อความที่เบราว์เซอร์เขียนเอง ไม่ใช่ Error ที่โค้ดเรา catch ได้ (แนวคิดที่ 11)

  • B ผิดเพราะ 404 ไม่ทำให้ fetch reject โค้ดจึงไม่เข้า catch ถ้าต้องการให้เข้า catch ต้องเขียน if (!res.ok) throw new Error(...) เอง

  • D ผิดเพราะ fetch failed คือข้อความของ Node.js เมื่อต่อ Server ไม่ได้ (ในเบราว์เซอร์จะเป็น Failed to fetch) แต่โจทย์บอกว่า Server เปิดอยู่และตอบกลับมาแล้ว

const cart = [

  { name: 'ขนมปังสังขยา', price: 35, qty: 3 },

// ค่าคงที่ของร้าน
const SHOP_NAME = 'ครัวสมชาย';
const RECEIPT_DATE = '2026-10-19'; // ใช้วันที่คงที่ เพื่อให้ผลลัพธ์เหมือนเดิมทุกครั้ง
const DISCOUNT_MIN = 300; // ยอดขั้นต่ำที่ได้ส่วนลด
const DISCOUNT_RATE = 0.1; // ส่วนลด 10%
const LINE = '-'.repeat(40);

// แปลงตัวเลขเป็นเงินบาท ทศนิยม 2 ตำแหน่ง มีจุลภาคคั่นหลักพัน
function formatMoney(n) {
  return n.toLocaleString('th-TH', { minimumFractionDigits: 2, maximumFractionDigits: 2 });
}

// สร้างข้อความ 1 บรรทัดต่อสินค้า 1 รายการ
// วางชื่อไว้ท้ายบรรทัด เพราะสระและวรรณยุกต์ไทยทำให้ padEnd นับความกว้างผิด
function formatLine(item, index) {
  const lineTotal = item.price * item.qty;
  const no = String(index + 1).padStart(2, ' ');
  const qty = String(item.qty).padStart(2, ' ');
  const price = formatMoney(item.price).padStart(6, ' ');
  const total = formatMoney(lineTotal).padStart(8, ' ');
  return `${no}. ${qty} x ${price} = ${total}  ${item.name}`;
}

// คำนวณตัวเลขทั้งหมดของใบเสร็จ แยกจากส่วนที่พิมพ์ เพื่อให้ทดสอบง่าย
function summarize(items) {
  const subtotal = items.reduce((sum, item) => sum + item.price * item.qty, 0);
  const itemCount = items.reduce((sum, item) => sum + item.qty, 0);
  const discount = subtotal >= DISCOUNT_MIN ? subtotal * DISCOUNT_RATE : 0;
  const total = subtotal - discount;
  // หาสินค้าที่ทำยอดสูงสุด โดยเริ่มจากรายการแรก
  const topItem = items.reduce((best, item) =>
    item.price * item.qty > best.price * best.qty ? item : best, items[0]);
  return { subtotal, itemCount, discount, total, topItem };
}

const lines = cart.map(formatLine);
const { subtotal, itemCount, discount, total, topItem } = summarize(cart);

export function filterAndSort(items, query = '', sortDir = 'none') {
  const keyword = query.trim().toLowerCase();
  const filtered = items.filter((item) => item.name.toLowerCase().includes(keyword));
  if (sortDir === 'asc') return filtered.toSorted((a, b) => a.price - b.price);
  if (sortDir === 'desc') return filtered.toSorted((a, b) => b.price - a.price);
  return filtered;
}

export function formatBaht(n) {
  return n.toLocaleString('th-TH', { minimumFractionDigits: 2, maximumFractionDigits: 2 }) + ' บาท';
}

// Error สำหรับ HTTP Status ที่ไม่ใช่ 2xx เก็บ status ไว้ให้โค้ดที่เรียกใช้ตัดสินใจต่อ
export class HttpError extends Error {
  constructor(status, url) {
    super(`HTTP ${status} จาก ${url}`);
    this.name = 'HttpError';
    this.status = status;
  }
}

// รอเป็นเวลา ms มิลลิวินาที (ห่อ setTimeout ด้วย Promise)
const sleep = (ms) => new Promise((resolve) => setTimeout(resolve, ms));

// ตัดสินว่า Error นี้ควรลองใหม่หรือไม่
export function isRetryable(error) {
  if (error instanceof HttpError) return error.status >= 500; // 5xx ลองใหม่, 4xx ไม่ลอง
  if (error.name === 'TimeoutError') return true; // AbortSignal.timeout หมดเวลา
  if (error.name === 'TypeError') return true; // fetch failed: ต่อ Server ไม่ได้
  return false; // เช่น SyntaxError จาก JSON เสีย ลองใหม่ก็เสียเหมือนเดิม
}

// ดึง JSON พร้อม Timeout และ Retry
// fetchImpl ส่งเข้ามาได้ เพื่อให้ Unit Test ใช้ fetch ปลอมแทนเครือข่ายจริง
export async function fetchJson(url, {
  retries = 2,
  timeoutMs = 2000,
  retryDelayMs = 300,
  fetchImpl = globalThis.fetch,
  onRetry = () => {},
} = {}) {
  const maxAttempts = retries + 1;
  for (let attempt = 1; attempt <= maxAttempts; attempt += 1) {
    try {
      const response = await fetchImpl(url, { signal: AbortSignal.timeout(timeoutMs) });
      if (!response.ok) throw new HttpError(response.status, url); // fetch ไม่ reject เมื่อได้ 404/500
      return await response.json();
    } catch (error) {
      if (!isRetryable(error)) throw error; // ส่ง Error เดิมต่อทันที ไม่ลองใหม่
      if (attempt === maxAttempts) {
        throw new Error(`ดึง ${url} ไม่สำเร็จหลังลอง ${attempt} ครั้ง`, { cause: error });
      }
      onRetry({ attempt, error });
      await sleep(retryDelayMs * attempt); // รอนานขึ้นทีละขั้น
    }
  }
}

แนวคิด
  • ตรวจ response.ok เอง: fetch ไม่ reject เมื่อได้ 404 หรือ 500 เราจึงแปลง Status ที่ไม่ใช่ 2xx เป็น HttpError ที่เก็บ status ไว้ ทำให้ทุก Error ไหลเข้า catch จุดเดียวและตัดสินใจได้ในที่เดียว (แนวคิดที่ 10 และ 11)
  • แยกนโยบายการลองใหม่ไว้ใน isRetryable: 5xx, TimeoutError และ TypeError (Network Error) เป็นปัญหาชั่วคราวที่ลองใหม่แล้วอาจหาย ส่วน 4xx และ SyntaxError จาก JSON เสียเป็นปัญหาถาวร ลองใหม่ก็ได้ผลเดิมและเปลืองเวลาผู้ใช้ จึงโยน Error เดิมต่อทันที
  • Timeout ด้วย AbortSignal.timeout: สร้าง Signal ใหม่ทุกรอบ เพราะ Signal ที่หมดเวลาไปแล้วจะอยู่ในสถานะ aborted ตลอด ถ้าใช้ตัวเดิมซ้ำ รอบถัดไปจะถูกยกเลิกทันที
  • return await ภายใน try: ทำให้ Error จาก response.json() ถูกจับโดย catch ของรอบนั้นและผ่าน isRetryable เหมือน Error อื่น
  • Error ที่มี cause: เมื่อลองครบแล้ว ข้อความหลักบอกผู้ใช้ว่าเกิดอะไรขึ้น (ดึง URL ไหน ลองกี่ครั้ง) ส่วน error.cause เก็บ Error ต้นเหตุไว้ให้นักพัฒนา Debug ต่อได้ ใน demo.js ไล่ลงไปได้ถึง error.cause.cause.code ซึ่งคือ ECONNREFUSED
  • Dependency Injection เพื่อทดสอบ: การรับ fetchImpl เป็นพารามิเตอร์ (ค่าเริ่มต้นคือ globalThis.fetch) ทำให้ Test ส่ง mock.fn() เข้าไปแทนได้ ควบคุมได้ว่าแต่ละรอบจะได้อะไร และนับจำนวนครั้งที่ถูกเรียกด้วย mock.callCount() นี่คือหลัก "ออกแบบโค้ดให้ทดสอบได้" จากแนวคิดที่ 12
  • รอนานขึ้นทีละขั้น: retryDelayMs * attempt ทำให้รอบที่ 2 รอนานกว่ารอบแรก ให้เวลา Server ฟื้นตัว และไม่ยิงคำขอซ้ำถี่ ๆ ใส่ Server ที่กำลังมีปัญหา
ไอเดียต่อยอด
  • เปลี่ยนการรอเป็น Exponential Backoff พร้อม Jitter เช่น retryDelayMs * 2 ** (attempt - 1) + Math.random() * 100 แล้วรับฟังก์ชัน random เป็นพารามิเตอร์ เพื่อให้ Test ยังได้ผลคงที่
  • รองรับ Header Retry-After ที่ Server ส่งมากับ 503 หรือ 429 โดยอ่านจาก response.headers.get('Retry-After') แล้วรอตามที่ Server บอก และเพิ่ม 429 (Too Many Requests) เป็นกรณีที่ลองใหม่ได้
  • รับ signal จากผู้เรียกเพิ่ม เพื่อให้ผู้ใช้กดปุ่ม "ยกเลิก" ได้ แล้วรวมกับ Timeout ด้วย AbortSignal.any([userSignal, AbortSignal.timeout(timeoutMs)]) และห้ามลองใหม่เมื่อผู้ใช้ยกเลิกเอง (Error ชื่อ AbortError)
  • นำ fetchJson ไปใช้ใน Mini Project Interactive Quiz App ของ Part 4 ตอนโหลด data/questions.json และแสดงข้อความ "กำลังลองใหม่ครั้งที่ 1" ผ่าน onRetry ในพื้นที่ aria-live
  • เพิ่ม Test ที่ใช้ mock.timers ตรวจว่าการรอระหว่างรอบเป็น 300 และ 600 มิลลิวินาทีจริง โดยไม่ต้องรอเวลาจริง
