Mini Project: Type-safe Task Manager

เป้าหมายของโปรเจกต์

สร้าง CLI ที่โฟลเดอร์ ~/projects/task-manager-ts สำหรับเพิ่ม ดู เริ่มทำ ปิด และลบงาน โดยเก็บข้อมูลไว้ในไฟล์ data/tasks.json โปรแกรมนี้เล็ก แต่ออกแบบแบบเดียวกับระบบจริงในบริษัท คือแยกเป็นชั้น (Layer) ชัดเจน และให้ Type ช่วยจับ Bug ในทุกชั้น

หัวใจของโปรเจกต์มี 3 ข้อ

  1. Type มาจากแหล่งเดียว: Type Task สร้างจาก zod Schema ด้วย z.infer ดังนั้นกฎตรวจข้อมูลตอนรันจริงกับ Type ตอน Compile จะตรงกันเสมอ
  2. ไม่เชื่อข้อมูลจากภายนอก: ทุกครั้งที่อ่านไฟล์ JSON จะตรวจด้วย zod ก่อนใช้ ถ้ามีคนแก้ไฟล์ด้วยมือจนผิด โปรแกรมจะบอกว่าผิดที่ช่องไหนของงานลำดับที่เท่าไร
  3. ผู้ใช้ไม่เห็น Stack Trace: ความผิดพลาดที่คาดได้ส่งกลับเป็นค่า Result ส่วนความผิดพลาดที่ไม่คาดคิดถูกจับไว้ที่จุดเดียว แล้วแสดงข้อความภาษาไทยพร้อม Exit Code 1

ความสามารถของโปรแกรม

  • Task model: id รูปแบบ T-001, title ยาว 1–100 ตัวอักษร, priority เป็น "low" | "medium" | "high", status เป็น "todo" | "doing" | "done", tags เป็น string[], dueDate แบบ YYYY-MM-DD (ไม่บังคับ) และ createdAt เป็นเวลาแบบ ISO 8601
  • คำสั่ง 7 แบบ เก็บเป็น Discriminated Union ที่แยกด้วยช่อง kind: add "ชื่องาน" [--priority high] [--tag study] [--due 2026-10-25], list [--status todo|doing|done], start <id>, done <id>, remove <id>, stats และ help โดยใช้ switch ที่ตรวจครบทุกกรณีด้วย assertNever
  • ชั้น Generic Repository: interface Repository<T extends Entity> มีเมธอด findAll, findById, save, remove ที่คืน Promise ทั้งหมด มีสองแบบคือ JsonFileRepository<T> สำหรับใช้งานจริง และ InMemoryRepository<T> สำหรับ Test
  • ชั้น Service: TaskService ใช้ Utility Types เช่น NewTask = Omit<Task, "id" | "createdAt" | "status">, TaskPatch และ stats(): Record<Status, number>
  • ผลลัพธ์อ่านง่าย: แสดงเป็นตารางข้อความที่จัดคอลัมน์ตรงกัน ข้อความเป็นภาษาไทย และตั้ง process.exitCode = 1 เมื่อผิดพลาด เพื่อให้ Script อื่นรู้ว่าคำสั่งล้มเหลว
  • Test: ไฟล์ src/**/*.test.ts ใช้ node:test กับ InMemoryRepository สั่งรันด้วย npm test ซึ่ง Compile ด้วย tsc ก่อนแล้วค่อยรัน Test จาก dist/
  • ข้อมูลตัวอย่าง: data/tasks.json มีงาน 2 ชิ้น และ data/bad.json เป็นไฟล์ที่ตั้งใจให้ผิด ใช้สาธิตการตรวจข้อมูล

  2. Step 2: สร้าง Type Result สำหรับส่งผลสำเร็จหรือผิดพลาดโดยไม่ต้อง throw

    ความผิดพลาดในโปรแกรมนี้ส่วนใหญ่ "คาดได้" เช่น ผู้ใช้พิมพ์ priority ผิด หรือขอปิดงานที่ไม่มีอยู่ ถ้าใช้ throw ผู้เรียกจะไม่รู้จาก Type เลยว่าฟังก์ชันนี้ล้มเหลวได้ และอาจลืมจับ Error เราจึงคืนค่าเป็น Result ซึ่งเป็น Discriminated Union สองแบบ แยกด้วยช่อง ok ผู้เรียกต้องตรวจ ok ก่อนจึงจะเข้าถึง value ได้ ถ้าลืมตรวจ tsc จะแจ้ง Error

    // Result: ผลลัพธ์ของงานที่ "สำเร็จ" หรือ "ล้มเหลว" โดยไม่ต้อง throw
// E มีค่าเริ่มต้นเป็น string คือข้อความผิดพลาดภาษาไทยที่แสดงให้ผู้ใช้ได้ทันที
export type Result<T, E = string> =
  | { ok: true; value: T }
  | { ok: false; error: E };

// ตัวช่วยสร้าง Result ฝั่งสำเร็จ
export function ok<T>(value: T): Result<T, never> {
  return { ok: true, value };
}

// ตัวช่วยสร้าง Result ฝั่งล้มเหลว
export function err<E = string>(error: E): Result<never, E> {
  return { ok: false, error };
}
    บรรทัด / ส่วนความหมาย
    type Result<T, E = string>Generic Type ที่มีสองพารามิเตอร์ T คือชนิดของผลสำเร็จ E คือชนิดของข้อผิดพลาด และมีค่าเริ่มต้นเป็น string จึงเขียนสั้น ๆ ว่า Result<Task> ได้
    { ok: true; value: T } | { ok: false; error: E }Union สองแบบ ช่อง ok เป็น Literal Type true หรือ false จึงใช้ Narrow ได้: ใน if (result.ok) TypeScript รู้ว่ามี value
    ok<T>(value: T): Result<T, never>ฝั่งสำเร็จไม่มีทางมี Error จึงใช้ never ค่านี้นำไปใช้แทน Result<T, string> ได้ทุกที่ เพราะ never เข้ากับทุก Type
    err<E = string>(error: E): Result<never, E>ฝั่งล้มเหลวไม่มีทางมีค่าผลลัพธ์ จึงใช้ never ในตำแหน่ง T
    Tip

    แนวคิด Result มาจากภาษา Rust และ Go ที่ส่ง Error กลับเป็นค่า ใน TypeScript ไม่มีของในตัวภาษา แต่เขียนเองได้ใน 15 บรรทัด ทีมจริงหลายทีมใช้ Library อย่าง neverthrow แทน ถ้าต้องการเมธอดเสริม เช่น map หรือ andThen

  3. Step 3: สร้าง Domain Model จาก zod Schema และไฟล์ข้อมูลตัวอย่าง

    ไฟล์นี้คือหัวใจของโปรเจกต์ เราเขียนกฎของข้อมูลเป็น zod Schema เพียงครั้งเดียว แล้วให้ z.infer สร้าง Type ให้ ถ้าวันหนึ่งเพิ่ม priority แบบใหม่ เราแก้แค่ PRIORITIES ที่เดียว ทั้งการตรวจไฟล์ การตรวจคำสั่ง ข้อความ Error และ Type ทุกตัวจะเปลี่ยนตามทันที

    import { z } from "zod";

// ค่าที่อนุญาต เขียนเป็น const array เพื่อใช้ทั้งตอนตรวจข้อมูลและตอนแสดงผล
export const PRIORITIES = ["low", "medium", "high"] as const;
export const STATUSES = ["todo", "doing", "done"] as const;

export const PrioritySchema = z.enum(PRIORITIES);

type SplitArgs = { positional: string[]; flags: Record<string, string[]> };

// แยกอาร์กิวเมนต์ธรรมดาออกจากตัวเลือกแบบ --name value
function splitArgs(args: readonly string[], allowed: readonly string[]): Result<SplitArgs> {
  const positional: string[] = [];
  const flags: Record<string, string[]> = {};
  for (let i = 0; i < args.length; i++) {
    const arg = args[i];
    // noUncheckedIndexedAccess ทำให้ args[i] เป็น string | undefined
    if (arg === undefined) continue;
    if (!arg.startsWith("--")) {
      positional.push(arg);
      continue;
    }
    const name = arg.slice(2);
    if (!allowed.includes(name)) {
      return err(`ไม่รู้จักตัวเลือก --${name}`);
    }
    const value = args[i + 1];
    if (value === undefined || value.startsWith("--")) {
      return err(`ตัวเลือก --${name} ต้องมีค่าตามหลัง`);
    }
    (flags[name] ??= []).push(value);
    i++; // ข้ามค่าที่อ่านไปแล้ว
  }
  return ok({ positional, flags });
}

// แปลง process.argv (ตัดสองช่องแรกออกแล้ว) ให้เป็น Command หรือข้อความผิดพลาด
export function parseArgs(argv: readonly string[]): Result<Command> {
  const [name, ...rest] = argv;

  switch (name) {
    case undefined:
    case "help":
    case "--help":
      return ok({ kind: "help" });

    case "add": {
      const parsed = splitArgs(rest, ["priority", "tag", "due"]);
      if (!parsed.ok) return parsed;
      const { positional, flags } = parsed.value;
      const title = positional.join(" ").trim();
      if (title === "") {
        return err('ต้องระบุชื่องาน เช่น add "อ่านบท Generics"');
      }
      const priority = flags["priority"]?.at(-1) ?? "medium";
      if (!isPriority(priority)) {
        return err(`priority ต้องเป็น ${PRIORITIES.join(" | ")} แต่ได้รับ "${priority}"`);
      }
      const due = flags["due"]?.at(-1);
      // exactOptionalPropertyTypes: ใส่ dueDate เฉพาะเมื่อมีค่าจริง
      return ok({
        kind: "add",
        title,
        priority,
        tags: flags["tag"] ?? [],
        ...(due !== undefined ? { dueDate: due } : {}),
      });
    }

    case "list": {
      const parsed = splitArgs(rest, ["status"]);
      if (!parsed.ok) return parsed;
      const status = parsed.value.flags["status"]?.at(-1);
      if (status === undefined) return ok({ kind: "list" });
      if (!isStatus(status)) {
        return err(`status ต้องเป็น ${STATUSES.join(" | ")} แต่ได้รับ "${status}"`);
      }
      return ok({ kind: "list", status });
    }

    case "start":
    case "done":
    case "remove": {
      // ตรงนี้ name ถูก Narrow เหลือ "start" | "done" | "remove"
      const id = rest[0]?.toUpperCase();
      if (id === undefined) {
        return err(`คำสั่ง ${name} ต้องระบุ id เช่น ${name} T-001`);
      }
      if (!ID_PATTERN.test(id)) {
        return err(`id "${id}" ไม่ถูกรูปแบบ ต้องเป็นแบบ T-001`);
      }
      return ok({ kind: name, id });
    }

    case "stats":
      return ok({ kind: "stats" });

    default:
      return err(`ไม่รู้จักคำสั่ง "${name}" พิมพ์ help เพื่อดูคำสั่งทั้งหมด`);
  }
}

// สัญญา (Contract) ของที่เก็บข้อมูล: ใช้ได้กับทุก T ที่มี id
// ทุกเมธอดคืน Promise เพื่อให้สลับไปใช้ไฟล์ ฐานข้อมูล หรือ API ได้โดยไม่ต้องแก้ผู้เรียก
export interface Repository<T extends Entity> {
  findAll(): Promise<T[]>;
  findById(id: string): Promise<T | undefined>;
  save(entity: T): Promise<void>; // เพิ่มใหม่ หรือแทนที่ตัวเดิมที่ id ตรงกัน
  remove(id: string): Promise<boolean>; // คืน true ถ้าลบได้จริง
}

export class InMemoryRepository<T extends Entity> implements Repository<T> {
  readonly #items = new Map<string, T>();

  constructor(initial: readonly T[] = []) {
    for (const item of initial) {
      this.#items.set(item.id, item);
    }
  }

  async findAll(): Promise<T[]> {
    return [...this.#items.values()];
  }

  async findById(id: string): Promise<T | undefined> {
    return this.#items.get(id);
  }

  async save(entity: T): Promise<void> {
    this.#items.set(entity.id, entity);
  }

  async remove(id: string): Promise<boolean> {
    return this.#items.delete(id);
  }
}

export class JsonFileRepository<T extends Entity> implements Repository<T> {
  // #private ของ JavaScript: ซ่อนจริงตอนรัน ไม่ใช่แค่ตอน Compile
  readonly #filePath: string;
  readonly #listSchema: z.ZodType<T[]>;

  constructor(filePath: string, itemSchema: z.ZodType<T>) {
    this.#filePath = filePath;
    this.#listSchema = z.array(itemSchema);
  }

  async findAll(): Promise<T[]> {
    let text: string;
    try {
      text = await readFile(this.#filePath, "utf8");
    } catch (error) {
      // ยังไม่มีไฟล์ = ยังไม่มีงาน ไม่ถือว่าผิดพลาด
      if (error instanceof Error && "code" in error && error.code === "ENOENT") {
        return [];
      }
      throw error;
    }

    // JSON.parse คืน any จึงเก็บไว้เป็น unknown แล้วให้ zod ตรวจ
    let data: unknown;
    try {
      data = JSON.parse(text);
    } catch {
      throw new DataFileError(`ไฟล์ ${this.#filePath} ไม่ใช่ JSON ที่ถูกต้อง`);
    }

    const result = this.#listSchema.safeParse(data);
    if (!result.success) {
      throw new DataFileError(
        `ไฟล์ ${this.#filePath} มีข้อมูลไม่ถูกต้อง:\n${z.prettifyError(result.error)}`,
      );
    }
    return result.data;
  }

  async findById(id: string): Promise<T | undefined> {
    const items = await this.findAll();
    return items.find((item) => item.id === id);
  }

  async save(entity: T): Promise<void> {
    const items = await this.findAll();
    const index = items.findIndex((item) => item.id === entity.id);
    if (index === -1) {
      items.push(entity);
    } else {
      items[index] = entity;
    }
    await this.#writeAll(items);
  }

  async remove(id: string): Promise<boolean> {
    const items = await this.findAll();
    const kept = items.filter((item) => item.id !== id);
    if (kept.length === items.length) return false;
    await this.#writeAll(kept);
    return true;
  }

  // เขียนลงไฟล์ชั่วคราวก่อนแล้วค่อยเปลี่ยนชื่อ ไฟล์จริงจะไม่เสียถ้าโปรแกรมหยุดกลางทาง
  async #writeAll(items: readonly T[]): Promise<void> {
    await mkdir(dirname(this.#filePath), { recursive: true });
    const tempPath = `${this.#filePath}.tmp`;
    await writeFile(tempPath, JSON.stringify(items, null, 2) + "\n", "utf8");
    await rename(tempPath, this.#filePath);
  }
}

export class TaskService {
  readonly #repo: Repository<Task>;
  readonly #now: () => Date;

  // now รับเข้ามาได้ เพื่อให้ Test กำหนดเวลาตายตัวได้
  constructor(repo: Repository<Task>, now: () => Date = () => new Date()) {
    this.#repo = repo;
    this.#now = now;
  }

  async list(status?: Status): Promise<Task[]> {
    const tasks = await this.#repo.findAll();
    return status === undefined ? tasks : tasks.filter((task) => task.status === status);
  }

  async create(input: NewTask): Promise<Result<Task>> {
    const tasks = await this.#repo.findAll();
    const candidate = {
      ...input,
      id: nextId(tasks),
      status: "todo",
      createdAt: this.#now().toISOString(),
    };
    // ตรวจด้วย Schema เดียวกับตอนอ่านไฟล์ ข้อมูลเสียจึงเข้าไฟล์ไม่ได้
    const parsed = TaskSchema.safeParse(candidate);
    if (!parsed.success) return err(z.prettifyError(parsed.error));
    await this.#repo.save(parsed.data);
    return ok(parsed.data);
  }

  async update(id: string, patch: TaskPatch): Promise<Result<Task>> {
    const task = await this.#repo.findById(id);
    if (task === undefined) return err(`ไม่พบงาน ${id}`);
    const parsed = TaskSchema.safeParse({ ...task, ...patch });
    if (!parsed.success) return err(z.prettifyError(parsed.error));
    await this.#repo.save(parsed.data);
    return ok(parsed.data);
  }

  start(id: string): Promise<Result<Task>> {
    return this.#changeStatus(id, "doing");
  }

  complete(id: string): Promise<Result<Task>> {
    return this.#changeStatus(id, "done");
  }

  async remove(id: string): Promise<Result<Task>> {
    const task = await this.#repo.findById(id);
    if (task === undefined) return err(`ไม่พบงาน ${id}`);
    await this.#repo.remove(id);
    return ok(task);
  }

  // Record<Status, number> บังคับให้มีครบทุกสถานะ ขาดตัวไหน tsc จะแจ้ง
  async stats(): Promise<Record<Status, number>> {
    const counts: Record<Status, number> = { todo: 0, doing: 0, done: 0 };
    for (const task of await this.#repo.findAll()) {
      counts[task.status] += 1;
    }
    return counts;
  }

  async #changeStatus(id: string, status: Status): Promise<Result<Task>> {
    const task = await this.#repo.findById(id);
    if (task === undefined) return err(`ไม่พบงาน ${id}`);
    if (task.status === status) return err(`งาน ${id} อยู่ในสถานะ ${status} อยู่แล้ว`);
    return this.update(id, { status });
  }
}

// หา id ถัดไปจากเลขที่มากที่สุด เช่น มี T-001, T-002 จะได้ T-003
function nextId(tasks: readonly Task[]): string {
  const max = tasks.reduce((highest, task) => {
    const n = Number(task.id.slice(2));
    return Number.isNaN(n) ? highest : Math.max(highest, n);
  }, 0);
  return `T-${String(max + 1).padStart(3, "0")}`;
}

type Column = { header: string; value: (task: Task) => string };

const COLUMNS: readonly Column[] = [
  { header: "ID", value: (t) => t.id },
  { header: "STATUS", value: (t) => t.status },
  { header: "PRIORITY", value: (t) => t.priority },
  { header: "DUE", value: (t) => t.dueDate ?? "-" },
  { header: "TAGS", value: (t) => (t.tags.length > 0 ? t.tags.join(",") : "-") },
  { header: "TITLE", value: (t) => t.title },
];

// สร้างตารางข้อความที่จัดคอลัมน์ตรงกัน (คอลัมน์ TITLE อยู่ท้ายสุด
// เพราะสระและวรรณยุกต์ภาษาไทยทำให้นับความกว้างตัวอักษรไม่ตรง)
export function formatTable(tasks: readonly Task[]): string {
  if (tasks.length === 0) return "ยังไม่มีงาน";
  const rows = tasks.map((task) => COLUMNS.map((col) => col.value(task)));
  const widths = COLUMNS.map((col, i) =>
    Math.max(col.header.length, ...rows.map((row) => row[i]?.length ?? 0)),
  );
  const line = (cells: readonly string[]): string =>
    cells
      .map((cell, i) => (i === cells.length - 1 ? cell : cell.padEnd(widths[i] ?? 0)))
      .join("  ");
  const header = line(COLUMNS.map((col) => col.header));
  const divider = "-".repeat(header.length);
  return [header, divider, ...rows.map(line), divider, `ทั้งหมด ${tasks.length} งาน`].join("\n");
}

// สรุปจำนวนงานตามสถานะ พร้อมเปอร์เซ็นต์งานที่เสร็จ
export function formatStats(stats: Record<Status, number>): string {
  const total = STATUSES.reduce((sum, status) => sum + stats[status], 0);
  const percent = total === 0 ? 0 : Math.round((stats.done / total) * 100);
  const lines = STATUSES.map((status) => `${status.padEnd(6)}${String(stats[status]).padStart(3)}`);
  return [...lines, `${"total".padEnd(6)}${String(total).padStart(3)}`, `เสร็จแล้ว ${percent}%`].join("\n");
}

async function run(command: Command, service: TaskService): Promise<Result<string>> {
  switch (command.kind) {
    case "help":
      return ok(HELP_TEXT);
    case "add": {
      // ตัด kind ออก ส่วนที่เหลือคือ NewTask พอดี
      const { kind: _kind, ...input } = command;
      const result = await service.create(input);
      if (!result.ok) return result;
      return ok(`เพิ่มงาน ${result.value.id} แล้ว: ${result.value.title}`);
    }
    case "list":
      return ok(formatTable(await service.list(command.status)));
    case "start": {
      const result = await service.start(command.id);
      return result.ok ? ok(`เริ่มทำ ${command.id} แล้ว: ${result.value.title}`) : result;
    }
    case "done": {
      const result = await service.complete(command.id);
      return result.ok ? ok(`ปิดงาน ${command.id} แล้ว: ${result.value.title}`) : result;
    }
    case "remove": {
      const result = await service.remove(command.id);
      return result.ok ? ok(`ลบงาน ${command.id} แล้ว: ${result.value.title}`) : result;
    }
    case "stats":
      return ok(formatStats(await service.stats()));
    default:
      // ถ้าเพิ่ม kind ใหม่ใน Command แล้วลืมเขียน case บรรทัดนี้จะ Compile ไม่ผ่าน
      return assertNever(command);
  }
}

    process.exitCode = 1;
    return;

    const result = await run(parsed.value, service);

    } else {

      process.exitCode = 1;

      console.error("เกิดข้อผิดพลาดที่ไม่คาดคิด:", error instanceof Error ? error.message : String(error));
    }
    process.exitCode = 1;
  }
}

CLI จัดการรายการงาน เขียนด้วย TypeScript 7 แบบ strict ทั้งโปรเจกต์

## ความสามารถ

- เพิ่ม ดู เริ่มทำ ปิด และลบงาน พร้อมกำหนด priority, tag และวันครบกำหนด
- สรุปจำนวนงานตามสถานะ และเปอร์เซ็นต์งานที่เสร็จ
- ตรวจไฟล์ `data/tasks.json` ทุกครั้งที่อ่าน ถ้าไฟล์ผิดจะบอกว่าผิดที่ช่องไหน
- ข้อความภาษาไทย และคืน Exit Code 1 เมื่อผิดพลาด

## สิ่งที่โปรเจกต์นี้แสดง

- Type มาจาก zod Schema แหล่งเดียว (`z.infer`)
- คำสั่งเป็น Discriminated Union และตรวจครบทุกกรณีด้วย `assertNever`
- Generic Repository (`Repository<T extends Entity>`) สองแบบ: ไฟล์ JSON และหน่วยความจำ
- Utility Types: `Omit`, `Partial`, `Pick`, `Record`
- tsconfig แบบ strict พร้อม `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, `erasableSyntaxOnly`
- Test 13 ข้อด้วย node:test และ CI บน GitHub Actions

Interview Questions

คำถาม 5 ข้อนี้พบบ่อยในการสัมภาษณ์ตำแหน่ง Frontend, Backend และ Full-stack ที่ใช้ TypeScript ข้อ 1–3 เป็นระดับ Junior ข้อ 4–5 เป็นระดับ Mid-level ลองตอบด้วยคำพูดของตัวเองก่อน แล้วค่อยเปิดดูแนวคำตอบ

1. TypeScript ต่างจาก JavaScript อย่างไร และ Type ยังอยู่ไหมตอนโปรแกรมรันจริง

แนวคำตอบ: TypeScript คือ JavaScript ที่เพิ่มระบบ Type แบบ Static เข้าไป Compiler (tsc) ตรวจ Type ก่อนรัน แล้วลบ Type ทิ้งจนเหลือ JavaScript ธรรมดา เรียกว่า Type Erasure ดังนั้นตอนรันจริงไม่มี Type เหลืออยู่เลย

  • ประโยชน์หลักคือจับ Bug ตอนเขียน เช่น พิมพ์ชื่อช่องผิด ส่ง string ไปที่ต้องการ number หรือลืมตรวจ undefined และทำให้ Editor แนะนำโค้ดและ Refactor ได้ปลอดภัย
  • ผลที่ตามมาคือ Type ป้องกันข้อมูลจากภายนอกไม่ได้ เช่น Body ของ Request ไฟล์ JSON หรือคำตอบจาก API เพราะข้อมูลพวกนี้มาตอนรัน ต้องตรวจด้วย Runtime Validation เช่น zod ที่ขอบระบบ
  • ตั้งแต่ Node.js 22.18.0 และ 23.6.0 สามารถรันไฟล์ .ts ได้ตรง ๆ ด้วย Type Stripping แต่ Node แค่ลบ Type ไม่ได้ตรวจ จึงยังต้องรัน tsc --noEmit
  • TypeScript 7 เปลี่ยน Compiler มาเขียนด้วยภาษา Go ทำให้เร็วขึ้นมาก แต่คำสั่งยังเป็น tsc และภาษายังเหมือนเดิม

2. any, unknown และ never ต่างกันอย่างไร ควรใช้ตัวไหนเมื่อไร

แนวคำตอบ: ทั้งสามเป็น Type พิเศษที่อยู่คนละขั้วของระบบ Type

  • any ปิดการตรวจ Type ทุกอย่าง ทำอะไรกับค่านี้ก็ได้ และมัน "ติดต่อ" ไปยังค่าอื่นที่คำนวณจากมัน ควรเลี่ยง ใช้เฉพาะตอนย้ายโค้ด JavaScript เก่าชั่วคราว
  • unknown รับค่าอะไรก็ได้เหมือน any แต่ห้ามใช้จนกว่าจะ Narrow ด้วย typeof, instanceof, Type Guard หรือ Schema เหมาะกับข้อมูลจากภายนอก เช่นผลของ JSON.parse และตัวแปรใน catch ซึ่ง strict mode กำหนดให้เป็น unknown อยู่แล้ว
  • never คือ Type ที่ไม่มีค่าใดเป็นได้เลย ใช้เป็น Type คืนของฟังก์ชันที่ throw เสมอ และใช้ตรวจว่าจัดการ Union ครบทุกกรณี

จุดที่ผู้สัมภาษณ์อยากได้ยินคือ "ใช้ unknown แทน any ที่ขอบระบบ แล้ว Narrow ด้วย Schema" และยกตัวอย่าง never กับ Exhaustive Check ได้

function assertNever(value: never): never {
  throw new Error(`ไม่ได้จัดการ: ${JSON.stringify(value)}`);
}

try {
  await loadTasks();
} catch (error) {
  // error เป็น unknown ต้องตรวจก่อนอ่าน message
  console.error(error instanceof Error ? error.message : String(error));
}
3. type alias กับ interface ต่างกันอย่างไร ในทีมควรเลือกใช้อย่างไร

แนวคำตอบ: สำหรับ Object ทั้งสองแบบใช้แทนกันได้เกือบทุกกรณี ความต่างที่ควรรู้มีดังนี้

  • type ตั้งชื่อให้ Type ได้ทุกแบบ ทั้ง Union, Tuple, Function, Mapped Type และ Conditional Type ส่วน interface ใช้ได้กับรูปร่างของ Object เท่านั้น
  • interface ขยายต่อด้วย extends และรวมร่างกันได้ถ้าประกาศชื่อซ้ำ (Declaration Merging) ซึ่งมีประโยชน์ตอนเพิ่มช่องให้ Type ของ Library แต่ก็อาจทำให้งงถ้าเผลอตั้งชื่อซ้ำ
  • type รวม Type ด้วย & (Intersection) แทน extends
  • ข้อความ Error ของ interface มักแสดงเป็นชื่อสั้น ๆ อ่านง่ายกว่าในบางกรณี

สิ่งสำคัญกว่าการเลือกคือความสม่ำเสมอในทีม แนวที่ใช้ในหัวข้อนี้คือ ใช้ type สำหรับข้อมูลและ Union และใช้ interface สำหรับสัญญาที่ Class จะ implements หรือที่ต้องขยายต่อ เช่น interface Repository<T extends Entity>

4. Discriminated Union คืออะไร และช่วยลด Bug ในงานจริงได้อย่างไร

แนวคำตอบ: Discriminated Union คือ Union ของ Object หลายแบบที่ทุกแบบมีช่องร่วมกันหนึ่งช่อง (เช่น kind หรือ type) ซึ่งเป็น Literal Type คนละค่า เมื่อตรวจช่องนั้นด้วย if หรือ switch TypeScript จะ Narrow ให้เหลือแบบเดียว จึงเข้าถึงช่องเฉพาะของแบบนั้นได้อย่างปลอดภัย

  • ทำให้ "สถานะที่เป็นไปไม่ได้เขียนไม่ได้" เช่น Result ที่มีทั้ง value และ error พร้อมกันจะไม่ผ่าน tsc
  • เมื่อรวมกับ assertNever ใน default ถ้ามีคนเพิ่มแบบใหม่แต่ลืมจัดการ tsc จะแจ้ง Error ทุกจุดที่ต้องแก้ เหมาะกับ Command, Event, Action ของ Redux และสถานะการโหลดข้อมูล
  • ใน Mini Project ใช้ทั้งกับ Command และ Result
type LoadState<T> =
  | { status: "loading" }
  | { status: "success"; data: T }
  | { status: "error"; message: string };

function render(state: LoadState<string[]>): string {
  switch (state.status) {
    case "loading":
      return "กำลังโหลด";
    case "success":
      return state.data.join(", "); // ตรงนี้รู้ว่ามี data
    case "error":
      return `ผิดพลาด: ${state.message}`;
    default:
      return assertNever(state);
  }
}
5. ถ้าต้องย้ายโปรเจกต์ JavaScript ขนาดกลางมาเป็น TypeScript แบบ strict จะวางแผนอย่างไร

แนวคำตอบ: ย้ายทีละขั้นโดยไม่หยุดงานส่วนอื่น และให้ CI ป้องกันไม่ให้ถอยหลัง

  1. ติดตั้ง typescript และ @types ของ Library ที่ใช้ สร้าง tsconfig.json ที่เปิด allowJs เพื่อให้ไฟล์ .js กับ .ts อยู่ร่วมกันได้ และเพิ่ม tsc --noEmit เข้า CI ตั้งแต่วันแรก
  2. เริ่มตรวจไฟล์ JavaScript เดิมด้วย // @ts-check และ JSDoc หรือเปิด checkJs เพื่อเจอปัญหาโดยยังไม่ต้องเปลี่ยนนามสกุล
  3. เปลี่ยนนามสกุลทีละไฟล์ เริ่มจากไฟล์ที่ไม่มีใครพึ่งพา (ปลายทาง) เช่น Utility แล้วไล่ขึ้นไปหาไฟล์ที่ใช้มัน สำหรับ Library ที่ไม่มี Type ให้เขียนไฟล์ .d.ts เอง
  4. ใส่ Schema (เช่น zod) ที่ขอบระบบก่อน เพราะเป็นจุดที่ Bug จากข้อมูลผิดรูปแบบเกิดบ่อยที่สุด
  5. เปิด strict และตัวเลือกเข้มงวดอื่นทีละตัว แก้ Error ให้หมดก่อนเปิดตัวถัดไป และจำกัดการใช้ any หรือ // @ts-expect-error พร้อมเหตุผลในโค้ด
  6. วัดความคืบหน้า เช่น จำนวนไฟล์ .js ที่เหลือ และห้าม Merge โค้ดที่เพิ่ม Error ใหม่

ผู้สมัครที่ดีจะพูดถึงความเสี่ยงด้วย เช่น Type ที่เขียนเองใน .d.ts อาจไม่ตรงกับโค้ดจริง จึงต้องมี Test รองรับ และเครื่องมือบางตัวที่เรียก TypeScript API โดยตรง เช่น typescript-eslint ยังต้องใช้ TypeScript 6.x ในช่วงที่ TypeScript 7 เพิ่งออก
