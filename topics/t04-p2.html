4.2Core Concept & Quick Guide

ส่วนนี้คือแกนกลางของหัวข้อ JavaScript เราจะเรียน 12 แนวคิดหลัก เรียงจากง่ายไปยากตามเส้นทางใน Part 1 แนวคิดที่ 1–4 เป็นระดับ Beginner (การรันโค้ด ตัวแปรและชนิดข้อมูล เงื่อนไข ลูปและฟังก์ชัน HTML/CSS พื้นฐาน และ Array) แนวคิดที่ 5–8 เป็นระดับ Intermediate (Object, ES Modules กับ npm, DOM และ Events กับ Forms) และแนวคิดที่ 9–12 เป็นระดับ Advanced (Closure กับ Class, Error Handling กับ localStorage, Asynchronous JavaScript และ Debugging กับ Testing)

ทุกแนวคิดมีโค้ดที่รันได้จริงพร้อมผลลัพธ์จากการรันจริง โค้ดฝั่ง Node.js รันด้วยคำสั่ง node ใน Ubuntu (WSL) ส่วนโค้ดฝั่งเบราว์เซอร์เปิดผ่าน Web Server ในเครื่อง (python3 -m http.server) แล้วดูผลใน DevTools ของ Chrome หรือ Edge ผลลัพธ์ฝั่งเบราว์เซอร์ในหน้านี้ผู้เขียนตรวจด้วยการรันเบราว์เซอร์แบบ Headless แล้วคัดลอกข้อความจาก Console มาแสดง คุณจะเห็นข้อความเดียวกันในแท็บ Console ของ DevTools

ถ้ายังไม่คล่องคำสั่ง Linux อย่าง cd, mkdir หรือการแก้ ~/.bashrc ให้ทบทวน ก่อน เราจะเก็บงานทุกแนวคิดไว้ใน Git ตามที่เรียนใน และเพราะคุณเรียน มาแล้ว หลายแนวคิดจะเทียบกับ Python ให้เห็น เช่น list กับ Array, dict กับ Object, f-string กับ Template literal และ None กับ null/undefined

1. ติดตั้ง nvm และ Node.js LTS

3. ตัวแก้ไขโค้ดและเบราว์เซอร์

  • VS Code + ส่วนขยาย WSL: ติดตั้ง VS Code บน Windows แล้วติดตั้งส่วนขยาย "WSL" ของ Microsoft จากนั้นพิมพ์ code . ในโฟลเดอร์ ~/projects/js-lab VS Code จะเปิดไฟล์ที่อยู่ใน Ubuntu โดยตรง และ Terminal ใน VS Code จะเป็น Bash ของ Ubuntu
  • เบราว์เซอร์: ใช้ Google Chrome หรือ Microsoft Edge รุ่นล่าสุดบน Windows เปิด DevTools ด้วย F12 หรือ Ctrl+Shift+I และเปิดแท็บ Console โดยตรงด้วย Ctrl+Shift+J
  • Web Server ในเครื่อง: หน้าเว็บที่ใช้ <script type="module"> หรือ fetch ต้องเปิดผ่าน http:// เสมอ ไม่ใช่ดับเบิลคลิกไฟล์ (file://) เราใช้ python3 -m http.server 8000 --bind 127.0.0.1 แล้วเปิด http://127.0.0.1:8000/ ใน Chrome บน Windows ได้เลย เพราะ WSL2 ส่งต่อพอร์ตของ 127.0.0.1 ให้ Windows อัตโนมัติ

คืออะไร ทำไมต้องใช้ และใช้เมื่อไร

JavaScript รันได้สองที่หลัก ที่แรกคือเบราว์เซอร์ ซึ่งมี Engine (เช่น V8 ใน Chrome และ Edge) อยู่ข้างใน ที่สองคือ Node.js ซึ่งเป็น Runtime ที่นำ V8 มารันนอกเบราว์เซอร์ เราจึงทดลองโค้ดได้สามวิธี ได้แก่ (1) พิมพ์ใน Console ของ DevTools (กด F12 แล้วเลือกแท็บ Console) (2) พิมพ์ใน REPL ของ Node.js โดยพิมพ์ node เฉย ๆ จะเห็นเครื่องหมาย > ให้พิมพ์โค้ดทีละบรรทัด และออกด้วย .exit หรือ Ctrl+D (3) เขียนโค้ดลงไฟล์แล้วรันด้วย node ชื่อไฟล์.js ซึ่งเป็นวิธีหลักของเรา คำสั่ง console.log() ใช้แสดงค่าออกหน้าจอ เหมือน print() ใน Python

Variable (ตัวแปร) ประกาศได้สองแบบ const ใช้กับค่าที่ไม่เปลี่ยนตัวแปรอีก และ let ใช้กับค่าที่ต้องกำหนดใหม่ภายหลัง ส่วน var เป็นแบบเก่าที่มีพฤติกรรมแปลก (จะเห็นในแนวคิดที่ 9) จึงไม่ใช้ในโค้ดใหม่ ชื่อตัวแปรเขียนแบบ camelCase เช่น isMember ค่าใน JavaScript มี 7 ชนิดที่เป็น Primitive (ค่าพื้นฐาน) คือ string, number, boolean, null, undefined, bigint และ symbol ค่าอื่นทั้งหมด (Object, Array, Function) เป็นชนิด object ตรวจชนิดด้วย typeof

  • ตัวเลข มีชนิดเดียวคือ number (ไม่แยก int กับ float แบบ Python) จึงมีปัญหาทศนิยมอย่าง 0.1 + 0.2 และค่า NaN (Not a Number) เมื่อแปลงข้อความที่ไม่ใช่ตัวเลข
  • Template literal คือ String ที่ครอบด้วย Backtick (`) และแทรกค่าด้วย ${...} เหมือน f-string ใน Python
  • === (Strict equality) เทียบทั้งค่าและชนิด ส่วน == แปลงชนิดก่อนเทียบ ทำให้ได้ผลที่คาดไม่ถึง ในงานจริงใช้ === เสมอ
  • Truthy/Falsy คือการที่ค่าทุกค่าถูกตีความเป็นจริงหรือเท็จเมื่ออยู่ใน if ค่า Falsy มีแค่ 8 ค่า ที่เหลือเป็น Truthy ทั้งหมด

ใช้ความรู้นี้ตั้งแต่บรรทัดแรกของทุกโปรแกรม ทั้งตอนคำนวณราคา ตรวจค่าที่ผู้ใช้กรอก และเปรียบเทียบข้อมูลจาก API

เปรียบเทียบ

ตัวแปรเหมือนกล่องที่ติดป้ายชื่อ const คือกล่องที่ติดกาวป้ายแน่น ใส่ของแล้วเปลี่ยนกล่องไม่ได้ ส่วน let คือกล่องที่เปิดเปลี่ยนของข้างในได้ == เหมือนพนักงานที่ยอมรับเหรียญ 10 บาทกับธนบัตร 10 บาทว่า "เท่ากัน" ส่วน === เหมือนเครื่องหยอดเหรียญที่รับเฉพาะเหรียญ ต้องตรงทั้งมูลค่าและชนิด

# สร้างโฟลเดอร์ของแนวคิดนี้และเปิดด้วย VS Code
mkdir -p ~/projects/js-lab/c01-basics
cd ~/projects/js-lab/c01-basics

// basics.js — ตัวแปร ชนิดข้อมูล ตัวดำเนินการ และการเปรียบเทียบ
// ข้อมูลออเดอร์กาแฟ (ค่าที่ไม่เปลี่ยนใช้ const)
const item = 'ชาไทยเย็น';
const price = 45;
const qty = 3;
const isMember = true;
const coupon = null;
let note; // ยังไม่กำหนดค่า จึงเป็น undefined
let discount = 0.1; // ใช้ let เพราะจะเปลี่ยนค่าภายหลัง

// แสดงค่าและชนิดข้อมูลของแต่ละตัวแปร
console.log('--- ค่าและชนิดข้อมูล ---');
console.log(item, typeof item);
console.log(price, typeof price);
console.log(isMember, typeof isMember);
console.log(coupon, typeof coupon); // typeof null ได้ 'object' (ข้อบกพร่องดั้งเดิมของภาษา)
console.log(note, typeof note);
console.log(10n, typeof 10n);
console.log(typeof Symbol('id'), typeof { a: 1 }, typeof [1, 2], typeof console.log);

// คำนวณราคา
console.log('--- คำนวณราคา ---');
const subtotal = price * qty;
if (!isMember) {
  discount = 0; // ไม่ใช่สมาชิก ไม่มีส่วนลด
}
const total = subtotal - subtotal * discount;
console.log(`${item} x ${qty} = ${subtotal} บาท`);
console.log(`ยอดสุทธิ ${total.toFixed(2)} บาท`);
console.log(`แบบมีจุลภาค: ${(1234567.5).toLocaleString('th-TH')} บาท`);
console.log('หารเอาเศษ 17 % 5 =', 17 % 5, '| ยกกำลัง 2 ** 10 =', 2 ** 10);

// กับดักของตัวเลข
console.log('--- กับดักของตัวเลข ---');
console.log(0.1 + 0.2);
console.log((0.1 + 0.2).toFixed(2));
console.log(Number('12a'), Number.isNaN(Number('12a')));
console.log(parseInt('42px', 10), Number('42'));
console.log(price + note); // number + undefined = NaN

// == กับ === เปรียบเทียบ 6 คู่
console.log('--- == กับ === ---');
// ฟังก์ชันช่วยแสดงค่า (ใส่เครื่องหมายคำพูดให้ String)
const show = (v) => (typeof v === 'string' ? `'${v}'` : String(v));
const pairs = [[0, ''], [null, undefined], ['5', 5], [0, false], ['', false], [NaN, NaN]];
for (const [a, b] of pairs) {
  console.log(`${show(a).padEnd(9)} vs ${show(b).padEnd(9)} ==: ${String(a == b).padEnd(5)} ===: ${a === b}`);
}

// ค่า Falsy ทั้งหมด (ค่าอื่นทุกค่าเป็น Truthy)
console.log('--- Truthy / Falsy ---');
const falsyValues = [false, 0, -0, 0n, '', null, undefined, NaN];
console.log(falsyValues.map((v) => Boolean(v)).join(' '));
console.log(Boolean('0'), Boolean([]), Boolean({}), Boolean(' '));
cd ~/projects/js-lab/c01-basics
node basics.js

เงื่อนไข ลูป และฟังก์ชัน: if/switch, for...of, Arrow Function และ Parameters

คืออะไร ทำไมต้องใช้ และใช้เมื่อไร

โปรแกรมทุกตัวต้อง "ตัดสินใจ" และ "ทำซ้ำ" ได้ เงื่อนไข ใน JavaScript มี if / else if / else สำหรับเงื่อนไขทั่วไป Ternary (เงื่อนไข ? ค่าถ้าจริง : ค่าถ้าเท็จ) สำหรับเลือกค่าสั้น ๆ ในบรรทัดเดียว และ switch สำหรับเทียบค่าเดียวกับหลายกรณี (ต้องมี break หรือ return ไม่อย่างนั้นจะไหลลงกรณีถัดไป) ตัวดำเนินการตรรกะคือ && (และ), || (หรือ) และ ! (ไม่) ซึ่งตรงกับ and, or, not ใน Python

ลูป มีหลายแบบ for (let i = 0; i < n; i++) ใช้เมื่อต้องการเลขลำดับ for...of วนทุกค่าใน Array หรือทุกตัวอักษรใน String (เหมือน for x in list ของ Python) และ while วนจนกว่าเงื่อนไขจะเป็นเท็จ ใช้ break เพื่อออกจากลูปทันที และ continue เพื่อข้ามไปรอบถัดไป

ฟังก์ชัน คือชุดคำสั่งที่ตั้งชื่อไว้เรียกซ้ำได้ เขียนได้สามแบบ

  • Function declaration: function toGrade(score) { ... } เรียกใช้ก่อนบรรทัดที่ประกาศได้ (เรื่อง Hoisting ในแนวคิดที่ 9)
  • Function expression: const toGrade = function (score) { ... }; เก็บฟังก์ชันไว้ในตัวแปร
  • Arrow function: const isPass = (score) => score >= 50; เขียนสั้น ถ้าไม่มีปีกกา ค่าหลัง => จะถูก return อัตโนมัติ (Implicit return) ถ้าจะคืน Object ต้องครอบด้วยวงเล็บ => ({ ... })
  • Default parameter (name = 'ผู้เรียน') ให้ค่าเริ่มต้นเมื่อไม่ส่งค่ามา และ Rest parameter (...nums) รวบค่าที่ส่งมาทั้งหมดเป็น Array เหมือน *args ใน Python

ฟังก์ชันที่ดีควรเป็น Pure function คือรับค่าเข้า คืนค่าออกด้วย return ไม่แก้ตัวแปรข้างนอก และไม่ console.log เอง เพราะนำไปใช้ซ้ำและทดสอบได้ง่าย (เราจะทดสอบฟังก์ชันแบบนี้ในแนวคิดที่ 12)

เปรียบเทียบ

ฟังก์ชันเหมือนเครื่องคั้นน้ำส้ม ใส่ส้มเข้าไป (Parameter) ได้น้ำส้มออกมา (Return value) เครื่องที่ดีไม่ควรเทน้ำส้มใส่แก้วเอง (console.log) แต่ส่งน้ำส้มคืนให้คนใช้ตัดสินใจว่าจะใส่แก้วไหน ส่วนลูปเหมือนพนักงานตรวจข้อสอบที่หยิบกระดาษทีละแผ่นจากกอง (for...of) เจอแผ่นที่เขียนไม่ถูกแบบก็วางข้ามไป (continue)

// grades.js — เงื่อนไข ลูป และฟังก์ชัน
const scores = [95, 82, 74, 61, 48, 105];

// Function declaration: แปลงคะแนนเป็นเกรด
function toGrade(score) {
  if (score >= 80) {
    return 'A';
  } else if (score >= 70) {
    return 'B';
  } else if (score >= 60) {
    return 'C';
  } else if (score >= 50) {
    return 'D';
  }
  return 'F';
}

// Arrow function + Rest parameter: รับตัวเลขกี่ตัวก็ได้
const average = (...nums) => {
  let sum = 0;
  for (const n of nums) {
    sum += n;
  }
  return nums.length === 0 ? 0 : sum / nums.length;
};

// Default parameters
function greet(name = 'ผู้เรียน', greeting = 'สวัสดี') {
  return `${greeting} ${name}`;
}

// Arrow function แบบสั้น (Implicit return) และการคืน Object ต้องครอบด้วยวงเล็บ
const isPass = (score) => score >= 50;
const makeResult = (score) => ({ score, grade: toGrade(score) });

console.log('--- ตัดเกรดด้วย for...of ---');
let index = 0;
let passCount = 0;
const validScores = [];
for (const score of scores) {
  index++;
  if (score < 0 || score > 100) {
    console.log(`คนที่ ${index}: ${score} -> ข้าม (คะแนนไม่ถูกต้อง)`);
    continue; // ข้ามไปรอบถัดไป
  }
  validScores.push(score);
  if (isPass(score)) {
    passCount++;
  }
  console.log(`คนที่ ${index}: ${score} -> ${toGrade(score)}`);
}
console.log(`สอบผ่าน ${passCount} จาก ${validScores.length} คน`);
console.log(`ค่าเฉลี่ย ${average(...validScores).toFixed(2)}`);
console.log('ค่าเฉลี่ยของ 10, 20 =', average(10, 20), '| ไม่มีข้อมูล =', average());

console.log('--- Ternary และ Logical operators ---');
const top = validScores[0];
console.log(top >= 90 ? 'ยอดเยี่ยม' : 'ดี');
console.log(top >= 80 && top <= 100, top < 50 || top > 100, !isPass(top));
console.log(makeResult(74));

console.log('--- switch ---');
function dayType(day) {
  switch (day) {
    case 'sat':
    case 'sun':
      return 'วันหยุด';
    case 'mon':
    case 'tue':
    case 'wed':
    case 'thu':
    case 'fri':
      return 'วันทำงาน';
    default:
      return 'ไม่รู้จักวันนี้';
  }
}
for (const day of ['sat', 'mon', 'xyz']) {
  console.log(day, '->', dayType(day));
}

console.log('--- while, for แบบนับ และ break ---');
let countdown = 3;
while (countdown > 0) {
  console.log('นับถอยหลัง', countdown);
  countdown--; // ถ้าลืมบรรทัดนี้ ลูปจะไม่มีวันจบ
}
for (let i = 0; i < scores.length; i++) {
  if (scores[i] < 60) {
    console.log(`พบคนแรกที่ได้ต่ำกว่า 60 คือคนที่ ${i + 1}`);
    break; // เจอแล้ว หยุดลูปทันที
  }
}
for (const ch of 'JS') {
  console.log('ตัวอักษร:', ch);
}

console.log('--- Default parameters ---');
console.log(greet());
console.log(greet('สมชาย'));
console.log(greet('somchai', 'Hello'));

HTML และ CSS ที่ต้องรู้ก่อนแตะ DOM: Semantic Tags, Form, Selector, Box Model และ Flexbox

คืออะไร ทำไมต้องใช้ และใช้เมื่อไร

JavaScript ในเบราว์เซอร์ทำงานกับหน้าเว็บที่สร้างจาก HTML (โครงสร้างและเนื้อหา) และตกแต่งด้วย CSS (หน้าตาและการจัดวาง) ถ้าไม่เข้าใจสองภาษานี้ จะเลือก Element ด้วย JavaScript ไม่ถูก และจะไม่รู้ว่าควรเปลี่ยน Class หรือเปลี่ยนข้อความ หลักสูตรนี้ไม่มีหัวข้อ HTML/CSS แยก จึงสอนส่วนที่จำเป็นตรงนี้ตั้งแต่ศูนย์

HTML ประกอบด้วย Tag ที่เปิดและปิด เช่น <p>ข้อความ</p> แต่ละ Tag พร้อมเนื้อหาข้างในเรียกว่า Element ซึ่งมี Attribute เพิ่มข้อมูลได้ เช่น <a href="..."> สิ่งที่ต้องรู้มีดังนี้

  • โครงไฟล์: <!DOCTYPE html>, <html lang="th">, <meta charset="UTF-8"> (ให้อ่านภาษาไทยถูก), <meta name="viewport"> (ให้แสดงผลบนมือถือถูกขนาด) และ <title>
  • Semantic tags: Tag ที่บอกความหมาย ได้แก่ header, nav, main, section, article และ footer ช่วยให้โปรแกรมอ่านหน้าจอ (Screen reader) และ Search engine เข้าใจหน้าเว็บ หัวข้อใช้ h1 ถึง h6 ตามลำดับโดยไม่ข้ามขั้น และรูปภาพต้องมี alt อธิบายภาพ
  • Form: <label for="email"> ต้องจับคู่กับ <input id="email"> เพื่อให้คลิกชื่อแล้วโฟกัสช่องได้ type มี text, email, number และ Attribute required, min, max ให้เบราว์เซอร์ตรวจค่าให้ ปุ่มส่งใช้ <button type="submit">

CSS เขียนเป็น selector { property: value; } Selector ที่ใช้บ่อยคือ Type (nav), Class (.card), ID (#contact), Descendant (nav a คือ a ที่อยู่ใน nav) และ Pseudo-class (:hover, :focus-visible) ถ้าหลายกฎชนกัน กฎที่ Specificity สูงกว่าชนะ (ID > Class > Type) ถ้าเท่ากันกฎที่อยู่ล่างกว่าชนะ แนวคิดสำคัญอีกสามเรื่อง

  • Box model: ทุก Element เป็นกล่องที่มี Content, Padding (ระยะด้านใน), Border (เส้นขอบ) และ Margin (ระยะด้านนอก) ค่าเริ่มต้น box-sizing: content-box นับ width เฉพาะ Content ส่วน border-box นับรวม Padding และ Border ทำให้คำนวณขนาดง่ายกว่า
  • display: block (เช่น div, p) ขึ้นบรรทัดใหม่และกว้างเต็มแถว inline (เช่น a, span) อยู่ในบรรทัดเดียวกับข้อความ
  • Flexbox: ใส่ display: flex ที่ แม่ (Flex container) แล้วลูกทุกตัวจะเรียงเป็นแถว ปรับด้วย gap, justify-content (แนวหลัก), align-items (แนวขวาง), flex-wrap และให้ลูกขยายเท่ากันด้วย flex: 1 เสริมด้วย Media query @media (max-width: 600px) เปลี่ยนการจัดวางบนจอเล็ก และ CSS Custom property (--brand) เก็บค่าที่ใช้ซ้ำ
เปรียบเทียบ

HTML คือโครงบ้านและห้องต่าง ๆ ที่ติดป้ายชื่อห้องชัดเจน (Semantic tags) CSS คือการทาสีและจัดเฟอร์นิเจอร์ Box model เหมือนกรอบรูป: รูปคือ Content, ช่องว่างขาวรอบรูปคือ Padding, กรอบไม้คือ Border และระยะห่างจากรูปอื่นบนผนังคือ Margin ส่วน border-box คือการสั่งช่างว่า "กรอบรูปทั้งชิ้นต้องกว้าง 200 มม." แทนที่จะบอกแค่ขนาดรูป

Array และ Array Methods: map, filter, reduce, find, some/every และกับดักของ sort

คืออะไร ทำไมต้องใช้ และใช้เมื่อไร

Array คือรายการของค่าที่เรียงลำดับ เขียนด้วย [ ] เหมือน list ใน Python ตำแหน่ง (Index) เริ่มที่ 0 ความยาวดูจาก .length (ไม่ใช่ len()) และเก็บค่าได้ทุกชนิดรวมถึง Object ข้อมูลจริงเกือบทุกอย่างในเว็บมาเป็น Array เช่น รายการสินค้า รายการคำถาม หรือผลลัพธ์จาก API

เมธอดพื้นฐานที่ต้องรู้คือ push/pop (เพิ่ม/เอาออกท้าย), unshift/shift (เพิ่ม/เอาออกหน้า), includes (มีค่านี้ไหม), indexOf (อยู่ตำแหน่งไหน ไม่เจอได้ -1), slice (ตัดสำเนาออกมา ไม่แก้ Array เดิม) และ splice (ตัดออก แก้ Array เดิม) จุดที่ต้องจำคือบางเมธอดแก้ Array เดิม (Mutating) และบางเมธอดคืน Array ใหม่

หัวใจของแนวคิดนี้คือ Higher-order function คือเมธอดที่รับฟังก์ชัน (Callback) เข้าไปเรียกกับทุกสมาชิก ทำให้ไม่ต้องเขียนลูปเอง

  • map(fn) แปลงทุกตัว ได้ Array ใหม่ความยาวเท่าเดิม (เหมือน List comprehension [f(x) for x in xs])
  • filter(fn) เก็บเฉพาะตัวที่ฟังก์ชันคืนค่าจริง
  • reduce(fn, ค่าเริ่มต้น) รวมทุกตัวให้เหลือค่าเดียว เช่น ยอดรวม
  • find(fn)/findIndex(fn) หาตัวแรกที่ตรงเงื่อนไข ไม่เจอได้ undefined/-1
  • some(fn) มีอย่างน้อยหนึ่งตัวที่จริงไหม every(fn) ทุกตัวจริงไหม
  • forEach(fn) วนทำงานกับทุกตัวแต่ ไม่คืนค่า และ join(', ') ต่อเป็น String
  • sort มีกับดักสองข้อ: ถ้าไม่ส่งฟังก์ชันเปรียบเทียบจะแปลงเป็น String ก่อนเรียง ([10, 9, 1, 100] จึงได้ [1, 10, 100, 9]) และแก้ Array เดิม ทางแก้คือใช้ (a, b) => a - b และใช้ toSorted() (มีใน Node 20 ขึ้นไป) หรือ [...arr].sort() เมื่อไม่อยากแก้ของเดิม ชื่อภาษาไทยเรียงด้วย localeCompare(b, 'th')
เปรียบเทียบ

Array เหมือนสายพานในร้านอาหาร map คือพนักงานที่ใส่ซอสให้ทุกจานที่ผ่านมา filter คือคนคัดเฉพาะจานที่สั่งเผ็ด reduce คือแคชเชียร์ที่รวมราคาทุกจานเป็นยอดเดียว โดยเริ่มนับจาก 0 บาท และ find คือคนที่หยิบจานแรกที่ตรงออเดอร์แล้วหยุดทันที ส่วน sort แบบไม่มีกฎเหมือนจัดเรียงตามตัวอักษรตัวแรกบนป้ายราคา ป้าย "100" จึงมาก่อน "9"

  { name: 'ขนมปังสังขยา', price: 35, qty: 3 },

tags.push('ของหวาน'); // เพิ่มท้าย

console.log('splice(1, 2) เอาออก', removed, '| nums กลายเป็น', nums);

const pricey = cart.filter((item) => item.price >= 40).map((item) => item.name);
console.log('ราคาตั้งแต่ 40 บาท:', pricey.join(', '));

console.log('--- find / findIndex / some / every ---');
const bulk = cart.find((item) => item.qty >= 3);
console.log('รายการแรกที่ซื้อ 3 ชิ้นขึ้นไป:', bulk);
console.log('ตำแหน่งของน้ำเปล่า:', cart.findIndex((item) => item.name === 'น้ำเปล่า'));
console.log('หาไม่เจอได้:', cart.find((item) => item.price > 1000));
console.log('มีรายการที่ qty เป็น 0 ไหม:', cart.some((item) => item.qty === 0));
console.log('ทุกรายการราคามากกว่า 0 ไหม:', cart.every((item) => item.price > 0));

console.log('--- forEach (ไม่คืนค่า) ---');
cart.forEach((item, i) => {
  console.log(`${i + 1}. ${item.name} x${item.qty}`);
});

console.log('--- sort และกับดัก ---');
// toSorted คืน Array ใหม่ ไม่แก้ cart เดิม
const byPriceDesc = cart.toSorted((a, b) => b.price - a.price);
console.log('เรียงราคามากไปน้อย:', byPriceDesc.map((item) => `${item.name} ${item.price}`).join(' | '));
console.log('cart เดิมยังเรียงเหมือนเดิม:', cart.map((item) => item.name).join(', '));

const numbers = [10, 9, 1, 100];
console.log('sort() เฉย ๆ:', [...numbers].sort());
console.log('sort((a, b) => a - b):', [...numbers].sort((a, b) => a - b));
const original = [3, 1, 2];
original.sort();
console.log('sort() แก้ Array เดิมด้วย:', original);

const names = ['สมชาย', 'กมล', 'วิภา', 'ณัฐ', 'ขวัญใจ'];
console.log('เรียงชื่อไทย:', names.toSorted((a, b) => a.localeCompare(b, 'th')).join(', '));

some, everyตอบคำถามแบบใช่/ไม่ใช่กับทั้ง Array ใช้ตรวจความถูกต้องของข้อมูล

cart.toSorted((a, b) => b.price - a.price)ฟังก์ชันเปรียบเทียบคืนค่าลบ ศูนย์ หรือบวก b - a เรียงจากมากไปน้อย และ toSorted คืน Array ใหม่ cart จึงเรียงเหมือนเดิม

Object, Destructuring, Spread, Optional Chaining (?.) และ Nullish Coalescing (??)

คืออะไร ทำไมต้องใช้ และใช้เมื่อไร

Object คือกลุ่มของคู่ key: value ที่อยู่ใน { } คล้าย dict ใน Python แต่เขียน key ได้โดยไม่ต้องมีเครื่องหมายคำพูด อ่านค่าได้สองแบบ คือ Dot (user.name) และ Bracket (user['name'] หรือ user[key] เมื่อชื่อ key อยู่ในตัวแปร) เพิ่ม key ด้วยการกำหนดค่า ลบด้วย delete และตรวจว่ามี key ไหมด้วย 'key' in obj ฟังก์ชันที่อยู่ใน Object เรียกว่า Method ส่วน Object.keys, Object.values, Object.entries และ Object.fromEntries แปลง Object เป็น Array และกลับ ข้อมูล JSON จาก API ทุกตัวกลายเป็น Object เมื่ออ่านเข้ามา แนวคิดนี้จึงใช้ทุกวัน

ไวยากรณ์สมัยใหม่ (ES2015 ขึ้นไป) ที่ทำให้โค้ดสั้นและปลอดภัยขึ้น

  • Destructuring: ดึงค่าออกจาก Object หรือ Array มาเป็นตัวแปรในบรรทัดเดียว const { name, age } = user; ตั้งค่าเริ่มต้น (phone = 'ไม่ระบุ') และเปลี่ยนชื่อ (username: login) ได้ และใช้ใน Parameter ของฟังก์ชันได้
  • Spread (...): กระจาย Object หรือ Array ออก ใช้รวมค่า { ...defaults, ...settings } โดย key ที่มาทีหลังชนะ และใช้ทำสำเนาชั้นเดียว (Shallow copy)
  • Optional chaining (?.): ถ้าค่าทางซ้ายเป็น null หรือ undefined จะหยุดแล้วคืน undefined แทนที่จะเกิด Error ใช้ได้กับ obj?.a, arr?.[0] และ fn?.()
  • Nullish coalescing (??): ใช้ค่าทางขวาเฉพาะเมื่อทางซ้ายเป็น null หรือ undefined ต่างจาก || ที่ใช้ค่าทางขวาเมื่อทางซ้ายเป็น Falsy ใด ๆ ทำให้ 0 และ '' ที่เป็นค่าที่ถูกต้องหายไป

เรื่องที่ต้องเข้าใจให้ลึกคือ Reference: ตัวแปรที่เก็บ Object เก็บแค่ "ที่อยู่" ของ Object การเขียน const b = a จึงได้ Object ตัวเดียวกัน และ Spread คัดลอกแค่ชั้นนอก Object ที่ซ้อนอยู่ข้างในยังใช้ร่วมกัน ถ้าต้องการสำเนาทุกชั้น (Deep copy) ให้ใช้ structuredClone() ส่วน JSON.stringify(obj, null, 2) แปลง Object เป็นข้อความ JSON แบบย่อหน้า และ JSON.parse แปลงกลับ (จะใช้มากในแนวคิดที่ 10)

เปรียบเทียบ

Object เหมือนบัตรประจำตัวที่มีช่องชื่อ อายุ ที่อยู่ Destructuring เหมือนการคัดลอกเฉพาะช่องที่ต้องใช้ลงกระดาษโน้ต Reference เหมือนการให้เพื่อนถือกุญแจบ้านหลังเดียวกัน ใครย้ายเฟอร์นิเจอร์ อีกคนก็เห็น ส่วน Shallow copy เหมือนสร้างบ้านใหม่แต่ยังใช้โกดังเก็บของหลังเดิมร่วมกัน structuredClone คือสร้างทั้งบ้านและโกดังใหม่หมด ส่วน ?? เหมือนพนักงานที่ถามว่า "ลูกค้ากรอกช่องนี้หรือยัง" ถ้ากรอกเลข 0 ก็ถือว่ากรอกแล้ว แต่ || เข้าใจผิดว่า 0 คือไม่ได้กรอก

เมื่อโปรแกรมยาวขึ้น การเขียนทุกอย่างไว้ในไฟล์เดียวจะอ่านยากและแก้ยาก Module คือไฟล์ JavaScript หนึ่งไฟล์ที่มีขอบเขตตัวแปรของตัวเอง และเลือกส่งออก (export) เฉพาะสิ่งที่ไฟล์อื่นควรใช้ ไฟล์อื่นนำเข้าด้วย import เหมือน from price import with_vat ใน Python มาตรฐานนี้เรียกว่า ES Modules (ESM) ใช้ได้ทั้งในเบราว์เซอร์และ Node.js

  • Named export (export const VAT_RATE, export function withVat) มีได้หลายตัวต่อไฟล์ นำเข้าด้วยชื่อที่ตรงกันในปีกกา import { withVat } from ... เปลี่ยนชื่อได้ด้วย as
  • Default export (export default function formatBaht) มีได้ตัวเดียว นำเข้าโดยไม่มีปีกกาและตั้งชื่ออะไรก็ได้ และ import * as price นำเข้าทุกอย่างเป็น Namespace object
  • กฎของ Node.js: ต้องมี "type": "module" ใน package.json (npm 11 สร้างไฟล์ด้วย "type": "commonjs" จึงต้องรัน npm pkg set type=module) Path ของไฟล์เราเองต้องขึ้นต้นด้วย ./ หรือ ../ และต้องมีนามสกุล .js ครบ ใช้ await ที่ระดับบนสุดของไฟล์ได้ (Top-level await) และโมดูลในตัวของ Node.js ขึ้นต้นด้วย node: เช่น node:fs/promises
  • กฎของเบราว์เซอร์: โหลดด้วย <script type="module" src="main.js"> ต้องเปิดผ่าน http:// เท่านั้น (เปิดแบบ file:// จะถูกบล็อกด้วย CORS) สคริปต์แบบ Module รันหลัง HTML โหลดเสร็จ (Deferred) และอยู่ใน Strict mode อัตโนมัติ
  • CommonJS คือระบบเก่าของ Node.js ที่ใช้ require() และ module.exports คุณจะเห็นในบทความและโปรเจกต์เก่า ให้อ่านออก แต่โค้ดใหม่ในหลักสูตรนี้ใช้ ESM เสมอ

npm (Node Package Manager) คือเครื่องมือติดตั้งแพ็กเกจที่คนอื่นเขียนไว้ และจัดการไฟล์ package.json ซึ่งเก็บชื่อโปรเจกต์ scripts (คำสั่งลัดที่รันด้วย npm start หรือ npm test) และ dependencies (แพ็กเกจที่โปรแกรมต้องใช้ตอนรัน) แพ็กเกจที่ใช้แค่ตอนพัฒนา เช่น ESLint ให้ติดตั้งด้วย npm install --save-dev ซึ่งจะไปอยู่ใน devDependencies เลข ^1.11.23 หมายถึงยอมรับรุ่น 1.x.x ที่ใหม่กว่าหรือเท่ากับ 1.11.23 (ตามหลัก Semantic Versioning: MAJOR.MINOR.PATCH) ไฟล์ package-lock.json บันทึกรุ่นที่ติดตั้งจริงทุกตัว ต้อง Commit เข้า Git ส่วนโฟลเดอร์ node_modules ห้าม Commit เพราะสร้างใหม่ได้ด้วย npm ci (ติดตั้งตาม Lock file เป๊ะ ใช้บน CI และเครื่องเพื่อนร่วมทีม)

เปรียบเทียบ

Module เหมือนแผนกในบริษัท แต่ละแผนกทำงานภายในของตัวเอง และเปิดเคาน์เตอร์บริการ (export) ให้แผนกอื่นมาขอใช้ (import) Default export คือบริการหลักของแผนก ส่วน Named export คือบริการเสริมที่ต้องเรียกชื่อให้ถูก npm เหมือนร้านขายอะไหล่ package.json คือใบสั่งของ และ package-lock.json คือใบเสร็จที่ระบุรุ่นและล็อตของอะไหล่ทุกชิ้น เพื่อให้อู่อื่นสั่งของได้ตรงกันทุกชิ้น

Security

แพ็กเกจจาก npm คือโค้ดของคนอื่นที่รันบนเครื่องคุณด้วยสิทธิ์ของคุณ ก่อนติดตั้งให้ตรวจชื่อให้ถูกทุกตัวอักษร เพราะมีแพ็กเกจปลอมที่ตั้งชื่อคล้ายของจริง (Typosquatting) เช่น สะกดผิดหนึ่งตัว ดูจำนวนดาวน์โหลดและ Repository ต้นทางบน npmjs.com ระวัง npx ชื่อแพ็กเกจ ซึ่งดาวน์โหลดแล้วรันทันที และรัน npm audit เป็นประจำเพื่อดูช่องโหว่ที่รู้จักแล้ว

Best Practice
  • Commit package.json และ package-lock.json ทุกครั้ง ใส่ node_modules/ ใน .gitignore และใช้ npm ci บนเครื่อง CI
  • เลือกใช้ Named export เป็นหลัก เพราะชื่อตรงกันทุกไฟล์ ค้นหาและ Refactor ง่าย ใช้ Default export เมื่อไฟล์มีสิ่งหลักเพียงอย่างเดียว
  • เพิ่มแพ็กเกจเมื่อจำเป็นจริง แต่ละแพ็กเกจคือภาระด้านความปลอดภัยและการอัปเดต ถ้าเขียนเองได้ใน 10 บรรทัด ให้เขียนเอง
  • รวมคำสั่งที่ใช้บ่อยไว้ใน scripts (start, test, lint) เพื่อให้คนในทีมรันได้เหมือนกัน

  • เลือก: document.querySelector('#id') คืน Element แรกที่ตรงกับ CSS Selector หรือ null ถ้าไม่เจอ querySelectorAll('li') คืน NodeList ที่ใช้ forEach ได้แต่ไม่มี map (แปลงด้วย Array.from) และ getElementById('id') รับชื่อ id โดยไม่มี #
  • แก้ข้อความ: textContent ใส่ข้อความล้วน ปลอดภัยเสมอ ส่วน innerHTML แปลงข้อความเป็น HTML จึงอันตรายถ้าข้อความมาจากผู้ใช้ เพราะเปิดช่องให้โจมตีแบบ XSS (Cross-site scripting) คือการฝังสคริปต์ให้รันในเบราว์เซอร์ของคนอื่น
  • Attribute และ Class: setAttribute/getAttribute, dataset อ่านเขียน data-* และ classList.add/remove/toggle/contains เปลี่ยนหน้าตาด้วยการสลับ Class ที่กำหนดไว้ใน CSS ดีกว่าแก้ element.style ทีละค่า
  • สร้างและลบ: document.createElement('li'), append/prepend, remove(), replaceChildren() (แทนที่ลูกทั้งหมด) และ DocumentFragment (ภาชนะชั่วคราว ประกอบหลาย Element ก่อนใส่ลงหน้าในครั้งเดียว)

รูปแบบที่ใช้ในงานจริงคือ Render from data: เก็บข้อมูลไว้ใน Array (State) เมื่อข้อมูลเปลี่ยนให้เรียก render() สร้างรายการใหม่ทั้งหมดจากข้อมูล แทนที่จะไล่แก้ Element ทีละจุด วิธีนี้ทำให้หน้าจอตรงกับข้อมูลเสมอ และเป็นแนวคิดเดียวกับที่ Mini Project ใน Part 4 ใช้

const topics = [
  { id: 1, title: 'HTML', done: true },
  { id: 2, title: 'CSS', done: true },
  { id: 3, title: 'DOM', done: false },
  { id: 4, title: 'Fetch', done: false },

// เลือก Element ด้วย CSS Selector (ต้องมี # สำหรับ id)
const list = document.querySelector('#topic-list');
const summary = document.getElementById('summary'); // getElementById ไม่ต้องมี #

// render(): สร้างรายการใหม่ทั้งหมดจากข้อมูลทุกครั้ง
function render() {
  const fragment = document.createDocumentFragment();
  for (const topic of topics) {
    const li = document.createElement('li');
    li.textContent = topic.title; // ใส่ข้อความอย่างปลอดภัย
    li.dataset.id = topic.id; // ได้ attribute data-id="1"
    li.classList.toggle('done', topic.done); // ใส่หรือเอา class ออกตามค่าจริง/เท็จ
    fragment.append(li);
  }
  list.replaceChildren(fragment); // แทนที่ลูกเดิมทั้งหมดในครั้งเดียว
  const doneCount = topics.filter((t) => t.done).length;
  summary.textContent = `เรียนแล้ว ${doneCount} จาก ${topics.length} หัวข้อ`;
}

render();

Best Practice
  • แยกข้อมูล (State) ออกจากการแสดงผล และสร้างหน้าจอจากข้อมูลด้วยฟังก์ชัน render() ฟังก์ชันเดียว

  • เปลี่ยนหน้าตาด้วย classList แทน element.style เพื่อให้ CSS อยู่ในไฟล์ CSS ที่เดียว
  • ใช้ textContent เป็นค่าเริ่มต้น และใช้ innerHTML เฉพาะกับ HTML ที่เขียนเองทั้งหมดและไม่มีข้อมูลภายนอกปน

Events, Event Delegation และ Forms: addEventListener, preventDefault, FormData และ Validation

คืออะไร ทำไมต้องใช้ และใช้เมื่อไร

Event คือ "สิ่งที่เกิดขึ้นบนหน้าเว็บ" เช่น ผู้ใช้คลิกปุ่ม (click) พิมพ์ในช่องกรอก (input) กดส่งฟอร์ม (submit) หรือกดแป้นพิมพ์ (keydown) เราสั่งให้ JavaScript "รอฟัง" Event เหล่านี้ด้วย element.addEventListener('ชื่อ Event', ฟังก์ชัน) ฟังก์ชันที่ส่งเข้าไปเรียกว่า Event listener หรือ Handler เบราว์เซอร์จะเรียกฟังก์ชันนี้ให้เองเมื่อ Event เกิดขึ้น และส่ง Event object มาเป็นพารามิเตอร์ตัวแรก ในนั้นมีข้อมูลสำคัญ เช่น event.target (Element ที่ถูกกดจริงๆ) event.currentTarget (Element ที่เราติด listener ไว้) และ event.key (แป้นที่กด)

Event ส่วนใหญ่ Bubbling คือเกิดที่ Element ลูกแล้ว "ลอยขึ้น" ไปหาแม่ ปู่ จนถึง document เราใช้คุณสมบัตินี้ทำ Event delegation คือติด listener ไว้ที่แม่ตัวเดียว แล้วใช้ event.target.closest('button') หาว่าคลิกโดนปุ่มไหน วิธีนี้ใช้ listener ตัวเดียวแทนหลายสิบตัว และปุ่มที่สร้างเพิ่มทีหลัง (เช่น หลัง render ใหม่) ก็ทำงานได้ทันที

ส่วน Form เป็นที่ที่ Event สำคัญที่สุด เพราะเมื่อกด submit เบราว์เซอร์จะส่งข้อมูลและ รีโหลดหน้า ตามค่าเริ่มต้น ถ้าเราจะจัดการข้อมูลเองด้วย JavaScript ต้องเรียก event.preventDefault() แล้วอ่านค่าทั้งฟอร์มด้วย new FormData(form) นอกจากนี้ HTML มี Constraint validation ในตัว เช่น required, type="email", minlength, min, pattern ซึ่ง JavaScript ตรวจได้ด้วย form.checkValidity() และ input.validity

  • ใช้เมื่อ: ทุกครั้งที่หน้าเว็บต้องตอบสนองผู้ใช้ เช่น ปุ่มตอบคำถามใน Quiz App ฟอร์มสมัครสมาชิก ช่องค้นหาที่กรองผลทันทีที่พิมพ์ และคีย์ลัด
  • ใช้ delegation เมื่อ: มีรายการหลายชิ้นที่ทำงานเหมือนกัน หรือรายการถูกสร้างใหม่บ่อย
  • ตรวจฟอร์มสองชั้นเสมอ: ฝั่งเบราว์เซอร์เพื่อให้ผู้ใช้รู้ผลเร็ว และฝั่ง Server เพื่อความปลอดภัย เพราะผู้ใช้ปิด JavaScript หรือส่ง Request ตรงได้
เปรียบเทียบ

Event delegation เหมือน พนักงานต้อนรับที่ล็อบบี้คอนโด แทนที่จะจ้างยามเฝ้าหน้าห้องทุกห้อง (ติด listener ทุกปุ่ม) เราให้คนเดียวยืนที่ล็อบบี้ ใครมาก็ต้องผ่านล็อบบี้ (Bubbling) แล้วพนักงานดูป้ายชื่อว่ามาหาห้องไหน (closest('button') และ dataset.index) เมื่อมีห้องใหม่สร้างเพิ่ม ก็ไม่ต้องจ้างยามเพิ่ม ส่วน preventDefault() เหมือนบอกบุรุษไปรษณีย์ว่า "ไม่ต้องส่งจดหมายฉบับนี้ไปที่อื่น เดี๋ยวผมจัดการเอง"

// ข้อความภาษาไทยสำหรับแต่ละช่อง ตามชนิดของปัญหา
function thaiMessage(input) {
  const v = input.validity;
  if (v.valueMissing) return 'กรุณากรอกช่องนี้';
  if (v.typeMismatch) return 'รูปแบบอีเมลไม่ถูกต้อง';
  if (v.tooShort) return `ต้องยาวอย่างน้อย ${input.minLength} ตัวอักษร`;
  if (v.rangeUnderflow) return `ต้องไม่น้อยกว่า ${input.min}`;
  if (v.patternMismatch) return 'ใช้ได้เฉพาะ a-z, 0-9 และ _';
  return '';
}

// submit: ฟังที่ form ไม่ใช่ที่ปุ่ม เพื่อให้กด Enter ก็ทำงาน
form.addEventListener('submit', (event) => {
  event.preventDefault(); // ไม่ให้เบราว์เซอร์ส่งฟอร์มและรีโหลดหน้า
  const errors = [];
  for (const input of form.querySelectorAll('input')) {
    const text = thaiMessage(input);
    input.setAttribute('aria-invalid', String(text !== ''));
    if (text) errors.push(`${input.labels[0].textContent}: ${text}`);
  }
  if (!form.checkValidity()) {
    message.textContent = errors.join(' / ');
    console.log(`ฟอร์มไม่ผ่าน ${errors.length} ช่อง`);
    form.querySelector('[aria-invalid="true"]').focus(); // พาไปช่องแรกที่ผิด

  data.age = Number(data.age);
  console.log('ส่งข้อมูล:', JSON.stringify({ ...data, password: '********' }));

  console.log(message.textContent);
});

function selectChoice(button) {
  for (const b of choices.querySelectorAll('button')) {
    b.classList.toggle('selected', b === button);
  }
  const label = button.textContent.replace(/^\d\.\s*/, '');
  console.log(`เลือกตัวเลือกที่ ${button.dataset.index}: ${label}`);
}

choices.addEventListener('click', (event) => {
  console.log('target:', event.target.tagName, '| currentTarget:', event.currentTarget.id);
  const button = event.target.closest('button'); // คลิกโดน span ก็หาปุ่มที่ครอบอยู่
  if (!button || !choices.contains(button)) return;
  selectChoice(button);
});

  if (button) {
    console.log('กดปุ่ม', event.key);
    selectChoice(button);
  }

Best Practice
  • ใช้ Element ที่ถูกความหมาย: ปุ่มคือ <button> ลิงก์คือ <a> จะได้รองรับคีย์บอร์ดและโปรแกรมอ่านหน้าจอฟรี
  • ฟัง submit ที่ form เสมอ และตรวจข้อมูลซ้ำที่ Server ทุกครั้ง การตรวจในเบราว์เซอร์เป็นแค่ความสะดวกของผู้ใช้
  • ใช้ Event delegation กับรายการที่ render ใหม่บ่อย และใช้ closest() คู่กับ contains() เพื่อให้แน่ใจว่าเป็นปุ่มของเรา
  • ข้อความผิดพลาดต้องบอกวิธีแก้ (เช่น "ต้องยาวอย่างน้อย 8 ตัวอักษร") ไม่ใช่แค่ "ผิด" และไม่ใช้สีแดงเป็นสัญญาณเดียว

Scope, Closures, Hoisting, this และ Classes

คืออะไร ทำไมต้องใช้ และใช้เมื่อไร

Scope คือ "ขอบเขตที่ตัวแปรมองเห็นได้" JavaScript มี 3 ระดับหลัก: Global scope (ทั้งไฟล์ หรือทั้งหน้า) Function scope (ภายในฟังก์ชัน) และ Block scope (ภายใน { } ของ if, for ซึ่ง let และ const เคารพ แต่ var ไม่เคารพ) JavaScript ใช้ Lexical scope แปลว่าฟังก์ชันมองเห็นตัวแปรตาม "ตำแหน่งที่เขียนโค้ด" ไม่ใช่ตามตำแหน่งที่ถูกเรียก

Closure เกิดเมื่อฟังก์ชันด้านในยัง "จำ" ตัวแปรของฟังก์ชันด้านนอกได้ แม้ฟังก์ชันด้านนอกทำงานจบไปแล้ว เราใช้ Closure สร้างสถานะส่วนตัว (Private state) เช่น ตัวนับที่คนข้างนอกแก้ตรงๆ ไม่ได้ และฟังก์ชันอย่าง once() ที่ยอมให้ทำงานครั้งเดียว ทุก Event listener และ Callback ที่อ้างถึงตัวแปรข้างนอกก็คือ Closure ทั้งหมด

Hoisting คือพฤติกรรมที่ JavaScript "รู้จัก" การประกาศก่อนรันโค้ดบรรทัดแรก: Function declaration ถูกยกขึ้นไปทั้งตัว (เรียกก่อนประกาศได้) var ถูกยกขึ้นไปพร้อมค่า undefined ส่วน let, const และ class ถูกยกขึ้นไปแต่อยู่ใน TDZ (Temporal Dead Zone) ถ้าแตะก่อนถึงบรรทัดที่ประกาศจะได้ ReferenceError ทันที ซึ่งดีกว่าเงียบแล้วได้ undefined

this คือ "Object ที่เรียกฟังก์ชันนี้" ค่าของมันขึ้นกับ วิธีเรียก ไม่ใช่ที่เขียน: account.deposit(100) ทำให้ this เป็น account แต่ถ้าดึงเมธอดออกไปเรียกเฉยๆ หรือส่งไปเป็น Callback this จะเป็น undefined (ใน ES Module ซึ่งเป็น strict mode เสมอ) Arrow function ไม่มี this ของตัวเอง มันใช้ this ของที่ที่มันถูกเขียน สุดท้าย Class คือไวยากรณ์สำหรับสร้าง Object หลายตัวที่มีโครงสร้างและเมธอดเหมือนกัน มี constructor, เมธอด, getter, static, Private field (#balance) และการสืบทอดด้วย extends/super เบื้องหลังมันทำงานด้วย Prototype ของ JavaScript (เมธอดเก็บไว้ที่ BankAccount.prototype และทุก Object ที่สร้างจากคลาสใช้ร่วมกัน)

  • ใช้ Closure เมื่อ: ต้องการซ่อนข้อมูล สร้างฟังก์ชันจากโรงงาน (Factory) หรือจำค่าระหว่างการเรียกหลายครั้ง
  • ใช้ Class เมื่อ: มี Object หลายตัวที่มีข้อมูลและพฤติกรรมเดียวกัน เช่น บัญชีธนาคาร ผู้เล่นในเกม หรือ Error ชนิดใหม่ (แนวคิดที่ 10)
  • ต้องเข้าใจ this เมื่อ: ส่งเมธอดไปเป็น Callback เช่น addEventListener, setTimeout, forEach
เปรียบเทียบ

Closure เหมือนเป้ที่ฟังก์ชันสะพายติดตัวไปตลอด ในเป้มีตัวแปรจากบ้านเกิด (ฟังก์ชันด้านนอก) แม้จะเดินออกจากบ้านไปแล้วก็ยังหยิบของในเป้ได้ และคนอื่นเปิดเป้ไม่ได้ ส่วน this เหมือนคำว่า "ฉัน" ในประโยค "ฉันฝากเงิน 100 บาท" ความหมายเปลี่ยนตามว่า ใคร เป็นคนพูด ถ้าเอาประโยคนี้ไปให้คนอื่นอ่านโดยไม่บอกว่าใครพูด (ส่งเมธอดไปเป็น Callback) ก็ไม่รู้ว่าเงินเข้าบัญชีใคร bind(account) คือการเขียนชื่อเจ้าของกำกับไว้

class BankAccount {
  #balance; // private field: ใช้ได้เฉพาะในคลาสนี้

  constructor(owner, balance = 0) {
    this.owner = owner;
    this.#balance = balance;
  }

  deposit(amount) {
    this.#balance += amount;
    return this.#balance;
  }

  withdraw(amount) {
    if (amount > this.#balance) {
      throw new RangeError('ยอดเงินไม่พอ');
    }
    this.#balance -= amount;
    return this.#balance;
  }

  get balance() {
    return this.#balance;
  }

  static fromJSON(json) {
    const data = JSON.parse(json);
    return new BankAccount(data.owner, data.balance);
  }
}

class SavingsAccount extends BankAccount {
  constructor(owner, balance, rate) {
    super(owner, balance); // ต้องเรียก super() ก่อนใช้ this
    this.rate = rate;
  }

  addInterest() {
    const interest = this.balance * this.rate;
    return this.deposit(interest);
  }
}

Error Handling, JSON และ localStorage: try/catch/finally, Error Types, Custom Error และการบันทึกข้อมูลในเบราว์เซอร์

คืออะไร ทำไมต้องใช้ และใช้เมื่อไร

โปรแกรมจริงเจอสิ่งที่ไม่คาดคิดเสมอ: ผู้ใช้กรอกอายุเป็น "abc" ไฟล์ JSON เสีย หรือเบราว์เซอร์ไม่ยอมให้บันทึกข้อมูล Error handling คือการวางแผนรับมือเรื่องเหล่านี้ เมื่อเจอปัญหา เราใช้ throw โยน Error object ออกไป แล้วโค้ดที่เรียกใช้จับไว้ด้วย try { ... } catch (error) { ... } ส่วน finally { ... } ทำงานทุกครั้งไม่ว่าจะสำเร็จหรือล้ม เหมาะกับงานเก็บกวาด เช่น ปิดสถานะ "กำลังโหลด"

JavaScript มี Error ในตัวหลายชนิด แต่ละชนิดบอกประเภทปัญหา: TypeError (ใช้ค่าผิดชนิด เช่น อ่าน property ของ null) RangeError (ค่าอยู่นอกช่วง) SyntaxError (เช่น JSON ผิดรูปแบบ) และ ReferenceError (ใช้ตัวแปรที่ไม่มีอยู่) ทุกตัวมี error.name, error.message และ error.stack (เส้นทางการเรียกฟังก์ชันที่นำไปสู่ Error) เราสร้าง Custom Error ได้ด้วย class ValidationError extends Error เพื่อแยกปัญหาที่ "คาดไว้แล้ว" (ผู้ใช้กรอกผิด) ออกจากบั๊กจริง และใช้ new Error('ข้อความ', { cause: errorเดิม }) ห่อ Error เดิมไว้โดยรายละเอียดไม่หาย

JSON (JavaScript Object Notation) คือรูปแบบข้อความสำหรับเก็บและส่งข้อมูล JSON.stringify(obj) แปลง Object เป็น String และ JSON.parse(text) แปลงกลับ ส่วน localStorage คือที่เก็บข้อมูลในเบราว์เซอร์แบบ key-value ที่อยู่ถาวรแม้ปิดเบราว์เซอร์ (แยกตาม Origin เช่น http://127.0.0.1:8000) มันเก็บได้ เฉพาะ String เราจึงใช้คู่กับ JSON เสมอ และต้องห่อด้วย try/catch เพราะข้อมูลอาจเสีย พื้นที่อาจเต็ม (ปกติประมาณ 5 MB ต่อ Origin ขึ้นกับเบราว์เซอร์) หรือเบราว์เซอร์บางโหมดอาจบล็อก

  • Fail fast (ล้มทันที): เมื่อข้อมูลผิดจนทำงานต่อไม่ได้ เช่น อายุติดลบ ให้ throw ทันทีพร้อมข้อความชัดเจน
  • Graceful fallback (ถอยไปใช้ค่าสำรอง): เมื่อทำงานต่อได้ เช่น การตั้งค่าที่บันทึกไว้เสีย ให้ใช้ค่าเริ่มต้นแทนและแจ้งเตือน
  • ห้ามกลืน Error เงียบๆ: catch {} ที่ว่างเปล่าทำให้บั๊กหายไปจากสายตา แต่ยังอยู่ในโปรแกรม
  • ใช้ localStorage เมื่อ: เก็บค่าที่ไม่ลับและเสียได้ไม่เป็นไร เช่น ธีม ขนาดตัวอักษร คะแนนสูงสุดของ Quiz App
เปรียบเทียบ

try/catch เหมือน ตาข่ายใต้นักกายกรรม นักกายกรรม (โค้ดใน try) แสดงตามปกติ ถ้าพลาดตก ตาข่าย (catch) รับไว้ไม่ให้ทั้งโชว์พัง ส่วน finally คือทีมงานที่เก็บอุปกรณ์หลังโชว์ทุกครั้งไม่ว่าจะสำเร็จหรือพลาด และ localStorage เหมือน ล็อกเกอร์หน้าห้าง ใส่ได้เฉพาะของที่พับเป็นแผ่น (String) ถ้าจะเก็บกล่อง (Object) ต้องพับด้วย JSON.stringify ก่อน และเวลาเปิดออกมาต้องระวังว่าของข้างในอาจเสียหายแล้ว

// Custom Error: สืบทอดจาก Error แล้วตั้งชื่อของตัวเอง
class ValidationError extends Error {
  constructor(message, options) {
    super(message, options); // options ใช้ส่ง { cause } ต่อได้
    this.name = 'ValidationError';
  }
}

function parseAge(input) {
  if (typeof input !== 'string' || input.trim() === '') {
    throw new ValidationError('กรุณากรอกอายุ');
  }
  const age = Number(input);
  if (!Number.isInteger(age)) {
    throw new ValidationError(`"${input}" ไม่ใช่จำนวนเต็ม`);
  }
  if (age < 0 || age > 150) {
    throw new ValidationError(`อายุ ${age} อยู่นอกช่วง 0-150`);
  }
  return age;
}

console.log('=== parseAge ===');
let checked = 0;
for (const input of ['28', '', 'abc', '-5', '200']) {
  try {
    const age = parseAge(input);
    console.log(`"${input}" -> ผ่าน ได้ ${age}`);
  } catch (error) {
    if (error instanceof ValidationError) {
      console.log(`"${input}" -> ${error.name}: ${error.message}`);
    } else {
      throw error; // Error ที่เราไม่รู้จัก ห้ามกลืน โยนต่อไป
    }
  } finally {
    checked += 1; // finally ทำงานทุกครั้ง ไม่ว่าจะสำเร็จหรือ error
  }
}

// storage-demo.js — บันทึกและโหลดข้อมูลจาก localStorage อย่างปลอดภัย
const DEFAULTS = { theme: 'light', fontSize: 16, lastVisit: null };

// รับ storage เป็นพารามิเตอร์ เพื่อให้ทดสอบด้วย storage ปลอมได้
export function createStore(storage, key) {
  return {
    save(data) {
      try {
        storage.setItem(key, JSON.stringify(data)); // ต้องแปลงเป็น String ก่อนเสมอ
        return true;
      } catch (error) {
        // เช่น พื้นที่เต็ม (QuotaExceededError) หรือเบราว์เซอร์บล็อก storage
        console.warn('บันทึกไม่สำเร็จ:', error.name);
        return false;
      }
    },
    load() {
      let text;
      try {
        text = storage.getItem(key);
      } catch (error) {
        console.warn('อ่าน storage ไม่ได้:', error.name);
        return { ...DEFAULTS };
      }
      if (text === null) return { ...DEFAULTS }; // ยังไม่เคยบันทึก
      try {
        return { ...DEFAULTS, ...JSON.parse(text) };
      } catch (error) {
        console.warn(`ข้อมูลเสีย ใช้ค่าเริ่มต้นแทน (${error.message})`);
        return { ...DEFAULTS };
      }
    },
    clear() {
      storage.removeItem(key);
    },
  };
}

Asynchronous JavaScript: Callback, Promise, async/await, fetch และ Event Loop

คืออะไร ทำไมต้องใช้ และใช้เมื่อไร

JavaScript ทำงานบน Thread เดียว คือทำโค้ดได้ทีละบรรทัด ถ้าการโหลดข้อมูลจาก Server ที่ใช้เวลา 2 วินาทีทำให้ทุกอย่างหยุดรอ หน้าเว็บจะค้างกดอะไรไม่ได้เลย ทางแก้คือ Asynchronous (async): เราสั่งงานที่ต้องรอ (Network, Timer, อ่านไฟล์) ให้เบราว์เซอร์หรือ Node ไปทำเบื้องหลัง แล้วบอกว่า "เสร็จเมื่อไรค่อยเรียกโค้ดนี้" ระหว่างรอ JavaScript ทำงานอื่นต่อได้ แบบนี้เรียกว่า Non-blocking I/O

วิธีบอก "เสร็จแล้วทำต่อ" พัฒนามา 3 รุ่น: (1) Callback ส่งฟังก์ชันไปให้เรียกทีหลัง เช่น setTimeout(fn, 1000) แต่ถ้าต้องทำต่อกันหลายขั้นจะซ้อนกันลึกจนอ่านยาก เรียกว่า Callback hell (2) Promise คือ Object ที่แทน "ผลลัพธ์ในอนาคต" มี 3 สถานะ: pending (รออยู่), fulfilled (สำเร็จ ได้ค่า) และ rejected (ล้มเหลว ได้ Error) ต่อด้วย .then(), .catch(), .finally() (3) async/await ไวยากรณ์ที่ทำให้โค้ด Promise อ่านเหมือนโค้ดธรรมดา await หยุดรอเฉพาะในฟังก์ชันนั้น และใช้ try/catch จับ Error ได้ตามปกติ

เบื้องหลังคือ Event loop: โค้ดปกติทำบน Call stack จนหมดก่อน จากนั้น Event loop ดึงงานจาก Microtask queue (งานต่อจาก Promise, await, queueMicrotask) ให้หมดทุกตัว แล้วจึงหยิบงานหนึ่งชิ้นจาก Macrotask queue (เช่น setTimeout, Event จากผู้ใช้) ด้วยเหตุนี้ Promise.then จึงทำก่อน setTimeout(fn, 0) เสมอ สุดท้าย fetch คือฟังก์ชันเรียก HTTP ที่คืน Promise มีทั้งในเบราว์เซอร์และใน Node 18 ขึ้นไป (Node 24 ที่หลักสูตรใช้มีในตัว)

  • ใช้ async/await เมื่อ: โหลดข้อมูลจาก API หรือไฟล์ JSON (เช่น data/questions.json ของ Quiz App) อ่านเขียนไฟล์ใน Node และรอเวลา
  • ใช้ Promise.all เมื่อ: งานหลายชิ้นไม่ขึ้นต่อกัน ให้เริ่มพร้อมกันเพื่อประหยัดเวลา และต้องการให้ล้มทั้งหมดถ้าตัวใดล้ม
  • ใช้ Promise.allSettled เมื่อ: อยากได้ผลของทุกตัว ทั้งที่สำเร็จและล้มเหลว
  • ใช้ Promise.race / Promise.any เมื่อ: ต้องการผลของตัวที่เสร็จก่อน (race) หรือตัวแรกที่สำเร็จ (any) เช่น เลือก Server สำรองที่ตอบเร็วที่สุด
เปรียบเทียบ

Promise เหมือน บัตรคิวร้านก๋วยเตี๋ยว สั่งแล้วได้บัตร (Promise สถานะ pending) ไม่ต้องยืนจ้องหม้อ ไปนั่งเล่นมือถือได้ (Non-blocking) เมื่ออาหารเสร็จ (fulfilled) หรือวัตถุดิบหมด (rejected) จะมีคนเรียก ส่วน Event loop เหมือนพนักงานคนเดียวที่ทำงานตามกฎ: ทำงานตรงหน้าให้เสร็จก่อน (Sync) จากนั้นเคลียร์ "งานด่วนของลูกค้าที่รับออร์เดอร์แล้ว" ทั้งหมด (Microtask) แล้วจึงหยิบ "งานที่ตั้งเวลาไว้" มาทำทีละชิ้น (Macrotask) การสั่ง await ทีละอย่างเหมือนสั่งก๋วยเตี๋ยวเสร็จแล้วค่อยไปต่อคิวน้ำ ส่วน Promise.all คือให้เพื่อนไปต่อคิวน้ำพร้อมกัน

// ห่อ setTimeout ให้กลายเป็น Promise
function delay(ms, value) {
  return new Promise((resolve) => {
    setTimeout(() => resolve(value), ms);
  });
}

function failAfter(ms, message) {
  return new Promise((_, reject) => {
    setTimeout(() => reject(new Error(message)), ms);
  });
}

// ปัดเวลาเป็นทศนิยม 1 ตำแหน่ง เพื่อให้ผลลัพธ์อ่านง่ายและคงที่

// 1) then/catch/finally แบบดั้งเดิม
await delay(100, 'ข้อมูลผู้ใช้')
  .then((value) => console.log('then ได้:', value))
  .catch((error) => console.log('catch:', error.message))
  .finally(() => console.log('finally: ทำงานเสมอ'));

// 2) await ทีละตัว: รอ 300ms สองครั้ง = ประมาณ 0.6 วินาที
let start = Date.now();
const a = await delay(300, 'คะแนน');
const b = await delay(300, 'โปรไฟล์');
console.log(`ทีละตัว: ${a}, ${b} ใช้เวลาประมาณ ${seconds(start)} วินาที`);

// 3) Promise.all: เริ่มพร้อมกัน รอตัวที่ช้าที่สุด = ประมาณ 0.3 วินาที
start = Date.now();
const [c, d] = await Promise.all([delay(300, 'คะแนน'), delay(300, 'โปรไฟล์')]);
console.log(`พร้อมกัน: ${c}, ${d} ใช้เวลาประมาณ ${seconds(start)} วินาที`);

// 4) Promise.all ล้มทั้งหมดถ้ามีตัวเดียว reject
try {
  await Promise.all([delay(100, 'ok'), failAfter(50, 'เซิร์ฟเวอร์ล่ม')]);
} catch (error) {
  console.log('Promise.all ล้ม:', error.message);
}

// 5) allSettled: รอครบทุกตัว แล้วบอกสถานะของแต่ละตัว

  if (!response.ok) {
    throw new Error(`HTTP ${response.status} ที่ ${url}`);
  }
  return response.json();
}

const urls = [`${BASE}/data/questions.json`, `${BASE}/data/missing.json`];
const results = await Promise.allSettled(urls.map((url) => fetchJson(url)));

results.forEach((result, i) => {
  if (result.status === 'fulfilled') {
    const questions = result.value;

    // ถ้าเชื่อมต่อไม่ได้เลย รายละเอียดจริงจะอยู่ใน error.cause
    const code = result.reason.cause?.code;
    console.log(`[${i + 1}] rejected: ${result.reason.message}${code ? ` (${code})` : ''}`);
  }
});

Best Practice
  • ใช้ async/await เป็นหลัก และมี try/catch ในชั้นที่แสดงผลให้ผู้ใช้ (เช่น แสดงสถานะ "โหลดไม่สำเร็จ" พร้อมปุ่ม "ลองใหม่")
  • เช็ค response.ok ทุกครั้ง และตั้ง timeout ให้ทุก Request ด้วย AbortSignal.timeout() เพื่อไม่ให้หน้าเว็บรอตลอดไป
  • งานที่ไม่ขึ้นต่อกันให้ทำพร้อมกันด้วย Promise.all หรือ Promise.allSettled แต่ถ้ามีหลายร้อยงาน ให้แบ่งเป็นชุด เพื่อไม่ยิง Server พร้อมกันมากเกินไป
  • ใน Front-end ใช้ path แบบ Relative (fetch('data/questions.json')) เพื่อให้ทำงานได้ทั้งบนเครื่องและบน GitHub Pages
  • อย่าทำงานหนักที่กิน CPU นานบน Main thread (เช่น ลูปล้านรอบ) เพราะ Event loop จะไม่ได้ทำงานอื่น หน้าเว็บจะค้าง

export function average(nums) {
  if (!Array.isArray(nums) || nums.length === 0) {
    throw new TypeError('ต้องส่ง Array ที่มีตัวเลขอย่างน้อย 1 ตัว');
  }
  const total = nums.reduce((sum, n) => sum + n, 0);
  return total / nums.length;
}

// มีบั๊กโดยตั้งใจ: sort() เรียงแบบ String และแก้ Array ต้นฉบับ
export function median(nums) {
  const sorted = nums.sort();
  const mid = Math.floor(sorted.length / 2);
  if (sorted.length % 2 === 0) {
    return (sorted[mid - 1] + sorted[mid]) / 2;
  }
  return sorted[mid];
}
// countdown.js — นับถอยหลังทีละ 1 วินาที
export function startCountdown(seconds, onTick, onDone) {
  let left = seconds;
  const id = setInterval(() => {
    left -= 1;
    onTick(left);
    if (left === 0) {
      clearInterval(id);
      onDone();
    }
  }, 1000);
  // คืนฟังก์ชันสำหรับหยุดก่อนเวลา

// stats.js — ฟังก์ชันสถิติแบบ Pure function (ทดสอบง่าย)

export function average(nums) {
  if (!Array.isArray(nums) || nums.length === 0) {
    throw new TypeError('ต้องส่ง Array ที่มีตัวเลขอย่างน้อย 1 ตัว');
  }
  const total = nums.reduce((sum, n) => sum + n, 0);
  return total / nums.length;
}

// แก้แล้ว: toSorted() คืน Array ใหม่ และ (a, b) => a - b เรียงแบบตัวเลข
export function median(nums) {
  const sorted = nums.toSorted((a, b) => a - b);
  const mid = Math.floor(sorted.length / 2);
  if (sorted.length % 2 === 0) {
    return (sorted[mid - 1] + sorted[mid]) / 2;
  }
  return sorted[mid];
}

Best Practice
  • เมื่อเจอบั๊ก ให้เขียนเทสต์ที่ล้มเพราะบั๊กนั้นก่อน แล้วแก้จนผ่าน บั๊กเดิมจะไม่กลับมาโดยไม่มีใครรู้ (Regression test)
  • หนึ่งเทสต์ตรวจหนึ่งพฤติกรรม ตั้งชื่อเป็นประโยคที่อ่านแล้วรู้ว่าอะไรพัง และอย่าให้เทสต์ขึ้นกับลำดับหรือเวลาจริง (ใช้ mock timers และ fake random)
  • ทดสอบกรณีขอบ (Edge case) เสมอ: Array ว่าง ค่าติดลบ ค่า 0 ข้อมูลเสีย และจำนวนคู่/คี่
  • รัน npm test ก่อน commit ทุกครั้ง และในงานจริงตั้งให้รันอัตโนมัติบน GitHub Actions ()
  • ลบ debugger; และ console.log ที่ใช้ดีบักออกก่อน commit เครื่องมือ Lint อย่าง ESLint 10.13.0 (ไม่บังคับ) ช่วยเตือนเรื่องนี้ได้
