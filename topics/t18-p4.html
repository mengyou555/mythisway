18.4ส่วนเสริม: Mini Project, Cheat Sheet, Interview

ส่วนนี้รวมทุกอย่างที่เรียนมาในหัวข้อ Android เป็นแอปเดียวที่ใช้งานได้จริงและใส่ใน Portfolio ได้ คือ Notes App แอปจดโน้ตที่สร้างด้วย Kotlin และ Jetpack Compose เก็บข้อมูลใน Room, เก็บค่าตั้งค่าใน DataStore, แยกชั้นตามสถาปัตยกรรม MVVM, มี Unit test และ Compose UI Test และจบด้วยไฟล์ app-release.aab ที่เซ็นแล้ว หลังจากนั้นเป็น Cheat Sheet ที่จัดกลุ่มตามงาน คำถามสัมภาษณ์ 5 ข้อพร้อมคำตอบตัวอย่าง และแหล่งเรียนต่อ

หมายเหตุ

ส่วนที่ 1–3 เขียนบนเครื่องทดสอบที่ไม่มี Android SDK แต่ Notes App ในส่วนนี้ Build และทดสอบจริงทั้งโปรเจกต์ บน Windows 11 ด้วย Android Studio Rabbit 1 (2026.2.1) และ Gradle 9.7.1 เมื่อเดือนพฤศจิกายน 2026 ได้แก่ testDebugUnitTest (Unit test 10 ตัว), connectedDebugAndroidTest (Compose UI Test 5 ตัวบน Emulator ที่ใช้ System image ของ Android 17), bundleRelease (AAB ที่เปิด R8 และเซ็นแล้ว) และติดตั้ง Release build บน Emulator เพื่อลองสร้าง แก้ไข ปักหมุด ลบ เลิกทำ และเปลี่ยนธีมด้วยมือ โค้ดทุกไฟล์ในหน้านี้คัดลอกจากโปรเจกต์ที่ผ่านการทดสอบนั้น ผลลัพธ์ทุกกล่องเป็นข้อความจริงจาก Terminal ส่วนเวลาที่ Gradle ใช้ ชื่อ Emulator และ Path ในเครื่องของคุณจะต่างไป

ระวัง

การ Build จริงพบเรื่องสำคัญ 2 เรื่องที่ส่วนก่อนหน้ายังไม่ได้บอก

  1. compileSdk ต้องเป็น 37: Library ในเวอร์ชันที่หลักสูตรใช้ ได้แก่ Compose BOM 2026.09.00 (Compose UI 1.12.1), core-ktx 1.19.1, Lifecycle 2.11.0 และ Navigation Compose 2.10.2 กำหนดให้แอปคอมไพล์ด้วย Android API 37 ขึ้นไป ถ้าใช้ compileSdk = 36 งาน checkDebugAarMetadata จะล้มทันที ให้ติดตั้ง SDK Platform ของ Android 17 (API 37) ใน SDK Manager แล้วตั้ง compileSdk = 37 ส่วน targetSdk ยังเป็น 36 ได้ตามเกณฑ์ของ Google Play เพราะ compileSdk แค่กำหนดว่าคอมไพล์กับ API ชุดไหน ไม่เปลี่ยนพฤติกรรมของแอปบนเครื่องผู้ใช้
  2. เครื่องที่ตั้งภาษาระบบเป็นไทย: ถ้า Windows ตั้ง System locale เป็น Thai Java จะใช้ปฏิทินพุทธศักราช (ปี 2569) และ bundleRelease จะล้มที่งาน mergeReleaseJavaResource เพราะวันที่ในไฟล์ ZIP รองรับได้ถึงปี ค.ศ. 2107 เท่านั้น วิธีแก้คือบังคับ Locale ของ Gradle เป็นภาษาอังกฤษใน gradle.properties ตามที่แสดงใน Step 1

เป้าหมาย

สร้างแอปจดโน้ตแบบ Offline ที่ทำงานครบเหมือนแอปจริง ผู้ใช้สร้าง แก้ไข ลบ ค้นหา และปักหมุดโน้ตได้ ข้อมูลอยู่ครบหลังปิดแอปหรือรีสตาร์ทเครื่อง และเลือกธีมกับวิธีเรียงโน้ตได้เอง แอปนี้ไม่ต้องใช้อินเทอร์เน็ตหรือ API Key จึงรันได้ทันทีบน Emulator และบนมือถือจริง

Notes App ดูเรียบง่าย แต่ครอบคลุมเกือบทุกเรื่องที่ผู้สัมภาษณ์งาน Android ระดับ Junior ถาม ได้แก่ Compose, State, Navigation, ViewModel, Coroutine และ Flow, Room, DataStore, Test และ Release build เมื่อทำเสร็จ คุณจะมี Repository notes-app บน GitHub ที่อธิบายได้ว่าแต่ละชั้นทำหน้าที่อะไร และทำไมจึงออกแบบแบบนั้น ซึ่งสำคัญกว่าจำนวนฟีเจอร์

ฟีเจอร์ทั้งหมด

  • หน้ารายการโน้ต: TopAppBar "โน้ตของฉัน" พร้อมปุ่ม "ตั้งค่า", ช่องค้นหาที่ค้นทั้งชื่อและเนื้อหา (ViewModel รอให้หยุดพิมพ์ 300 ms ด้วย debounce ก่อนค้น), LazyColumn ที่ใช้ key = id, โน้ตปักหมุดอยู่บนสุดเสมอ และการ์ดแต่ละใบแสดงชื่อ บรรทัดแรกของเนื้อหา และป้าย "ปักหมุด"
  • สถานะว่าง 2 แบบ: "ยังไม่มีโน้ต กดปุ่ม + เพื่อเริ่มจด" เมื่อยังไม่มีโน้ตเลย และ "ไม่พบโน้ตที่ตรงกับ "คำค้น"" เมื่อค้นแล้วไม่เจอ
  • หน้าแก้ไข: ใช้ทั้งสร้างและแก้ไข ชื่อโน้ตต้องไม่ว่างและยาวไม่เกิน 50 ตัวอักษรหลังตัดช่องว่างหัวท้าย (Error "กรุณาใส่ชื่อโน้ต" และ "ชื่อโน้ตต้องยาวไม่เกิน 50 ตัวอักษร" มาจาก NoteValidator) มีตัวนับจำนวนตัวอักษร และกดบันทึกแล้วกลับหน้ารายการ
  • ลบพร้อมเลิกทำ: ปุ่ม "ลบ" มีเฉพาะตอนแก้ไข กดแล้วถามด้วย AlertDialog "ลบโน้ตนี้ไหม" เมื่อลบแล้วหน้ารายการแสดง Snackbar "ลบโน้ตแล้ว" ที่มีปุ่ม "เลิกทำ" เพื่อกู้โน้ตกลับมาด้วย id เดิม
  • หน้าตั้งค่า: ธีม (ตามระบบ สว่าง มืด) และการเรียงโน้ต (แก้ไขล่าสุด หรือชื่อ) เก็บใน DataStore ค่าที่เลือกมีผลทันทีและยังอยู่หลังเปิดแอปใหม่
  • Navigation แบบ Type-safe: 3 Route คือ NoteListRoute, NoteEditorRoute(noteId: Long = 0L) และ SettingsRoute ปุ่ม Back ของระบบทำงานถูกต้องทุกหน้า
  • สถาปัตยกรรม MVVM และ Unidirectional Data Flow: UiState หนึ่งตัวต่อหนึ่งหน้าจอ ส่งออกเป็น StateFlow, Repository แยกหน้าจอออกจาก Room และ Manual Dependency Injection ผ่าน AppContainer
  • Test: Unit test 10 ตัวบน JVM (NoteValidatorTest และ NoteListViewModelTest) และ Compose UI Test 5 ตัวบน Emulator (NoteListScreenTest และ NoteEditorScreenTest)
  • Release: versionCode = 1, versionName = "1.0.0", เปิด R8 และ Resource shrinking, เซ็นด้วย Upload key ที่อ่านรหัสผ่านจาก keystore.properties ซึ่งไม่ Commit ขึ้น Git

// สัญญาที่ ViewModel ใช้ ทำให้สลับเป็น FakeNoteRepository ตอนเขียน Test ได้
interface NoteRepository {
    fun observeNotes(query: String): Flow<List<Note>>
    suspend fun getNote(id: Long): Note?
    suspend fun saveNote(id: Long, title: String, content: String): Long
    suspend fun deleteNote(note: Note)
    suspend fun restoreNote(note: Note)
    suspend fun setPinned(id: Long, pinned: Boolean)

class OfflineNoteRepository(
    private val dao: NoteDao,
    private val clock: () -> Long = System::currentTimeMillis,   // แยกออกมาเพื่อให้ Test กำหนดเวลาได้
) : NoteRepository {

    override fun observeNotes(query: String): Flow<List<Note>> =
        dao.observeNotes(query).map { entities -> entities.map { it.toNote() } }

    override suspend fun getNote(id: Long): Note? = dao.getNote(id)?.toNote()

    // id = 0 คือโน้ตใหม่ ค่าอื่นคือแก้ไขโน้ตเดิม คืน id ของโน้ตที่บันทึก
    override suspend fun saveNote(id: Long, title: String, content: String): Long {
        val now = clock()
        val existing = if (id == 0L) null else dao.getNote(id)
        return if (existing == null) {
            dao.upsert(NoteEntity(title = title, content = content, createdAt = now, updatedAt = now))
        } else {
            dao.upsert(existing.copy(title = title, content = content, updatedAt = now))
            existing.id
        }
    }

    override suspend fun deleteNote(note: Note) = dao.delete(note.toEntity())

    // ใส่โน้ตกลับด้วย id เดิม ใช้กับปุ่ม "เลิกทำ"
    override suspend fun restoreNote(note: Note) {
        dao.upsert(note.toEntity())
    }

    override suspend fun setPinned(id: Long, pinned: Boolean) = dao.setPinned(id, pinned)
}

    }

    val settings: Flow<AppSettings> = dataStore.data.map { prefs ->
        AppSettings(
            themeMode = ThemeMode.fromStorage(prefs[Keys.THEME_MODE]),
            sortOrder = SortOrder.fromStorage(prefs[Keys.SORT_ORDER]),
        )
    }

    suspend fun setThemeMode(mode: ThemeMode) {
        dataStore.edit { it[Keys.THEME_MODE] = mode.storageValue }
    }

    suspend fun setSortOrder(order: SortOrder) {
        dataStore.edit { it[Keys.SORT_ORDER] = order.storageValue }
    }
}

// เรียงลำดับแบบ Kotlin ล้วน: โน้ตปักหมุดอยู่บนเสมอ
private val thaiCollator: Collator = Collator.getInstance(Locale.forLanguageTag("th-TH"))

fun List<Note>.sortedFor(order: SortOrder): List<Note> = when (order) {
    SortOrder.UPDATED -> sortedWith(compareByDescending<Note> { it.pinned }.thenByDescending { it.updatedAt })
    SortOrder.TITLE -> sortedWith(
        compareByDescending<Note> { it.pinned }.thenComparator { a, b -> thaiCollator.compare(a.title, b.title) }
    )
}

@OptIn(FlowPreview::class, ExperimentalCoroutinesApi::class)
class NoteListViewModel(
    private val repository: NoteRepository,
    sortOrder: Flow<SortOrder>,
) : ViewModel() {

    private val query = MutableStateFlow("")
    private val deletedNote = MutableStateFlow<Note?>(null)

    // รอให้หยุดพิมพ์ 300 ms ก่อนค้นหา และยกเลิกการค้นหาเก่าเมื่อคำค้นเปลี่ยน
    private val searchResults: Flow<List<Note>> = query
        .debounce(300)
        .map { it.trim() }
        .distinctUntilChanged()
        .flatMapLatest { repository.observeNotes(it) }

    val uiState: StateFlow<NoteListUiState> =
        combine(query, searchResults, sortOrder, deletedNote) { q, notes, order, deleted ->
            NoteListUiState(
                isLoading = false,
                query = q,
                notes = notes.sortedFor(order),
                sortOrder = order,
                deletedNote = deleted,
            )
        }.stateIn(
            scope = viewModelScope,
            started = SharingStarted.WhileSubscribed(5_000),
            initialValue = NoteListUiState(),
        )

    fun onQueryChange(newQuery: String) {
        query.value = newQuery
    }

    fun togglePin(note: Note) {
        viewModelScope.launch { repository.setPinned(note.id, !note.pinned) }
    }

    // ลบแล้วจำโน้ตไว้ เพื่อให้กด "เลิกทำ" ได้
    fun deleteNote(id: Long) {
        viewModelScope.launch {
            val note = repository.getNote(id) ?: return@launch
            repository.deleteNote(note)
            deletedNote.value = note
        }
    }

    fun undoDelete() {
        val note = deletedNote.value ?: return
        deletedNote.value = null
        viewModelScope.launch { repository.restoreNote(note) }
    }

    fun onDeleteMessageShown() {
        deletedNote.value = null
    }

    companion object {
        val Factory: ViewModelProvider.Factory = viewModelFactory {
            initializer {
                val app = this[APPLICATION_KEY] as NotesApplication
                NoteListViewModel(
                    repository = app.container.noteRepository,
                    sortOrder = app.container.settingsRepository.settings.map { it.sortOrder },
                )
            }
        }
    }
}

class NoteEditorViewModel(
    savedStateHandle: SavedStateHandle,
    private val repository: NoteRepository,

    // อ่านอาร์กิวเมนต์ของ Route แบบ Type-safe: 0L = สร้างโน้ตใหม่
    private val noteId: Long = savedStateHandle.toRoute<NoteEditorRoute>().noteId

    // หน้าจอนี้มีข้อมูลที่ผู้ใช้พิมพ์เป็นแหล่งหลัก จึงเก็บใน MutableStateFlow โดยตรง
    private val _uiState = MutableStateFlow(NoteEditorUiState(noteId = noteId, isLoading = noteId != 0L))
    val uiState: StateFlow<NoteEditorUiState> = _uiState.asStateFlow()

    init {
        if (noteId != 0L) {
            viewModelScope.launch {
                val note = repository.getNote(noteId)
                _uiState.update {
                    it.copy(title = note?.title.orEmpty(), content = note?.content.orEmpty(), isLoading = false)
                }
            }
        }
    }

    fun onTitleChange(title: String) {
        // ถ้ากำลังแสดง Error อยู่ ให้ตรวจใหม่ทุกครั้งที่พิมพ์ เพื่อให้ Error หายทันทีเมื่อแก้ถูก
        _uiState.update {
            it.copy(title = title, titleError = if (it.titleError != null) NoteValidator.validateTitle(title) else null)
        }
    }

    fun onContentChange(content: String) {
        _uiState.update { it.copy(content = content) }
    }

    fun save() {
        val state = _uiState.value
        val error = NoteValidator.validateTitle(state.title)
        if (error != null) {
            _uiState.update { it.copy(titleError = error) }
            return
        }
        viewModelScope.launch {
            repository.saveNote(noteId, state.title.trim(), state.content)
            _uiState.update { it.copy(isSaved = true) }
        }
    }

    companion object {
        val Factory: ViewModelProvider.Factory = viewModelFactory {
            initializer {
                val app = this[APPLICATION_KEY] as NotesApplication
                NoteEditorViewModel(createSavedStateHandle(), app.container.noteRepository)
            }
        }
    }
}

private const val DELETE_NOTE_ID_KEY = "delete_note_id"

@Composable
fun NotesNavHost(
    modifier: Modifier = Modifier,
    navController: NavHostController = rememberNavController(),
) {
    NavHost(navController = navController, startDestination = NoteListRoute, modifier = modifier) {

        composable<NoteListRoute> { backStackEntry ->
            val viewModel: NoteListViewModel = viewModel(factory = NoteListViewModel.Factory)
            val uiState by viewModel.uiState.collectAsStateWithLifecycle()
            val snackbarHostState = remember { SnackbarHostState() }

            // รับ id ที่หน้าแก้ไขส่งกลับมา แล้วให้ ViewModel ลบ (จึงกด "เลิกทำ" ที่หน้านี้ได้)
            val deleteId by backStackEntry.savedStateHandle
                .getStateFlow(DELETE_NOTE_ID_KEY, 0L)
                .collectAsStateWithLifecycle()
            LaunchedEffect(deleteId) {
                if (deleteId != 0L) {
                    viewModel.deleteNote(deleteId)
                    backStackEntry.savedStateHandle[DELETE_NOTE_ID_KEY] = 0L
                }
            }

            // เมื่อมีโน้ตที่เพิ่งลบ ให้แสดง Snackbar พร้อมปุ่ม "เลิกทำ"
            LaunchedEffect(uiState.deletedNote) {
                if (uiState.deletedNote != null) {
                    val result = snackbarHostState.showSnackbar(
                        message = "ลบโน้ตแล้ว",
                        actionLabel = "เลิกทำ",
                        duration = SnackbarDuration.Short,
                    )
                    if (result == SnackbarResult.ActionPerformed) viewModel.undoDelete()
                    else viewModel.onDeleteMessageShown()
                }
            }

            NoteListScreen(
                uiState = uiState,
                snackbarHostState = snackbarHostState,
                onQueryChange = viewModel::onQueryChange,
                onNoteClick = { id -> navController.navigate(NoteEditorRoute(noteId = id)) },
                onAddClick = { navController.navigate(NoteEditorRoute()) },
                onTogglePin = viewModel::togglePin,
                onSettingsClick = { navController.navigate(SettingsRoute) },
            )
        }

        composable<NoteEditorRoute> {
            val viewModel: NoteEditorViewModel = viewModel(factory = NoteEditorViewModel.Factory)
            val uiState by viewModel.uiState.collectAsStateWithLifecycle()

            // บันทึกเสร็จแล้วกลับไปหน้ารายการ
            LaunchedEffect(uiState.isSaved) {
                if (uiState.isSaved) navController.popBackStack()
            }

            NoteEditorScreen(
                uiState = uiState,
                onTitleChange = viewModel::onTitleChange,
                onContentChange = viewModel::onContentChange,
                onSave = viewModel::save,
                onDeleteConfirmed = {
                    navController.previousBackStackEntry?.savedStateHandle?.set(DELETE_NOTE_ID_KEY, uiState.noteId)
                    navController.popBackStack()
                },
                onBack = { navController.popBackStack() },
            )
        }

        composable<SettingsRoute> {
            val viewModel: SettingsViewModel = viewModel(factory = SettingsViewModel.Factory)
            val uiState by viewModel.uiState.collectAsStateWithLifecycle()
            SettingsScreen(
                uiState = uiState,
                onThemeModeChange = viewModel::setThemeMode,
                onSortOrderChange = viewModel::setSortOrder,
                onBack = { navController.popBackStack() },
            )
        }
    }
}

// Repository ปลอมที่เก็บโน้ตในหน่วยความจำ ทำงานเหมือน Room แต่ไม่ต้องใช้ Android
class FakeNoteRepository(initial: List<Note> = emptyList()) : NoteRepository {
    private val notes = MutableStateFlow(initial)
    private var clock = 1_000L                       // เวลาปลอมที่เพิ่มขึ้นทุกครั้งที่บันทึก

    val currentNotes: List<Note> get() = notes.value

    override fun observeNotes(query: String): Flow<List<Note>> = notes.map { list ->
        list.filter { it.title.contains(query, ignoreCase = true) || it.content.contains(query, ignoreCase = true) }
            .sortedWith(compareByDescending<Note> { it.pinned }.thenByDescending { it.updatedAt })
    }

    override suspend fun getNote(id: Long): Note? = notes.value.firstOrNull { it.id == id }

    override suspend fun saveNote(id: Long, title: String, content: String): Long {
        clock += 1
        val existing = notes.value.firstOrNull { it.id == id }
        return if (existing == null) {
            val newId = (notes.value.maxOfOrNull { it.id } ?: 0L) + 1
            notes.update { it + Note(newId, title, content, pinned = false, createdAt = clock, updatedAt = clock) }
            newId
        } else {
            notes.update { list -> list.map { if (it.id == id) it.copy(title = title, content = content, updatedAt = clock) else it } }
            id
        }
    }

    override suspend fun deleteNote(note: Note) {
        notes.update { list -> list.filterNot { it.id == note.id } }
    }

    override suspend fun restoreNote(note: Note) {
        notes.update { list -> list.filterNot { it.id == note.id } + note }
    }

    override suspend fun setPinned(id: Long, pinned: Boolean) {
        notes.update { list -> list.map { if (it.id == id) it.copy(pinned = pinned) else it } }
    }
}

  8. Step 8: Release build ที่เซ็นแล้ว (Upload key, R8 และ app-release.aab)

    Google Play รับแอปเป็นไฟล์ Android App Bundle (.aab) ที่เซ็นด้วย Upload key ของคุณ เมื่อเปิด Play App Signing (ค่าเริ่มต้นของแอปใหม่) Google จะเก็บกุญแจที่ใช้เซ็นแอปจริงไว้เอง และใช้ Upload key ของคุณแค่ยืนยันว่าไฟล์มาจากคุณ ถ้าทำ Upload key หาย ยังขอเปลี่ยนกุญแจผ่าน Play Console ได้ แต่ต้องรอกระบวนการตรวจสอบ จึงควรสำรองไฟล์ .jks และรหัสผ่านไว้ในที่ปลอดภัย เช่น Password manager

    สร้าง Upload key ได้ 2 วิธี วิธีแรกคือใช้หน้าต่าง Build > Generate Signed App Bundle or APK แล้วกด Create new... ใต้ช่อง Key store path วิธีที่สองคือใช้ keytool ที่มากับ JDK ใน Android Studio ตามคำสั่งด้านล่าง ซึ่งเก็บไฟล์ไว้นอกโฟลเดอร์โปรเจกต์ จึงไม่มีโอกาสหลุดขึ้น Git

## ฟีเจอร์
- สร้าง แก้ไข และลบโน้ต พร้อมหน้าต่างยืนยัน และปุ่ม "เลิกทำ" ใน Snackbar
- ค้นหาทั้งชื่อและเนื้อหา (debounce 300 ms)
- ปักหมุดโน้ตให้อยู่บนสุด
- ตั้งค่าธีม (ตามระบบ / สว่าง / มืด) และการเรียง (แก้ไขล่าสุด / ชื่อ) เก็บใน DataStore
- ข้อมูลทั้งหมดอยู่ในเครื่อง ไม่ต้องใช้อินเทอร์เน็ต

## สถาปัตยกรรม
MVVM และ Unidirectional Data Flow

```
UI (Compose) → ViewModel (StateFlow<UiState>) → Repository → Room / DataStore
```

- หน้าจอเป็น Stateless Composable ที่รับ UiState และส่ง Event ออก
- Manual DI ด้วย `AppContainer` ใน `NotesApplication`
- Navigation Compose แบบ Type-safe (`@Serializable` routes)

คำถามเหล่านี้พบบ่อยในการสัมภาษณ์ตำแหน่ง Android Developer ระดับ Junior ถึง Mid ผู้สัมภาษณ์มักถามต่อจากโปรเจกต์ใน Portfolio ให้ลองตอบด้วยคำพูดของตัวเองก่อน แล้วจึงเปิดดูคำตอบตัวอย่าง คำตอบที่ดีมักมี 3 ส่วน คือคำอธิบายที่ถูกต้อง เหตุผลว่าทำไมจึงสำคัญ และตัวอย่างจากงานที่ทำจริง

1. ViewModel ทำหน้าที่อะไร และทำไมไม่เก็บข้อมูลของหน้าจอไว้ใน Activity หรือ Composable (Junior)

คำตอบตัวอย่าง: ViewModel ถือ State ของหน้าจอและ Logic ที่ตัดสินใจว่าจะแสดงอะไร มันอยู่รอดเมื่อเกิด Configuration change เช่นหมุนจอ เปลี่ยนภาษา หรือเปลี่ยนขนาดหน้าต่าง ซึ่ง Activity จะถูกทำลายและสร้างใหม่ ถ้าเก็บรายการโน้ตไว้ใน Activity ทุกครั้งที่หมุนจอก็ต้องโหลดใหม่ และงานที่กำลังทำอยู่จะหายไป

  • ViewModel มี viewModelScope ที่ยกเลิก Coroutine ทุกตัวให้อัตโนมัติเมื่อผู้ใช้ออกจากหน้าจอนั้นจริงๆ จึงไม่มีงานค้างทำงานต่อหลังปิดหน้า
  • ViewModel ไม่ขึ้นกับ Android UI จึงเขียน Unit test บน JVM ได้ ใน Notes App ผมทดสอบการค้นหา การเรียง การปักหมุด และการลบพร้อมเลิกทำของ NoteListViewModel ด้วย FakeNoteRepository โดยไม่ต้องเปิด Emulator
  • ข้อห้ามสำคัญคือห้ามเก็บ Activity, View หรือ NavController ไว้ใน ViewModel เพราะ ViewModel อยู่นานกว่าหน้าจอ และจะทำให้เกิด Memory leak ถ้าต้องใช้ Context ให้ใช้ Application context ผ่าน Dependency
  • ViewModel ไม่ได้รอดทุกกรณี ถ้าระบบฆ่า Process ของแอปตอนอยู่เบื้องหลัง ViewModel จะหายไปด้วย ข้อมูลที่ต้องรอดกรณีนี้ต้องอยู่ใน SavedStateHandle หรือฐานข้อมูล
2. remember, rememberSaveable และ ViewModel ต่างกันอย่างไร ควรเลือกใช้เมื่อไร (Junior)

คำตอบตัวอย่าง: ทั้ง 3 อย่างเก็บ State ได้ แต่อายุต่างกัน

  • remember เก็บค่าข้าม Recomposition แต่หายเมื่อหมุนจอ เพราะ Activity ถูกสร้างใหม่ เหมาะกับค่าชั่วคราวที่สร้างใหม่ได้ไม่เสียหาย เช่น SnackbarHostState
  • rememberSaveable เก็บค่าลง Bundle จึงรอดจากการหมุนจอและจากการที่ระบบฆ่า Process แต่ควรเก็บแค่ข้อมูลเล็กๆ ที่เป็นของหน้าจอล้วน ใน Notes App ผมใช้กับ showDeleteDialog ของหน้าต่างยืนยันการลบ
  • ViewModel ใช้กับ State ที่มาจากข้อมูลหรือต้องมี Logic เช่น รายการโน้ต ผลค้นหา และ Error ของการตรวจชื่อ เพราะทดสอบได้ และหลายหน้าจอใช้ Logic เดียวกันได้

หลักที่ผมใช้คือถามว่า "ถ้าค่านี้หาย ผู้ใช้จะรู้สึกไหม และค่านี้มี Logic ไหม" ถ้ามี Logic ให้อยู่ใน ViewModel ถ้าเป็นแค่สถานะของ UI ให้ใช้ rememberSaveable และใช้ remember กับสิ่งที่สร้างใหม่ได้เสมอ

3. อธิบาย stateIn(viewModelScope, SharingStarted.WhileSubscribed(5_000), initialValue) และทำไมต้องเป็น 5 วินาที (Mid)

คำตอบตัวอย่าง: Flow จาก Room เป็น Cold flow คือจะเริ่ม Query เมื่อมีผู้ collect และแต่ละผู้ collect ได้ Query แยกกัน stateIn แปลงเป็น StateFlow ที่เป็น Hot flow แชร์ผลให้ผู้เก็บค่าทุกตัว จำค่าล่าสุด และมี initialValue ให้หน้าจอวาดได้ทันที ใน Notes App ค่าเริ่มต้นคือ NoteListUiState(isLoading = true) หน้าจอจึงแสดง Progress ก่อนข้อมูลมาถึง

  • WhileSubscribed(5_000) แปลว่าทำงานเมื่อมีผู้เก็บค่าอย่างน้อยหนึ่งตัว และเมื่อผู้เก็บค่าตัวสุดท้ายหายไป ให้รออีก 5 วินาทีก่อนหยุด
  • ตอนหมุนจอ Activity เก่าหยุดเก็บค่าและ Activity ใหม่เริ่มเก็บค่าภายในเวลาไม่ถึงวินาที การรอ 5 วินาทีจึงทำให้ Query ไม่ต้องเริ่มใหม่ ส่วนตอนผู้ใช้กด Home ไปทำอย่างอื่น collectAsStateWithLifecycle() หยุดเก็บค่าตามสถานะ Lifecycle และ Flow ต้นทางจะหยุดหลัง 5 วินาที ไม่เปลืองแบตเตอรี่
  • ถ้าใช้ SharingStarted.Eagerly Flow จะทำงานตลอดอายุ ViewModel แม้ไม่มีใครดู ถ้าใช้ Lazily จะเริ่มเมื่อมีผู้เก็บค่าครั้งแรกแต่ไม่หยุดเลย
  • ผลข้างเคียงที่ต้องรู้ตอนเขียน Test คือ uiState.value จะค้างที่ค่าเริ่มต้นถ้าไม่มีผู้เก็บค่า ผมจึงเปิด Collector ใน backgroundScope ของ runTest ทุก Test
4. ถ้าแอปที่ปล่อยไปแล้วต้องเพิ่มคอลัมน์ใหม่ในตาราง Room คุณจะทำอย่างไร และถ้าทำผิดจะเกิดอะไรขึ้น (Mid)

คำตอบตัวอย่าง: ผู้ใช้ที่อัปเดตแอปยังมีไฟล์ฐานข้อมูลเวอร์ชันเก่าอยู่ในเครื่อง ผมต้องเพิ่มเลข version ใน @Database และบอก Room ว่าจะแปลงข้อมูลเก่าอย่างไร มี 2 วิธี

  1. Auto migration: ใส่ autoMigrations = [AutoMigration(from = 1, to = 2)] ใช้ได้กับการเปลี่ยนแปลงที่ Room อนุมานเองได้ เช่นเพิ่มคอลัมน์ที่มีค่าเริ่มต้น โดย Room จะเทียบไฟล์ Schema JSON ของเวอร์ชัน 1 กับ 2 ในโฟลเดอร์ schemas/ ซึ่งเป็นเหตุผลที่ต้องเปิด exportSchema และ Commit โฟลเดอร์นี้ตั้งแต่เวอร์ชันแรก
  2. Manual migration: เขียน object : Migration(1, 2) ที่สั่ง ALTER TABLE notes ADD COLUMN color INTEGER NOT NULL DEFAULT 0 เอง แล้วลงทะเบียนด้วย addMigrations(...) ใช้เมื่อต้องย้ายหรือแปลงข้อมูล เช่นแยกคอลัมน์หนึ่งเป็นสองคอลัมน์

ถ้าแก้ Entity แต่ไม่เพิ่ม version แอปจะ Crash ด้วย Room cannot verify the data integrity ถ้าเพิ่ม version แต่ไม่มี Migration จะ Crash ด้วย A migration from 1 to 2 was required but not found ส่วน fallbackToDestructiveMigration() ทำให้ไม่ Crash ก็จริง แต่ลบข้อมูลผู้ใช้ทิ้งทั้งหมด ซึ่งรับไม่ได้สำหรับแอปจดโน้ต สุดท้ายผมจะเขียน Test ด้วย MigrationTestHelper ที่สร้างฐานข้อมูลเวอร์ชัน 1 ใส่ข้อมูล แล้ว Migrate เป็นเวอร์ชัน 2 และตรวจว่าข้อมูลยังอยู่ครบ

5. AAB ต่างจาก APK อย่างไร และถ้าแอปทำงานปกติใน Debug แต่ Crash ใน Release คุณจะหาสาเหตุอย่างไร (Mid)

คำตอบตัวอย่าง: APK คือไฟล์ที่ติดตั้งลงเครื่องได้ทันที ส่วน AAB (Android App Bundle) คือไฟล์ที่ส่งให้ Google Play ซึ่งจะสร้าง APK ที่เหมาะกับแต่ละเครื่องจาก AAB เช่นใส่เฉพาะ Native library ของ CPU และ Resource ของความหนาแน่นจอที่เครื่องนั้นใช้ ผู้ใช้จึงดาวน์โหลดไฟล์เล็กลง Google Play กำหนดให้แอปใหม่ส่งเป็น AAB และใช้ Play App Signing โดยเราเซ็น AAB ด้วย Upload key ส่วน Google เซ็น APK ด้วย App signing key ที่ Google เก็บไว้

สาเหตุที่พบบ่อยที่สุดของการ Crash เฉพาะใน Release คือ R8 ลบหรือเปลี่ยนชื่อคลาสที่ถูกเรียกผ่าน Reflection เช่นคลาสที่ Library JSON หรือ Library เก่าบางตัวอ่านด้วยชื่อ ขั้นตอนที่ผมใช้มีดังนี้

  1. ติดตั้ง Release build บน Emulator ด้วย installRelease ทำให้ Crash เกิดซ้ำ แล้วอ่าน Stack trace ใน Logcat
  2. ชื่อคลาสใน Stack trace จะถูกย่อเป็นตัวอักษรสั้นๆ ให้แปลงกลับด้วยไฟล์ mapping.txt ใน app/build/outputs/mapping/release/ ผ่านเครื่องมือ retrace หรืออัปโหลดไฟล์นี้ใน Play Console เพื่อให้รายงาน Crash อ่านได้
  3. เพิ่มกฎ -keep ที่แคบที่สุดใน proguard-rules.pro เฉพาะคลาสที่ต้องเก็บ ไม่ใช้ -dontobfuscate หรือ Keep ทั้ง Package เพราะทำให้แอปใหญ่และเสียประโยชน์ของ R8
  4. ทดสอบ Release build ทุกครั้งก่อนส่ง ใน Notes App ผมลองทุกหน้าใน Release build ก่อนเรียกว่าเสร็จ และพบว่า Route ที่ใช้ @Serializable ทำงานได้โดยไม่ต้องเพิ่มกฎ เพราะ kotlinx.serialization มีกฎของตัวเองมากับ Library
