[1]+ sleep 300 &

    1. SIGTERM (15) ซึ่งเป็นค่าเริ่มต้นของคำสั่ง kill

    4. SIGKILL (9) ที่ส่งด้วย kill -9

    #!/usr/bin/env bash

echo "พบ ERROR $count บรรทัด"
    1. พิมพ์ พบ ERROR 0 บรรทัด และจบด้วย exit code 0
    2. ไม่พิมพ์อะไรเลย และจบด้วย exit code 1
    3. พิมพ์ count: unbound variable แล้วจบด้วย exit code 1
    4. พิมพ์ พบ ERROR บรรทัด (ตัวเลขว่าง) และจบด้วย exit code 0

curl exit=28

    สาเหตุที่ curl ได้ 000 และ exit code 28 (หมดเวลา) คืออะไร

    1. Ctrl+Z ปิด Process ไปแล้ว Port 8091 จึงไม่มีใครเปิดอยู่
    2. Firewall ของ Windows บล็อก Port 8091 ไว้
    3. 127.0.0.1 ใช้ใน WSL ไม่ได้ ต้องใช้ IP ของ eth0 แทน
    4. Process ยังอยู่แต่ถูกหยุดชั่วคราว (สถานะ T) จึงไม่ตอบ Request ต้องสั่ง bg %1 หรือ fg ก่อน

สถานการณ์

ร้าน "บ้านกาแฟ" มีหน้าเว็บเช็กสต็อกภายในร้าน รันด้วย python3 -m http.server บน WSL ของเครื่องหน้าร้าน ปัญหาคือบางครั้ง Process ตายไปเอง บางครั้งค้างจนไม่ตอบ พนักงานต้องโทรเรียกคุณทุกครั้ง คุณจึงต้องเขียน Script ชื่อ webwatch.sh ที่เปิด ปิด และตรวจสถานะเว็บได้ และให้ cron เรียกตรวจทุกนาที ถ้าเว็บไม่ตอบ Script ต้องปิดตัวเก่าอย่างปลอดภัยแล้วเปิดใหม่เองโดยอัตโนมัติ

Security

ให้เว็บฟังเฉพาะ 127.0.0.1 (เครื่องตัวเอง) เท่านั้น และทดสอบด้วย curl กับเครื่องของคุณเองเท่านั้น การยิง Request ตรวจสอบหรือสแกนเครื่องของผู้อื่นโดยไม่ได้รับอนุญาตผิด พ.ร.บ.ว่าด้วยการกระทำความผิดเกี่ยวกับคอมพิวเตอร์

สิ่งที่ต้องทำ
  1. สร้างโฟลเดอร์ ~/projects/linux-lab/challenge3/site และไฟล์ site/index.html ที่มีหัวข้อ BaanKafae Stock
  2. เขียน webwatch.sh ที่รับคำสั่งย่อย 4 แบบ คือ start, stop, status และ check ด้วย case คำสั่งอื่นให้พิมพ์วิธีใช้ทาง stderr และจบด้วย exit code 3 ใช้ set -euo pipefail, ตัวแปร readonly และฟังก์ชันที่ใช้ local
  3. start ต้องเปิดเว็บที่ Port 8091 บน 127.0.0.1 ด้วย nohup ... & เก็บ PID ไว้ใน run/web.pid และเขียน Log พร้อมเวลาแบบ [YYYY-MM-DD HH:MM:SS] ข้อความ ลง logs/webwatch.log และบนจอ ถ้าเว็บทำงานอยู่แล้วต้องไม่เปิดซ้ำ
  4. stop ต้องส่ง SIGTERM ก่อน รอได้สูงสุด 5 วินาที ถ้ายังไม่ปิดจึงใช้ SIGKILL แล้วลบ PID file ส่วน status ต้องพิมพ์ running pid=... http=... หรือ stopped http=...
  5. check ต้องถามเว็บด้วย curl --max-time 3 ถ้าได้ 200 ให้ Log คำว่า OK และจบด้วย 0 ถ้าไม่ได้ 200 ให้ Log คำว่า DOWN ปิดตัวเก่า เปิดใหม่ แล้วตรวจซ้ำ ถ้ากลับมาได้ให้ Log RECOVERED และจบด้วย 1 ถ้าไม่ได้ให้ Log FAILED และจบด้วย 2
  6. ทดสอบ 2 สถานการณ์จำลอง คือ Process ตายกะทันหัน (kill -9) และ Process ค้าง (kill -STOP) แล้วดูว่า check กู้เว็บคืนได้ทั้งสองแบบ
  7. ติดตั้ง cron ให้เรียก webwatch.sh check ทุกนาที โดยเก็บผลลง logs/cron.log รอดูว่า cron ทำงานจริง แล้วถอดบรรทัดนี้ออกจาก crontab และปิดเว็บเมื่อทดสอบเสร็จ

ข้อ 3

คำตอบ: {001..005} (คำสั่งเต็มคือ touch orders/order-{001..005}.txt)

นี่คือ Brace expansion ซึ่ง Bash จะขยายเป็น 5 ชื่อก่อนส่งให้ touch เมื่อเลขเริ่มต้นมีเลข 0 นำหน้า Bash จะเติม 0 ให้ทุกตัวจนยาวเท่ากัน จึงได้ 001 ถึง 005 ถ้าเขียน {1..5} จะได้ order-1.txt ถึง order-5.txt ซึ่งไม่ตรงโจทย์

ข้อแตกต่างสำคัญ: Brace expansion สร้างชื่อใหม่ ได้แม้ไฟล์ยังไม่มีอยู่ ส่วน Wildcard (Globbing) เช่น * หรือ [1-3] จับเฉพาะไฟล์ที่มีอยู่แล้ว จึงใช้ Wildcard สร้างไฟล์ใหม่แบบนี้ไม่ได้

ข้อ 5

คำตอบ: 2>&1 (คำสั่งเต็มคือ ls /etc/hostname /nope > all.txt 2>&1)

Bash อ่าน Redirection จากซ้ายไปขวา > all.txt ส่ง stdout (หมายเลข 1) ไปที่ไฟล์ก่อน จากนั้น 2>&1 แปลว่า "ให้ stderr (หมายเลข 2) ไปที่เดียวกับ stdout ตอนนี้" ซึ่งก็คือ all.txt ทั้งสองบรรทัดจึงอยู่ในไฟล์เดียวกัน ใน Bash เขียนย่อเป็น &> all.txt ก็ได้ แต่ > file 2>&1 ใช้ได้กับ Shell มาตรฐาน POSIX ทุกตัว (เช่น sh และ dash ที่ cron ใช้) จึงพบบ่อยกว่าใน Script และในบรรทัด cron

สังเกตว่าบรรทัด Error อยู่บนสุด เพราะ ls พิมพ์ Error ทันทีที่หาไฟล์ไม่เจอ ก่อนพิมพ์รายชื่อไฟล์ที่พบ

ข้อ 6

คำตอบ: uniq -c

uniq รวมบรรทัดที่ซ้ำกันติดกัน และ -c (count) ใส่จำนวนครั้งไว้หน้าบรรทัด จึงต้อง sort ก่อนเพื่อให้ IP เดียวกันมาอยู่ติดกัน จากนั้น sort -rn เรียงตามตัวเลขจากมากไปน้อย และ head -n 3 ตัดเอา 3 อันดับแรก Pipeline sort | uniq -c | sort -rn เป็นสูตรนับความถี่ที่ใช้บ่อยที่สุดสูตรหนึ่งในงาน Admin

ข้อ 7

คำตอบ: -euo pipefail (บรรทัดเต็มคือ set -euo pipefail)

  • -e ทำให้ Script หยุดทันทีเมื่อคำสั่งใดคืน exit code ที่ไม่ใช่ 0
  • -u ทำให้การใช้ตัวแปรที่ไม่เคยตั้งค่าเป็น Error ซึ่งเป็นตัวที่ทำให้เกิดข้อความ USERNAME_TYPO: unbound variable ในโจทย์ และบรรทัดที่ 5 ไม่ถูกพิมพ์
  • -o pipefail ทำให้ exit code ของ Pipe เป็นค่าที่ไม่ใช่ 0 ถ้าคำสั่งใดคำสั่งหนึ่งใน Pipe ล้มเหลว ไม่ใช่ดูแค่คำสั่งสุดท้าย

ถ้าใส่แค่ set -u ก็จะเห็นผลลัพธ์เหมือนโจทย์ แต่ไม่ครบเงื่อนไขทั้งสามข้อที่โจทย์กำหนด

ข้อ 9

คำตอบ: bg (คำสั่งเต็มคือ bg %1)

Ctrl+Z ส่ง Signal SIGTSTP ทำให้งานหยุดชั่วคราว (สถานะ T ใน ps) แต่ยังไม่ตาย bg %1 สั่งให้งานหมายเลข 1 ทำงานต่อเบื้องหลัง Bash จึงพิมพ์ [1]+ sleep 300 & และ jobs แสดงสถานะ Running ถ้าใช้ fg %1 งานจะทำงานต่อเหมือนกัน แต่กลับมาอยู่ Foreground ทำให้พิมพ์คำสั่งอื่นไม่ได้ จึงไม่ตรงโจทย์ เราดูสถานะจริงด้วย ps ได้ดังนี้

sleep 300
# (กด Ctrl+Z ตรงนี้)
ps -o pid,stat,cmd -p $(jobs -p %1)
bg %1
ps -o pid,stat,cmd -p $(jobs -p %1)
kill %1
^Z

PID บนเครื่องของคุณจะต่างออกไป สถานะ T คือ Stopped และ S คือ Sleeping (รออยู่เฉย ๆ แต่ยังทำงาน)

#!/usr/bin/env bash
# log-report.sh : สรุป access.log ของร้านค้าออนไลน์ให้หัวหน้าอ่านง่าย
# ใช้: log-report.sh <access_log> [top_n]
set -euo pipefail

# แสดงวิธีใช้ทาง stderr แล้วจบด้วย exit code 2
usage() {
  echo "ใช้: $(basename "$0") <access_log> [top_n]" >&2
  exit 2
}

# ต้องมี argument 1 หรือ 2 ตัวเท่านั้น
[[ $# -ge 1 && $# -le 2 ]] || usage

log_file="$1"
top_n="${2:-3}"   # ถ้าไม่ระบุ ใช้ค่าเริ่มต้น 3

# ตรวจว่าไฟล์มีอยู่จริง
if [[ ! -f "$log_file" ]]; then
  echo "ผิดพลาด: ไม่พบไฟล์ $log_file" >&2
  exit 1
fi

# ตรวจว่า top_n เป็นตัวเลขบวก
if [[ ! "$top_n" =~ ^[1-9][0-9]*$ ]]; then
  echo "ผิดพลาด: top_n ต้องเป็นจำนวนเต็มบวก (ได้รับ '$top_n')" >&2
  exit 1
fi

# นับจำนวนบรรทัดทั้งหมด และจำนวน Request ที่ Status ตั้งแต่ 400 ขึ้นไป
total=$(wc -l < "$log_file")
errors=$(awk '$9 >= 400' "$log_file" | wc -l)

echo "=== รายงาน Log: $(basename "$log_file") ==="
echo "สร้างเมื่อ: $(date '+%F %T')"
echo "จำนวน Request ทั้งหมด: $total"
echo "จำนวน Request ที่ผิดพลาด (4xx/5xx): $errors"
echo

echo "--- Status Code ---"
awk '{print $9}' "$log_file" | sort | uniq -c | sort -rn
echo

echo "--- Top $top_n IP ---"
awk '{print $1}' "$log_file" | sort | uniq -c | sort -rn | head -n "$top_n"
echo

echo "--- Path ที่ได้ 404 ---"
awk '$9 == 404 {print $7}' "$log_file" | sort | uniq -c | sort -rn
echo

echo "--- IP น่าสงสัย (404 ตั้งแต่ 2 ครั้ง) ---"
awk '$9 == 404 {c[$1]++} END {for (ip in c) if (c[ip] >= 2) print ip, c[ip], "ครั้ง"}' "$log_file" | sort
echo

echo "--- ข้อมูลที่ส่งออกทั้งหมด ---"
awk '{s += $10} END {print s, "bytes"}' "$log_file"

โจทย์ที่ 3: Watchdog ปลุกเว็บภายในร้านที่ล่มบ่อย

สร้างไฟล์ด้วย nano ~/projects/linux-lab/challenge3/webwatch.sh แล้ววางเนื้อหาด้านล่าง (ต้องสร้างโฟลเดอร์ challenge3 ก่อน ตามคำสั่งในก้อนถัดไป)

#!/usr/bin/env bash
# webwatch.sh : เปิด ปิด ตรวจสถานะ และเฝ้าดูเว็บภายในร้าน (python3 -m http.server)
# ใช้: webwatch.sh {start|stop|status|check}
# exit code ของ check: 0 = ปกติ, 1 = เว็บล่มแต่กู้คืนสำเร็จ, 2 = กู้คืนไม่สำเร็จ, 3 = ใช้คำสั่งผิด
set -euo pipefail

readonly BASE_DIR="$HOME/projects/linux-lab/challenge3"
readonly SITE_DIR="$BASE_DIR/site"
readonly RUN_DIR="$BASE_DIR/run"
readonly LOG_DIR="$BASE_DIR/logs"
readonly PID_FILE="$RUN_DIR/web.pid"
readonly LOG_FILE="$LOG_DIR/webwatch.log"
readonly PORT="${WEB_PORT:-8091}"
readonly URL="http://127.0.0.1:$PORT/"

# เขียนข้อความพร้อมเวลา ทั้งบนจอและลงไฟล์ Log
log() {
  local msg
  msg="[$(date '+%F %T')] $*"
  echo "$msg" | tee -a "$LOG_FILE"
}

# คืนค่า 0 ถ้า PID นี้ยังมีชีวิตอยู่ (มีอยู่จริงและไม่ใช่ Zombie ที่สถานะขึ้นต้นด้วย Z)
alive() {
  local state
  state="$(ps -o stat= -p "$1" 2>/dev/null)" || return 1
  [[ "$state" != Z* ]]
}

# คืนค่า 0 ถ้ามี PID file และ Process ใน PID file ยังทำงานอยู่
is_running() {
  [[ -f "$PID_FILE" ]] && alive "$(cat "$PID_FILE")"
}

# ถามเว็บด้วย curl แล้วพิมพ์ HTTP status code (000 = ติดต่อไม่ได้หรือหมดเวลา)
http_code() {
  curl -s -o /dev/null -w '%{http_code}' --max-time 3 "$URL" || true
}

start_web() {
  if is_running; then
    log "เว็บทำงานอยู่แล้ว (PID $(cat "$PID_FILE"))"
    return 0
  fi
  # nohup ทำให้ Process ไม่ตายตอนปิด Terminal ส่วน & ส่งไปทำงานเบื้องหลัง
  nohup python3 -m http.server "$PORT" --bind 127.0.0.1 --directory "$SITE_DIR" \
    >> "$LOG_DIR/web.out" 2>&1 &
  echo "$!" > "$PID_FILE"
  sleep 1
  log "เริ่มเว็บแล้ว PID $(cat "$PID_FILE") ที่ $URL"
}

stop_web() {
  if ! is_running; then
    log "ไม่มีเว็บทำงานอยู่"
    rm -f "$PID_FILE"
    return 0
  fi
  local pid
  pid="$(cat "$PID_FILE")"
  kill "$pid"   # ส่ง SIGTERM ก่อนเสมอ เพื่อให้ปิดอย่างปลอดภัย
  for _ in 1 2 3 4 5; do
    alive "$pid" || break
    sleep 1
  done
  if alive "$pid"; then
    log "PID $pid ไม่ยอมปิดภายใน 5 วินาที จึงใช้ SIGKILL"
    kill -9 "$pid"
    sleep 1
  fi
  rm -f "$PID_FILE"
  log "หยุดเว็บแล้ว (PID $pid)"
}

status_web() {
  local code
  code="$(http_code)"
  if is_running; then
    echo "running pid=$(cat "$PID_FILE") http=$code"
  else
    echo "stopped http=$code"
  fi
}

check_web() {
  local code
  code="$(http_code)"
  if [[ "$code" == "200" ]]; then
    log "OK http=$code"
    return 0
  fi
  log "DOWN http=$code กำลังเริ่มเว็บใหม่"
  stop_web
  start_web
  code="$(http_code)"
  if [[ "$code" == "200" ]]; then
    log "RECOVERED http=$code"
    return 1
  fi
  log "FAILED http=$code กู้คืนไม่สำเร็จ"
  return 2
}

main() {
  mkdir -p "$RUN_DIR" "$LOG_DIR"
  local rc=0
  case "${1:-}" in
    start)  start_web ;;
    stop)   stop_web ;;
    status) status_web ;;
    check)  check_web || rc=$? ;;
    *)
      echo "ใช้: $(basename "$0") {start|stop|status|check}" >&2
      rc=3
      ;;
  esac
  return "$rc"
}

main "$@"

แนวคิด
  • PID file คือความจำของ Script start เขียน $! ลง run/web.pid ทำให้คำสั่งย่อยอื่นที่รันทีหลัง (รวมถึงตอน cron เรียก) รู้ว่าต้องดูแล Process ใด และ stop ลบไฟล์นี้ทุกครั้ง เพื่อไม่ให้มี PID ค้างที่อาจบังเอิญชี้ไปที่ Process อื่นในอนาคต
  • "มี Process" ไม่ได้แปลว่า "ใช้งานได้" ฟังก์ชัน alive ใช้ ps -o stat= ตรวจว่ายังมี Process อยู่และไม่ใช่ Zombie แต่การตัดสินว่าเว็บล่มใช้ curl ที่ได้ 200 เท่านั้น สถานการณ์ที่ 2 แสดงให้เห็นว่า Process ที่ค้างยังมี PID อยู่ แต่ไม่ตอบ
  • ปิดอย่างสุภาพก่อน แล้วค่อยบังคับ stop_web ส่ง SIGTERM ก่อน ให้โปรแกรมมีโอกาสปิดไฟล์และเก็บกวาด รอสูงสุด 5 วินาที แล้วจึงใช้ SIGKILL ซึ่งเป็นรูปแบบเดียวกับที่ systemd ใช้หยุด Service
  • ตัดขาดจาก Terminal nohup กับการ Redirect stdout และ stderr ไปที่ logs/web.out ทำให้เว็บไม่ตายเมื่อปิด Terminal และทำให้งาน cron จบได้ทันที ไม่ต้องรอ Process ลูก
  • exit code ที่มีความหมาย 0 = ปกติ, 1 = ล่มแต่กู้ได้, 2 = กู้ไม่ได้, 3 = ใช้ผิด ทำให้ระบบอื่นนำไปใช้ต่อได้ เช่นส่งแจ้งเตือนเฉพาะเมื่อได้ 2 การเขียน check_web || rc=$? ทำให้เก็บค่าได้โดย set -e ไม่ตัดจบ Script กลางทาง
  • Log ที่อ่านแล้วเล่าเรื่องได้ ทุกเหตุการณ์มีเวลากำกับ และถูกเขียนทั้งบนจอและในไฟล์ด้วย tee -a เมื่อมีปัญหาตอนตีสาม คุณจะย้อนดูได้ว่าเกิดอะไรขึ้นและกู้คืนเมื่อใด

  2. เปลี่ยนไปใช้ systemd แทน Watchdog ที่เขียนเอง โดยสร้าง Unit file ที่มี Restart=on-failure แบบในแนวคิดที่ 10 แล้วเปรียบเทียบข้อดีข้อเสียของทั้งสองแบบ
  3. ส่งแจ้งเตือนเข้า Discord หรือ LINE เมื่อได้ exit code 2 โดยอ่าน Webhook URL จาก Environment variable ถ้าไม่มีตัวแปรนี้ให้เข้าโหมด Mock ที่แค่พิมพ์ข้อความลง Log
  4. ตรวจเนื้อหาหน้าเว็บด้วย curl -s URL | grep -q 'BaanKafae Stock' นอกจาก Status 200 เพื่อจับกรณีที่เว็บตอบแต่แสดงหน้าผิด
