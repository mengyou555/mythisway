9.1Learning Roadmap

ภาพรวมเส้นทาง

Python คือภาษาโปรแกรมที่อ่านง่ายที่สุดภาษาหนึ่ง โค้ดของ Python หน้าตาใกล้เคียงประโยคภาษาอังกฤษ จึงเหมาะเป็น ภาษาแรก ของคนที่ไม่เคยเขียนโปรแกรมมาก่อน และไม่ได้เป็นแค่ภาษาสำหรับฝึกหัด บริษัทจริงใช้ Python ทำงานได้เกือบทุกสาย ทั้งเขียน Script ทำงานอัตโนมัติ (Automation) สร้างเว็บและ API วิเคราะห์ข้อมูล สร้างและเรียกใช้โมเดล AI ไปจนถึงเขียนเครื่องมือด้าน Cyber Security

หัวข้อนี้เป็นลำดับที่ 3 ของเส้นทางที่แนะนำ ต่อจาก และ ที่คุณเรียนจบแล้ว คุณจะใช้ Terminal ของ Ubuntu เพื่อรันโปรแกรม ใช้ Git เก็บประวัติโค้ด และ Push งานขึ้น GitHub ตลอดหัวข้อนี้ เส้นทางแบ่งเป็น 17 ขั้นใน 3 ระดับ ระดับ Beginner เดินช้าๆ และอธิบายทุกอย่างตั้งแต่ศูนย์ว่าโปรแกรม ตัวแปร และฟังก์ชันคืออะไร ระดับ Intermediate สอนสิ่งที่ทำให้เขียนโปรแกรมใช้งานจริงได้ เช่น Module, venv, ไฟล์ และการจัดการ Error ส่วนระดับ Advanced ลงลึกเรื่องที่นักพัฒนามืออาชีพใช้ทุกวัน คือ OOP, Generator, Decorator, การเขียน Test, การวัดความเร็วของโค้ด และการเรียก API ก่อนจบด้วย Mini Project Expense Tracker CLI ที่นำไปใส่ Portfolio ได้

ใช้เวลารวมประมาณ 83–117 ชั่วโมง (ตรงกับกรอบ 80–120 ชั่วโมงของหัวข้อนี้) ถ้าเรียนวันละ 1–1.5 ชั่วโมง สัปดาห์ละ 6 วัน จะจบในราว 13–14 สัปดาห์ ทุกขั้นมี Checkpoint ที่บอกว่าต้องทำอะไรได้ก่อนไปขั้นถัดไป ให้ทำ Checkpoint ให้ผ่านจริงด้วยการพิมพ์โค้ดเอง อย่าข้ามขั้น เพราะการเขียนโปรแกรมเป็นทักษะที่ต่อยอดกันทุกขั้น

  3. Beginner Step 3 · String, f-string และการรับ Input

  7. Intermediate Step 7 · Functions: Parameters, Return, Type Hints และ Docstrings
  8. Intermediate Step 8 · Modules, Packages, venv, pip และ requirements.txt
  9. Intermediate Step 9 · ทำงานกับไฟล์: pathlib, open, csv และ json
  10. Intermediate Step 10 · Exceptions และการ Debug
  11. Intermediate Step 11 · Standard Library: datetime, collections, itertools, random, argparse, logging
  12. Advanced Step 12 · Object-Oriented Programming และ Dataclass
  13. Advanced Step 13 · Iterator, Generator, Decorator และ Context Manager
  14. Advanced Step 14 · Testing ด้วย pytest และ Code Quality ด้วย ruff
  15. Advanced Step 15 · Data Structures, Algorithms และ Big-O เบื้องต้น
  16. Advanced Step 16 · เรียก HTTP API ด้วย requests และ httpx
  17. Advanced Step 17 · Mini Project: Expense Tracker CLI

เปรียบเทียบ

การเรียนเขียนโปรแกรมเหมือนการหัดทำอาหาร ระดับ Beginner คือรู้จักวัตถุดิบ (ตัวแปรและชนิดข้อมูล) รู้จักการปรุงตามเงื่อนไข ("ถ้าลูกค้าไม่ทานเผ็ด ไม่ต้องใส่พริก") และการทำซ้ำ ("ตอกไข่ทีละฟองจนครบ 10 ฟอง") ระดับ Intermediate คือการจัดครัวให้เป็นระบบ แยกสูตรเป็นเมนูย่อย (ฟังก์ชัน) จัดชั้นเครื่องปรุง (Module) และรับมือเมื่อของหมดกลางทาง (Exception) ส่วนระดับ Advanced คือการเปิดร้านจริง มีมาตรฐานการชิมก่อนเสิร์ฟ (Test) และจัดครัวให้ทำอาหารได้เร็วแม้ลูกค้าเยอะ (Algorithm) ไม่มีใครเป็นเชฟจากการอ่านตำรา ต้องลงมือทำทุกวัน

คำศัพท์ความหมายตัวอย่างในหัวข้อนี้
Programชุดคำสั่งที่เขียนเรียงกันไว้ให้คอมพิวเตอร์ทำตามทีละบรรทัด จากบนลงล่าง คอมพิวเตอร์ไม่คิดเอง ทำตามที่เขียนไว้ทุกตัวอักษรโปรแกรมคิดเกรดจากคะแนน และโปรแกรมบันทึกรายจ่าย
Programming Languageภาษาที่มนุษย์ใช้เขียนคำสั่งให้คอมพิวเตอร์ มีกฎไวยากรณ์ชัดเจน แต่ละภาษาเหมาะกับงานต่างกันPython, JavaScript, Go, Kotlin, SQL
Source Codeข้อความที่เราเขียนเป็นภาษาโปรแกรม เก็บเป็นไฟล์ข้อความธรรมดา ไฟล์ของ Python ลงท้ายด้วย .pyhello.py, grade.py
Interpreterโปรแกรมที่อ่าน Source Code แล้วสั่งให้คอมพิวเตอร์ทำตามทีละคำสั่ง Python เป็นภาษาแบบ Interpreted คือรันได้ทันทีโดยไม่ต้อง Compile เป็นไฟล์ .exe ก่อนคำสั่ง python3 ใน Ubuntu ซึ่งคือ CPython 3.12.3
Scriptไฟล์ .py ที่สั่งรันได้ทั้งไฟล์ด้วยคำสั่งเดียว เหมาะกับงานที่ต้องรันซ้ำpython3 hello.py
REPLRead-Eval-Print Loop โหมดโต้ตอบที่พิมพ์คำสั่งทีละบรรทัดแล้วเห็นผลทันที เหมาะกับการทดลองสั้นๆพิมพ์ python3 เฉยๆ จะเห็น Prompt >>>
Syntaxกฎไวยากรณ์ของภาษา เช่น Python บังคับให้ย่อหน้า (Indentation) ให้ถูกต้อง ถ้าผิดกฎจะเกิด SyntaxError และโปรแกรมไม่ทำงานเลยif score >= 80: ต้องมีเครื่องหมาย : ท้ายบรรทัด
Bug และ DebugBug คือข้อผิดพลาดในโปรแกรมที่ทำให้ผลลัพธ์ผิดหรือโปรแกรมพัง Debug คือกระบวนการหาและแก้ Bugใช้ print(), breakpoint() และ Debugger ของ VS Code ใน Step 10
Library และ Packageโค้ดสำเร็จรูปที่คนอื่นเขียนไว้ให้เรียกใช้ Python มี Standard Library ติดมากับตัว และมี Package อีกหลายแสนตัวบน PyPI (Python Package Index)csv, json (มากับ Python) และ requests, pytest (ติดตั้งจาก PyPI)
Virtual Environment (venv)โฟลเดอร์ที่แยก Package ของแต่ละโปรเจกต์ออกจากกัน ไม่ให้ไปปนกับ Python ของระบบ Ubuntu 24.04 บังคับให้ติดตั้ง Package ผ่าน venv เท่านั้นโฟลเดอร์ .venv ที่สร้างด้วย python3 -m venv .venv
เปรียบเทียบ

Source Code คือ สูตรอาหาร ที่เขียนไว้บนกระดาษ Interpreter คือ พ่อครัว ที่อ่านสูตรทีละบรรทัดแล้วลงมือทำตามทันที ถ้าสูตรเขียนว่า "ใส่เกลือ 1 ช้อน" พ่อครัวก็ใส่ 1 ช้อน แม้เราตั้งใจจะเขียน 1 ช้อนชา ส่วน Syntax Error คือสูตรที่เขียนผิดไวยากรณ์จนพ่อครัวอ่านไม่ออก เขาจึงไม่เริ่มทำอาหารเลยตั้งแต่ต้น

เหตุผลที่ Python เหมาะเป็นภาษาแรกและใช้ได้ทุกสาย

  • อ่านง่าย เขียนสั้น Python ใช้การย่อหน้าแทนวงเล็บปีกกา และใช้คำภาษาอังกฤษอย่าง if, for, in, not, and ทำให้มือใหม่โฟกัสที่วิธีคิด ไม่ต้องเสียแรงกับสัญลักษณ์
  • Automation งานซ้ำๆ อย่างเปลี่ยนชื่อไฟล์ทีละร้อยไฟล์ สรุปยอดจาก Excel หรือ CSV และส่งรายงานทุกเช้า เขียนเป็น Script สั้นๆ ได้
  • Web และ API Framework อย่าง Django, Flask และ FastAPI ใช้สร้างระบบหลังบ้าน ซึ่งจะเรียนต่อใน
  • Data และ AI pandas, NumPy, scikit-learn และ PyTorch ล้วนเป็น Library ของ Python และ SDK ของผู้ให้บริการ AI ส่วนใหญ่ก็มีเวอร์ชัน Python เป็นอันดับแรก ต่อยอดใน และ
  • Security และ Network นักทดสอบเจาะระบบและนักวิเคราะห์ใช้ Python เขียนเครื่องมือสแกน วิเคราะห์ Log และทำ Network Automation ต่อยอดใน และ
  • ชุมชนใหญ่ เมื่อเจอ Error เกือบทุกแบบ จะมีคนเคยเจอและเขียนวิธีแก้ไว้แล้ว และเอกสารทางการที่ docs.python.org ละเอียดและเป็นระเบียบมาก

Prerequisites: ต้องรู้อะไรมาก่อน

หัวข้อนี้ ไม่ต้องมีพื้นฐานการเขียนโปรแกรมมาก่อน และไม่ต้องเก่งคณิตศาสตร์ ใช้แค่บวก ลบ คูณ หาร และร้อยละระดับมัธยมต้น แต่ต้องเรียนจบ 2 หัวข้อนี้แล้ว เพราะจะใช้ทุกวัน

  • ต้องเปิด Terminal ของ Ubuntu แล้วใช้ cd, ls, mkdir, cat ได้คล่อง แยก Absolute path กับ Relative path ได้ เข้าใจ Permission และติดตั้งโปรแกรมด้วย sudo apt install ได้
  • ต้องสร้าง Repository, git add, git commit, เขียน .gitignore และ Push ขึ้น GitHub ผ่าน SSH Key ได้ เพราะทุกแบบฝึกหัดและ Mini Project ของหัวข้อนี้จะเก็บไว้ใน Git
  • ติดตั้ง VS Code พร้อม Extension WSL แล้ว และพิมพ์ code . จาก Ubuntu แล้วเปิดได้ (ทำไว้แล้วตั้งแต่ Day 0)
  • อ่านข้อความภาษาอังกฤษสั้นๆ ได้ โดยเฉพาะบรรทัดสุดท้ายของข้อความ Error เช่น NameError: name 'pirnt' is not defined. Did you mean: 'print'? ซึ่ง Python บอกทั้งสาเหตุและวิธีแก้ไว้ให้แล้ว
  • มีความอดทนกับ Error เพราะนักพัฒนาทุกคนเจอ Error ทุกวัน สิ่งที่แยกมือใหม่กับมืออาชีพคือการอ่าน Error แล้วแก้ได้ ไม่ใช่การไม่เคยเจอ Error

เรื่องสิ่งที่เกิดขึ้นบน Ubuntu 24.04สิ่งที่ต้องทำ
คำสั่ง pythonไม่มีคำสั่ง python มีแต่ python3 ถ้าพิมพ์ python จะเจอ Command 'python' not found, did you mean: ...พิมพ์ python3 เสมอ ทั้งนอกและใน venv หลักสูตรนี้ใช้ python3 ทุกตัวอย่าง
Python ของระบบUbuntu ใช้ /usr/bin/python3 รันโปรแกรมของระบบเอง เช่น ตัวติดตั้งแพ็กเกจบางตัว ถ้า Package ของระบบพัง Ubuntu อาจทำงานผิดปกติห้ามลบหรือเปลี่ยน /usr/bin/python3 และห้ามใช้ sudo pip
pip install นอก venvถูกปิดกั้นด้วย Error externally-managed-environment ตามมาตรฐาน PEP 668 เพื่อป้องกันไม่ให้ Package ที่ติดตั้งจาก PyPI ไปทับ Package ของ Ubuntuสร้าง venv ด้วย python3 -m venv .venv แล้วติดตั้งใน venv เท่านั้น อย่าใช้ Option --break-system-packages
โมดูล venvUbuntu แยก ensurepip ออกไปไว้ในแพ็กเกจ python3.12-venv ถ้ายังไม่ติดตั้ง การสร้าง venv จะล้มเหลวพร้อมข้อความ ensurepip is not availableติดตั้งครั้งเดียวด้วย sudo apt install -y python3-venv python3-pip
เรียก pipเครื่องเดียวอาจมี pip หลายตัว ถ้าเรียกผิดตัว Package จะไปอยู่ผิดที่ใช้ python3 -m pip ... เสมอ เพื่อให้แน่ใจว่าเป็น pip ของ Python ตัวที่กำลังใช้อยู่

3 วัน · 4–6 ชม.
หัวข้อย่อย

  • ข้อควรรู้เรื่องภาษาไทย: สระบนล่างและวรรณยุกต์ไม่กินที่บนจอ การจัดคอลัมน์ด้วย :<10 จึงอาจไม่ตรงกันเมื่อมีภาษาไทยปน

3 วัน · 4–5 ชม.
หัวข้อย่อย
  • ตัวดำเนินการเปรียบเทียบ: ==, !=, <, >, <=, >= ทุกตัวให้ผลเป็น bool และความต่างของ = (กำหนดค่า) กับ == (เปรียบเทียบ)
  • ตัวดำเนินการทางตรรกะ: and, or, not และการเปรียบเทียบต่อเนื่องแบบ Python อย่าง 0 <= score <= 100
  • โครงสร้าง if / elif / else: เครื่องหมาย : ท้ายบรรทัด การย่อหน้า 4 Space และการที่ Python ตรวจเงื่อนไขจากบนลงล่างแล้วหยุดที่เงื่อนไขแรกที่เป็นจริง
  • ลำดับของเงื่อนไขสำคัญ: ตรวจเงื่อนไขที่แคบกว่าหรือกรณีผิดปกติก่อน เช่น ตรวจคะแนนเกิน 100 ก่อนตรวจว่าได้ A
  • Truthiness: ค่าที่ถือว่าเป็นเท็จคือ 0, 0.0, "", [], {}, None และ False ค่าอื่นถือว่าเป็นจริง เช่น if name: แปลว่า "ถ้ามีชื่อ"

STEP 5

ทำซ้ำด้วย Loop: for, while, break, continue

4 วัน · 5–7 ชม.
หัวข้อย่อย
  • for Loop วนตามสมาชิกทีละตัวของสิ่งที่วนได้ (Iterable) เช่น ตัวอักษรใน String และสมาชิกใน List
  • range(stop), range(start, stop) และ range(start, stop, step) รวมถึงการที่ stop ไม่ถูกนับรวม เช่น range(1, 6) ได้ 1 ถึง 5
  • while Loop ทำซ้ำตราบใดที่เงื่อนไขยังเป็นจริง ต้องมีบรรทัดที่เปลี่ยนค่าในเงื่อนไข ไม่อย่างนั้นจะวนไม่จบ (Infinite loop) หยุดด้วย Ctrl+C ซึ่งจะเห็น KeyboardInterrupt
  • break ออกจาก Loop ทันที, continue ข้ามไปรอบถัดไป และ else ของ Loop ที่ทำงานเมื่อ Loop จบโดยไม่เจอ break
  • รูปแบบที่ใช้บ่อย (Loop patterns): ตัวสะสมผลรวม (Accumulator), ตัวนับ (Counter), หาค่ามากที่สุด และวนถามผู้ใช้จนกว่าจะกรอกถูก
  • enumerate() เพื่อได้ทั้งลำดับและค่า และ zip() เพื่อวนสองชุดข้อมูลไปพร้อมกัน
  • Loop ซ้อน Loop (Nested loops) เช่น ตารางสูตรคูณ และความเข้าใจว่าจำนวนรอบเพิ่มขึ้นแบบทวีคูณ
  • print(..., end=" ") เพื่อพิมพ์ต่อกันในบรรทัดเดียว

หัวข้อย่อย

  • ความต่างของ list.sort() (เรียงในที่เดิมและคืน None) กับ sorted(list) (คืน List ใหม่) และการเรียงด้วย key= กับ reverse=True

หัวข้อย่อย

  • Parameter กับ Argument, Positional argument กับ Keyword argument (calculate_total(prices, discount=0.1)) และค่าเริ่มต้น (Default value)
  • return ส่งค่ากลับให้ผู้เรียก ต่างจาก print() ที่แค่แสดงบนจอ ฟังก์ชันที่ไม่มี return จะคืน None และการคืนหลายค่าเป็น Tuple
  • *args รับ Argument แบบไม่จำกัดจำนวนเป็น Tuple และ **kwargs รับ Keyword argument แบบไม่จำกัดเป็น Dict รวมถึงลำดับการเขียน Parameter ที่ถูกต้อง
  • Scope: ตัวแปรที่สร้างในฟังก์ชันเป็น Local ใช้นอกฟังก์ชันไม่ได้ ทำไมควรเลี่ยง global และ Error UnboundLocalError
  • กับดัก Mutable default argument: def add(item, items=[]) ทำให้ List ถูกใช้ร่วมกันทุกครั้งที่เรียก ให้ใช้ items=None แทน
  • Type hints: def f(price: float, tags: list[str]) -> float:, dict[str, int], float | None ซึ่งช่วยให้ VS Code เตือนและเติมโค้ดได้ แต่ Python ไม่ได้บังคับตอนรัน
  • Docstring: ข้อความใน """...""" บรรทัดแรกของฟังก์ชัน อธิบายว่าทำอะไร รับอะไร คืนอะไร และดูได้ด้วย help(ชื่อฟังก์ชัน) ใน REPL
  • Lambda: ฟังก์ชันบรรทัดเดียวไม่มีชื่อ ใช้กับ sorted(key=...), min(), max() และหลักการเขียนฟังก์ชันที่ดี คือทำงานเดียว ชื่อบอกหน้าที่ และไม่แก้ตัวแปรภายนอก

class InvalidAmountError(ValueError):
    """Error ของเราเอง ใช้เมื่อจำนวนเงินไม่ถูกต้อง"""


def parse_amount(text: str) -> float:
    try:
        amount = float(text)
    except ValueError:
        # แปลง Error ทั่วไปให้เป็น Error ที่สื่อความหมายกับโปรแกรมของเรา
        raise InvalidAmountError(f"'{text}' ไม่ใช่ตัวเลข") from None
    if amount <= 0:
        raise InvalidAmountError(f"จำนวนเงินต้องมากกว่า 0 (ได้ {amount})")
    return amount


for raw in ["120", "abc", "-30"]:
    try:
        value = parse_amount(raw)
    except InvalidAmountError as err:
        print("ข้าม:", err)
    else:
        print("ใช้ได้:", value)
    finally:
        print("ตรวจแล้ว:", raw)

Object-Oriented Programming และ Dataclass

1 สัปดาห์ · 7–9 ชม.
หัวข้อย่อย
  • Class คือแม่แบบ Object คือสิ่งที่สร้างจากแม่แบบ: class BankAccount: และ acc = BankAccount("somchai") รวมถึงความจริงที่ว่าทุกอย่างใน Python เป็น Object แม้แต่ int และฟังก์ชัน
  • __init__ กับ self: กำหนดค่าเริ่มต้นของ Attribute และความต่างของ Instance attribute กับ Class attribute
  • Method คือฟังก์ชันที่อยู่ใน Class เช่น deposit() และ withdraw() ที่ตรวจข้อมูลก่อนเปลี่ยนสถานะ (Invariant) และ raise ValueError เมื่อผิดเงื่อนไข
  • Dunder methods (Magic methods): __str__ (สำหรับผู้ใช้อ่าน), __repr__ (สำหรับนักพัฒนา Debug), __eq__, __len__ และ __lt__ สำหรับการเรียงลำดับ
  • Encapsulation แบบ Python: ใช้ _ชื่อ บอกว่าเป็นของภายใน และ @property สร้าง Attribute ที่อ่านได้แต่ควบคุมการแก้ไขได้ รวมถึง @classmethod และ @staticmethod
  • Inheritance: class SavingsAccount(BankAccount):, super().__init__(), การ Override method, Polymorphism (Object ต่างชนิดตอบสนองต่อ Method ชื่อเดียวกันได้) และ isinstance()
  • Composition over inheritance: เมื่อไรควรให้ Class หนึ่ง "มี" อีก Class (has-a) แทนการสืบทอด (is-a)
  • @dataclass จากโมดูล dataclasses: สร้าง __init__, __repr__, __eq__ ให้อัตโนมัติ, ค่าเริ่มต้น, field(default_factory=list), frozen=True (แก้ไขไม่ได้), order=True และ __post_init__ สำหรับตรวจข้อมูล

from dataclasses import dataclass


@dataclass
class Transaction:
    """ข้อมูลการเงิน 1 รายการ dataclass สร้าง __init__ และ __repr__ ให้อัตโนมัติ"""
    kind: str
    amount: float


class BankAccount:
    def __init__(self, owner: str, balance: float = 0.0) -> None:
        self.owner = owner
        self.balance = balance
        self.history: list[Transaction] = []

    def deposit(self, amount: float) -> None:
        self.balance += amount
        self.history.append(Transaction("deposit", amount))

    def withdraw(self, amount: float) -> None:
        if amount > self.balance:
            raise ValueError("ยอดเงินไม่พอ")
        self.balance -= amount
        self.history.append(Transaction("withdraw", amount))

    def __str__(self) -> str:
        return f"บัญชีของ {self.owner}: {self.balance:,.2f} บาท"


class SavingsAccount(BankAccount):
    """บัญชีออมทรัพย์ สืบทอดทุกอย่างจาก BankAccount และเพิ่มดอกเบี้ย"""

    def __init__(self, owner: str, balance: float = 0.0, rate: float = 0.015) -> None:
        super().__init__(owner, balance)
        self.rate = rate

    def add_interest(self) -> None:
        self.deposit(round(self.balance * self.rate, 2))


acc = SavingsAccount("somchai", 10_000)
acc.withdraw(2_500)
acc.add_interest()
print(acc)

1 สัปดาห์ · 6–8 ชม.
หัวข้อย่อย
  • Iterable กับ Iterator: for Loop ทำงานโดยเรียก iter() แล้วเรียก next() ซ้ำจนเจอ StopIteration และการสร้าง Iterator เองด้วย __iter__ กับ __next__
  • Generator function ที่ใช้ yield: สร้างค่าทีละตัวเมื่อถูกขอ (Lazy evaluation) จำสถานะระหว่างการเรียก และใช้ได้ครั้งเดียว (วนซ้ำรอบสองจะได้ว่าง)

import functools
from contextlib import contextmanager


def log_call(func):
    """Decorator: พิมพ์ชื่อฟังก์ชันและผลลัพธ์ทุกครั้งที่ถูกเรียก"""
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        result = func(*args, **kwargs)
        print(f"[log] {func.__name__}{args} -> {result}")
        return result
    return wrapper


def even_numbers(limit: int):
    """Generator: สร้างเลขคู่ทีละตัวเมื่อถูกขอ ไม่สร้างทั้งหมดไว้ในหน่วยความจำ"""
    n = 0
    while n <= limit:
        yield n
        n += 2


@contextmanager
def section(title: str):
    """Context manager: พิมพ์หัวและท้ายให้อัตโนมัติ แม้โค้ดข้างในจะเกิด Error"""
    print(f"=== {title} ===")
    try:
        yield
    finally:
        print("=== จบ ===")


@log_call
def add(a: int, b: int) -> int:
    return a + b


with section("ทดลอง"):
    print(list(even_numbers(10)))
    gen = even_numbers(4)
    print(next(gen), next(gen))
    add(2, 3)

Data Structures, Algorithms และ Big-O เบื้องต้น

4 วัน · 4–6 ชม.
หัวข้อย่อย
  • Big-O คือการบอกว่าเวลาทำงานโตขึ้นอย่างไรเมื่อข้อมูลเพิ่มขึ้น: O(1) คงที่, O(log n) ลอการิทึม, O(n) เชิงเส้น, O(n log n) และ O(n²) พร้อมตัวอย่างโค้ดของแต่ละแบบ
  • ความเร็วของโครงสร้างข้อมูลใน Python: ค้นหาใน List เป็น O(n) แต่ค้นหาใน Dict และ Set เป็น O(1) โดยเฉลี่ยเพราะใช้ Hash table และ list.append() เร็ว แต่ list.insert(0, x) ช้า (ใช้ collections.deque แทน)
  • วัดเวลาจริงด้วยโมดูล timeit ทั้งใน Script และบน Command Line (python3 -m timeit) และเหตุผลที่ต้องวัดหลายรอบ
  • Searching: Linear search เทียบกับ Binary search ที่ต้องใช้ข้อมูลที่เรียงแล้ว เขียนเองด้วย while และใช้โมดูล bisect ที่มากับ Python
  • Sorting: เข้าใจหลักการของ Bubble sort (O(n²)) ด้วยการเขียนเอง แล้วรู้ว่าในงานจริงใช้ sorted() และ list.sort() ที่เป็น Timsort (O(n log n)) และเรียงแบบ Stable
  • Recursion: ฟังก์ชันที่เรียกตัวเอง Base case, RecursionError เมื่อเรียกลึกเกิน (ค่าเริ่มต้นประมาณ 1,000 ชั้น) และการแก้ด้วย Loop หรือ @functools.cache
  • โครงสร้างข้อมูลพื้นฐานที่ใช้บ่อยในการสัมภาษณ์: Stack (ใช้ List), Queue (ใช้ deque), Hash map (ใช้ Dict) และ Heap (ใช้ heapq)
  • หลักการปรับความเร็ว: วัดก่อนปรับเสมอ (Measure, don't guess) และเลือกโครงสร้างข้อมูลให้ถูกมักได้ผลมากกว่าปรับโค้ดทีละบรรทัด
ทำไมต้องเรียน
โค้ดที่ทำงานเร็วกับข้อมูล 100 แถว อาจใช้เวลาหลายชั่วโมงกับข้อมูล 10 ล้านแถว ถ้าเลือกโครงสร้างข้อมูลผิด เช่น ตรวจรหัสสมาชิกซ้ำด้วยการค้นใน List ภายใน Loop การสัมภาษณ์งานนักพัฒนาเกือบทุกที่มีโจทย์ Algorithm และคำถาม "โค้ดนี้มี Big-O เท่าไร" ขั้นนี้ไม่ได้สอนแบบนักคณิตศาสตร์ แต่ให้ "ความรู้สึก" ที่ถูกต้อง และพิสูจน์ด้วยการวัดเวลาจริง

Must-know Skills

ถ้าต้องสรุปหัวข้อนี้ให้เหลือทักษะที่งานจริงและผู้สัมภาษณ์คาดหวังจากคนที่ "เขียน Python เป็น" จะได้รายการนี้

  1. อ่าน Traceback และแก้ Error ได้เอง เพราะนักพัฒนาใช้เวลากับการแก้บั๊กมากกว่าการเขียนโค้ดใหม่ และคนที่อ่าน Error เป็นจะไม่ติดอยู่กับปัญหาเดิมนานเป็นชั่วโมง
  2. ใช้ชนิดข้อมูลพื้นฐานและแปลงชนิดข้อมูลได้ถูกต้อง เพราะข้อมูลจากผู้ใช้ ไฟล์ และ API มาเป็นข้อความเสมอ การแปลงผิดคือต้นเหตุของ TypeError และ ValueError ส่วนใหญ่
  3. ควบคุมลำดับการทำงานด้วยเงื่อนไขและ Loop เพราะเป็นโครงสร้างพื้นฐานของทุกโปรแกรม และบั๊กเรื่องลำดับเงื่อนไขกับการนับรอบผิดเป็นบั๊กที่พบบ่อยที่สุด
  4. เลือกใช้ List, Tuple, Set และ Dict ให้เหมาะกับงาน เพราะการเลือกโครงสร้างข้อมูลถูกตัวทำให้โค้ดสั้นลงและเร็วขึ้นได้หลายพันเท่า
  5. เขียนฟังก์ชันที่ดีพร้อม Type hints และ Docstring เพราะฟังก์ชันที่ทำงานเดียวและชัดเจนคือหน่วยที่อ่านง่าย ใช้ซ้ำได้ และเขียน Test ได้
  6. จัดการ venv, pip และ requirements.txt อย่างถูกวิธี เพราะ Ubuntu 24.04 บังคับใช้ venv และโปรเจกต์ที่ติดตั้งซ้ำไม่ได้จะพังในเครื่องของเพื่อนร่วมทีมและบน Server
  7. อ่านเขียนไฟล์ CSV และ JSON ด้วย pathlib เพราะงาน Automation และงานข้อมูลส่วนใหญ่คือการแปลงไฟล์จากรูปแบบหนึ่งเป็นอีกรูปแบบหนึ่ง
  8. จัดการ Exception อย่างเจาะจงและสร้าง Custom exception เพราะโปรแกรมที่ใช้งานจริงต้องรับมือกับข้อมูลผิดและระบบภายนอกที่ล่มได้ โดยไม่ซ่อนบั๊กจริงไว้
  9. ใช้ Debugger (pdb และ VS Code) เพราะการดูค่าตัวแปรขณะโปรแกรมหยุดอยู่ หาสาเหตุของบั๊กได้เร็วกว่าการเดาและเติม print()
  10. ออกแบบโปรแกรมด้วย Class และ Dataclass เพราะ Framework และ Library ทุกตัวที่จะใช้ต่อจากนี้ออกแบบด้วย OOP
  11. เข้าใจ Generator, Decorator และ Context Manager เพราะเป็นสำนวนที่เห็นใน FastAPI, pytest และโค้ดอาชีพทั่วไป และเป็นคำถามสัมภาษณ์ระดับ Mid ที่พบบ่อย
  12. เขียน Test ด้วย pytest และรักษาคุณภาพโค้ดด้วย ruff เพราะทีมพัฒนาจริงไม่รับโค้ดที่ไม่มี Test และไม่ผ่าน Linter และ CI จะตรวจทุก Pull Request โดยอัตโนมัติ
  13. ใช้ Standard Library ก่อนเขียนเองหรือติดตั้งเพิ่ม เพราะ argparse, datetime, collections และ logging แก้ปัญหาทั่วไปได้ดีกว่าโค้ดที่เขียนเองและไม่เพิ่ม Dependency
  14. เรียก HTTP API อย่างปลอดภัย เพราะระบบสมัยใหม่คุยกันผ่าน API และการตั้ง Timeout กับการเก็บ API Key ใน Environment variable ป้องกันระบบค้างและข้อมูลรั่ว
