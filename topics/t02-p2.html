2.2Core Concept & Quick Guide

ส่วนนี้คือแกนกลางของหัวข้อ Vibe Coding เราจะเรียน 12 แนวคิดหลัก เรียงจากง่ายไปยากตามเส้นทางใน Part 1 แนวคิดที่ 1–4 เป็นระดับ Beginner (ความหมายของ Vibe Coding, การเตรียมโปรเจกต์ให้ปลอดภัย, Spec กับ Acceptance Criteria และการทำงานเป็นก้าวเล็กพร้อม Git Checkpoint) แนวคิดที่ 5–8 เป็นระดับ Intermediate (Context File กับ ruff, Test-first Prompting, การรีวิว Diff และการ Debug ร่วมกับ AI) และแนวคิดที่ 9–12 เป็นระดับ Advanced (Refactor อย่างปลอดภัย, Security Review, Supply Chain กับความเป็นส่วนตัวของข้อมูล และ Quality Gate อัตโนมัติ)

ทุกแนวคิดทำงานในโปรเจกต์เดียวกันชื่อ vibe-lab ซึ่งเป็นตัวช่วยคำนวณเวลาเรียน โปรเจกต์จะโตขึ้นทีละขั้น เริ่มจากฟังก์ชันเล็ก ๆ ไปจนถึง API ที่สร้างด้วย Flask + SQLite พร้อม Test, Security Test และ Quality Gate ครบชุด โค้ดทุกชิ้นรันจริงบน Ubuntu 24.04 ใน WSL2 และทุกบล็อก "ผลลัพธ์ที่ได้จริง" มาจากการรันจริง ส่วนโค้ดที่ติดป้าย "(โค้ดที่ AI เขียน)" คือคำตอบตัวอย่างที่บันทึกไว้ให้ฝึกรีวิว คำตอบจาก AI ของคุณจะใช้ถ้อยคำและโค้ดต่างไปทุกครั้งที่ถาม จึงฝึกครบทุกแนวคิดได้โดยไม่ต้องมีเครื่องมือ AI ตัวไหนเลย และไม่ต้องมี API Key

ก่อนเริ่ม ควรผ่าน (เขียน Prompt ให้ชัด), (Commit, Branch และการย้อนกลับ) และ (อ่านโค้ด Python ได้คล่อง) มาแล้ว เพราะหัวใจของหัวข้อนี้คือ คุณยังต้องรับผิดชอบโค้ดทุกบรรทัด แม้ AI จะเป็นคนพิมพ์ แนวคิดที่ 8–10 ใช้ Flask และ SQL ด้วย ถ้ายังไม่คุ้นให้ทบทวน และ ประกอบ

Vibe Coding คืออะไร: สเปกตรัมจาก AI Chat ถึง Agentic Coding

คืออะไร ทำไมต้องใช้ และใช้เมื่อไร

Vibe Coding เป็นคำที่ Andrej Karpathy ทำให้แพร่หลายเมื่อต้นปี 2025 หมายถึงการสร้างซอฟต์แวร์ด้วยการ "บอกสิ่งที่อยากได้เป็นภาษาคน" แล้วให้ AI เขียนโค้ดให้ เรารับโค้ดนั้นมาใช้โดยแทบไม่อ่าน ถ้าพังก็คัดลอก Error กลับไปให้ AI แก้ แล้วปรับไปเรื่อย ๆ ตามความรู้สึกว่า "ใช้ได้แล้ว" วิธีนี้เร็วมากและเหมาะกับงานทดลองที่ทิ้งได้ เช่น ต้นแบบที่ทำในช่วงสุดสัปดาห์ หรือสคริปต์ที่ใช้ครั้งเดียว

หัวข้อนี้สอนอีกระดับหนึ่งที่ใช้ในงานจริง คือ AI-assisted Development อย่างมีวินัย เรายังพิมพ์คำสั่งเป็นภาษาคนเหมือนเดิม แต่ คุณยังต้องรับผิดชอบโค้ดทุกบรรทัด จึงต้องมี Spec ที่ชัด แบ่งงานเป็นก้าวเล็ก ตรวจด้วย Test และรีวิว Diff ก่อนรับเสมอ ใช้แนวทางนี้ทุกครั้งที่โค้ดจะถูกใช้ต่อ ถูกส่งให้คนอื่น หรือแตะข้อมูลจริง ส่วน Vibe Coding แบบปล่อยตามความรู้สึกให้จำกัดไว้กับงานทดลองที่ไม่มีข้อมูลสำคัญเท่านั้น

เครื่องมือ AI สำหรับเขียนโค้ดเรียงเป็นสเปกตรัม ยิ่งไปทางขวา AI ยิ่งลงมือเองได้มาก และความเสียหายเมื่อผิดก็ยิ่งกว้าง หน้าตาและชื่อเมนูของเครื่องมือเปลี่ยนบ่อย บทเรียนนี้จึงอธิบายแบบทั่วไป ส่วนวิธีติดตั้งให้ดูจากเอกสารทางการ: Claude Code, GitHub Copilot และ Cursor

ระดับทำงานอย่างไรตัวอย่างความเสี่ยงหลัก
1. AI Chat Assistantคุยในหน้าเว็บหรือแอป แล้วคัดลอกโค้ดไปวางเอง AI ไม่เห็นโปรเจกต์ของเราClaude บนเว็บหรือแอปแชตอื่นAI เดาบริบทผิด, คัดลอกมาไม่ครบ, เผลอวาง Secret ลงในแชต
2. Inline Completionเติมโค้ดต่อจากเคอร์เซอร์ใน Editor ทีละบรรทัดหรือทีละบล็อกGitHub Copilot ใน VS Codeกด Tab รับโดยไม่อ่าน, ได้รูปแบบโค้ดเก่าหรือ API ที่เลิกใช้แล้ว
3. Chat / Agent ใน Editorอ่านไฟล์ที่เปิดอยู่ แก้ได้หลายไฟล์ และเสนอ Diff ให้กดรับCursor, โหมด Agent ของ GitHub Copilotแก้เกินขอบเขต, แก้หลายไฟล์พร้อมกันจนรีวิวไม่ทัน
4. Agentic Coding Tool ใน Terminalอ่านทั้ง Repository, รันคำสั่ง เช่น Test หรือ Git, แก้หลายไฟล์ และทำงานหลายขั้นต่อเนื่องเองClaude Codeรันคำสั่งที่ทำลายข้อมูล, อ่านไฟล์ลับ, เปลี่ยนเยอะจนย้อนยาก ถ้าไม่มี Git Checkpoint

จุดแข็งของ AI คือความเร็ว เขียนโค้ดซ้ำ ๆ (Boilerplate) ได้ดี อธิบายโค้ดที่เราอ่านไม่เข้าใจ และเสนอ Test ที่เรานึกไม่ถึง ส่วนความล้มเหลวที่พบบ่อยคือ

"""ตรวจคำตอบแรกของ AI เทียบกับตัวอย่างใน Spec ก่อนเชื่อและนำไปใช้"""


# ----- โค้ดที่ AI ตอบกลับมาครั้งแรก (คัดลอกมาทั้งก้อน ยังไม่แก้อะไร) -----
def format_minutes(total: int) -> str:
    """แปลงจำนวนนาทีเป็นข้อความภาษาไทย"""
    hours = total / 60
    minutes = total % 60
    return f"{hours} ชม. {minutes} นาที"


# ----- ตัวอย่างที่ต้องได้ คัดลอกมาจาก Spec ตรงๆ (Input, ผลที่ต้องได้) -----
EXPECTED = [
    (45, "45 นาที"),
    (60, "1 ชม."),
    (95, "1 ชม. 35 นาที"),
    (0, "0 นาที"),
]


def main() -> None:
    passed = 0
    for total, expected in EXPECTED:
        got = format_minutes(total)
        if got == expected:
            passed += 1
            print(f"PASS format_minutes({total}) -> {got!r}")
        else:
            print(f"FAIL format_minutes({total}) ได้ {got!r} แต่ต้องได้ {expected!r}")
    print(f"ผ่าน {passed}/{len(EXPECTED)}")

    # Spec บอกว่าค่าติดลบต้อง Error ลองดูว่าโค้ดของ AI ทำตามหรือไม่
    try:
        result = format_minutes(-5)
        print(f"ตรวจเพิ่ม: format_minutes(-5) ไม่ Error แต่คืน {result!r}")
    except ValueError:
        print("ตรวจเพิ่ม: format_minutes(-5) -> ValueError ถูกต้อง")


if __name__ == "__main__":
    main()

Spec หรือ Mini PRD (Product Requirements Document) คือเอกสารสั้น ๆ ที่ตอบว่าจะสร้างอะไร ให้ใคร ทำอะไรได้ และอะไรที่จะไม่ทำ AI เติมช่องว่างที่เราไม่ได้บอกด้วยการเดาเสมอ ยิ่ง Spec กำกวม AI ยิ่งเดาเยอะ และเราก็ยิ่งตรวจไม่ได้ว่าถูกหรือผิด Spec ที่ดีมี 6 หัวข้อ: เป้าหมาย, ผู้ใช้, ฟีเจอร์แบ่งเป็น Must / Should / Won't, Acceptance Criteria, ข้อจำกัดทางเทคนิค และ Out of Scope

หัวใจคือ Acceptance Criteria ที่ทดสอบได้ เขียนเป็นตัวอย่าง Input -> Output ที่ชัดจนเครื่องตรวจได้ เช่น "แสดงเวลาให้อ่านง่าย" ตรวจไม่ได้ แต่ format_minutes(95) -> "1 ชม. 35 นาที" ตรวจได้ทันที ส่วน "ต้องไม่พังเมื่อข้อมูลว่าง" ยังกำกวม ให้เขียนเป็น average_minutes([]) -> 0.0 แทน ใช้แนวคิดนี้ก่อนสั่ง AI ทำงานที่ใหญ่กว่า 1 ฟังก์ชันทุกครั้ง และเมื่อความต้องการเปลี่ยน ให้แก้ Spec ก่อนแก้โค้ดเสมอ ถ้ายังคิดไม่ครบ ให้ใช้ Prompt แบบ Spec Interview ให้ AI เป็นฝ่ายถามเราก่อนเขียนอะไรทั้งนั้น

สั่งเค้กวันเกิดว่า "ขอเค้กอร่อย ๆ" ร้านจะทำตามรสนิยมของร้าน แล้วเราก็บอกไม่ได้ว่าร้านทำผิด แต่ถ้าสั่งว่า "ช็อกโกแลต 2 ปอนด์ เขียนชื่อ สมชาย ไม่ใส่ถั่ว รับ 5 โมงเย็น" ทุกข้อตรวจได้ตอนรับของ Acceptance Criteria คือใบสั่งเค้กแบบหลัง และข้อ "ไม่ใส่ถั่ว" ก็คือ Won't / Out of Scope ที่กันไม่ให้ร้านใส่ของที่เราไม่ได้ขอ

def format_minutes(total: int) -> str:
    """แปลงจำนวนนาทีเป็นข้อความ เช่น 95 -> '1 ชม. 35 นาที'"""
    if total < 0:
        raise ValueError("นาทีต้องไม่ติดลบ")
    hours, minutes = divmod(total, 60)
    if hours == 0:
        return f"{minutes} นาที"
    if minutes == 0:
        return f"{hours} ชม."
    return f"{hours} ชม. {minutes} นาที"

"""ตรวจ Acceptance Criteria ทั้ง 7 ข้อใน SPEC.md แบบอัตโนมัติ"""

import sys

import duration

# (เลขข้อ, สิ่งที่เรียก, ฟังก์ชันที่เรียกจริง, ผลที่ต้องได้ตาม Spec)
# ใช้ lambda เพื่อให้เรียกตอนตรวจ ถ้ายังไม่มีฟังก์ชันจะได้รายงานว่า "รอทำ" แทนการพังทั้งไฟล์
CRITERIA = [
    (1, "format_minutes(45)", lambda: duration.format_minutes(45), "45 นาที"),
    (2, "format_minutes(60)", lambda: duration.format_minutes(60), "1 ชม."),
    (3, "format_minutes(95)", lambda: duration.format_minutes(95), "1 ชม. 35 นาที"),
    (4, "format_minutes(0)", lambda: duration.format_minutes(0), "0 นาที"),
    (5, "format_minutes(-5)", lambda: duration.format_minutes(-5), ValueError),
    (6, "average_minutes([30, 60, 90])", lambda: duration.average_minutes([30, 60, 90]), 60.0),
    (7, "average_minutes([])", lambda: duration.average_minutes([]), 0.0),
]


def run_check(func, expected) -> tuple[str, str]:
    """รันเกณฑ์ 1 ข้อ แล้วคืน (สถานะ, รายละเอียดเมื่อไม่ผ่าน)"""
    expects_error = isinstance(expected, type) and issubclass(expected, Exception)
    try:
        got = func()
    except AttributeError as e:
        return "รอทำ", f"ยังไม่มีฟังก์ชันนี้ ({e})"
    except Exception as e:
        if expects_error and isinstance(e, expected):
            return "ผ่าน", ""
        return "ไม่ผ่าน", f"เกิด {type(e).__name__}: {e}"
    if expects_error:
        return "ไม่ผ่าน", f"ไม่ Error แต่ได้ {got!r}"
    if got == expected:
        return "ผ่าน", ""
    return "ไม่ผ่าน", f"ได้ {got!r}"


def main() -> int:
    counts = {"ผ่าน": 0, "ไม่ผ่าน": 0, "รอทำ": 0}
    for no, call, func, expected in CRITERIA:
        status, detail = run_check(func, expected)
        counts[status] += 1
        want = expected.__name__ if isinstance(expected, type) else repr(expected)
        line = f"[{status}] AC{no}: {call} -> {want}"
        print(line + (f" · {detail}" if detail else ""))
    total = len(CRITERIA)

Best Practice
  • เก็บ SPEC.md ไว้ใน Repository และ Commit ทุกครั้งที่แก้ เพื่อให้คน AI และ Test ใช้เอกสารฉบับเดียวกัน
  • ใส่เลขกำกับ Acceptance Criteria ทุกข้อ แล้วอ้างเลขนั้นใน Prompt, Test และข้อความ Commit
  • ทุกฟีเจอร์ต้องมีอย่างน้อย 1 กรณีปกติ 1 กรณีขอบ (ศูนย์ ว่าง ค่าสูงสุด) และ 1 กรณีที่ต้อง Error
  • เขียน Won't และ Out of Scope ทุกครั้ง เพราะเป็นเครื่องมือหลักที่กันไม่ให้ AI เพิ่มฟีเจอร์ที่ไม่ได้ขอ
  • คุม Spec ให้จบในหน้าเดียว ถ้ายาวกว่านั้นให้แบ่งงานเป็นหลายรอบ

คืออะไร ทำไมต้องใช้ และใช้เมื่อไร

ถ้าสั่ง AI ว่า "ทำทั้งโปรเจกต์ให้หน่อย" จะได้ Diff ยาวหลายร้อยบรรทัดที่รีวิวไม่ไหว วิธีที่ใช้ในงานจริงคือวงจร 4 จังหวะ: Plan ให้ AI เสนอแผนเป็นข้อ ๆ โดยยังไม่เขียนโค้ด เราอนุมัติแล้วบันทึกเป็น PLAN.md แบบ Checklist Implement สั่งทำทีละ 1 ขั้น Verify รันโค้ดและตรวจกับ Spec และ Commit ทันทีที่ขั้นนั้นทำงานถูก ข้อความ Commit ใช้รูปแบบ Conventional Commits เช่น feat: ฟีเจอร์ใหม่, fix: แก้บั๊ก, test: เพิ่ม Test, refactor: ปรับโครงสร้างโดยพฤติกรรมเดิม, docs: เอกสาร และ chore: งานดูแลโปรเจกต์

ทุก Commit คือ Checkpoint ถ้า AI ทำพังในขั้นถัดไป เราย้อนกลับได้ในคำสั่งเดียว เลือกคำสั่งตามสถานะของงาน: ยังไม่ Commit ใช้ git restore, Commit ไปแล้วใช้ git revert ซึ่งสร้าง Commit ใหม่ที่กลับการแก้ไขโดยประวัติเดิมยังอยู่ครบ ใช้วงจรนี้กับทุกงานที่ให้ AI แก้โค้ด โดยเฉพาะเมื่อใช้ Agent ที่แก้หลายไฟล์ได้เอง

def format_minutes(total: int) -> str:
    """แปลงจำนวนนาทีเป็นข้อความ เช่น 95 -> '1 ชม. 35 นาที'"""

Best Practice
  • ขอแผนก่อนโค้ดเสมอ และสั่งทำทีละขั้นด้วยข้อความชัด ๆ เช่น "ทำขั้นที่ 2 เท่านั้น"
  • ดู git diff --stat ทุกครั้งหลัง AI แก้ ถ้าจำนวนบรรทัดหรือจำนวนไฟล์มากเกินที่คาด ให้หยุดถามเหตุผลก่อนอ่านต่อ
  • Commit ทันทีที่ขั้นนั้นผ่านการตรวจ 1 Commit ต่อ 1 เรื่อง เพื่อให้ git revert ย้อนได้ตรงจุด
  • Commit ที่ Push ไปแล้วให้ย้อนด้วย git revert ไม่ใช่ git reset เพราะไม่เขียนประวัติที่คนอื่นมีอยู่แล้วทับ

Test-first Prompting: ให้ AI เขียน Test จาก Spec แล้วรันเองด้วย pytest

คืออะไร ทำไมต้องใช้ และใช้เมื่อไร

Test-first Prompting คือการสั่งให้ AI เขียน Test จาก Acceptance Criteria ก่อน มี Implementation แล้วเรารัน Test เองตามวงจร Red → Green: Red รันแล้วต้องล้ม และต้องล้มด้วยเหตุผลที่ถูก (เช่น ยังไม่มีฟังก์ชัน ไม่ใช่ Test พิมพ์ผิด) จากนั้น Commit Test เก็บไว้เป็น Checkpoint แล้วจึงให้ AI เขียน Implementation จนถึง Green คือผ่านครบ Test ที่ Commit ไว้ก่อนเป็นเหมือนสัญญาที่ล็อกแล้ว ถ้าภายหลัง AI แอบแก้ Test ให้ง่ายลง git diff tests/ จะฟ้องทันที

พื้นฐาน pytest ที่ต้องใช้: ไฟล์ชื่อ test_*.py, ฟังก์ชันชื่อ test_*, ตรวจด้วย assert, ตรวจ Error ด้วย pytest.raises, รวมหลายกรณีด้วย @pytest.mark.parametrize และสั่งรันด้วย pytest -q (สรุปสั้น), -x (หยุดที่ Test แรกที่ล้ม) หรือ -k คำ (รันเฉพาะ Test ที่ชื่อมีคำนั้น) Test ที่ AI เขียนต้องรีวิวด้วย ระวัง 3 แบบที่พบบ่อย: Test ที่ไม่ได้ตรวจอะไรจริง (เช่น is not None), Test ที่คัดลอกสูตรเดียวกับ Implementation มาคำนวณค่าคาดหวัง (ผิดก็ผิดด้วยกัน) และ Test ที่ถูกแก้ให้ผ่าน (แนวคิดที่ 7) ใช้แนวคิดนี้กับทุกฟังก์ชันที่มี Acceptance Criteria ชัดเจน

เปรียบเทียบ

ครูที่ดีเขียนเฉลยข้อสอบไว้ก่อนแจกข้อสอบ แล้วเก็บเฉลยใส่ซองปิดผนึก ถ้าปล่อยให้นักเรียนเขียนเฉลยเองหลังทำข้อสอบเสร็จ คะแนนเต็มก็ไม่ได้พิสูจน์อะไร Test ที่เขียนและ Commit ก่อน Implementation คือเฉลยในซองปิดผนึก และ Test แบบ is not None ก็คือเฉลยที่เขียนว่า "ขอแค่ตอบมาก็ได้คะแนน"

def format_minutes(total: int) -> str:
    """แปลงจำนวนนาทีเป็นข้อความ เช่น 95 -> '1 ชม. 35 นาที'"""
    if total < 0:
        raise ValueError("นาทีต้องไม่ติดลบ")
    hours, minutes = divmod(total, 60)
    if hours == 0:
        return f"{minutes} นาที"
    if minutes == 0:
        return f"{hours} ชม."
    return f"{hours} ชม. {minutes} นาที"


def average_minutes(sessions: list[int]) -> float:
    """คืนค่าเฉลี่ยนาทีต่อครั้ง ถ้าไม่มีข้อมูลเลยให้คืน 0.0 ตาม AC7"""
    if not sessions:
        return 0.0
    return sum(sessions) / len(sessions)

รีวิวทุก Diff ด้วย Checklist 8 ข้อ: 1) ตรงตาม Spec ไหม 2) กรณีขอบ (ว่าง ศูนย์ ติดลบ) 3) ชื่อและ Type Hint 4) Import ที่ไม่ใช้ 5) มีการแก้ไฟล์ใน tests/ หรือไม่ 6) Dependency ใหม่ 7) Secret 8) ความปลอดภัย เครื่องมือที่ใช้คือ git apply --check (ลองว่า Patch ใช้ได้ไหมโดยยังไม่แก้ไฟล์), git apply, git apply -R (ถอน Patch) และ git add -p (เลือกรับทีละ Hunk) ใช้แนวคิดนี้กับทุกการแก้ของ AI ก่อน Commit หรือก่อน Merge

"""API บันทึกเวลาเรียน: เก็บข้อมูลการเรียนแต่ละครั้งลง SQLite"""

import sqlite3

from flask import Flask, jsonify, request

SCHEMA = """
CREATE TABLE IF NOT EXISTS sessions (
    id INTEGER PRIMARY KEY,
    topic TEXT NOT NULL,
    minutes INTEGER NOT NULL
)
"""


def create_app(db_path: str = "studylog.db") -> Flask:
    """สร้างแอป Flask ที่เก็บข้อมูลในไฟล์ SQLite ตาม db_path"""
    app = Flask(__name__)
    conn = sqlite3.connect(db_path)
    conn.execute(SCHEMA)
    conn.close()

    @app.get("/api/sessions")
    def list_sessions():
        conn = sqlite3.connect(db_path)
        rows = conn.execute("SELECT id, topic, minutes FROM sessions ORDER BY id").fetchall()
        conn.close()
        return jsonify([{"id": r[0], "topic": r[1], "minutes": r[2]} for r in rows])

    @app.post("/api/sessions")
    def add_session():
        data = request.get_json()
        topic = data["topic"]
        minutes = int(data["minutes"])
        conn = sqlite3.connect(db_path)
        cur = conn.execute("INSERT INTO sessions (topic, minutes) VALUES (?, ?)", (topic, minutes))
        conn.commit()
        conn.close()
        return jsonify({"id": cur.lastrowid, "topic": topic, "minutes": minutes}), 201

    return app

"""ฟังก์ชันจัดการฐานข้อมูล SQLite ของ API บันทึกเวลาเรียน"""

import sqlite3
from collections.abc import Iterator
from contextlib import contextmanager

SCHEMA = """
CREATE TABLE IF NOT EXISTS sessions (
    id INTEGER PRIMARY KEY,
    topic TEXT NOT NULL,
    minutes INTEGER NOT NULL
)
"""


@contextmanager
def get_conn(db_path: str) -> Iterator[sqlite3.Connection]:
    """เปิด Connection ให้ใช้ใน with เมื่อจบบล็อกจะ Commit แล้วปิดให้เสมอ"""
    conn = sqlite3.connect(db_path)
    try:
        yield conn
        conn.commit()
    finally:
        conn.close()


def init_db(db_path: str) -> None:
    """สร้างตาราง sessions ถ้ายังไม่มี"""
    with get_conn(db_path) as conn:
        conn.execute(SCHEMA)


def add_session(db_path: str, topic: str, minutes: int) -> int:
    """บันทึกการเรียน 1 ครั้ง แล้วคืน id ที่ได้"""
    with get_conn(db_path) as conn:
        cur = conn.execute("INSERT INTO sessions (topic, minutes) VALUES (?, ?)", (topic, minutes))
        return cur.lastrowid


def list_sessions(db_path: str) -> list[dict]:
    """คืนการเรียนทั้งหมด เรียงตาม id"""
    with get_conn(db_path) as conn:
        rows = conn.execute("SELECT id, topic, minutes FROM sessions ORDER BY id").fetchall()
    return [{"id": r[0], "topic": r[1], "minutes": r[2]} for r in rows]
"""ตรวจข้อมูลที่ผู้ใช้ส่งมาก่อนบันทึกลงฐานข้อมูล"""


def parse_session(payload: object) -> tuple[str, int]:
    """ตรวจ payload แล้วคืน (topic, minutes) ถ้าข้อมูลผิดให้ raise ValueError พร้อมข้อความภาษาไทย"""
    if not isinstance(payload, dict):
        raise ValueError("ต้องส่งข้อมูลเป็น JSON object")
    topic = payload.get("topic")
    if not isinstance(topic, str) or not topic.strip():
        raise ValueError("ต้องระบุ topic")
    if "minutes" not in payload:
        raise ValueError("ต้องระบุ minutes")
    minutes = payload["minutes"]
    # bool เป็นชนิดย่อยของ int ใน Python (True == 1) จึงต้องกันออกก่อน
    if isinstance(minutes, bool) or not isinstance(minutes, int) or minutes <= 0:
        raise ValueError("minutes ต้องเป็นจำนวนเต็มที่มากกว่า 0")
    return topic.strip(), minutes

import json
import sys
import urllib.error
import urllib.request


def check(name: str) -> bool:
    url = f"https://pypi.org/pypi/{name}/json"
    try:
        with urllib.request.urlopen(url, timeout=10) as resp:
            data = json.load(resp)
    except urllib.error.HTTPError as e:
        if e.code == 404:
            print(f"[ไม่พบ] {name}: ไม่มีบน PyPI ห้ามติดตั้ง อาจเป็นชื่อที่ AI แต่งขึ้น")
            return False
        raise
    info = data["info"]
    uploads = [f["upload_time"][:10] for files in data["releases"].values() for f in files]
    license_ = info.get("license_expression") or info.get("license") or "ไม่ระบุ"
    source = (info.get("project_urls") or {}).get("Source", "ไม่ระบุ")
    print(f"[พบ] {info['name']} {info['version']} | ออกครั้งแรก {min(uploads)} | License {license_}")
    print(f"      Source: {source}")
    return True


if __name__ == "__main__":
    results = [check(name) for name in sys.argv[1:]]
    sys.exit(0 if all(results) else 1)

"""ปิดบัง Secret และข้อมูลส่วนตัวในข้อความ ก่อนส่งให้ AI หรือแนบใน Issue"""

import re
import sys

# (ชื่อกฎ, Pattern, ข้อความที่ใช้แทน) เรียงจากกฎที่เจาะจงที่สุดไปกว้างที่สุด
RULES = [
    ("API Key แบบ sk-", re.compile(r"\bsk-[A-Za-z0-9_-]{16,}"), "[REDACTED_API_KEY]"),
    ("GitHub Token", re.compile(r"\bgh[pousr]_[A-Za-z0-9]{36,}"), "[REDACTED_GITHUB_TOKEN]"),
    ("AWS Access Key ID", re.compile(r"\bAKIA[0-9A-Z]{16}\b"), "[REDACTED_AWS_KEY]"),
    (
        "ค่าลับแบบ KEY=VALUE",
        # ชื่อที่มีคำว่า password/secret/token/api_key ตามด้วย = หรือ : แล้วค่า (มีเครื่องหมายคำพูดก็ได้)
        # (?!\[REDACTED_) กันไม่ให้นับซ้ำค่าที่กฎก่อนหน้าปิดบังไปแล้ว
        re.compile(
            r"(?i)\b(\w*(?:password|passwd|secret|token|api_key)\w*)"
            r"((?:['\"]\])?\s*[=:]\s*)(['\"]?)(?!\[REDACTED_)[^\s'\"]+\3"
        ),
        r"\1\2\3****\3",
    ),
    ("Email", re.compile(r"\b[\w.+-]+@[\w-]+(?:\.[\w-]+)+\b"), "[REDACTED_EMAIL]"),
]


def redact(text: str) -> tuple[str, int]:
    """คืนข้อความที่ปิดบังแล้ว และจำนวนจุดที่ถูกปิดบัง"""
    total = 0
    for _name, pattern, replacement in RULES:
        text, count = pattern.subn(replacement, text)
        total += count
    return text, total

  • ทุกแพ็กเกจใหม่ที่ AI เสนอต้องผ่าน 4 ข้อก่อนติดตั้ง: มีอยู่จริง, อายุและจำนวนเวอร์ชันสมเหตุสมผล, มี Source และผู้ดูแลที่ตรวจสอบได้, License ใช้กับงานของเราได้
  • Pin เวอร์ชันใน requirements.txt และรัน pip-audit ทั้งในเครื่องและใน CI (แนวคิดที่ 12)

  • ส่งทุก Log และ Error ผ่าน redact.py แล้วอ่านทวนด้วยตาก่อนวางให้ AI

import os
import re
import sys

from tools.redact import redact

MODEL = os.environ.get("CLAUDE_MODEL", "claude-opus-5-5")

CHECKLIST = """รีวิว Diff ด้านล่างตาม Checklist นี้ ตอบเป็นภาษาไทย ระบุไฟล์และบรรทัดทุกข้อ
1. ตรงกับ Spec และไม่แก้เกินขอบเขต
2. SQL ที่ต่อ String เอง (เสี่ยง SQL Injection)
3. Secret หรือรหัสผ่านที่เขียนไว้ในโค้ด
4. subprocess ที่ใช้ shell=True และการเปิด debug=True
5. การแก้ไฟล์ใน tests/ เพื่อให้ Test ผ่านง่ายขึ้น
6. Dependency ใหม่ที่ไม่ได้ขอ
ข้อไหนไม่พบปัญหาให้เขียนว่า "ไม่พบ" ห้ามเดาปัญหาที่ไม่มีหลักฐานใน Diff"""

# กฎของโหมดจำลอง: ตรวจเฉพาะบรรทัดที่ถูกเพิ่ม (ขึ้นต้นด้วย +) ผลจึงเหมือนเดิมทุกครั้งที่รัน
MOCK_RULES = [
    (
        re.compile(r"f[\"'].*\b(SELECT|INSERT|UPDATE|DELETE)\b", re.IGNORECASE),
        "ต่อ SQL ด้วย f-string เสี่ยง SQL Injection",
    ),
    (re.compile(r"shell\s*=\s*True"), "subprocess ใช้ shell=True เสี่ยง Command Injection"),
    (re.compile(r"debug\s*=\s*True"), "เปิด debug=True ห้ามใช้ใน Production"),
    (
        re.compile(r"(?i)\w*(password|secret|token|api_key)\w*['\"]?\]?\s*=\s*['\"]"),
        "Secret เขียนไว้ในโค้ด ให้ย้ายไป Environment Variable",
    ),
]


def mock_review(diff: str) -> list[str]:
    """รีวิวด้วยกฎตายตัวในเครื่อง ใช้แทน AI เมื่อไม่มี API Key"""
    findings = []
    path, line_no = "?", 0
    for line in diff.splitlines():
        if line.startswith("+++ "):
            path = line.removeprefix("+++ b/")
            if path.startswith("tests/"):
                findings.append(f"{path}: มีการแก้ไฟล์ Test ตรวจว่าไม่ได้แก้ให้ Test ผ่านง่ายขึ้น")
            continue
        if line.startswith("@@"):
            # หัว Hunk เช่น @@ -10,6 +13,14 @@ แปลว่าบรรทัดใหม่เริ่มที่บรรทัด 13
            line_no = int(re.search(r"\+(\d+)", line).group(1)) - 1
            continue
        if line.startswith("-"):
            continue
        line_no += 1
        if line.startswith("+"):
            for pattern, message in MOCK_RULES:
                if pattern.search(line):
                    findings.append(f"{path}:{line_no}: {message}")
    return findings


def claude_review(diff: str) -> str:
    """ส่ง Diff ที่ปิดบัง Secret แล้วให้ Claude รีวิว (โหมดจริง)"""
    import anthropic  # import เฉพาะโหมดจริง โหมดจำลองจึงไม่ต้องติดตั้งแพ็กเกจนี้

    client = anthropic.Anthropic()  # อ่าน ANTHROPIC_API_KEY จาก Environment Variable
    try:
        response = client.messages.create(
            model=MODEL,
            max_tokens=16000,
            system="คุณคือ Senior Python Reviewer ที่เข้มงวด ตอบเป็นภาษาไทย",
            messages=[{"role": "user", "content": f"{CHECKLIST}\n\n```diff\n{diff}\n```"}],
        )
    except anthropic.AuthenticationError:
        return "[ERROR] API Key ไม่ถูกต้อง ตรวจค่า ANTHROPIC_API_KEY"
    except anthropic.RateLimitError:
        return "[ERROR] เรียกถี่เกินกำหนด รอสักครู่แล้วลองใหม่"
    except anthropic.APIStatusError as e:
        return f"[ERROR] API ตอบกลับด้วยสถานะ {e.status_code}"
    except anthropic.APIConnectionError:
        return "[ERROR] เชื่อมต่อ API ไม่ได้ ตรวจการเชื่อมต่ออินเทอร์เน็ต"
    if response.stop_reason == "refusal":
        return "[ERROR] โมเดลปฏิเสธคำขอนี้"
    text = "".join(block.text for block in response.content if block.type == "text")
    if response.stop_reason == "max_tokens":
        text += "\n[คำเตือน] คำตอบถูกตัด เพราะใช้ครบ max_tokens"
    return text


def main() -> int:
    if len(sys.argv) > 1:
        with open(sys.argv[1], encoding="utf-8") as f:
            diff = f.read()
    else:
        diff = sys.stdin.read()
    if not diff.strip():
        print("ไม่มี Diff ให้รีวิว (ลืม git add หรือเปล่า)")
        return 0
    safe_diff, hidden = redact(diff)
    print(f"[ai_review] ปิดบัง Secret ก่อนส่ง {hidden} จุด")
    if os.environ.get("ANTHROPIC_API_KEY"):

    findings = mock_review(safe_diff)
    for item in findings:
        print(" -", item)
    print(f"พบ {len(findings)} ประเด็นที่ต้องให้คนตรวจต่อ")
    return 1 if findings else 0
