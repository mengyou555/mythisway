Mini Project: Interactive Quiz App

เป้าหมายของโปรเจกต์

สร้างเว็บแอป Quiz ทดสอบความรู้ JavaScript 10 ข้อด้วย HTML, CSS และ JavaScript ล้วน ไม่มี Framework ไม่มี Bundler และไม่มีแพ็กเกจ npm ตอนรันจริง (Runtime dependency) แอปโหลดคำถามจากไฟล์ JSON ด้วย fetch วาดหน้าจอจาก state ด้วย DOM รับคำตอบได้ทั้งการคลิกและการกดปุ่ม 1 ถึง 4 จับเวลาข้อละ 15 วินาที และจำคะแนนสูงสุดไว้ใน localStorage

สิ่งที่ทำให้โปรเจกต์นี้ "ใส่ Portfolio ได้" ไม่ใช่ความยาวของโค้ด แต่เป็นวิธีออกแบบ: เราแยก Logic ที่ไม่แตะ DOM (src/quiz.js และ src/storage.js) ออกจากส่วนที่แตะหน้าจอ (src/main.js) ทำให้เขียน Unit test ได้ 16 Test โดยไม่ต้องเปิดเบราว์เซอร์ ผู้สัมภาษณ์งานมักถามเรื่องนี้โดยตรง และโปรเจกต์นี้ให้คุณมีตัวอย่างจริงไว้เล่า

เปรียบเทียบ

ให้นึกถึงร้านอาหาร quiz.js คือห้องครัวที่มีสูตรชัดเจน รับวัตถุดิบ (state เดิม) แล้วส่งจานใหม่ออกมา (state ใหม่) โดยไม่สนว่าลูกค้านั่งโต๊ะไหน ส่วน main.js คือพนักงานหน้าร้านที่รับออร์เดอร์ (Event) ไปส่งครัว แล้วนำจานไปเสิร์ฟ (Render) เราตรวจคุณภาพครัวได้โดยไม่ต้องเปิดร้าน ซึ่งก็คือการรัน Unit test โดยไม่ต้องเปิดเบราว์เซอร์

ความสามารถ (Features)

  • โหลดคำถามด้วย fetch จาก data/questions.json ด้วย Path แบบ Relative เช็ก response.ok มีหน้าจอ "กำลังโหลด" และหน้าจอ Error ที่มีปุ่ม "ลองใหม่"
  • ตรวจรูปแบบข้อมูล ด้วย validateQuestions() ถ้าไฟล์ JSON ผิดรูปแบบจะแจ้ง TypeError เป็นภาษาไทย แทนที่จะพังกลางเกม
  • 3 หน้าจอหลัก (เริ่ม, คำถาม, สรุปผล) และหน้าจอเสริมอีก 2 แบบ (กำลังโหลด, Error) สลับด้วย attribute hidden
  • ตอบได้ 2 วิธี คลิกปุ่มตัวเลือก (Event delegation บน #choices) หรือกดปุ่ม 1 ถึง 4
  • จับเวลาข้อละ 15 วินาที ด้วย setInterval และ clearInterval แสดงทั้งตัวเลขและแถบ <progress> หมดเวลานับว่าผิด
  • แสดงผลถูก/ผิดแบบไม่พึ่งสีอย่างเดียว ใช้ทั้งสี เส้นขอบ (ผิดเป็นเส้นประ) และข้อความ "✓ ถูกต้อง" หรือ "✗ ผิด คำตอบที่ถูกคือ ..." ในพื้นที่ aria-live="polite"
  • จัดการ Focus ย้าย Focus ไปที่หัวข้อคำถามทุกครั้งที่ขึ้นข้อใหม่ ผู้ใช้คีย์บอร์ดและ Screen reader ใช้งานได้ครบ
  • สรุปคะแนน แสดงคะแนน เปอร์เซ็นต์ และคะแนนสูงสุด พร้อมปุ่ม "เล่นอีกครั้ง"
  • คะแนนสูงสุดอยู่ถาวร ใน localStorage ที่ Key quiz-app:highscore ปิดเบราว์เซอร์แล้วเปิดใหม่ก็ยังอยู่ ถ้าข้อมูลเสียหรือใช้ storage ไม่ได้ แอปไม่พัง
  • Responsive แบบ Mobile-first ด้วย Flexbox มือถือเรียงตัวเลือก 1 คอลัมน์ จอกว้างตั้งแต่ 600px เรียง 2 คอลัมน์ และปิด Transition เมื่อผู้ใช้ตั้งค่า prefers-reduced-motion
  • Unit test 16 Test ใน 2 ไฟล์ ด้วย node:test และ node:assert/strict ที่ติดมากับ Node.js ไม่ต้องติดตั้งอะไรเพิ่ม

ภาพรวมการทำงานของแอป

ก่อนเริ่มเขียน ให้เข้าใจเส้นทางของข้อมูลก่อน ทุกอย่างวนอยู่ในรูปแบบเดียวกันคือ "Event เกิดขึ้น → เรียกฟังก์ชันใน quiz.js ได้ state ใหม่ → Render หน้าจอจาก state"

  1. เปิดหน้าเว็บ main.js เรียก loadQuestions() ซึ่ง fetch('data/questions.json') แล้วตรวจด้วย validateQuestions()
  2. โหลดสำเร็จ แสดงหน้าจอเริ่มพร้อมคะแนนสูงสุดจาก loadHighScore() โหลดไม่สำเร็จ แสดงหน้าจอ Error พร้อมปุ่ม "ลองใหม่"
  3. กด "เริ่มทำ Quiz" เรียก createQuiz(questions) ได้ state เริ่มต้น แล้ว renderQuestion() และเริ่มจับเวลา
  4. ผู้ใช้คลิกหรือกด 1 ถึง 4 เรียก answer(state, index) ถ้าหมดเวลาก่อนเรียก timeout(state) แล้ว showFeedback()
  5. กด "ข้อต่อไป" เรียก next(state) ถ้า finished เป็น true ไปหน้าสรุปผลและเรียก saveHighScore()

  5. Step 5: เขียน Logic ล้วนใน src/quiz.js (ไม่แตะ DOM)

    นี่คือหัวใจของแอป ทุกฟังก์ชันในไฟล์นี้เป็น Pure function หรือใกล้เคียง คือรับค่าเข้าไป แล้วคืนค่าใหม่ออกมา ไม่แก้ตัวแปรภายนอก ไม่แตะ document และไม่แตะ localStorage หลักสำคัญมี 2 ข้อ

    • Dependency injection: ฟังก์ชันที่ต้องใช้ค่าที่เปลี่ยนทุกครั้ง เช่น การสุ่มหรือเวลาปัจจุบัน จะรับค่านั้นเป็น Parameter (random, nowMs) Test จึงส่งค่าคงที่เข้าไปแล้วได้ผลเดิมทุกครั้ง

// ทุกฟังก์ชันรับ state เดิมแล้วคืน state ใหม่ (Immutable) จึงทดสอบด้วย node:test ได้ง่าย

// เวลาต่อข้อ (วินาที)
export const TIME_LIMIT = 15;

// ตรวจรูปแบบข้อมูลคำถามที่โหลดมา ถ้าผิดให้โยน TypeError พร้อมข้อความภาษาไทย
export function validateQuestions(data) {
  if (!Array.isArray(data)) {
    throw new TypeError('ข้อมูลคำถามต้องเป็น Array');
  }
  if (data.length === 0) {
    throw new TypeError('ต้องมีคำถามอย่างน้อย 1 ข้อ');
  }
  data.forEach((q, i) => {
    const isValid =
      q !== null &&
      typeof q === 'object' &&
      typeof q.question === 'string' &&
      q.question.trim() !== '' &&
      Array.isArray(q.choices) &&
      q.choices.length === 4 &&
      q.choices.every((choice) => typeof choice === 'string') &&
      Number.isInteger(q.answer) &&
      q.answer >= 0 &&
      q.answer < q.choices.length;
    if (!isValid) {
      throw new TypeError(`คำถามลำดับที่ ${i + 1} มีรูปแบบไม่ถูกต้อง`);
    }
  });
  return data;
}

// สลับลำดับแบบ Fisher-Yates คืน Array ใหม่ ไม่แก้ Array เดิม
// รับ random เป็น Parameter เพื่อให้ Test ส่งฟังก์ชันสุ่มปลอมที่ได้ผลเดิมทุกครั้งได้
export function shuffle(array, random = Math.random) {
  const result = [...array];
  for (let i = result.length - 1; i > 0; i -= 1) {
    const j = Math.floor(random() * (i + 1));
    [result[i], result[j]] = [result[j], result[i]];
  }
  return result;
}

// สร้าง state เริ่มต้นของ Quiz
export function createQuiz(questions, { shuffle: shouldShuffle = false, random = Math.random } = {}) {
  validateQuestions(questions);
  const list = shouldShuffle ? shuffle(questions, random) : [...questions];
  return { questions: list, index: 0, score: 0, answers: [], finished: false };
}

// คำถามข้อปัจจุบัน หรือ null เมื่อจบแล้ว
export function currentQuestion(state) {
  if (state.finished) {
    return null;
  }
  return state.questions[state.index] ?? null;
}

// ข้อปัจจุบันตอบไปแล้วหรือยัง (จำนวนคำตอบมากกว่า index แปลว่าตอบแล้ว)
export function isAnswered(state) {
  return state.answers.length > state.index;
}

// บันทึกคำตอบ คืน state ใหม่ คำตอบล่าสุดอยู่ที่ answers.at(-1) ซึ่งมี correct เป็น true หรือ false
export function answer(state, choiceIndex) {
  if (state.finished) {
    throw new Error('Quiz จบแล้ว ตอบเพิ่มไม่ได้');
  }
  if (isAnswered(state)) {
    throw new Error('ข้อนี้ตอบไปแล้ว');
  }
  const question = currentQuestion(state);
  const correct = choiceIndex === question.answer;
  return {
    ...state,
    score: correct ? state.score + 1 : state.score,
    answers: [...state.answers, { id: question.id, choice: choiceIndex, correct }],
  };
}

// หมดเวลา: บันทึกคำตอบเป็น null และนับว่าผิด
export function timeout(state) {
  return answer(state, null);
}

// ไปข้อถัดไป ถ้าเป็นข้อสุดท้ายแล้วให้ finished เป็น true
export function next(state) {
  if (!isAnswered(state)) {
    throw new Error('ต้องตอบข้อนี้ก่อนไปข้อถัดไป');
  }
  const nextIndex = state.index + 1;
  return {
    ...state,
    index: nextIndex,
    finished: nextIndex >= state.questions.length,
  };
}

// คำนวณเปอร์เซ็นต์ ปัดเป็นจำนวนเต็ม (กติกาเดียวกับ score.js ใน Part 1)
export function percent(score, total) {
  if (!Number.isInteger(total) || total <= 0) {
    throw new RangeError('total ต้องเป็นจำนวนเต็มที่มากกว่า 0');
  }
  return Math.round((score / total) * 100);
}

// เวลาที่เหลือเป็นวินาที ไม่ต่ำกว่า 0 และไม่เกิน limit
export function remainingSeconds(startedAtMs, nowMs, limit = TIME_LIMIT) {
  const elapsed = Math.floor((nowMs - startedAtMs) / 1000);
  return Math.min(limit, Math.max(0, limit - elapsed));
}

// รับ storage เป็น Parameter: ในเบราว์เซอร์ใช้ localStorage ใน Test ใช้ที่เก็บจำลอง
import { percent } from './quiz.js';

// ใส่ชื่อแอปนำหน้า Key เพื่อไม่ให้ชนกับแอปอื่นใน Origin เดียวกัน
export const HIGH_SCORE_KEY = 'quiz-app:highscore';

// คืน localStorage ถ้าใช้ได้ ถ้าไม่มี (เช่นรันใน Node.js) หรือถูกบล็อกให้คืน null
function defaultStorage() {
  try {
    return globalThis.localStorage ?? null;
  } catch {
    return null;
  }
}

// อ่านคะแนนสูงสุด ถ้าไม่มี ข้อมูลเสีย หรือค่าติดลบ ให้คืน 0
export function loadHighScore(storage = defaultStorage()) {
  try {
    const raw = storage?.getItem(HIGH_SCORE_KEY);
    if (raw === null || raw === undefined) {
      return 0;
    }
    const data = JSON.parse(raw);
    const score = data?.score;
    return Number.isInteger(score) && score >= 0 ? score : 0;
  } catch {
    // JSON เสียหรืออ่าน storage ไม่ได้ เริ่มนับใหม่จาก 0 แทนการทำให้แอปพัง
    return 0;
  }
}

// บันทึกเฉพาะเมื่อคะแนนใหม่สูงกว่าเดิม แล้วคืนคะแนนสูงสุดล่าสุด
// date รับเข้ามาได้ เพื่อให้ Test ใช้วันที่คงที่
export function saveHighScore(
  score,
  storage = defaultStorage(),
  { total = null, date = new Date().toISOString().slice(0, 10) } = {},
) {
  const current = loadHighScore(storage);
  if (!Number.isInteger(score) || score <= current) {
    return current;
  }
  const record = {
    score,
    percent: total === null ? null : percent(score, total),
    date,
  };
  try {
    storage?.setItem(HIGH_SCORE_KEY, JSON.stringify(record));
  } catch (error) {
    // เช่น โหมดส่วนตัวบางเบราว์เซอร์ หรือพื้นที่เต็ม: แจ้งใน Console แต่ไม่ทำให้เกมพัง
    console.warn('บันทึกคะแนนสูงสุดไม่สำเร็จ:', error.message);
  }
  return score;
}

## ความสามารถ

- โหลดคำถามจาก `data/questions.json` ด้วย `fetch` พร้อมหน้าจอ Loading และ Error ที่กด "ลองใหม่" ได้

- จับเวลาข้อละ 15 วินาที หมดเวลานับว่าผิด
- แสดงผลถูก/ผิดด้วยทั้งสีและข้อความ พร้อมเฉลย
- เก็บคะแนนสูงสุดใน `localStorage` (Key: `quiz-app:highscore`)
- รองรับ Screen reader (`aria-live`, ย้าย Focus) และผู้ที่ตั้งค่าลดการเคลื่อนไหว
- Responsive ด้วย Flexbox (มือถือ 1 คอลัมน์ จอกว้าง 2 คอลัมน์)

## เทคโนโลยีที่ใช้

## โครงสร้างโค้ด

- `src/quiz.js` Logic ล้วน ไม่แตะ DOM ทุกฟังก์ชันคืน state ใหม่ (Immutable)
- `src/storage.js` อ่านและบันทึกคะแนนสูงสุด รับ storage เป็น Parameter เพื่อให้ทดสอบได้
- `src/main.js` ต่อ state เข้ากับหน้าจอ: fetch, render, events, timer

## สิ่งที่ได้เรียนรู้

- แยก Logic ออกจาก DOM ทำให้เขียน Unit test ได้โดยไม่ต้องเปิดเบราว์เซอร์
- Event delegation ด้วย `closest()` ทำให้ปุ่มที่สร้างใหม่ทุกข้อทำงานได้โดยไม่ต้องผูก Event ซ้ำ

- (เขียนเพิ่มเองว่าติดปัญหาอะไรและแก้อย่างไร)

1. == กับ === ต่างกันอย่างไร และคุณใช้แบบไหน (Junior)

คำตอบที่ดี: === (Strict equality) เปรียบเทียบทั้งค่าและชนิดข้อมูล ถ้าชนิดต่างกันได้ false ทันที ส่วน == (Loose equality) จะพยายามแปลงชนิดข้อมูลให้ตรงกันก่อน (Type coercion) แล้วค่อยเทียบ ทำให้ได้ผลที่คาดเดายาก ผมใช้ === เสมอ และตั้ง ESLint กฎ eqeqeq ไว้กันเผลอ

ประเด็นสำคัญที่ควรพูดถึง

  • ตัวอย่างที่ == ให้ผลแปลก: 0 == '' ได้ true, [] == false ได้ true
  • กรณีพิเศษ: null == undefined ได้ true บางทีมยอมให้ใช้ x == null เพื่อเช็กทั้งสองค่าในครั้งเดียว แต่ x ?? fallback หรือ x === null || x === undefined อ่านชัดกว่า
  • NaN ไม่เท่ากับอะไรเลย แม้แต่ตัวเอง ต้องใช้ Number.isNaN()
  • การเปรียบเทียบ Object เทียบว่าเป็นตัวเดียวกันในหน่วยความจำ (Reference) ไม่ได้เทียบเนื้อหา
console.log(0 == '', null == undefined, [] == false, '5' === 5, NaN === NaN);

โยงกับโปรเจกต์: ใน Quiz App ฟังก์ชัน answer() ใช้ choiceIndex === question.answer ถ้าใช้ == แล้วค่าที่มาจาก dataset เป็น String '2' ก็จะเทียบผ่านโดยบังเอิญ และซ่อน Bug ที่ลืมแปลงชนิดไว้ ผมจึงแปลงด้วย Number(button.dataset.index) ก่อนเสมอ

2. Closure คืออะไร ยกตัวอย่างการใช้งานจริง (Junior ถึง Mid)

คำตอบที่ดี: Closure คือการที่ฟังก์ชันยังเข้าถึงตัวแปรใน Scope ที่มันถูกสร้างขึ้นได้ แม้ฟังก์ชันภายนอกจะทำงานจบไปแล้ว เพราะ JavaScript ใช้ Lexical scope คือ Scope ถูกกำหนดจากตำแหน่งที่เขียนโค้ด ไม่ใช่จากตำแหน่งที่เรียกใช้

// count อยู่ใน Scope ของ makeCounter ภายนอกเข้าถึงตรง ๆ ไม่ได้
function makeCounter() {
  let count = 0;
  return {
    increment: () => ++count,
    get: () => count,
  };
}

const a = makeCounter();
a.increment();
a.increment();
const b = makeCounter(); // ได้ count ชุดใหม่ แยกจาก a
b.increment();
console.log(a.get(), b.get(), typeof count);

  • ใช้ทำ Private state (ข้อมูลที่ภายนอกแก้ไม่ได้) ก่อนจะมี Private field # ใน Class
  • ใช้ใน Event handler และ Callback ทุกวัน เช่น Callback ของ setInterval ใน Quiz App ที่จำ startedAt ไว้
  • ใช้ทำ Function factory เช่น once(), debounce, หรือฟังก์ชันที่ตั้งค่าไว้ล่วงหน้า
  • ข้อควรระวัง: Closure ถือตัวแปรไว้ในหน่วยความจำตราบที่ฟังก์ชันยังถูกอ้างอิง ถ้าผูก Listener แล้วไม่ถอด อาจเกิด Memory leak ได้
3. Event delegation คืออะไร ทำไมต้องใช้ (Junior ถึง Mid)

คำตอบที่ดี: Event delegation คือการผูก Event listener ตัวเดียวไว้ที่ Element แม่ แทนการผูกที่ลูกทุกตัว แล้วอาศัย Event bubbling ที่ Event จากลูกจะลอยขึ้นไปหาแม่ ในฟังก์ชันจัดการ เราใช้ event.target.closest(selector) หาว่าลูกตัวไหนถูกคลิกจริง

ข้อดีที่ควรพูดถึง

  • Element ที่สร้างใหม่ภายหลังทำงานได้ทันทีโดยไม่ต้องผูก Event ใหม่ เหมาะกับหน้าที่ Render จากข้อมูลซ้ำ ๆ
  • ใช้หน่วยความจำน้อยกว่า เพราะมี Listener ตัวเดียวแทนหลายร้อยตัว
  • โค้ดรวมอยู่ที่เดียว อ่านและแก้ง่าย

ข้อควรระวัง: event.target อาจเป็น Element ข้างในปุ่ม เช่น <span> จึงต้องใช้ closest() และต้องเช็กว่าผลไม่ใช่ null ส่วน Event บางชนิดไม่ Bubble เช่น focus และ blur ต้องใช้ focusin และ focusout แทน

// ฟังที่ #choices ตัวเดียว ใช้ได้กับปุ่มของทุกข้อที่สร้างใหม่
document.querySelector('#choices').addEventListener('click', (event) => {
  const button = event.target.closest('button[data-index]');
  if (button && !button.disabled) {
    handleAnswer(Number(button.dataset.index));
  }
});

โยงกับโปรเจกต์: Quiz App สร้างปุ่มตัวเลือกใหม่ทุกข้อด้วย replaceChildren() ถ้าผูก Listener ที่ปุ่มโดยตรง ต้องผูกใหม่ทุกข้อและเสี่ยงลืม การใช้ Delegation ทำให้ผูกครั้งเดียวตอนโหลดหน้า

4. อธิบาย Event loop และความต่างระหว่าง Microtask กับ Macrotask (Mid)

คำตอบที่ดี: JavaScript รันบน Thread เดียว มี Call stack เดียว งานที่ต้องรอ เช่น Timer หรือ Network จะถูกส่งให้ Web APIs (ในเบราว์เซอร์) หรือ libuv (ใน Node.js) ทำแทน เมื่อเสร็จแล้ว Callback จะเข้าคิว Event loop จะหยิบงานจากคิวมาใส่ Call stack เมื่อ Stack ว่างเท่านั้น

มีคิวสำคัญ 2 แบบ Microtask queue คือ Callback ของ Promise (then, catch, finally, โค้ดหลัง await) และ queueMicrotask กับ Macrotask queue (Task queue) คือ setTimeout, setInterval, Event จากผู้ใช้ และ I/O กติกาคือ หลังโค้ด Sync จบ Event loop จะล้าง Microtask ทั้งหมดจนว่างก่อน แล้วจึงหยิบ Macrotask มาทำทีละ 1 งาน

// คำถามข้อ 4: ลำดับของ Event loop
console.log('1 sync');
setTimeout(() => console.log('4 setTimeout (macrotask)'), 0);
Promise.resolve().then(() => console.log('3 promise (microtask)'));
console.log('2 sync');

ประเด็นสำคัญที่ควรพูดถึง

  • setTimeout(fn, 0) ไม่ได้แปลว่าทำทันที แต่แปลว่า "ไม่เร็วกว่า 0 มิลลิวินาที และหลังจาก Microtask ทั้งหมด"
  • โค้ด Sync ที่ใช้เวลานาน (เช่น Loop คำนวณหนัก ๆ) จะบล็อกทุกอย่าง หน้าเว็บค้างและ Timer ไม่ตรง
  • ถ้าสร้าง Microtask ต่อกันไม่รู้จบ เบราว์เซอร์จะไม่ได้วาดหน้าจอเลย (Starvation)

โยงกับโปรเจกต์: Timer ใน Quiz App ไม่นับจำนวนครั้งที่ setInterval ทำงาน แต่คำนวณจาก Date.now() เพราะ Macrotask อาจมาช้ากว่ากำหนดเมื่อ Thread ไม่ว่างหรือแท็บอยู่เบื้องหลัง

5. var, let และ const ต่างกันอย่างไร และ Hoisting คืออะไร (Junior)

คำตอบที่ดี: ต่างกัน 3 เรื่อง

  • Scope: var เป็น Function scope ส่วน let และ const เป็น Block scope (อยู่แค่ใน { } ที่ประกาศ)
  • การกำหนดค่าใหม่: const กำหนดค่าใหม่ไม่ได้ แต่ถ้าเป็น Object หรือ Array ยังแก้เนื้อหาข้างในได้ let และ var กำหนดค่าใหม่ได้
  • Hoisting: ทุกการประกาศถูก "ยกขึ้น" ไปต้น Scope ตอนเตรียมรันโค้ด แต่ var ถูกตั้งค่าเริ่มต้นเป็น undefined ส่วน let และ const อยู่ใน Temporal Dead Zone (TDZ) จนถึงบรรทัดที่ประกาศ ถ้าเข้าถึงก่อนจะได้ ReferenceError ส่วน Function declaration ถูกยกขึ้นทั้งฟังก์ชัน เรียกใช้ก่อนบรรทัดที่ประกาศได้
// ตัวอย่างเดียวในหลักสูตรที่ใช้ var เพื่อแสดงความต่าง

Loop ที่ใช้ var พิมพ์ 3 สามครั้ง เพราะทั้ง 3 Callback ใช้ตัวแปร i ตัวเดียวกัน ซึ่งเป็น 3 แล้วตอน Timer ทำงาน ส่วน let สร้างตัวแปร j ใหม่ทุกรอบของ Loop แต่ละ Callback จึงจำค่าของรอบตัวเอง (นี่คือ Closure อีกตัวอย่างหนึ่ง)

ปิดท้ายคำตอบ: ผมใช้ const เป็นค่าเริ่มต้น ใช้ let เมื่อต้องกำหนดค่าใหม่จริง ๆ เช่นตัวนับ หรือ state ใน Quiz App และไม่ใช้ var ในโค้ดใหม่เลย
