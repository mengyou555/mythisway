Mini Project: Expense Tracker CLI

เป้าหมาย

สร้างโปรแกรมบันทึกค่าใช้จ่ายส่วนตัวชื่อ Expense Tracker CLI ที่รันด้วยคำสั่ง python3 -m expense_tracker บน Ubuntu 24.04 (WSL2) โปรแกรมเก็บข้อมูลในไฟล์ data/expenses.csv ซึ่งเปิดดูด้วย Excel หรือ Text editor ได้ทันที รองรับ 6 Subcommand คือ add, list, edit, delete, summary และ export

โปรเจกต์นี้ตั้งใจให้หน้าตาเหมือนงานจริงในบริษัท ไม่ใช่สคริปต์ไฟล์เดียว คือแยกโค้ดเป็น Package หลาย Module ตามหน้าที่ ตรวจ Input ทุกช่องแล้วแสดงข้อความภาษาไทยที่เข้าใจง่ายแทน Traceback คืน Exit code ที่ถูกต้องเพื่อให้สคริปต์อื่นเรียกใช้ต่อได้ ใช้ Decimal แทน float เพื่อให้ยอดเงินไม่คลาดเคลื่อน มีชุดทดสอบ pytest 27 กรณีที่รันจบในเสี้ยววินาที และผ่าน ruff check กับ ruff format --check ทั้งหมด

เมื่อทำเสร็จ คุณจะมี Repository บน GitHub ที่แสดงให้ผู้สัมภาษณ์เห็นว่าคุณออกแบบโครงสร้างโปรแกรมได้ เขียน Test ได้ จัดการไฟล์และข้อผิดพลาดเป็น และใช้เครื่องมือมาตรฐานของวงการ Python ได้ ซึ่งเป็นทักษะพื้นฐานของทุกสายที่ใช้ Python ตั้งแต่ Backend, Data ไปจนถึง Automation

Features

  • add เพิ่มรายการด้วย --date YYYY-MM-DD (ไม่ใส่จะใช้วันนี้), --category (เลือกได้เฉพาะ 7 หมวด), --amount (ต้องมากกว่า 0 และมีทศนิยมไม่เกิน 2 ตำแหน่ง) และ --note (ไม่บังคับ) id ใหม่คือ id มากที่สุดที่มีอยู่บวก 1
  • list แสดงตารางที่จัดคอลัมน์ตรงกัน (id, date, category, amount, note) กรองด้วย --month YYYY-MM และ --category ได้ พร้อมบรรทัดยอดรวมท้ายตาราง
  • edit ID แก้เฉพาะช่องที่ระบุ ช่องที่ไม่ระบุคงค่าเดิม ถ้าไม่พบ id จะแสดง ไม่พบรายการ id 99 และจบด้วย Exit code 1
  • delete ID ลบรายการเดียว ถ้าไม่พบ id จบด้วย Exit code 1
  • summary --month YYYY-MM สรุปยอดรายหมวด เรียงจากมากไปน้อย พร้อมยอดรวมของเดือน ข้อมูลตัวอย่างเดือน 2026-10 ให้ผล bills 1,250.50 / shopping 299.00 / food 185.00 / transport 184.00 / health 85.00 / รวม 2,003.50 บาท
  • export --output FILE ส่งออกเป็น JSON ที่อ่านภาษาไทยออก (ensure_ascii=False, indent=2) เก็บจำนวนเงินเป็นข้อความ เช่น "1250.50" เพื่อไม่ให้เสียความแม่นยำ และสร้างโฟลเดอร์ปลายทางให้เอง
  • Validation: วันที่ผิดรูปแบบ จำนวนเงินติดลบหรือทศนิยมเกิน เดือนผิดรูปแบบ แถวเสียในไฟล์ CSV ทุกกรณีแสดงข้อความภาษาไทยทาง stderr และจบด้วย Exit code 1 ส่วนหมวดหมู่ที่ไม่มีในระบบให้ argparse จัดการ (Exit code 2) ผู้ใช้ไม่เห็น Traceback เลย
  • ตั้งค่าไฟล์ข้อมูลได้ 3 ระดับ: Option --file มาก่อน ถัดมาคือ Environment Variable EXPENSES_FILE และค่าเริ่มต้นคือ data/expenses.csv
  • Test และ Tooling: pytest 27 กรณีใน 4 ไฟล์ ใช้ tmp_path จึงไม่แตะข้อมูลจริง ตั้งค่า pytest กับ ruff ใน pyproject.toml และติดตั้งเครื่องมือจาก requirements.txt ที่ Pin เวอร์ชันไว้ทุกตัว

            f"เดือนต้องอยู่ในรูปแบบ YYYY-MM เช่น 2026-10 (ได้รับ '{text}')"
        ) from None
    return text.strip()


def parse_amount(text: str) -> Decimal:
    """แปลงข้อความเป็น Decimal ที่มากกว่า 0 และมีทศนิยมไม่เกิน 2 ตำแหน่ง"""
    try:
        amount = Decimal(text.strip())
    except InvalidOperation:
        raise ValidationError(
            f"จำนวนเงินต้องเป็นตัวเลข เช่น 89.50 (ได้รับ '{text}')"
        ) from None
    if not amount.is_finite():
        raise ValidationError(f"จำนวนเงินต้องเป็นตัวเลขจริง (ได้รับ '{text}')")
    if amount <= 0:
        raise ValidationError(f"จำนวนเงินต้องมากกว่า 0 (ได้รับ '{text}')")
    if amount.as_tuple().exponent < -2:
        raise ValidationError(f"จำนวนเงินมีทศนิยมได้ไม่เกิน 2 ตำแหน่ง (ได้รับ '{text}')")
    # ปัดให้มีทศนิยม 2 ตำแหน่งเสมอ เช่น 89.5 -> 89.50
    return amount.quantize(Decimal("0.01"))

def load_expenses(path: Path) -> list[Expense]:
    """อ่านทุกรายการจาก CSV ถ้ายังไม่มีไฟล์ให้คืน list ว่าง"""
    if not path.exists():
        return []
    expenses: list[Expense] = []
    with path.open("r", encoding="utf-8", newline="") as f:
        reader = csv.DictReader(f)
        if reader.fieldnames != FIELDNAMES:
            raise ValidationError(f"หัวตารางของ {path} ต้องเป็น {','.join(FIELDNAMES)}")
        # start=2 เพราะบรรทัดที่ 1 คือหัวตาราง
        for line_no, row in enumerate(reader, start=2):
            try:
                expenses.append(Expense.from_row(row))
            except ValidationError as e:
                raise ValidationError(f"{path} บรรทัด {line_no}: {e}") from e
    return expenses


def save_expenses(path: Path, expenses: list[Expense]) -> None:

    path.parent.mkdir(parents=True, exist_ok=True)
    tmp_path = path.with_name(path.name + ".tmp")
    with tmp_path.open("w", encoding="utf-8", newline="") as f:
        writer = csv.DictWriter(f, fieldnames=FIELDNAMES)
        writer.writeheader()
        for expense in sorted(expenses, key=lambda e: e.id):
            writer.writerow(expense.to_row())

def filter_expenses(
    expenses: list[Expense],
    month: str | None = None,
    category: str | None = None,
) -> list[Expense]:
    """คืนเฉพาะรายการที่ตรงเดือน (YYYY-MM) และหมวดหมู่ที่ระบุ"""

def find_index(expenses: list[Expense], expense_id: int) -> int:
    """หาตำแหน่งของรายการใน list ถ้าไม่พบให้ raise ValidationError"""
    for index, expense in enumerate(expenses):
        if expense.id == expense_id:
            return index
    raise ValidationError(f"ไม่พบรายการ id {expense_id}")


def cmd_add(args: argparse.Namespace, path: Path) -> None:
    expenses = load_expenses(path)
    expense = Expense(
        id=next_id(expenses),
        date=parse_date(args.date) if args.date else date.today(),
        category=args.category,
        amount=parse_amount(args.amount),
        note=args.note.strip(),
    )
    expenses.append(expense)
    save_expenses(path, expenses)
    print(
        f"เพิ่มรายการ id {expense.id}: {expense.date} {expense.category} "
        f"{expense.amount:,.2f} บาท {expense.note}".rstrip()
    )

def cmd_edit(args: argparse.Namespace, path: Path) -> None:
    # เก็บเฉพาะช่องที่ผู้ใช้ส่งมาจริง (ค่า None แปลว่าไม่ต้องแก้)
    changes: dict[str, object] = {}
    if args.date is not None:
        changes["date"] = parse_date(args.date)
    if args.category is not None:
        changes["category"] = args.category
    if args.amount is not None:
        changes["amount"] = parse_amount(args.amount)
    if args.note is not None:
        changes["note"] = args.note.strip()
    if not changes:
        raise ValidationError("ต้องระบุอย่างน้อยหนึ่งช่อง: --date --category --amount --note")
    expenses = load_expenses(path)
    index = find_index(expenses, args.id)
    # dataclasses.replace สร้าง Object ใหม่และเรียก __post_init__ ตรวจซ้ำให้
    expenses[index] = dataclasses.replace(expenses[index], **changes)
    save_expenses(path, expenses)
    e = expenses[index]
    print(f"แก้ไข id {e.id} แล้ว: {e.date} {e.category} {e.amount:,.2f} บาท {e.note}")


def cmd_delete(args: argparse.Namespace, path: Path) -> None:
    expenses = load_expenses(path)
    removed = expenses.pop(find_index(expenses, args.id))
    save_expenses(path, expenses)
    print(f"ลบรายการ id {removed.id} ({removed.note or removed.category}) แล้ว")


def cmd_summary(args: argparse.Namespace, path: Path) -> None:

    rows = filter_expenses(load_expenses(path), month)
    if not rows:
        print(f"ไม่มีรายการในเดือน {month}")

  • list เรียงลำดับ แก้ไขได้ (Mutable) มีค่าซ้ำได้ ใช้กับข้อมูลหลายรายการที่ต้องเพิ่ม ลบ หรือเรียง เช่นรายการค่าใช้จ่ายทั้งหมด
  • tuple เรียงลำดับแต่แก้ไขไม่ได้ (Immutable) ใช้กับข้อมูลชุดที่ขนาดคงที่ เช่นพิกัด (13.7563, 100.5018) หรือค่าคืนหลายค่าจาก Function และใช้เป็น Key ของ dict ได้เพราะ Hash ได้
  • set ไม่มีค่าซ้ำและไม่สนลำดับ ใช้ตัดค่าซ้ำ หาส่วนร่วมหรือผลต่าง และตรวจ x in s ได้เร็วเฉลี่ย O(1)
  • dict เก็บคู่ Key-Value ค้นด้วย Key ได้เฉลี่ย O(1) เพราะใช้ Hash table ใช้เมื่อต้องค้นหาด้วยชื่อหรือ id เช่นยอดรวมรายหมวด {"food": Decimal("185.00")} และตั้งแต่ Python 3.7 dict รักษาลำดับการใส่ข้อมูล

จุดที่ทำให้คำตอบโดดเด่นคือพูดถึง Big-O: x in list ต้องไล่ทีละตัว O(n) ส่วน x in set หรือ key in dict เฉลี่ย O(1) ถ้าต้องค้นซ้ำหลายพันครั้ง การแปลง list เป็น set ก่อนจะเร็วกว่ามาก ซึ่งวัดได้จริงด้วย timeit (ตัวเลขเวลาต่างกันตามเครื่อง)

2. Mutable default argument คืออะไร ทำไมเป็น Bug และแก้อย่างไร (Junior–Mid)

คำตอบที่ดี: ค่า Default ของ Parameter ถูกสร้างครั้งเดียวตอนที่ Python รันคำสั่ง def ไม่ใช่ทุกครั้งที่เรียก Function ถ้าค่า Default เป็น Object ที่แก้ไขได้ เช่น list หรือ dict ทุกการเรียกที่ไม่ส่งค่ามาจะใช้ Object ตัวเดียวกัน ข้อมูลจึงสะสมข้ามการเรียก

def add_item_bad(item, basket=[]):
    # basket ตัวเดียวกันถูกใช้ซ้ำทุกครั้งที่ไม่ส่ง basket มา
    basket.append(item)
    return basket


print(add_item_bad("ชาไทย"))
print(add_item_bad("กาแฟ"))
python3 default_bug.py
['ชาไทย']
['ชาไทย', 'กาแฟ']

วิธีแก้มาตรฐานคือใช้ None เป็นค่า Default แล้วสร้าง Object ใหม่ข้างใน Function:

def add_item(item: str, basket: list[str] | None = None) -> list[str]:
    # สร้าง list ใหม่ทุกครั้งที่ผู้เรียกไม่ได้ส่ง basket มา
    if basket is None:
        basket = []
    basket.append(item)
    return basket

ควรเสริมว่า ruff ตรวจจับปัญหานี้ได้ด้วยกฎ B006 (กลุ่ม flake8-bugbear ที่เปิดไว้ในโปรเจกต์) และใน Dataclass ต้องใช้ field(default_factory=list) ด้วยเหตุผลเดียวกัน

3. ทำไมต้องใช้ Virtual Environment และ requirements.txt และ error externally-managed-environment คืออะไร (Junior)

คำตอบที่ดี:

  • Virtual Environment คือโฟลเดอร์ที่มี Python และ Package แยกเฉพาะโปรเจกต์ โปรเจกต์ A ใช้ pytest เวอร์ชันหนึ่ง และโปรเจกต์ B ใช้อีกเวอร์ชันได้โดยไม่ชนกัน และไม่ไปทำให้ Python ของระบบเสีย
  • requirements.txt ที่ Pin เวอร์ชัน (เช่น pytest==9.1.1) ทำให้เพื่อนร่วมทีม เครื่อง CI และ Server ติดตั้ง Package ชุดเดียวกันทุกครั้ง ปัญหา "เครื่องผมรันได้" จึงลดลง
  • error: externally-managed-environment เกิดบน Ubuntu 24.04 เมื่อรัน pip install นอก venv เพราะระบบประกาศตามมาตรฐาน PEP 668 ว่า Python ของระบบถูกจัดการด้วย apt การติดตั้งทับอาจทำให้เครื่องมือของระบบพัง วิธีที่ถูกคือ python3 -m venv .venv, source .venv/bin/activate แล้วจึงติดตั้ง ไม่ควรแก้ด้วย --break-system-packages

ควรบอกด้วยว่าโฟลเดอร์ .venv/ ต้องอยู่ใน .gitignore เพราะสร้างใหม่ได้จาก requirements.txt เสมอ และควรใช้ python3 -m pip เพื่อให้แน่ใจว่า pip ตรงกับ Python ตัวที่กำลังใช้

4. Generator ต่างจาก List อย่างไร และควรใช้เมื่อไร (Mid)

คำตอบที่ดี: List เก็บทุกค่าไว้ในหน่วยความจำพร้อมกัน ส่วน Generator สร้างค่าทีละตัวเมื่อถูกขอ (Lazy evaluation) ผ่าน yield หรือ Generator expression ทำให้ใช้หน่วยความจำคงที่ไม่ว่าข้อมูลจะมากแค่ไหน

import sys

# List เก็บผลลัพธ์ทั้งหนึ่งล้านค่า ส่วน Generator เก็บแค่สถานะการวน
nums = [x * x for x in range(1_000_000)]
gen = (x * x for x in range(1_000_000))
print(sys.getsizeof(nums), sys.getsizeof(gen))
python3 gen_size.py
8448728 200

ผลนี้ได้จาก Python 3.12.3 ตัวเลขอาจต่างเล็กน้อยใน Python เวอร์ชันอื่น แต่ List จะใหญ่กว่า Generator หลายหมื่นเท่าเสมอ

  • ใช้ Generator เมื่อ: อ่านไฟล์ใหญ่ทีละบรรทัด ต่อ Pipeline หลายขั้น (กรอง แปลง รวม) หรือต้องการแค่ผลรวมเช่น sum(e.amount for e in october)
  • ใช้ List เมื่อ: ต้องเข้าถึงด้วย Index, วนซ้ำหลายรอบ, หาความยาวด้วย len() หรือเรียงลำดับ
  • ข้อควรระวัง: Generator ใช้ได้รอบเดียว วนครั้งที่สองจะได้ผลว่าง และ gen[0] จะได้ TypeError: 'generator' object is not subscriptable
