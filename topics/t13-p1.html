13.1Learning Roadmap

ภาพรวมเส้นทาง

Node.js คือ Runtime ที่ทำให้ JavaScript รันนอกเบราว์เซอร์ได้ เมื่อก่อน JavaScript ใช้ได้แค่ในหน้าเว็บ แต่เมื่อมี Node.js ภาษาเดียวกันนี้ก็ใช้สร้าง Web Server, REST API, เครื่องมือ Command Line (CLI), Script อัตโนมัติ และ Backend ของแอปขนาดใหญ่ได้ เครื่องมือที่นักพัฒนาใช้ทุกวันจำนวนมาก เช่น npm, ESLint, Prettier, Vite และ TypeScript Compiler รุ่นก่อน 7.0 ก็รันบน Node.js

หัวข้อนี้อยู่ลำดับที่ 9 ของเส้นทางที่แนะนำ ต่อจาก และ เหตุผลคือคุณเขียน JavaScript และ TypeScript เป็นแล้ว ตอนนี้จึงใช้ภาษาที่รู้อยู่สร้าง Server ได้ทันทีโดยไม่ต้องเรียนภาษาใหม่ และหัวข้อนี้ยังเป็นสะพานไปสู่ และ ที่ต้องเข้าใจว่า Server รับคำขอ ประมวลผล บันทึกข้อมูล และตอบกลับอย่างไร

เส้นทางนี้มี 13 ขั้นใน 3 ระดับ ระดับ Beginner ปูพื้นเรื่อง Runtime, Module, npm และ Core Module ระดับ Intermediate สอนการเขียนโปรแกรมแบบ Asynchronous, Event Loop และการสร้าง HTTP Server ทั้งแบบเขียนเองด้วย node:http และแบบใช้ Express 5 ระดับ Advanced พาไปสร้าง REST API ที่ตรวจข้อมูลด้วย zod เก็บข้อมูลใน SQLite มี Test อัตโนมัติ มีระบบความปลอดภัยและ Log ที่ใช้ในงานจริง และจบด้วยการเตรียมระบบขึ้น Production พร้อม Mini Project URL Shortener Service ลง Portfolio

ใช้เวลารวมประมาณ 52–76 ชั่วโมง (ช่วงที่วางไว้สำหรับหัวข้อนี้คือ 50–80 ชั่วโมง) ถ้าเรียนวันละ 1–1.5 ชั่วโมง สัปดาห์ละ 6 วัน จะจบในราว 8 สัปดาห์ ทุกขั้นมี Checkpoint ที่บอกชัดว่าต้องทำอะไรได้ก่อนไปขั้นถัดไป ให้ทำ Checkpoint ให้ผ่านจริงทุกข้อ เพราะขั้นหลังต่อยอดจากขั้นก่อนหน้าทั้งหมด

  1. Beginner Step 1 · รู้จัก Node.js ติดตั้งด้วย nvm และรันโค้ดแรก
  2. Beginner Step 2 · Modules: ES Modules กับ CommonJS
  3. Beginner Step 3 · npm, package.json, Semantic Versioning และ npx
  4. Beginner Step 4 · Core Modules: fs/promises, path, os, crypto และ url
  5. Intermediate Step 5 · process, Command-line Arguments, Environment Variables และ --env-file
  6. Intermediate Step 6 · Asynchronous Programming, Event Loop และ Error Handling
  7. Intermediate Step 7 · EventEmitter และ HTTP Server ด้วย node:http
  8. Intermediate Step 8 · Express 5: Routing, Middleware และ Error Handling
  9. Advanced Step 9 · REST API ที่ตรวจข้อมูลด้วย zod และเก็บข้อมูลใน SQLite
  10. Advanced Step 10 · Testing ด้วย node:test + supertest และ Debugging
  11. Advanced Step 11 · Security และ Logging: helmet, Rate Limit, npm audit และ pino
  12. Advanced Step 12 · Streams, Backpressure และ worker_threads
  13. Advanced Step 13 · Production: Process Manager, Graceful Shutdown, Docker และ Mini Project

เปรียบเทียบ

ถ้า JavaScript คือภาษาที่เชฟใช้สั่งงานในครัว เบราว์เซอร์ก็คือครัวเล็กหน้าร้านที่ทำได้แค่จัดจานให้ลูกค้าดู (หน้าเว็บ) ส่วน Node.js คือการพาเชฟคนเดิมไปทำงานในครัวกลางหลังร้าน ที่เข้าห้องเก็บของ (ไฟล์) รับออร์เดอร์จากหลายสาขา (HTTP Request) และคุยกับตู้เย็นขนาดใหญ่ (ฐานข้อมูล) ได้ ภาษาเหมือนเดิม แต่เครื่องมือที่หยิบใช้ได้ต่างกัน

Node.js คืออะไร และเหมาะกับงานแบบไหน

ก่อนเริ่ม Step 1 ให้รู้จักคำศัพท์ 8 คำนี้ เพราะจะเจอตลอดหัวข้อ และเป็นคำถามสัมภาษณ์งานตำแหน่ง Junior Node.js Developer ที่พบบ่อยที่สุด

คำศัพท์ความหมายตัวอย่างที่จะเจอในหัวข้อนี้
Runtimeโปรแกรมที่ใช้รันโค้ดของภาษาหนึ่ง พร้อมเครื่องมือที่โค้ดเรียกใช้ได้ เช่น การอ่านไฟล์หรือการเปิด Networkคำสั่ง node app.js คือการให้ Runtime ชื่อ Node.js รันไฟล์ app.js
V8JavaScript Engine ที่ Google พัฒนาสำหรับ Chrome ทำหน้าที่แปลง JavaScript เป็น Machine Code แล้วรัน Node.js นำ V8 มาใช้เป็นแกนกลางดูเวอร์ชันได้ด้วย node -p process.versions.v8 ฟีเจอร์ใหม่ของภาษา JavaScript มาถึง Node.js ผ่านการอัปเกรด V8
libuvไลบรารีภาษา C ที่ทำงาน I/O ให้ Node.js เช่น อ่านไฟล์ คุยกับ Network และนับเวลา โดยไม่ทำให้โค้ด JavaScript ต้องหยุดรอเมื่อเรียก readFile() งานอ่านไฟล์ถูกส่งไปให้ libuv ทำเบื้องหลัง
Event Loopวงรอบที่คอยดูว่ามีงานไหนเสร็จแล้ว แล้วเรียก Callback หรือ Promise ของงานนั้นให้ทำงานต่อ ทำให้ Thread เดียวรับงานพร้อมกันได้หลายพันงานStep 6 จะพิสูจน์ลำดับการทำงานของ Promise, setTimeout และ I/O ด้วยโค้ดจริง
Non-blocking I/Oรูปแบบที่สั่งงาน I/O แล้วไปทำงานอื่นต่อทันที ไม่ยืนรอจนงานเสร็จ เมื่องานเสร็จจึงกลับมาทำส่วนที่เหลือServer ตัวเดียวรับคำขอจากผู้ใช้หลายคนพร้อมกันได้ ขณะที่คำขอหนึ่งกำลังรอฐานข้อมูลอยู่
Moduleไฟล์ JavaScript หนึ่งไฟล์ที่ส่งออก (export) ฟังก์ชันหรือค่าให้ไฟล์อื่นนำเข้า (import) ไปใช้Core Module ที่มากับ Node.js เช่น node:fs และ node:http และ Module ที่คุณเขียนเอง
npmPackage Manager ที่มากับ Node.js ใช้ติดตั้งแพ็กเกจจาก npm Registry ซึ่งเป็นคลังแพ็กเกจ Open Source ที่ใหญ่ที่สุดในโลกnpm install express@5.3.0 ติดตั้ง Express ลงในโฟลเดอร์ node_modules
LTSLong Term Support คือรุ่นที่ได้รับการแก้ Bug และ Patch ความปลอดภัยเป็นเวลานาน เหมาะกับงานจริง Node.js รุ่นเลขคู่จะได้เป็น LTSหลักสูตรนี้ติดตั้งด้วย nvm install --lts
เปรียบเทียบ

Event Loop เหมือนพนักงานรับออร์เดอร์ในร้านกาแฟที่มีคนเดียว เมื่อรับออร์เดอร์ลาเต้แล้ว เขาไม่ยืนรอหน้าเครื่องชงจนเสร็จ แต่ส่งงานให้เครื่องชง (libuv) แล้วหันไปรับออร์เดอร์ลูกค้าคนถัดไป เมื่อเครื่องชงส่งเสียงว่าเสร็จ เขาจึงกลับไปเสิร์ฟ คนเดียวจึงดูแลลูกค้าได้หลายสิบคน แต่ถ้ามีลูกค้าสั่งให้เขาปอกผลไม้ 100 ลูกด้วยมือ (งานที่ใช้ CPU หนัก) ทั้งร้านจะต้องรอ นี่คือเหตุผลที่งานคำนวณหนักต้องย้ายไป worker_threads ใน Step 12

Node.js ไม่ได้เหมาะกับทุกงาน การรู้จุดแข็งและจุดอ่อนช่วยให้เลือกเครื่องมือได้ถูก และตอบคำถามสัมภาษณ์ได้อย่างมีเหตุผล

ลักษณะงานเหมาะกับ Node.js ไหมเหตุผล
REST API และ Backend ที่รอฐานข้อมูลหรือบริการอื่นเป็นส่วนใหญ่เหมาะมากงานส่วนใหญ่คือรอ I/O ซึ่ง Non-blocking I/O จัดการได้ดี และใช้ JavaScript/TypeScript ได้ทั้ง Frontend และ Backend
แอป Real-time เช่น แชต แจ้งเตือนสด และ Dashboard ที่อัปเดตตลอดเหมาะมากรักษาการเชื่อมต่อพร้อมกันจำนวนมากด้วยหน่วยความจำต่อการเชื่อมต่อที่ต่ำ
เครื่องมือ Command Line และ Script อัตโนมัติเหมาะเริ่มทำงานเร็ว และแจกจ่ายผ่าน npm หรือ npx ได้ง่าย
Backend ของแอป AI ที่เรียก LLM APIเหมาะงานหลักคือรอคำตอบจาก API และส่งต่อแบบ Streaming ซึ่งเป็นจุดแข็งของ Node.js (เรียนต่อใน )
งานคำนวณหนัก เช่น ประมวลผลวิดีโอ หรือ Train โมเดล Machine Learningไม่เหมาะงานใช้ CPU นานจะบล็อก Event Loop ทำให้คำขออื่นค้าง ต้องแยกไป worker_threads หรือใช้ภาษาอื่น เช่น Python หรือ Go
ระบบที่ต้องการประสิทธิภาพระดับต่ำสุดและควบคุมหน่วยความจำเองไม่เหมาะภาษาอย่าง Go, Rust หรือ C++ ควบคุมทรัพยากรได้ละเอียดกว่า (ดู )

หัวข้อย่อย

  • ความต่างจาก JavaScript ในเบราว์เซอร์: Node.js ไม่มี window, document และ DOM แต่มี process, globalThis, Buffer และเข้าถึงไฟล์กับ Network ได้โดยตรง ส่วน fetch, URL, setTimeout และ console ใช้ได้ทั้งสองที่
  • ภาพรวมของสถาปัตยกรรม Single Thread + Event Loop + Non-blocking I/O และงานแบบไหนเหมาะหรือไม่เหมาะกับ Node.js (ทบทวนตารางในหัวข้อ "Node.js คืออะไร" ด้านบน)

STEP 2

Modules: ES Modules กับ CommonJS

1–2 วัน · 3–4 ชม.
หัวข้อย่อย
  • ทำไมต้องแบ่งโค้ดเป็น Module: ตัวแปรในแต่ละไฟล์ไม่ปนกัน นำฟังก์ชันกลับมาใช้ซ้ำได้ ทดสอบแยกส่วนได้ และทำงานเป็นทีมโดยไม่แก้ไฟล์เดียวกัน
  • ES Modules (ESM) ซึ่งเป็นมาตรฐานของภาษา: export, export default, import { sum } from './price.js', import * as price from './price.js', Dynamic import() และ Top-level await
  • วิธีบอก Node.js ว่าไฟล์เป็น ESM: ใส่ "type": "module" ใน package.json (หลักสูตรนี้ใช้วิธีนี้ทุกโปรเจกต์) หรือใช้นามสกุล .mjs ส่วนนามสกุล .cjs บังคับให้เป็น CommonJS เสมอ
  • CommonJS (CJS) ระบบ Module ดั้งเดิมของ Node.js: require(), module.exports, exports, __dirname และ __filename ต้องอ่านออก เพราะโค้ดเก่า บทความ และคำตอบใน Stack Overflow จำนวนมากยังใช้แบบนี้
  • ความต่างที่ทำให้เกิด Error บ่อย: ESM ต้องใส่นามสกุลไฟล์ใน Relative Import, ใช้ import.meta.dirname และ import.meta.filename แทน __dirname และ __filename, ESM เป็น Strict Mode เสมอ และไม่มี require ให้ใช้
  • นำเข้า Core Module ด้วย Prefix node: เช่น import fs from 'node:fs' เพื่อให้ชัดเจนว่าเป็นของ Node.js ไม่ใช่แพ็กเกจจาก npm ที่ชื่อซ้ำกัน
  • การใช้ร่วมกัน (Interop): ESM import แพ็กเกจที่เป็น CommonJS ได้ และ Node.js 22.12 ขึ้นไปให้ CommonJS ใช้ require() โหลด ESM ที่ไม่มี Top-level await ได้
  • Error ที่ต้องรู้จัก: ERR_MODULE_NOT_FOUND, SyntaxError: Cannot use import statement outside a module และ ReferenceError: require is not defined in ES module scope
ทำไมต้องเรียน
ทุกโปรเจกต์จริงมีหลายสิบถึงหลายร้อยไฟล์ที่เชื่อมกันด้วย import ถ้าตั้งค่า Module ผิด โปรแกรมจะไม่เริ่มทำงานเลย และ Error เรื่อง Module เป็นปัญหาอันดับต้นที่มือใหม่เจอเมื่อคัดลอกโค้ดจากอินเทอร์เน็ต ซึ่งมีทั้งแบบ ESM และ CommonJS ปนกัน ระบบนิเวศของ JavaScript กำลังย้ายไป ESM ทั้งหมด แต่ต้องอ่าน CommonJS ออกเพื่อดูแลโค้ดเก่าได้
ลงมือทำ
  • สร้างโปรเจกต์ modules-lab ที่มี price.js และ main.js ตามตัวอย่างด้านล่าง
  • ลบ .js ออกจาก import แล้วรันใหม่เพื่อดู ERR_MODULE_NOT_FOUND จากนั้นแก้กลับ
  • สร้าง legacy.cjs ที่ใช้ require('node:path') และ __dirname แล้วรันในโฟลเดอร์เดียวกัน เพื่อเห็นว่า .cjs ยังเป็น CommonJS
  • เขียนตาราง 2 คอลัมน์เปรียบเทียบ ESM กับ CommonJS อย่างน้อย 6 แถวลง Learning Journal

STEP 3

npm, package.json, Semantic Versioning และ npx

2 วัน · 4–5 ชม.
หัวข้อย่อย
  • สร้างโปรเจกต์ด้วย npm init -y และฟิลด์สำคัญใน package.json: name, version, type, scripts, dependencies, devDependencies, engines และ private รวมถึงการแก้ค่าด้วย npm pkg set และ npm pkg get
  • คำสั่งจัดการแพ็กเกจ: npm install ชื่อ@เวอร์ชัน, npm install -D (ใช้ตอนพัฒนาเท่านั้น เช่น เครื่องมือ Test), npm uninstall, npm ls, npm outdated และ npm update
  • Semantic Versioning (semver) แบบ MAJOR.MINOR.PATCH: Major เปลี่ยนเมื่อมี Breaking Change, Minor เพิ่มฟีเจอร์ที่เข้ากันได้, Patch แก้ Bug และความหมายของ ^5.3.0 (ไม่ข้าม Major), ~5.3.0 (ไม่ข้าม Minor), 5.3.0 (ตรงตัว) และกรณีพิเศษของเวอร์ชัน 0.x
  • node_modules และ package-lock.json: Lockfile บันทึกเวอร์ชันจริงของทุกแพ็กเกจรวมถึงแพ็กเกจลูก ต้อง Commit Lockfile แต่ห้าม Commit node_modules และใช้ npm ci บน Server และ CI เพื่อติดตั้งตาม Lockfile เป๊ะ

STEP 12

Streams, Backpressure และ worker_threads

2 วัน · 3–5 ชม.
หัวข้อย่อย
  • Stream 4 ชนิด: Readable (อ่าน), Writable (เขียน), Duplex (ทั้งสองทาง เช่น Socket) และ Transform (แปลงข้อมูลระหว่างทาง เช่น บีบอัด) และเหตุที่ Stream ใช้หน่วยความจำคงที่ไม่ว่าไฟล์จะใหญ่แค่ไหน
  • fs.createReadStream, fs.createWriteStream, readline.createInterface สำหรับอ่านไฟล์ทีละบรรทัด และ for await...of บน Stream
  • Backpressure: write() คืนค่า false เมื่อ Buffer ภายในเต็ม (ขนาดตาม highWaterMark) ต้องรอ Event 'drain' ก่อนเขียนต่อ ถ้าไม่สนใจ หน่วยความจำจะบวมจนโปรแกรมล้ม
  • pipeline() จาก node:stream/promises ต่อ Stream หลายตัวเข้าด้วยกัน จัดการ Backpressure ให้อัตโนมัติ และปิดทุก Stream เมื่อเกิด Error เช่น pipeline(createReadStream('access.log'), createGzip(), createWriteStream('access.log.gz'))
  • HTTP Request และ Response เป็น Stream: ส่งไฟล์ขนาดใหญ่ให้ผู้ใช้ด้วย pipeline(createReadStream(file), res) โดยไม่ต้องอ่านทั้งไฟล์เข้าหน่วยความจำ
  • worker_threads: สร้าง Thread แยกด้วย new Worker(new URL('./worker.js', import.meta.url), { workerData }) รับผลผ่าน parentPort.postMessage() เพื่อย้ายงานคำนวณหนักออกจาก Event Loop
  • ความต่างของ worker_threads (Thread ในโปรเซสเดียวกัน), child_process (รันโปรแกรมอื่นเป็นโปรเซสใหม่) และ cluster หรือการรันหลาย Instance (ใช้ CPU หลาย Core สำหรับรับคำขอ)
  • วัดผลก่อนปรับปรุง: process.memoryUsage(), performance.now() และ node --cpu-prof สำหรับหาฟังก์ชันที่ใช้ CPU มากที่สุด

import { createWriteStream, createReadStream } from 'node:fs';
import { once } from 'node:events';
import { createInterface } from 'node:readline';

const FILE = 'access.log';
const LINES = 200_000;
const statuses = [200, 200, 200, 201, 301, 302, 404, 200, 500, 200];

// 1) เขียนไฟล์ใหญ่ทีละบรรทัด และเคารพ Backpressure
const out = createWriteStream(FILE);
for (let i = 0; i < LINES; i++) {
  const line = `2026-10-19T09:00:00Z GET /r/${i % 500} ${statuses[i % statuses.length]}\n`;
  // write() คืน false เมื่อ Buffer เต็ม ต้องรอ Event 'drain' ก่อนเขียนต่อ
  if (!out.write(line)) await once(out, 'drain');
}
out.end();
await once(out, 'finish');

// 2) อ่านกลับทีละบรรทัดด้วย Stream ไม่โหลดทั้งไฟล์เข้าหน่วยความจำ
const counts = {};
const rl = createInterface({ input: createReadStream(FILE), crlfDelay: Infinity });
for await (const line of rl) {
  const status = line.split(' ').at(-1);
  counts[status] = (counts[status] ?? 0) + 1;
}
console.log(`อ่านครบ ${LINES.toLocaleString('en-US')} บรรทัด`);
for (const [status, n] of Object.entries(counts)) {
  console.log(`  ${status}: ${n.toLocaleString('en-US')} ครั้ง`);
}

Must-know Skills

ถ้าต้องสรุปหัวข้อนี้ให้เหลือทักษะที่ผู้สัมภาษณ์และงานจริงคาดหวังจากคนที่ "เขียน Node.js เป็น" จะได้รายการนี้

  1. ติดตั้งและสลับเวอร์ชัน Node.js ด้วย nvm และ .nvmrc เพราะแต่ละโปรเจกต์ในบริษัทใช้ Node.js คนละรุ่น และการติดตั้งผิดวิธีทำให้เจอปัญหาสิทธิ์ของไฟล์และเวอร์ชันไม่ตรงกัน
  2. อธิบายและใช้ประโยชน์จาก Event Loop กับ Non-blocking I/O เพราะเป็นพื้นฐานของประสิทธิภาพทั้งหมดใน Node.js และเป็นคำถามสัมภาษณ์ที่พบบ่อยที่สุด
  3. เขียนโค้ดแบบ ES Modules และอ่านโค้ด CommonJS ออก เพราะโปรเจกต์ใหม่ใช้ ESM แต่โค้ดเก่าและบทความจำนวนมากยังเป็น CommonJS
  4. จัดการ Dependency ด้วย npm, semver และ package-lock.json เพราะทำให้ทุกเครื่องได้แพ็กเกจเวอร์ชันเดียวกันและอัปเดตได้อย่างปลอดภัย
  5. ใช้ Core Modules อย่าง fs/promises, path, crypto, events และ stream เพราะลดการพึ่งแพ็กเกจภายนอก และเป็นเครื่องมือที่ทุก Framework ใช้อยู่เบื้องหลัง
  6. เขียน async/await และจัดการ Error ครบทุกทาง เพราะ Promise ที่ลืม await หรือ Error ที่ไม่มีใครจับ ทำให้ Server ล่มทั้งตัวจากคำขอเดียว
  7. แยก Config ออกจากโค้ดด้วย Environment Variable และ --env-file เพราะทำให้โค้ดชุดเดียว Deploy ได้หลายสภาพแวดล้อม และป้องกัน Secret หลุดขึ้น Git
  8. สร้าง REST API ด้วย Express 5 ทั้ง Routing, Middleware และ Error Handler เพราะเป็นงานหลักของตำแหน่ง Node.js Developer และเป็น Framework ที่ประกาศงานระบุบ่อยที่สุด
  9. ตรวจข้อมูลที่ขอบระบบด้วย zod เพราะข้อมูลจากผู้ใช้ไว้ใจไม่ได้ และการตรวจที่ดีป้องกันทั้ง Bug และการโจมตี
  10. เก็บข้อมูลด้วย SQL และ Prepared Statement เพราะเกือบทุกระบบต้องเก็บข้อมูลถาวร และ Prepared Statement คือวิธีมาตรฐานที่ป้องกัน SQL Injection
  11. เขียน Test อัตโนมัติด้วย node:test และ supertest เพราะบริษัทส่วนใหญ่ไม่รับโค้ดที่ไม่มี Test และ Test ทำให้แก้โค้ดได้อย่างมั่นใจ
  12. Debug ด้วย --inspect และอ่าน Stack Trace เพราะช่วยหาสาเหตุของ Bug ได้เร็วกว่าการเดาด้วย console.log หลายเท่า
  13. ตั้งค่าความปลอดภัยพื้นฐานด้วย helmet, Rate Limit และ npm audit เพราะ API ที่เปิดสู่อินเทอร์เน็ตจะถูกสแกนและโจมตีทันทีที่ออนไลน์
  14. เขียน Structured Log ด้วย pino และปิดระบบแบบ Graceful Shutdown เพราะเป็นสิ่งที่ทำให้ Service ดูแลได้จริงใน Production และไม่ทำข้อมูลของผู้ใช้เสียหายระหว่าง Deploy

จบหัวข้อนี้แล้วไปต่อที่ไหน

เมื่อผ่าน Checkpoint ของ Step 13 และ Mini Project อยู่บน GitHub แล้ว แปลว่าคุณสร้าง Service ด้วย Node.js ได้ครบวงจร ลำดับที่แนะนำต่อจากนี้คือ

  1. หัวข้อถัดไปในเส้นทาง ออกแบบ API ให้เป็นมาตรฐาน ทั้งการตั้งชื่อ Resource, Versioning, Pagination, รูปแบบ Error และเอกสาร OpenAPI ซึ่งต่อยอดจาก API หนังสือและ URL Shortener ที่คุณสร้างไว้
  2. นำแนวคิดจากหัวข้อนี้ไปสร้างระบบที่ใหญ่ขึ้น ทั้ง Authentication, PostgreSQL, Cache, Docker Compose และ CI แม้ตัวอย่างหลักจะใช้ Python แต่หลักการเหมือนกับ Node.js ทุกข้อ
  3. ใช้ Node.js และ TypeScript สร้าง Backend ของแอป AI ที่เรียก LLM API และส่งคำตอบแบบ Streaming
  4. เทียบมุมมองกับภาษาที่ Compile และจัดการ Concurrency ด้วย Goroutine ซึ่งช่วยให้เข้าใจจุดแข็งและข้อจำกัดของ Event Loop ชัดขึ้น
  5. ใช้ AI ช่วยเขียนโค้ด Node.js ให้เร็วขึ้น โดยมีพื้นฐานพอจะตรวจและแก้โค้ดที่ AI สร้างได้
Tip

ไม่ต้องรอให้จำ API ของ Node.js ได้ทุกตัวก่อนเดินหน้า นักพัฒนามืออาชีพเปิดเอกสารที่ nodejs.org/api ทุกวัน สิ่งที่ต้องจำได้คือแนวคิด ได้แก่ Event Loop, Module, Middleware, Validation, Test และ Graceful Shutdown เก็บ Cheat Sheet ในส่วนที่ 4 ของหัวข้อนี้ไว้เปิดดูระหว่างเรียนหัวข้ออื่น และกลับมาทบทวน Step ที่ยังไม่มั่นใจเมื่อเจอปัญหาจริง
