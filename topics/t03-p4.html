Mini Project: 2D Arcade Game: Star Dodger

Star Dodger คือเกมเดียวกับที่คุณออกแบบไว้ในไฟล์ gdd-star-dodger.md ตอน Step 1 ของส่วนที่ 1 และสร้างทีละส่วนมาตั้งแต่ Step 5 ถึง Step 13 ในส่วนนี้คุณจะประกอบทุกชิ้นให้ครบเป็นเวอร์ชัน 1.0.0 พร้อมโค้ดเต็มทุกไฟล์ เพิ่ม Playtest อัตโนมัติ แล้วปล่อยขึ้น GitHub และ itch.io เพื่อใช้เป็นผลงานชิ้นแรกใน Portfolio

เป้าหมายของโปรเจกต์

สร้างเกม Arcade 2D มุมมองจากด้านบน (Top-down) ธีมอวกาศ ผู้เล่นบังคับยานเดินได้ 8 ทิศ หลบศัตรูที่ตกลงมาจากขอบบนของจอถี่ขึ้นเรื่อยๆ และเก็บดาวเพื่อทำคะแนน เกมนี้ไม่มีการยิง วงจรหลัก (Core Loop) จึงสั้นและชัด: หลบศัตรู → เก็บดาว → ได้คะแนน → ศัตรูเกิดถี่ขึ้น → แพ้ → เล่นใหม่เพื่อทำคะแนนให้สูงกว่าเดิม

เป้าหมายด้านทักษะคือทำเกมให้เสร็จตามมาตรฐานที่ผู้สัมภาษณ์มองหา ได้แก่ มีเมนู มีจุดจบ บันทึกสถิติได้ มีเสียงและ Game Feel ผ่านการทดสอบ และมีลิงก์ที่กดแล้วเล่นได้ทันที

ฟีเจอร์ทั้งหมด

  • Main Menu: ชื่อเกม ปุ่ม Play และ Quit พร้อม High Score ที่บันทึกไว้ ปุ่ม Play ได้ Focus ด้วย grab_focus() จึงกด Enter หรือปุ่มบนจอยเพื่อเริ่มได้ทันที
  • Player: CharacterBody2D เดิน 8 ทิศด้วย Input.get_vector() ความเร็ว 300 px/s อยู่ในจอขนาด 1152 × 648 เสมอ และอมตะ 1 วินาทีพร้อมกะพริบหลังโดนชน
  • Enemy: Area2D เกิดที่ y = -40 ตำแหน่ง x สุ่มระหว่าง 0–1152 ตกลงมาด้วยความเร็วสุ่ม 150–250 px/s และลบตัวเองเมื่อพ้นจอ ส่วน SpawnTimer เริ่มที่ 1.2 วินาที คูณ 0.97 ทุกครั้งที่ศัตรูเกิด และต่ำสุดที่ 0.35 วินาที
  • Star: Area2D ที่มี Signal collected(points: int) ได้ดวงละ 10 คะแนน เกิดทุก 2 วินาทีที่ตำแหน่งสุ่มในจอ มี Tween แบบเด้ง Particle และเสียงตอนเก็บ
  • Collision Layer ที่ตั้งชื่อไว้ใน Project Settings: 1 player, 2 enemies, 3 stars, 4 walls
  • Autoload GameState: เก็บ score, lives (เริ่มที่ 3) และ high_score ส่ง Signal score_changed(new_score: int) และ lives_changed(new_lives: int) มีฟังก์ชัน reset(), add_score() และ lose_life()
  • Autoload SaveManager: บันทึก High Score และการตั้งค่าด้วย ConfigFile ที่ user://savegame.cfg ถ้าไฟล์หายหรือเสียจะกลับไปใช้ค่าตั้งต้น
  • HUD และเมนู Pause: แสดง Score, Lives และ Best โดยอัปเดตผ่าน Signal เท่านั้น กด Esc หรือ P เพื่อหยุดเกม มีปุ่ม Resume, Screen Shake On/Off และ Main Menu
  • เสียง: Bus ชื่อ Master, Music และ SFX เพลงวนเล่นบน Bus Music ส่วนเสียงเก็บดาว เสียงชน และเสียงแพ้อยู่บน Bus SFX พร้อมสุ่ม pitch_scale 0.9–1.1
  • Game Feel: Screen Shake ด้วย add_trauma(0.6), Hit Flash ด้วย modulate, ดาวเด้งด้วย Tween และ Hitstop 0.08 วินาที
  • Game Over: แสดงคะแนน แสดงข้อความ "New High Score!" เมื่อทำลายสถิติ และมีปุ่ม Retry กับ Main Menu
  • Export: Preset "Windows Desktop" ได้ไฟล์ build/windows/StarDodger.exe และ Preset "Web" ได้ไฟล์ build/web/index.html (Compatibility Renderer, ปิด Thread Support)
  • การทดสอบ: Smoke Test 16 ข้อจากส่วนที่ 1 และ Playtest อัตโนมัติ 10 ข้อที่เล่นเกมจริงแบบ headless

ภาพรวมการทำงานของเกม

แผนภาพนี้แสดงว่า Scene และ Autoload คุยกันอย่างไร ลูกศรคือทิศทางของการเรียกฟังก์ชันหรือการส่ง Signal หลักที่ใช้ทั้งโปรเจกต์คือ Node ลูกส่ง Signal ขึ้นไป ส่วนข้อมูลที่ต้องอยู่ข้าม Scene เก็บไว้ใน Autoload

Autoload (โหลดก่อนทุก Scene และอยู่ตลอดการเล่น)
  SaveManager  ── อ่าน/เขียน ──▶ user://savegame.cfg
  GameState    ── เก็บ score, lives, high_score ──▶ ส่ง score_changed, lives_changed

main_menu.tscn ──Play──▶ game.tscn ──ชีวิตหมด──▶ game_over.tscn ──Retry──▶ game.tscn
      ▲                     │ (เมนู Pause)            │
      └────Main Menu────────┴──────────Main Menu──────┘

ภายใน game.tscn
  SpawnTimer ──▶ สร้าง Enemy ──ชนยาน──▶ Player.hit ──▶ GameState.lose_life()
  StarTimer  ──▶ สร้าง Star  ──collected(10)──▶ GameState.add_score()
  GameState.score_changed / lives_changed ──▶ HUD เปลี่ยนตัวเลขบนจอ

    """สร้างไฟล์เสียงชั่วคราว (Placeholder) ให้เกม Star Dodger ด้วย Python Standard Library ล้วน
วิธีใช้: python3 make_placeholder_audio.py <โฟลเดอร์ปลายทาง>
"""
import math
import random
import struct
import sys
import wave
from pathlib import Path

SAMPLE_RATE = 44100  # จำนวน Sample ต่อวินาที


def sweep(f_start: float, f_end: float, seconds: float, volume: float = 0.4) -> list[float]:
    """คลื่นสี่เหลี่ยม (Square Wave) ที่ความถี่ไล่จาก f_start ไป f_end แล้วค่อยๆ เบาลง"""
    total = int(SAMPLE_RATE * seconds)
    samples: list[float] = []
    phase = 0.0
    for i in range(total):
        progress = i / total                          # ความคืบหน้า 0.0 ถึง 1.0
        freq = f_start + (f_end - f_start) * progress
        phase += freq / SAMPLE_RATE                   # นับจำนวนรอบของคลื่น
        square = 1.0 if (phase % 1.0) < 0.5 else -1.0
        samples.append(square * volume * (1.0 - progress))
    return samples


def noise(seconds: float, volume: float = 0.5, seed: int = 7) -> list[float]:
    """เสียงซ่า (White Noise) สำหรับเสียงชน ใช้ seed คงที่ให้ได้ไฟล์เดิมทุกครั้งที่รัน"""
    rng = random.Random(seed)
    total = int(SAMPLE_RATE * seconds)
    return [rng.uniform(-1.0, 1.0) * volume * (1.0 - i / total) ** 2 for i in range(total)]


def note(freq: float, seconds: float, volume: float = 0.25) -> list[float]:
    """โน้ตหนึ่งตัวแบบคลื่นสามเหลี่ยม (Triangle Wave) เฟดหัวท้าย 10 ms กันเสียงคลิก"""
    total = int(SAMPLE_RATE * seconds)
    fade = int(SAMPLE_RATE * 0.01)
    samples: list[float] = []
    for i in range(total):
        cycle = (freq * i / SAMPLE_RATE) % 1.0
        triangle = 4.0 * abs(cycle - 0.5) - 1.0
        gain = min(1.0, i / fade, (total - i) / fade)
        samples.append(triangle * volume * gain)
    return samples


def write_wav(path: Path, samples: list[float]) -> None:
    """บันทึกเป็นไฟล์ WAV แบบ 16-bit Mono แล้วพิมพ์ความยาวกับขนาดไฟล์"""
    with wave.open(str(path), "wb") as wav:
        wav.setnchannels(1)
        wav.setsampwidth(2)
        wav.setframerate(SAMPLE_RATE)
        wav.writeframes(b"".join(struct.pack("<h", int(max(-1.0, min(1.0, s)) * 32767)) for s in samples))
    seconds = len(samples) / SAMPLE_RATE
    print(f"สร้าง {path.name:<18} {seconds:4.2f} วินาที {path.stat().st_size:>8,} bytes")


def main() -> None:
    if len(sys.argv) != 2:
        print("วิธีใช้: python3 make_placeholder_audio.py <โฟลเดอร์ปลายทาง>")
        sys.exit(1)
    out_dir = Path(sys.argv[1])
    out_dir.mkdir(parents=True, exist_ok=True)

    write_wav(out_dir / "sfx_pickup.wav", sweep(660, 1320, 0.15))           # เก็บดาว: เสียงไล่สูงขึ้นเร็วๆ
    write_wav(out_dir / "sfx_hit.wav", noise(0.25))                          # โดนชน: เสียงซ่าสั้นๆ
    write_wav(out_dir / "sfx_game_over.wav", sweep(440, 220, 0.4) + sweep(330, 110, 0.6))  # แพ้: เสียงต่ำลงสองช่วง

    # เพลงวน 4 วินาที: Arpeggio 16 โน้ต โน้ตละ 0.25 วินาที (Am, Am, F, G)
    melody = [220.0, 261.63, 329.63, 261.63] * 2 + [174.61, 220.0, 261.63, 220.0] + [196.0, 246.94, 293.66, 246.94]
    music: list[float] = []
    for freq in melody:
        music += note(freq, 0.25)
    write_wav(out_dir / "music_loop.wav", music)


if __name__ == "__main__":
    main()

    typeof(value) != typeof(fallback)การตั้งค่าแต่ละตัวต้องมีชนิดเดียวกับค่าตั้งต้น เช่น screen_shake ต้องเป็น bool ถ้าไม่ใช่ให้ใช้ค่าตั้งต้น เกมจะไม่พังเพราะไฟล์ผิดรูปแบบ
    linear_to_db()หูคนรับรู้ความดังแบบลอการิทึม Bus จึงตั้งเป็นเดซิเบล ค่า 1.0 คือ 0 dB, 0.5 ประมาณ -6 dB และ 0.0 คือเงียบสนิท

extends CharacterBody2D
# ยานของผู้เล่น: เดิน 8 ทิศ อยู่ในจอเสมอ และอมตะชั่วคราวหลังโดนชน

signal hit  # ส่งเมื่อโดนชนจริง (ระหว่างอมตะจะไม่ส่ง)

@export var speed: float = 300.0
@export var invincible_time: float = 1.0
# ครึ่งหนึ่งของขนาดยานบนจอ ใช้กันไม่ให้ยานล้นขอบ
@export var half_size := Vector2(25.0, 19.0)

@onready var sprite: Sprite2D = $Sprite2D
@onready var invincible_timer: Timer = $InvincibleTimer


func _ready() -> void:
    add_to_group("player")


func _physics_process(_delta: float) -> void:
    # get_vector() คืน Vector2 ที่ยาวไม่เกิน 1 เดินแนวทแยงจึงไม่เร็วกว่าแนวตรง
    var direction := Input.get_vector("move_left", "move_right", "move_up", "move_down")
    velocity = direction * speed
    move_and_slide()
    # จำกัดตำแหน่งให้อยู่ในจอ (1152 x 648)
    var screen := get_viewport_rect().size
    position = position.clamp(half_size, screen - half_size)


func take_hit() -> void:
    # Timer ยังเดินอยู่ แปลว่ายังอมตะ ชนแล้วไม่เสียชีวิต
    if not invincible_timer.is_stopped():
        return
    invincible_timer.start(invincible_time)
    hit.emit()
    _play_hit_effect()


func _play_hit_effect() -> void:
    var tween := create_tween()
    # Hit Flash: เปลี่ยนเป็นสีแดงทันที แล้วกลับเป็นสีปกติใน 0.1 วินาที
    sprite.modulate = Color(1.0, 0.3, 0.3)
    tween.tween_property(sprite, "modulate", Color.WHITE, 0.1)
    # กะพริบ 4 รอบ รอบละ 0.2 วินาที ให้ผู้เล่นรู้ว่ากำลังอมตะ
    for i in 4:
        tween.tween_property(sprite, "modulate:a", 0.2, 0.1)
        tween.tween_property(sprite, "modulate:a", 1.0, 0.1)
    • Input.get_vector() คืนเวกเตอร์ที่ยาวไม่เกิน 1 การเดินแนวทแยงจึงเร็วเท่าแนวตรง และรองรับจอยแบบอนาล็อกโดยไม่ต้องเขียนเพิ่ม
    • position.clamp(half_size, screen - half_size) บังคับให้ตัวยานทั้งลำอยู่ในจอ ยานกว้าง 49.5 px สูง 37.5 px หลังย่อ 0.5 เท่า จึงใช้ครึ่งหนึ่งแล้วปัดขึ้นเป็น 25 × 19
    • take_hit() ใช้ InvincibleTimer.is_stopped() เป็นตัวบอกว่าพ้นช่วงอมตะหรือยัง ไม่ต้องสร้างตัวแปร bool เพิ่ม
    • Tween ของ Hit Flash ใช้เวลา 0.1 วินาที ตามด้วยการกะพริบ 4 รอบ รอบละ 0.2 วินาที รวม 0.9 วินาที จบก่อนช่วงอมตะ 1 วินาทีพอดี

@export var max_speed: float = 250.0

@onready var notifier: VisibleOnScreenNotifier2D = $VisibleOnScreenNotifier2D

    body_entered.connect(_on_body_entered)

extends Camera2D
# กล้องที่สั่นได้ (Screen Shake) ด้วยค่า trauma: 0 = นิ่ง, 1 = สั่นแรงที่สุด

@export var decay: float = 2.0         # การสั่นลดลงเร็วแค่ไหน (ต่อวินาที)
@export var max_offset: float = 12.0   # ระยะสั่นสูงสุด หน่วยพิกเซล

var trauma: float = 0.0


func add_trauma(amount: float) -> void:
    # ผู้เล่นปิด Screen Shake ได้ในเมนู Pause (ช่วยคนที่เวียนหัวง่าย)
    if not SaveManager.get_setting("screen_shake"):
        return
    trauma = minf(trauma + amount, 1.0)


func _process(delta: float) -> void:
    if trauma > 0.0:
        trauma = maxf(trauma - decay * delta, 0.0)
        var power := trauma * trauma  # ยกกำลังสอง: สั่นแรงช่วงแรกแล้วเบาลงอย่างนุ่มนวล
        offset = Vector2(randf_range(-1.0, 1.0), randf_range(-1.0, 1.0)) * max_offset * power
    else:
        offset = Vector2.ZERO

func _on_spawn_timer_timeout() -> void:

    enemies.add_child(enemy)
    spawn_timer.wait_time = maxf(spawn_timer.wait_time * spawn_speedup, min_wait_time)


func _on_star_timer_timeout() -> void:
    var star := STAR_SCENE.instantiate() as Star
    # เว้นขอบจอและแถบ HUD ด้านบน ดาวจะได้ไม่เกิดใต้ตัวหนังสือ
    star.position = Vector2(randf_range(48.0, 1104.0), randf_range(96.0, 600.0))
    star.collected.connect(GameState.add_score)
    stars.add_child(star)

    camera.add_trauma(0.6)
    _hitstop(0.08)


func _hitstop(duration: float) -> void:

    Engine.time_scale = 0.05

    # Star Dodger

เกม Arcade 2D มุมมองจากด้านบน ธีมอวกาศ บังคับยานหลบศัตรูที่ตกลงมาถี่ขึ้นเรื่อยๆ และเก็บดาวเพื่อทำคะแนนให้สูงที่สุด สร้างด้วย Godot 4.7.2 และ GDScript

- **เล่นบน Browser:** https://somchai.itch.io/star-dodger
- **ดาวน์โหลดสำหรับ Windows:** หน้า [Releases](https://github.com/somchai/star-dodger/releases)

![ภาพหน้าจอ Star Dodger](docs/screenshot.png)

## วิธีเล่น

| ปุ่ม | การทำงาน |
|---|---|
| WASD, ปุ่มลูกศร หรือ Left Stick | บังคับยาน 8 ทิศ |
| Esc หรือ P | Pause และเล่นต่อ |
| Enter | กดปุ่มที่เลือกอยู่ในเมนู |

เริ่มด้วย 3 ชีวิต เก็บดาวได้ดวงละ 10 คะแนน ชนศัตรูเสีย 1 ชีวิตแล้วอมตะ 1 วินาที ชีวิตหมดคือจบเกม High Score ถูกบันทึกไว้ในเครื่องของผู้เล่น

## ฟีเจอร์

- เมนูหลัก เมนู Pause และหน้า Game Over ใช้คีย์บอร์ดหรือจอยได้โดยไม่ต้องใช้เมาส์
- ศัตรูเกิดถี่ขึ้นเรื่อยๆ: เริ่มทุก 1.2 วินาที เร็วขึ้น 3% ต่อตัว จนถึง 0.35 วินาที
- บันทึก High Score และการตั้งค่าด้วย ConfigFile ที่ `user://savegame.cfg` ถ้าไฟล์เสียจะกลับไปใช้ค่าตั้งต้นเอง
- Game Feel: Screen Shake (ปิดได้ในเมนู Pause), Hit Flash, Hitstop, ดาวเด้งด้วย Tween และ Particle
- เสียงแยก Bus เป็น Music และ SFX พร้อมสุ่ม Pitch ให้เสียงไม่ซ้ำ
- มีทั้งเวอร์ชัน Windows และ Web

## เทคโนโลยี

- Godot Engine 4.7.2 (Standard) ใช้ Renderer แบบ Compatibility
- GDScript แบบ Static Typing และ Autoload 2 ตัว (`GameState`, `SaveManager`)
- Smoke Test และ Playtest อัตโนมัติที่รันแบบ `--headless`

## สิ่งที่ได้เรียนรู้

- เก็บข้อมูลของรอบที่เล่นไว้ใน Autoload แล้วให้ HUD อัปเดตผ่าน Signal ทำให้แต่ละ Scene ไม่ผูกกันแน่นเกินไป
- `VisibleOnScreenNotifier2D` ไม่ส่ง `screen_exited` เมื่อรันแบบ `--headless` จึงเพิ่มเงื่อนไขลบศัตรูสำรอง ปัญหานี้เจอได้เพราะมี Playtest อัตโนมัติ
- Hitstop ที่ใช้ `Engine.time_scale` ต้องคืนค่าเป็น 1.0 เสมอ แม้ผู้เล่นจะออกจาก Scene กลางคัน

    Security

    ห้าม Commit โฟลเดอร์ build/ นอกจากทำให้ Repository บวม ไฟล์ StarDodger.exe ยังใหญ่ 104 MiB ซึ่งเกินขีดจำกัดไฟล์ละ 100 MiB ของ GitHub จน Push ไม่ผ่าน ไฟล์เกมให้แนบใน GitHub Releases หรือ itch.io เท่านั้น และอย่าใส่รหัสผ่านหรือ Key ใดๆ ลงใน export_presets.cfg ด้วยมือ Godot เก็บข้อมูลลับของ Export ไว้ใน .godot/export_credentials.cfg ซึ่งไม่ถูก Commit อยู่แล้ว

  • Leaderboard ออนไลน์: ส่งคะแนนไปยัง API ที่เขียนเองตามหัวข้อ ด้วย Node HTTPRequest และตรวจข้อมูลฝั่ง Server เสมอ เพราะผู้เล่นแก้คะแนนในเครื่องตัวเองได้

Interview Questions

คำถามที่พบบ่อยในการสัมภาษณ์ตำแหน่ง Junior ถึง Mid-level Game Developer พร้อมแนวคำตอบที่ดี ลองตอบด้วยตัวเองก่อนเปิดดู และยกตัวอย่างจาก Star Dodger ทุกครั้งที่ทำได้ เพราะผู้สัมภาษณ์อยากได้ยินประสบการณ์จริงมากกว่านิยาม

1. Delta Time คืออะไร และ _process() ต่างจาก _physics_process() อย่างไร (Junior)

Delta Time คือเวลาที่ผ่านไปตั้งแต่เฟรมก่อนหน้า หน่วยเป็นวินาที ทุกการเคลื่อนที่และการนับเวลาต้องคูณด้วย delta เพื่อให้เกมเร็วเท่ากันทุกเครื่อง เช่น ศัตรูความเร็ว 200 px/s ที่ 30 FPS ขยับเฟรมละ 6.67 px ส่วนที่ 144 FPS ขยับเฟรมละ 1.39 px แต่ใน 1 วินาทีได้ระยะ 200 px เท่ากัน ถ้าลืมคูณ delta เกมจะเร็วขึ้นตามความแรงของเครื่อง

  • _process(delta) ถูกเรียกทุกเฟรมที่วาดภาพ ค่า delta เปลี่ยนไปตาม FPS เหมาะกับงานด้านภาพ เช่น UI หรือ Screen Shake
  • _physics_process(delta) ถูกเรียกด้วยจังหวะคงที่ ค่าตั้งต้น 60 ครั้งต่อวินาที (Physics Ticks per Second) เหมาะกับการเคลื่อนที่ที่เกี่ยวกับการชน ผลจึงคงที่ทุกเครื่อง
  • จุดที่ผู้สัมภาษณ์ชอบถามต่อ: move_and_slide() ใช้ velocity หน่วย px/s และคูณ delta ให้เองแล้ว จึงห้ามคูณซ้ำ ส่วนการขยับ position เองต้องคูณ delta ทุกครั้ง

ตัวอย่างจาก Star Dodger: ยานเดินใน _physics_process() ด้วย velocity = direction * speed ศัตรูขยับ position.y += speed * delta ส่วนกล้องสั่นอยู่ใน _process() เพราะเป็นงานด้านภาพล้วน และ Hitstop ใช้ Engine.time_scale ซึ่งทำให้ delta ของทุก Node เล็กลงพร้อมกัน ผู้สมัครที่ดีจะพูดถึงการจำกัดค่า delta ที่ใหญ่ผิดปกติหลังเกมค้าง (Spiral of Death) ด้วย

2. Collision Layer กับ Collision Mask ต่างกันอย่างไร (Junior)

Layer บอกว่า Object นี้อยู่ชั้นไหน ส่วน Mask บอกว่า Object นี้มองหาชั้นไหน Area2D จะส่ง body_entered เมื่อ Mask ของมันตรงกับ Layer ของ Body ที่เข้ามา ถ้าตั้งผิดฝั่ง Signal จะไม่ถูกส่งเลยโดยไม่มี Error ให้เห็น ซึ่งเป็นบั๊กที่มือใหม่เจอบ่อยที่สุด

ใน Star Dodger ยานอยู่ Layer 1 (player) ศัตรูอยู่ Layer 2 และดาวอยู่ Layer 3 ทั้งคู่มี Mask 1 จึงเห็นเฉพาะยาน ศัตรูกับดาวไม่ตรวจกันเอง ประหยัดงานของ Physics Engine และไม่ต้องเขียน if กรองในโค้ด ส่วนยานมี Mask 4 (walls) เพื่อรองรับกำแพงในอนาคต

คำตอบที่ดีควรพูดถึงการตั้งชื่อ Layer ใน Project Settings > Layer Names เพื่อให้ทีมอ่านเข้าใจ และรู้ว่าไฟล์ .tscn เก็บเป็นบิต เช่น collision_layer = 4 คือ Layer 3 ซึ่งช่วยได้มากเวลารีวิวโค้ดผ่าน Git

3. เมื่อไรควรใช้ Signal เมื่อไรควรเรียกฟังก์ชันตรงๆ และควรใช้ Autoload แค่ไหน (Junior–Mid)

หลักที่ทีม Godot ใช้กันคือ "Call down, signal up" Node แม่รู้จักลูกของตัวเอง จึงเรียกฟังก์ชันของลูกได้ตรงๆ ส่วนลูกไม่ควรรู้ว่าใครฟังอยู่ จึงส่ง Signal ขึ้นไป

  • เรียกตรง: game.gd สั่ง spawn_timer.stop() และซ่อนยานเอง เพราะเป็นเจ้าของ Node เหล่านั้น อ่านง่ายและ Debug ง่าย
  • Signal: ดาวส่ง collected(points) โดยไม่รู้ว่าใครให้คะแนน ดาวจึงนำไปใช้ฉากอื่นได้ และมีผู้ฟังหลายรายพร้อมกันได้ ข้อเสียคือถ้าใช้มากเกินไปจะไล่ลำดับการทำงานยาก
  • Group: ใช้เมื่อต้องสั่งหรือค้นหา Node จำนวนมากที่ไม่รู้ตำแหน่ง เช่น get_tree().call_group("enemies", "stun")

Autoload เหมาะกับข้อมูลหรือบริการที่ต้องอยู่ข้าม Scene เช่น GameState และ SaveManager ข้อดีคือเรียกได้จากทุกที่และไม่หายตอนเปลี่ยน Scene ข้อเสียคือเป็น Global State ที่ซ่อนการพึ่งพากัน ทดสอบแยกส่วนยาก มีปัญหาเรื่องลำดับการโหลด (SaveManager ต้องอยู่ก่อน GameState) และโตเป็น God Object ได้ง่าย คำตอบที่ดีคือใช้ให้น้อย ให้แต่ละตัวมีหน้าที่เดียว และไม่ให้ Autoload อ้างอิง Node ใน Scene

4. จะบันทึกข้อมูลผู้เล่นอย่างไร res:// กับ user:// ต่างกันอย่างไร และรับมือไฟล์เสียแบบไหน (Mid)

res:// คือไฟล์ของโปรเจกต์ หลัง Export จะถูกแพ็กอยู่ใน .pck และอ่านได้อย่างเดียว ส่วน user:// คือโฟลเดอร์ที่เขียนได้ของผู้เล่นแต่ละคน บน Windows อยู่ที่ %APPDATA%\Godot\app_userdata\ชื่อโปรเจกต์\ ส่วนเวอร์ชัน Web เก็บใน IndexedDB ของ Browser ข้อมูลผู้เล่นทุกอย่างจึงต้องเขียนลง user://

  • เลือกรูปแบบไฟล์: ConfigFile เหมาะกับค่าตั้งและสถิติง่ายๆ อ่านด้วยตาได้ JSON ใช้ร่วมกับระบบอื่นได้ แต่ตัวเลขทุกตัวจะถูกอ่านกลับมาเป็น float ส่วน Resource (.tres) สะดวกที่สุดแต่ห้ามโหลดจากแหล่งที่ไม่น่าเชื่อถือ เพราะ Resource ฝัง Script ได้ ไฟล์ Save ที่ผู้เล่นแชร์กันจึงอาจรันโค้ดอันตรายได้
  • รับมือไฟล์เสีย: ตรวจค่า Error จาก load() ทุกครั้ง แยกกรณีไม่มีไฟล์ออกจากไฟล์พัง ตรวจชนิดของทุกค่าที่อ่าน และใช้ค่าตั้งต้นเมื่อผิด แบบเดียวกับ SaveManager ที่ทดสอบให้ดูแล้วว่าเกมไม่ Crash
  • ระดับ Mid ควรพูดต่อ: ใส่เลขเวอร์ชันของรูปแบบไฟล์เพื่อแปลงข้อมูลเก่าเมื่ออัปเดตเกม และเขียนลงไฟล์ชั่วคราวก่อนแล้วค่อยเปลี่ยนชื่อทับ เพื่อไม่ให้ไฟล์พังถ้าไฟดับระหว่างบันทึก
