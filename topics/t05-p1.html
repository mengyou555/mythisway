5.1Learning Roadmap

Security

อ่านก่อนเริ่มทุกครั้ง: ฝึกบนระบบของตัวเองเท่านั้น ทุกเทคนิคในหัวข้อนี้ให้ฝึกได้เฉพาะบนเครื่อง VM หรือ Container ของคุณเอง หรือบนแพลตฟอร์มฝึกที่อนุญาตอย่างถูกกฎหมาย เช่น TryHackMe, Hack The Box, OverTheWire และ picoCTF เท่านั้น การสแกน เจาะ หรือทดสอบระบบของผู้อื่นโดยไม่ได้รับอนุญาตเป็นเรื่องผิดกฎหมายตาม พ.ร.บ.ว่าด้วยการกระทำความผิดเกี่ยวกับคอมพิวเตอร์ ของไทย มีโทษทั้งจำและปรับ ในหลักสูตรนี้เราจะสแกนและทดสอบเฉพาะ 127.0.0.1, Container ของตัวเอง และช่วง IP สำหรับเอกสาร (192.0.2.0/24, 198.51.100.0/24, 203.0.113.0/24) ซึ่งไม่มีอยู่จริงบนอินเทอร์เน็ต

ภาพรวมเส้นทาง

Cyber Security คือศาสตร์ของการ ปกป้องระบบ ข้อมูล และผู้ใช้จากการโจมตี มีสองฝั่งหลักที่ทำงานเสริมกัน ฝั่งป้องกัน (Blue Team) ทำหน้าที่ทำให้ระบบแข็งแรง เฝ้าระวัง และตอบสนองเมื่อถูกโจมตี ส่วนฝั่งทดสอบเจาะระบบ (Red Team) จำลองการโจมตีในแล็บเพื่อหาช่องโหว่ก่อนที่คนร้ายจริงจะเจอ หัวข้อนี้สอนทั้งสองฝั่ง โดยเน้นที่ Blue Team ก่อน เพราะเป็นงานที่มีตำแหน่งเปิดรับมากที่สุดสำหรับคนเริ่มต้น และปูพื้นให้เข้าใจว่าควรป้องกันอะไร ก่อนจะไปเรียนรู้ว่าโจมตีอย่างไร

หัวข้อนี้เป็นหัวข้อ ลำดับที่ 17 ของเส้นทางที่แนะนำ และเป็นหัวข้อที่ยากที่สุด (ระดับความยาก 5 จาก 5) เพราะต้องใช้ความรู้แทบทุกหัวข้อที่ผ่านมารวมกัน ทั้ง Linux, Network, Web, SQL และ API คุณจะได้นำทักษะเหล่านั้นมาใช้จริงในบริบทความปลอดภัย เช่น อ่าน Log ของ Linux เพื่อจับการเดารหัสผ่าน แก้ช่องโหว่ SQL Injection ในเว็บแอป และตั้งค่า Firewall ให้ Server

เส้นทางนี้แบ่งเป็น 12 ขั้นใน 3 ระดับ เริ่มจากจริยธรรม กฎหมาย และการตั้งแล็บที่ปลอดภัย ต่อด้วยแนวคิดพื้นฐานอย่าง CIA Triad และวิธีคิดแบบผู้โจมตี แล้วลงมือ Hardening เครื่อง Linux ตั้ง Firewall จัดการการยืนยันตัวตน สแกนพอร์ตอย่างมีจริยธรรม จนถึงระดับสูงคือความปลอดภัยเว็บตาม OWASP Top 10 การเขียนโปรแกรมตรวจจับการโจมตีจาก Log การจัดการช่องโหว่ และการตอบสนองต่อเหตุการณ์ จบด้วย Mini Project ประเมินความปลอดภัยของแล็บตัวเองแบบมืออาชีพ

ใช้เวลารวมประมาณ 120–200 ชั่วโมง ถ้าเรียนวันละ 1.5–2 ชั่วโมง จะจบในราว 14–18 สัปดาห์ แต่ละขั้นมี Checkpoint ที่ระบุสิ่งที่ต้องทำได้จริงก่อนไปขั้นถัดไป ให้ทำ Checkpoint ให้ผ่านจริงเสมอ เพราะงานด้านความปลอดภัยพลาดไม่ได้

  1. Beginner Step 1 · จริยธรรม กฎหมาย และการตั้งแล็บที่ปลอดภัย
  2. Beginner Step 2 · แนวคิดพื้นฐาน: CIA Triad, Threat, Vulnerability, Risk
  3. Beginner Step 3 · เข้าใจผู้โจมตี: Cyber Kill Chain และ MITRE ATT&CK
  4. Beginner Step 4 · Cryptography พื้นฐาน: Hashing, Salt, Symmetric vs Asymmetric
  5. Intermediate Step 5 · Linux Hardening: Users, sudo, Permissions และ SSH
  6. Intermediate Step 6 · Firewall และ Intrusion Prevention ด้วย ufw และ fail2ban
  7. Intermediate Step 7 · Authentication และ Access Control
  8. Intermediate Step 8 · Network Security: nmap, tcpdump และ IDS/IPS
  9. Advanced Step 9 · Web Security และ OWASP Top 10
  10. Advanced Step 10 · Logging, Monitoring และ Detection
  11. Advanced Step 11 · Vulnerability Management และ Threat Modeling
  12. Advanced Step 12 · Incident Response และ Mini Project

เวลาข้างต้นเป็นช่วงกว้างเพราะความปลอดภัยเป็นหัวข้อที่ลึกมาก คนที่ผ่าน Linux, Network และ Web มาแน่นจะใช้เวลาน้อยกว่าช่วงล่าง ส่วนคนที่ต้องกลับไปทบทวนพื้นฐานบ่อยจะใช้เวลาใกล้ช่วงบน

จริยธรรมและกฎหมาย: กฎข้อแรกของสายงานนี้

ก่อนเรียนเทคนิคใดๆ ต้องเข้าใจเส้นแบ่งทางกฎหมายและจริยธรรมให้ชัดเจน เพราะเครื่องมือเดียวกันใช้ได้ทั้งเพื่อป้องกันและเพื่อโจมตี สิ่งที่ตัดสินว่าถูกหรือผิดคือ คุณได้รับอนุญาตให้ทำกับระบบนั้นหรือไม่

คำศัพท์ความหมายสิ่งที่ต้องจำ
Authorization (การได้รับอนุญาต)ความยินยอมเป็นลายลักษณ์อักษรให้ทดสอบระบบหนึ่ง เรียกว่า Scope และ Rules of Engagementไม่มีเอกสารอนุญาต = ห้ามทำ แม้จะหวังดีก็ผิดกฎหมาย
พ.ร.บ.คอมพิวเตอร์พ.ร.บ.ว่าด้วยการกระทำความผิดเกี่ยวกับคอมพิวเตอร์ของไทย กำหนดโทษการเข้าถึงระบบของผู้อื่นโดยมิชอบการเข้าถึงหรือสแกนระบบคนอื่นโดยไม่ได้รับอนุญาตมีโทษจำคุกและปรับ
White Hat / Black Hat / Grey HatWhite Hat ทำงานโดยได้รับอนุญาตและเปิดเผยช่องโหว่อย่างมีความรับผิดชอบ Black Hat โจมตีเพื่อผลประโยชน์ผิดกฎหมาย Grey Hat อยู่ตรงกลางแต่ยังเสี่ยงผิดกฎหมายเป้าหมายของหลักสูตรนี้คือ White Hat เท่านั้น
Responsible Disclosureการแจ้งเจ้าของระบบเมื่อพบช่องโหว่ ให้เวลาแก้ไขก่อนเปิดเผยต่อสาธารณะ มักผ่านโปรแกรม Bug Bountyเจอช่องโหว่ในระบบจริงโดยบังเอิญ ให้แจ้งเจ้าของ ห้ามใช้ประโยชน์
Scopeขอบเขตที่อนุญาตให้ทดสอบ ระบุ IP โดเมน และเทคนิคที่ทำได้/ห้ามทำทำนอก Scope แม้แต่นิดเดียวก็ถือว่าผิด
เปรียบเทียบ

ช่างกุญแจมืออาชีพรู้วิธีสะเดาะกุญแจทุกแบบ แต่เขาจะเปิดล็อกให้ก็ต่อเมื่อเจ้าของบ้านขอและพิสูจน์ได้ว่าเป็นบ้านของตัวเอง ความรู้เดียวกันนี้ถ้าใช้งัดบ้านคนอื่นคือการบุกรุก งาน Cyber Security ก็เหมือนกัน ทักษะไม่ใช่ปัญหา แต่ การได้รับอนุญาต คือเส้นแบ่งระหว่างอาชีพกับอาชญากรรม

Prerequisites: ต้องรู้อะไรมาก่อน

หัวข้อนี้อยู่ท้ายเส้นทางเพราะต้องนำความรู้จากหลายหัวข้อมาใช้พร้อมกัน ถ้ายังไม่แม่นหัวข้อด้านล่าง ให้กลับไปทบทวนก่อน มิฉะนั้นจะเรียนหัวข้อนี้ได้ไม่ลึก

  • จำเป็นมากที่สุด ต้องใช้ Terminal, Permissions, Users, sudo, SSH, การอ่าน Log ใน /var/log และ journalctl ทุกวันในหัวข้อนี้
  • ต้องเข้าใจ IP, Port, TCP/UDP, DNS, HTTP และ Firewall เพราะการโจมตีและการป้องกันเกือบทั้งหมดเกิดบนเครือข่าย
  • ใช้เขียนเครื่องมือตรวจจับการโจมตี วิเคราะห์ Log และเรียกใช้ไลบรารี Cryptography อย่าง hashlib และ argon2
  • ต้องเข้าใจ Query และ Parameterized Query เพื่อเข้าใจและแก้ช่องโหว่ SQL Injection
  • ต้องรู้พื้นฐานเว็บ HTML, JavaScript และ DOM เพื่อเข้าใจ XSS และการเข้ารหัส Output
  • ช่วยให้เข้าใจ Authentication, Token, Header และการออกแบบ API ที่ปลอดภัย

นอกจากนี้ควรมี Docker Desktop พร้อม WSL 2 backend ติดตั้งแล้ว เพื่อรันแอปที่มีช่องโหว่ไว้ฝึกในแล็บ (สอนวิธีติดตั้งในส่วนที่ 2) ทดสอบความพร้อมด้วยคำสั่งด้านล่างใน Ubuntu

วิธีเรียนหัวข้อนี้ให้ได้ผลและปลอดภัย

  1. แยกแล็บออกจากเครื่องใช้งานจริง ฝึกในเครื่อง VM, WSL หรือ Container ที่แยกต่างหาก ไม่ทดลองเทคนิคโจมตีบนเครื่องที่คุณใช้ทำงานหรือเก็บข้อมูลสำคัญ
  2. ผูกทุกบริการไว้กับ 127.0.0.1 เมื่อรันแอปที่มีช่องโหว่ใน Docker ให้ Bind กับ 127.0.0.1 เสมอ เพื่อไม่ให้คนอื่นในเครือข่ายเข้าถึงได้
  3. เรียนฝั่งป้องกันก่อนฝั่งโจมตี เข้าใจว่าควรป้องกันอะไรและอย่างไร ก่อนจะเรียนเทคนิคโจมตี เพราะทำให้เห็นภาพว่าการโจมตีไปกระทบอะไร
  4. จด Lab Journal บันทึกทุกคำสั่งที่รัน ผลลัพธ์ที่ได้ และข้อสรุปลงใน ~/projects/sec-lab/notes แล้ว Commit ด้วย Git ทุกวัน นี่คือพื้นฐานของการเขียนรายงานความปลอดภัยในงานจริง
  5. ฝึกบนแพลตฟอร์มถูกกฎหมายควบคู่ไป ใช้ TryHackMe, Hack The Box, OverTheWire Bandit และ picoCTF เสริม ซึ่งออกแบบมาให้ฝึกโจมตีได้อย่างถูกกฎหมาย
  6. อ่าน Error และ Log ให้เป็นนิสัย งานความปลอดภัยคือการสังเกตสิ่งผิดปกติ การอ่าน Log ทุกบรรทัดจนเข้าใจคือทักษะหลักของอาชีพนี้
ระวัง

อย่าดาวน์โหลดเครื่องมือหรือ Payload จากเว็บหรือกลุ่มที่ไม่น่าเชื่อถือมารันบนเครื่องตัวเอง เครื่องมือ "แฮก" ที่หาได้ฟรีจำนวนมากมีมัลแวร์ฝังอยู่ ให้ใช้เครื่องมือจากแหล่งทางการ เช่น apt ของ Ubuntu, PyPI ที่ Pin เวอร์ชัน และ Image ทางการบน Docker Hub เท่านั้น

Beginner รากฐาน: จริยธรรม แนวคิด และวิธีคิดด้านความปลอดภัย

ความรู้ด้านความปลอดภัยเป็นดาบสองคม ใช้ผิดที่แม้โดยไม่ตั้งใจก็ผิดกฎหมายและทำลายอาชีพได้ การเข้าใจเส้นแบ่งทางกฎหมายและตั้งแล็บที่แยกจากระบบจริงตั้งแต่ต้น คือสิ่งที่ทำให้คุณฝึกได้อย่างสบายใจตลอดหัวข้อนี้ และเป็นสิ่งแรกที่ผู้สัมภาษณ์งานสายนี้ถามเสมอ
ลงมือทำ
  • สร้างโฟลเดอร์ ~/projects/sec-lab และโฟลเดอร์ย่อย แล้ว Commit แรกด้วย Git

ใช้เวลา
8–12 ชั่วโมง แบ่งเป็นอ่านเรื่องกฎหมายและจริยธรรม 2–3 ชั่วโมง ตั้งแล็บและ Docker 3–4 ชั่วโมง และฝึก Bandit อีก 3–5 ชั่วโมง
Checkpoint

ก่อนไปขั้นถัดไป คุณต้องทำสิ่งเหล่านี้ได้: (1) อธิบายได้ว่าทำไมต้องได้รับอนุญาตก่อนทดสอบระบบ และยกตัวอย่างสิ่งที่ผิด พ.ร.บ.คอมพิวเตอร์ (2) มีโฟลเดอร์ ~/projects/sec-lab ที่ Commit ด้วย Git แล้ว (3) รันแอปทดสอบใน Docker ที่ผูกกับ 127.0.0.1 ได้ (4) ผ่านด่าน Bandit อย่างน้อยถึงด่าน 3 และจดวิธีผ่านลง Lab Journal

STEP 2

แนวคิดพื้นฐาน: CIA Triad, Threat, Vulnerability, Risk

1 สัปดาห์ · 8–10 ชม.
หัวข้อย่อย
  • CIA Triad: Confidentiality (ความลับ), Integrity (ความถูกต้อง), Availability (ความพร้อมใช้) และตัวอย่างการโจมตีที่กระทบแต่ละด้าน
  • ความต่างของ Threat (ภัยคุกคาม), Vulnerability (ช่องโหว่), Risk (ความเสี่ยง) และ Exploit พร้อมสูตรคิด Risk = Likelihood × Impact
  • แนวคิด Defense in Depth (ป้องกันเป็นชั้น), Least Privilege (ให้สิทธิ์น้อยที่สุดเท่าที่จำเป็น) และ Zero Trust (ไม่เชื่อใครโดยอัตโนมัติ)
  • ประเภทของ Asset (สิ่งที่ต้องปกป้อง) และ Attack Surface (ช่องทางที่ถูกโจมตีได้) และการทำ Asset Inventory เบื้องต้น
  • ความต่างของ Security กับ Privacy และแนวคิด AAA (Authentication, Authorization, Accounting)
  • เขียนสคริปต์ Python สั้นๆ ให้คะแนนความเสี่ยงของ Asset หลายตัวเพื่อฝึกคิดแบบจัดลำดับความสำคัญ
ทำไมต้องเรียน
ทุกการตัดสินใจด้านความปลอดภัยคือการจัดการความเสี่ยง ไม่ใช่การทำให้ปลอดภัย 100% ซึ่งเป็นไปไม่ได้ ถ้าไม่เข้าใจ CIA Triad และการประเมินความเสี่ยง จะเลือกไม่ถูกว่าควรทุ่มเวลาและงบไปป้องกันอะไรก่อน คำศัพท์เหล่านี้ยังเป็นภาษากลางที่ใช้ในเอกสาร รายงาน และการสัมภาษณ์งานสายนี้ทุกตำแหน่ง
ลงมือทำ
  • ทำ Asset Inventory ของเครื่องตัวเอง ระบุ 5 Asset ที่สำคัญที่สุดและภัยที่กระทบแต่ละ Asset
  • เขียนสคริปต์ Python คำนวณคะแนนความเสี่ยงของ Asset เหล่านั้น แล้วเรียงจากเสี่ยงมากไปน้อย
  • จับคู่เหตุการณ์ข่าวการโจมตีจริงกับด้านของ CIA ที่ถูกกระทบลง Lab Journal
ใช้เวลา
8–10 ชั่วโมง เน้นทำความเข้าใจคำศัพท์และฝึกคิดแบบความเสี่ยง มากกว่าการท่องจำ
Checkpoint

ก่อนไปขั้นถัดไป คุณต้องทำสิ่งเหล่านี้ได้: (1) อธิบาย CIA Triad พร้อมยกตัวอย่างการโจมตีที่กระทบแต่ละด้าน (2) แยก Threat, Vulnerability และ Risk ออกจากกันได้ด้วยตัวอย่างของตัวเอง (3) อธิบาย Least Privilege และ Defense in Depth ด้วยคำพูดของตัวเอง (4) รันสคริปต์ให้คะแนนความเสี่ยงและอ่านผลเพื่อบอกได้ว่าควรแก้ Asset ใดก่อน

STEP 3

เข้าใจผู้โจมตี: Cyber Kill Chain และ MITRE ATT&CK

1 สัปดาห์ · 8–10 ชม.
หัวข้อย่อย
  • Cyber Kill Chain ของ Lockheed Martin 7 ขั้น: Reconnaissance, Weaponization, Delivery, Exploitation, Installation, Command & Control (C2) และ Actions on Objectives
  • MITRE ATT&CK: ความต่างของ Tactic (ผู้โจมตีต้องการอะไร) กับ Technique (ทำอย่างไร) และวิธีเปิดดู Matrix ที่ attack.mitre.org
  • ประเภทของภัยคุกคาม: Malware (Virus, Worm, Trojan, Ransomware), Phishing และ Social Engineering, DoS/DDoS, Man-in-the-Middle และ Insider Threat
  • ประเภทของผู้โจมตี (Threat Actor): Script Kiddie, Hacktivist, Organized Crime, Nation-State (APT) และแรงจูงใจของแต่ละกลุ่ม
  • สายอาชีพด้านความปลอดภัย: Blue Team (ป้องกัน), Red Team (จำลองโจมตี), Purple Team (ผสานสองฝั่ง) และ GRC (Governance, Risk, Compliance)
  • จับคู่เทคนิคการโจมตีที่ได้ยินในข่าวกับขั้นใน Kill Chain และ Tactic ใน ATT&CK
ทำไมต้องเรียน
การป้องกันที่ดีต้องเข้าใจว่าผู้โจมตีทำงานเป็นขั้นตอนอย่างไร เพราะการตัดวงจรเพียงขั้นเดียวก็หยุดการโจมตีได้ Kill Chain และ ATT&CK เป็นกรอบที่ทีม SOC และ Incident Response ทั่วโลกใช้สื่อสารกัน การรู้จักกรอบเหล่านี้ทำให้คุณอ่านรายงานภัยคุกคามและคุยกับทีมได้รู้เรื่อง
ลงมือทำ
  • เปิด MITRE ATT&CK Matrix แล้วเลือก Technique 3 อันมาเขียนสรุปว่าป้องกันและตรวจจับอย่างไร
  • วาดแผนภาพ Kill Chain 7 ขั้นพร้อมตัวอย่างการป้องกันในแต่ละขั้น
  • เขียนลง Lab Journal ว่าตัวเองสนใจสาย Blue, Red, Purple หรือ GRC และเพราะอะไร
ใช้เวลา
8–10 ชั่วโมง ส่วนใหญ่ใช้อ่านและทำแผนภาพให้เข้าใจภาพรวม ไม่ต้องจำทุก Technique
Checkpoint

ก่อนไปขั้นถัดไป คุณต้องทำสิ่งเหล่านี้ได้: (1) ท่องและอธิบาย 7 ขั้นของ Cyber Kill Chain พร้อมตัวอย่างการป้องกันอย่างน้อย 1 อย่างต่อขั้น (2) อธิบายความต่างของ Tactic กับ Technique ใน MITRE ATT&CK (3) แยกประเภทภัยคุกคามหลัก 5 แบบและยกตัวอย่างได้ (4) อธิบายความต่างของ Blue, Red, Purple Team และ GRC

STEP 4

Cryptography พื้นฐาน: Hashing, Salt, Symmetric vs Asymmetric

1.5 สัปดาห์ · 10–14 ชม.
หัวข้อย่อย
  • Hashing ด้วย SHA-256: คุณสมบัติทางเดียว (One-way) และใช้ตรวจความถูกต้องของไฟล์ ด้วย sha256sum และ hashlib ใน Python
  • ความต่างของ Encoding (เช่น Base64, ย้อนกลับได้ ไม่ใช่ความปลอดภัย), Hashing (ทางเดียว) และ Encryption (ย้อนกลับได้ด้วย Key)
  • Symmetric (Key เดียว เช่น AES) กับ Asymmetric (Key คู่ Public/Private เช่น RSA, Ed25519) และบทบาทของแต่ละแบบ
  • พื้นฐาน TLS และ Certificate: Certificate Authority (CA), Chain of Trust และการสร้าง Self-signed Certificate ด้วย openssl สำหรับแล็บ
  • ทำไมห้ามเก็บรหัสผ่านเป็น Plaintext หรือ Hash ธรรมดา และความสำคัญของ Salt (เกริ่นก่อนลงลึกใน Step 7)
  • Digital Signature และ Hashing เพื่อตรวจ Integrity ของไฟล์ที่ดาวน์โหลด (เทียบ Checksum)
ทำไมต้องเรียน
Cryptography อยู่เบื้องหลังทุกอย่างที่ปลอดภัยบนอินเทอร์เน็ต ตั้งแต่รหัสผ่าน HTTPS SSH ไปจนถึงลายเซ็นดิจิทัล ถ้าไม่เข้าใจความต่างของ Hash กับ Encryption จะออกแบบระบบผิดพลาดร้ายแรง เช่น เก็บรหัสผ่านแบบย้อนกลับได้ ความเข้าใจนี้ยังเป็นพื้นฐานที่ต้องใช้ตลอดใน Step 5 (SSH Key), Step 7 (Password Hashing) และ Step 9 (TLS/HTTPS)
ลงมือทำ
  • ใช้ sha256sum สร้าง Checksum ของไฟล์ แก้ไฟล์ 1 ตัวอักษร แล้วตรวจว่า Hash เปลี่ยน
  • สร้าง Self-signed Certificate ด้วย openssl แล้วอ่านรายละเอียดด้วย openssl x509
  • เขียนสคริปต์ Python ที่ Hash ข้อความด้วย hashlib และอธิบายว่าทำไม Salt จึงจำเป็น
ใช้เวลา
10–14 ชั่วโมง เพราะมีทั้งทฤษฎีและการลงมือใช้ openssl กับ hashlib ซึ่งต้องฝึกจนเข้าใจว่าแต่ละคำสั่งทำอะไร
Checkpoint

ก่อนไปขั้นถัดไป คุณต้องทำสิ่งเหล่านี้ได้: (1) อธิบายความต่างของ Encoding, Hashing และ Encryption พร้อมยกตัวอย่างการใช้แต่ละแบบ (2) ใช้ sha256sum ตรวจว่าไฟล์ถูกแก้ไขหรือไม่ (3) อธิบายความต่างของ Symmetric กับ Asymmetric และยกตัวอย่าง (4) สร้างและอ่าน Self-signed Certificate ด้วย openssl ได้ (5) อธิบายว่าทำไมต้องใช้ Salt กับรหัสผ่าน

Intermediate ลงมือป้องกัน: Hardening, Firewall, Authentication และ Network

ระดับนี้เปลี่ยนจากแนวคิดเป็นการลงมือทำจริงบน Linux คุณจะทำให้เครื่องแข็งแรงขึ้นทีละชั้น ตั้ง Firewall และระบบกันการเดารหัสผ่าน จัดการการยืนยันตัวตนให้ปลอดภัย และสำรวจเครือข่ายในแล็บของตัวเองด้วยเครื่องมือมืออาชีพอย่างมีจริยธรรม

STEP 5

Linux Hardening: Users, sudo, Permissions และ SSH

1.5 สัปดาห์ · 12–16 ชม.
หัวข้อย่อย
  • จัดการผู้ใช้อย่างปลอดภัย: สร้างผู้ใช้ด้วย adduser, ให้สิทธิ์ผ่านกลุ่ม sudo, ตรวจสิทธิ์ด้วย sudo -l และหลักการ Least Privilege
  • File Permissions เชิงความปลอดภัย: chmod, chown, ความหมายของ 600 และ 700 กับไฟล์ลับ, ความเสี่ยงของ World-writable และ SUID bit
  • SSH Hardening: สร้างและใช้ SSH Key (ssh-keygen -t ed25519), ปิด PermitRootLogin, ปิด PasswordAuthentication, ตั้ง MaxAuthTries และ AllowUsers ในไฟล์ /etc/ssh/sshd_config.d/
  • ตรวจความถูกต้องของค่า SSH ด้วย sshd -t และ sshd -T ก่อน Restart บริการ
  • การ Patch: อัปเดตด้วย apt update && apt upgrade อย่างสม่ำเสมอ และเข้าใจว่าทำไมการอัปเดตคือการป้องกันที่คุ้มค่าที่สุด
  • เครื่องมือตรวจ Hardening อัตโนมัติ Lynis (lynis audit system) และการอ่าน Hardening Index
ทำไมต้องเรียน
Server ที่ถูกเจาะส่วนใหญ่ไม่ได้ถูกเจาะด้วยเทคนิคซับซ้อน แต่เพราะตั้งค่าหละหลวม เช่น เปิดให้ root ล็อกอินด้วยรหัสผ่าน หรือไม่อัปเดต การ Hardening คืองานประจำวันของ Blue Team และเป็นด่านป้องกันแรกที่ลดโอกาสถูกเจาะได้มากที่สุด ทักษะนี้ยังเป็นหัวใจของ Mini Project ในหัวข้อนี้
ลงมือทำ
  • สร้างไฟล์ Hardening ของ SSH ใน /etc/ssh/sshd_config.d/99-hardening.conf แล้วตรวจด้วย sshd -t
  • สร้าง SSH Key ด้วย Ed25519 และทดสอบ SSH เข้า localhost ด้วย Key แทนรหัสผ่าน
  • รัน lynis audit system จดคำแนะนำ 5 ข้อแรกและลงมือแก้อย่างน้อย 3 ข้อ
ใช้เวลา
12–16 ชั่วโมง เพราะต้องลงมือตั้งค่าจริง ทดสอบ และแก้ตามผล Lynis ซ้ำหลายรอบ
Checkpoint

ก่อนไปขั้นถัดไป คุณต้องทำสิ่งเหล่านี้ได้: (1) สร้างผู้ใช้ใหม่และให้สิทธิ์ sudo อย่างถูกต้อง พร้อมอธิบาย Least Privilege (2) ตั้ง Permission ของไฟล์ลับเป็น 600 และอธิบายได้ว่าทำไม (3) Hardening SSH ให้ปิด root login และ Password login โดยเข้าด้วย Key ได้ และยืนยันด้วย sshd -T (4) รัน Lynis และอ่าน Hardening Index พร้อมแก้ตามคำแนะนำได้

STEP 6

Firewall และ Intrusion Prevention ด้วย ufw และ fail2ban

1.5 สัปดาห์ · 10–14 ชม.
หัวข้อย่อย
  • ufw (Uncomplicated Firewall): แนวคิด Default Deny Incoming / Allow Outgoing, การเปิดพอร์ตเฉพาะที่จำเป็น และ ufw limit เพื่อจำกัดการเชื่อมต่อถี่ๆ
  • อ่านและเข้าใจ ufw status verbose และความสัมพันธ์ระหว่าง ufw กับ iptables/nftables ที่อยู่เบื้องหลัง
  • fail2ban: หลักการ Jail, Filter และ Action, การตั้ง jail.local สำหรับ sshd เพื่อแบน IP ที่พยายามเดารหัสผ่านเกินกำหนด
  • อ่านสถานะด้วย fail2ban-client status sshd เพื่อดู IP ที่ถูกแบนและจำนวนครั้งที่ล้มเหลว
  • unattended-upgrades: ตั้งให้ติดตั้ง Patch ความปลอดภัยอัตโนมัติ และตรวจไฟล์ /etc/apt/apt.conf.d/20auto-upgrades
  • ข้อควรรู้บน WSL: Service เหล่านี้ทำงานเฉพาะตอน WSL เปิดอยู่ และ ufw ใน WSL มีข้อจำกัดบางอย่างเมื่อเทียบกับ Server จริง
ทำไมต้องเรียน
Firewall คือการควบคุมว่าใครเข้าถึงบริการใดได้บ้าง ส่วน fail2ban คือการตอบโต้การเดารหัสผ่านอัตโนมัติ และ unattended-upgrades คือการอุดช่องโหว่ก่อนถูกใช้โจมตี ทั้งสามอย่างคือเครื่องมือป้องกันพื้นฐานที่ Server ทุกเครื่องควรมี และเป็นสิ่งที่ตรวจเจอว่า "ยังไม่ได้ทำ" บ่อยที่สุดในงานประเมินความปลอดภัย
ลงมือทำ
  • ตั้ง ufw ให้ Default Deny Incoming และเปิดเฉพาะ SSH ด้วย ufw limit 22/tcp แล้วอ่าน ufw status verbose
  • ตั้ง fail2ban jail สำหรับ sshd ให้แบน IP หลังล้มเหลว 5 ครั้ง แล้วตรวจด้วย fail2ban-client status sshd
  • เปิด unattended-upgrades และยืนยันการตั้งค่าในไฟล์ 20auto-upgrades
ใช้เวลา
10–14 ชั่วโมง เน้นการตั้งค่า อ่านสถานะ และทดสอบว่ากฎทำงานตามที่ตั้งใจ
Checkpoint

ก่อนไปขั้นถัดไป คุณต้องทำสิ่งเหล่านี้ได้: (1) ตั้ง ufw ให้ Default Deny Incoming และเปิดเฉพาะพอร์ตที่จำเป็น พร้อมอ่าน ufw status verbose เป็น (2) อธิบายหลักการ Jail, Filter, Action ของ fail2ban (3) ตั้ง fail2ban ให้แบน IP ที่เดารหัสผ่าน SSH และอ่านสถานะได้ (4) เปิด unattended-upgrades และอธิบายว่าทำไมการ Patch อัตโนมัติจึงสำคัญ

STEP 7

Authentication และ Access Control

1.5 สัปดาห์ · 10–14 ชม.
หัวข้อย่อย
  • ความต่างของ Authentication (คุณเป็นใคร), Authorization (คุณทำอะไรได้) และ Accounting (บันทึกว่าคุณทำอะไรไป)
  • รหัสผ่านที่ดี: ความยาวสำคัญกว่าความซับซ้อน, Passphrase, และเหตุผลที่ห้ามใช้รหัสผ่านซ้ำกันหลายที่
  • Password Hashing ที่ถูกต้อง ด้วย argon2 (แนะนำ) และ bcrypt: Salt อัตโนมัติ, Work Factor และทำไม SHA-256 ธรรมดาไม่เหมาะกับรหัสผ่าน
  • MFA (Multi-Factor Authentication): อะไรที่คุณรู้ มี และเป็น, TOTP (แอป Authenticator) และ Hardware Key
  • Password Manager และแนวคิด Passkeys (WebAuthn/FIDO2) ที่ใช้ Public/Private Key แทนรหัสผ่าน
  • Access Control Models: RBAC (ตามบทบาท) และ ABAC (ตามคุณสมบัติ) และหลักการ Least Privilege ในการให้สิทธิ์
ทำไมต้องเรียน
การยืนยันตัวตนที่อ่อนแอคือสาเหตุอันดับต้นของการถูกเจาะ ทั้งรหัสผ่านที่เดาง่าย การเก็บรหัสผ่านผิดวิธี และการไม่มี MFA เมื่อคุณสร้างระบบของตัวเองในงาน Backend หรือ Full-stack คุณต้องเก็บรหัสผ่านผู้ใช้ให้ถูกต้อง การเข้าใจ argon2 และ MFA จึงเป็นทักษะที่ใช้ได้ทันทีและผู้สัมภาษณ์ถามบ่อย
ลงมือทำ
  • เขียนสคริปต์ Python ที่ Hash และ Verify รหัสผ่านด้วย argon2 และแสดงรูปแบบ Hash ที่ได้
  • เปิด MFA แบบ TOTP ให้บัญชี GitHub ของตัวเองและบันทึก Recovery Code อย่างปลอดภัย
  • ติดตั้ง Password Manager และย้ายรหัสผ่านสำคัญเข้าไป พร้อมสร้างรหัสผ่านใหม่ที่ไม่ซ้ำกัน
ใช้เวลา
10–14 ชั่วโมง แบ่งเป็นทฤษฎีการยืนยันตัวตนและลงมือเขียน Password Hashing กับตั้งค่า MFA จริง
Checkpoint

ก่อนไปขั้นถัดไป คุณต้องทำสิ่งเหล่านี้ได้: (1) อธิบายความต่างของ Authentication, Authorization และ Accounting (2) Hash และ Verify รหัสผ่านด้วย argon2 ใน Python ได้ และอธิบายว่าทำไมต้องใช้ แทน SHA-256 (3) อธิบาย MFA ทั้งสามปัจจัยและเปิด TOTP ให้บัญชีจริงได้ (4) อธิบายแนวคิด Passkeys และข้อดีเหนือรหัสผ่าน

STEP 8

Network Security: nmap, tcpdump และ IDS/IPS

1.5 สัปดาห์ · 12–16 ชม.
หัวข้อย่อย
  • nmap: การสแกนหาพอร์ตที่เปิดและบริการที่รัน (-sV), ความต่างของ TCP Connect Scan กับ SYN Scan, และ สแกนได้เฉพาะ 127.0.0.1 หรือ Container ของตัวเองเท่านั้น
  • อ่านผลการสแกน: สถานะ open, closed, filtered และความหมายต่อการประเมินความปลอดภัย
  • tcpdump: การดักดูแพ็กเก็ตบน Loopback (-i lo) เพื่อเข้าใจ TCP Handshake และเห็นว่าข้อมูล HTTP ที่ไม่เข้ารหัสอ่านได้
  • แนวคิด IDS/IPS (Intrusion Detection/Prevention System) เช่น Suricata และ Snort และความต่างระหว่าง Detection กับ Prevention
  • Network Segmentation, VLAN และ DMZ ในการแบ่งโซนเครือข่ายเพื่อจำกัดความเสียหายเมื่อถูกเจาะ
  • ความสำคัญของ TLS/HTTPS เมื่อเห็นจาก tcpdump ว่าข้อมูลที่เข้ารหัสอ่านไม่ได้ ต่างจาก HTTP ธรรมดา
ทำไมต้องเรียน
การประเมินความปลอดภัยเริ่มจากการรู้ว่าเครื่องเปิดบริการอะไรไว้บ้าง เพราะทุกพอร์ตที่เปิดคือช่องทางที่อาจถูกโจมตี nmap คือเครื่องมือมาตรฐานสำหรับงานนี้ ส่วน tcpdump ช่วยให้เห็นด้วยตาตัวเองว่าทำไมต้องใช้ HTTPS ทักษะเหล่านี้ใช้ทั้งในการประเมินของ Red Team และการเฝ้าระวังของ Blue Team
ลงมือทำ
  • รันบริการทดสอบบน 127.0.0.1 แล้วสแกนด้วย nmap -sV -p <port> 127.0.0.1 และอ่านผล
  • ใช้ tcpdump ดักดู TCP Handshake บน Loopback ขณะเรียกบริการนั้นด้วย curl
  • เปรียบเทียบสิ่งที่ tcpdump เห็นเมื่อใช้ HTTP กับเมื่อใช้ HTTPS และจดข้อสรุป
ใช้เวลา
12–16 ชั่วโมง เพราะต้องฝึกอ่านผลสแกนและแพ็กเก็ตให้เข้าใจ ซึ่งต้องทำซ้ำหลายครั้ง
Checkpoint

ก่อนไปขั้นถัดไป คุณต้องทำสิ่งเหล่านี้ได้: (1) สแกนบริการบน 127.0.0.1 ด้วย nmap และอ่านได้ว่าพอร์ตใดเปิดและเป็นบริการอะไร (2) อธิบายได้ว่าทำไมห้ามสแกนระบบของผู้อื่น (3) ใช้ tcpdump ดู TCP Handshake บน Loopback และชี้ Flag SYN, SYN-ACK, ACK ได้ (4) อธิบายความต่างของ IDS กับ IPS และยกตัวอย่างเครื่องมือ

Advanced ลึกขึ้น: Web Security, Detection, Vulnerability และ Incident Response

ระดับนี้นำทุกอย่างมารวมกันเป็นงานจริง คุณจะหาและแก้ช่องโหว่เว็บตาม OWASP Top 10 เขียนโปรแกรมตรวจจับการโจมตีจาก Log จัดการช่องโหว่อย่างเป็นระบบ ทำ Threat Modeling และเรียนรู้กระบวนการตอบสนองเมื่อเกิดเหตุ จบด้วย Mini Project ที่รวมทักษะทั้งหมด

STEP 9

Web Security และ OWASP Top 10

2.5 สัปดาห์ · 16–22 ชม.
หัวข้อย่อย
  • OWASP Top 10: รายการความเสี่ยงเว็บที่สำคัญที่สุด ตรวจฉบับล่าสุดที่ owasp.org (ฉบับปี 2025 มี Broken Access Control, Security Misconfiguration, Software Supply Chain Failures, Cryptographic Failures, Injection เป็นต้น)
  • SQL Injection: สาธิตบนเว็บแอป Flask + SQLite เล็กๆ ที่รันบน 127.0.0.1 ว่าทำไมการต่อสตริงสร้าง Query จึงอันตราย และแก้ด้วย Parameterized Query
  • XSS (Cross-Site Scripting): สาธิต Stored/Reflected XSS และแก้ด้วย Output Encoding (Template ของ Jinja2 หนีอักขระให้อัตโนมัติ) และ Content Security Policy
  • CSRF (Cross-Site Request Forgery): แนวคิดและการป้องกันด้วย CSRF Token และ SameSite Cookie
  • Secure Headers: Content-Security-Policy, X-Content-Type-Options, Strict-Transport-Security และบทบาทของแต่ละตัว
  • Secrets Management: อ่าน Key จาก Environment Variable, ไฟล์ .env ที่อยู่ใน .gitignore, และห้าม Commit Secret ลง Git
  • ฝึกบน OWASP Juice Shop และ DVWA ใน Docker ที่ Bind กับ 127.0.0.1 เท่านั้น
ทำไมต้องเรียน
เว็บแอปคือพื้นผิวการโจมตีที่ใหญ่ที่สุดในปัจจุบัน และช่องโหว่อย่าง SQL Injection กับ XSS ยังพบได้ทั่วไป เมื่อคุณเป็นนักพัฒนา การเขียนโค้ดที่ปลอดภัยคือความรับผิดชอบโดยตรง ขั้นนี้สอนให้เห็นช่องโหว่ด้วยตาตัวเองและแก้ให้ถูกวิธี ซึ่งเป็นทักษะที่ทั้งสาย Application Security และ Backend ต้องมี
ลงมือทำ
  • รันเว็บแอปสาธิต SQL Injection บน 127.0.0.1 โจมตีด้วย ' OR '1'='1 แล้วแก้ด้วย Parameterized Query
  • สาธิต XSS ใน Flask template ที่ปิดการหนีอักขระ แล้วแก้ด้วยการเข้ารหัส Output
  • รัน OWASP Juice Shop ใน Docker บน 127.0.0.1:3000 แล้วทำโจทย์ระดับง่าย 3 ข้อ พร้อมจดว่าช่องโหว่ตรงกับ OWASP Top 10 ข้อใด
ใช้เวลา
16–22 ชั่วโมง เป็นขั้นที่ใหญ่ที่สุด เพราะครอบคลุมช่องโหว่หลายแบบและต้องลงมือทั้งโจมตีในแล็บและแก้ไข
Checkpoint

ก่อนไปขั้นถัดไป คุณต้องทำสิ่งเหล่านี้ได้: (1) อธิบาย OWASP Top 10 อย่างน้อย 5 ข้อและยกตัวอย่าง (2) สาธิต SQL Injection บนแอปของตัวเองและแก้ด้วย Parameterized Query ได้ (3) สาธิต XSS และแก้ด้วย Output Encoding ได้ (4) อธิบาย CSRF และ Secure Headers หลัก 3 ตัว (5) อ่าน Secret จาก Environment Variable และไม่ Commit ลง Git

STEP 10

Logging, Monitoring และ Detection

2 สัปดาห์ · 14–20 ชม.
หัวข้อย่อย
  • Log สำคัญบน Linux: /var/log/auth.log (การล็อกอินและ sudo), journalctl (Log ของ systemd) และการกรองด้วย grep, awk, cut, sort, uniq
  • รูปแบบของ Log การล็อกอิน SSH: บรรทัด Failed password, Invalid user และ Accepted และวิธีอ่านว่าใครพยายามเข้าจาก IP ใด
  • เขียน Python Log Analyzer ที่ตรวจจับรูปแบบการเดารหัสผ่าน (Brute-force) โดยนับความล้มเหลวต่อ IP และแจ้งเตือนเมื่อเกินเกณฑ์
  • แนวคิด SIEM (Security Information and Event Management) เช่น การรวม Log จากหลายเครื่อง การทำ Correlation และ Dashboard (เครื่องมืออย่าง Wazuh, Splunk, Elastic)
  • พื้นฐาน SOC (Security Operations Center): การทำงานเป็นกะ, การจัดลำดับ Alert (Triage), True Positive vs False Positive
  • แนวคิด Detection Engineering: เขียนกฎตรวจจับจากพฤติกรรม ไม่ใช่แค่ลายเซ็น และการลด False Positive
ทำไมต้องเรียน
ถ้าป้องกันแล้วยังถูกเจาะ สิ่งที่ช่วยคุณได้คือการตรวจจับให้เร็วที่สุด Log คือหลักฐานเดียวที่บอกว่าเกิดอะไรขึ้น การเขียนโปรแกรมวิเคราะห์ Log คือทักษะที่แยก SOC Analyst ที่เก่งออกจากคนที่ได้แต่จ้องหน้าจอ และเป็นหัวใจของส่วน Detection ใน Mini Project
ลงมือทำ
  • ใช้ grep และ awk นับจำนวน Failed password ต่อ IP จากไฟล์ auth.log ตัวอย่าง
  • เขียน Python Log Analyzer ที่อ่าน auth.log และแจ้ง IP ที่ล้มเหลวเกิน 5 ครั้ง พร้อมบอกว่าเดาสำเร็จหรือไม่
  • จำลองสถานการณ์ SOC: จัดลำดับ Alert 3 อันว่าอันไหนต้องรีบดูก่อนและเพราะอะไร
ใช้เวลา
14–20 ชั่วโมง เน้นการเขียนโปรแกรมวิเคราะห์ Log และฝึกอ่าน Log จริงจนจับรูปแบบผิดปกติได้
Checkpoint

ก่อนไปขั้นถัดไป คุณต้องทำสิ่งเหล่านี้ได้: (1) อ่าน /var/log/auth.log และ journalctl แล้วหาการล็อกอินที่ล้มเหลวได้ (2) ใช้ grep กับ awk สรุปจำนวนการโจมตีต่อ IP (3) เขียน Python Log Analyzer ที่ตรวจจับ Brute-force ได้จริง (4) อธิบายแนวคิด SIEM และการทำ Alert Triage ของ SOC

STEP 11

Vulnerability Management และ Threat Modeling

2 สัปดาห์ · 12–18 ชม.
หัวข้อย่อย
  • CVE (Common Vulnerabilities and Exposures): รหัสช่องโหว่สากล และวิธีอ่านรายละเอียดจากฐานข้อมูล NVD
  • CVSS (Common Vulnerability Scoring System): การให้คะแนนความรุนแรง 0–10 และการแบ่งระดับ Low, Medium, High, Critical
  • สแกนช่องโหว่ของ Dependency: pip-audit สำหรับ Python และ npm audit สำหรับ Node.js และการอ่านผลเพื่อตัดสินใจอัปเกรด
  • Patch Management: การจัดลำดับความสำคัญของการแก้ช่องโหว่ตามคะแนน CVSS และความเสี่ยงต่อระบบจริง
  • Threat Modeling ด้วย STRIDE: Spoofing, Tampering, Repudiation, Information Disclosure, Denial of Service, Elevation of Privilege และการวาด Data Flow Diagram
  • SBOM (Software Bill of Materials) และความเสี่ยงจาก Software Supply Chain (OWASP Top 10 ปี 2025 ยกเป็นข้อ A03)
ทำไมต้องเรียน
ทุกระบบใช้ไลบรารีของคนอื่นจำนวนมาก และช่องโหว่ใหม่ถูกค้นพบทุกวัน การจัดการช่องโหว่อย่างเป็นระบบ คือการรู้ว่ามีช่องโหว่อะไรบ้าง รุนแรงแค่ไหน และควรแก้อะไรก่อน ส่วน Threat Modeling ช่วยให้คิดถึงความปลอดภัยตั้งแต่ตอนออกแบบ ไม่ใช่มาแก้ทีหลัง ทั้งสองอย่างเป็นทักษะที่สาย Application Security และ DevSecOps ใช้ทุกวัน
ลงมือทำ
  • รัน pip-audit กับ requirements เก่าที่มีช่องโหว่ แล้วอ่านรหัส CVE/PYSEC และเวอร์ชันที่แก้
  • เลือก CVE หนึ่งอันมาอ่านคะแนน CVSS และอธิบายว่าทำไมได้คะแนนเท่านั้น
  • ทำ Threat Modeling ด้วย STRIDE ให้เว็บแอปสาธิตจาก Step 9 พร้อมวาด Data Flow Diagram
ใช้เวลา
12–18 ชั่วโมง แบ่งเป็นฝึกใช้เครื่องมือสแกนช่องโหว่และฝึกคิดแบบ Threat Modeling
Checkpoint

ก่อนไปขั้นถัดไป คุณต้องทำสิ่งเหล่านี้ได้: (1) อธิบายว่า CVE และ CVSS คืออะไรและต่างกันอย่างไร (2) รัน pip-audit หรือ npm audit และอ่านผลเพื่อตัดสินใจอัปเกรดได้ (3) จัดลำดับการแก้ช่องโหว่ตามคะแนน CVSS และความเสี่ยง (4) ทำ Threat Modeling ด้วย STRIDE กับระบบหนึ่งและระบุภัยในแต่ละหมวดได้

Incident Response และ Mini Project

2.5 สัปดาห์ · 16–24 ชม.
หัวข้อย่อย

Must-know Skills

ถ้าต้องสรุปหัวข้อนี้ให้เหลือทักษะที่ผู้สัมภาษณ์และงานจริงคาดหวังจากคนที่ "ทำงานความปลอดภัยเป็น" จะได้รายการนี้

  1. เข้าใจจริยธรรม กฎหมาย และขอบเขต (Scope) เพราะเป็นเส้นแบ่งระหว่างงานกับอาชญากรรม และเป็นสิ่งแรกที่ผู้ว่าจ้างต้องมั่นใจว่าคุณเข้าใจ
  2. คิดด้วยกรอบ CIA Triad และการจัดการความเสี่ยง เพราะทุกการตัดสินใจด้านความปลอดภัยคือการเลือกว่าจะลดความเสี่ยงใดก่อนภายใต้ทรัพยากรที่จำกัด
  3. Hardening เครื่อง Linux ทั้ง Users, sudo, Permissions, SSH และการ Patch เพราะเป็นด่านป้องกันแรกที่ลดโอกาสถูกเจาะได้มากที่สุด
  4. ตั้ง Firewall และระบบกันการเดารหัสผ่าน ด้วย ufw และ fail2ban เพราะเป็นการควบคุมการเข้าถึงและตอบโต้อัตโนมัติที่ Server ทุกเครื่องควรมี
  5. ใช้ Cryptography พื้นฐานให้ถูก แยก Hashing กับ Encryption, ใช้ Salt, Hash รหัสผ่านด้วย argon2 และเข้าใจ TLS/Certificate เพราะเป็นหัวใจของทุกระบบที่ปลอดภัย
  6. จัดการการยืนยันตัวตนอย่างปลอดภัย ทั้งรหัสผ่านที่ดี MFA และ Password Manager เพราะการยืนยันตัวตนที่อ่อนแอคือสาเหตุการถูกเจาะอันดับต้น
  7. สแกนและสำรวจเครือข่ายอย่างมีจริยธรรม ด้วย nmap และ tcpdump บน 127.0.0.1 เพราะต้องรู้ว่าเครื่องเปิดบริการอะไรจึงจะประเมินความเสี่ยงได้
  8. หาและแก้ช่องโหว่เว็บตาม OWASP Top 10 โดยเฉพาะ SQL Injection และ XSS เพราะเว็บคือพื้นผิวการโจมตีที่ใหญ่ที่สุด และการแก้คือความรับผิดชอบของนักพัฒนา
  9. อ่าน Log และเขียนโปรแกรมตรวจจับการโจมตี เพราะเมื่อป้องกันแล้วยังถูกเจาะ การตรวจจับให้เร็วคือสิ่งที่จำกัดความเสียหายได้
  10. จัดการช่องโหว่ด้วย CVE และ CVSS พร้อมเครื่องมืออย่าง pip-audit และ npm audit เพราะทุกระบบใช้ไลบรารีของคนอื่นที่มีช่องโหว่ใหม่ทุกวัน
  11. ทำ Threat Modeling ด้วย STRIDE เพราะช่วยให้คิดเรื่องความปลอดภัยตั้งแต่ออกแบบ ซึ่งถูกและได้ผลกว่ามาแก้ทีหลัง
  12. เขียนรายงานและตอบสนองต่อเหตุการณ์ ตามกระบวนการ NIST เพราะการสื่อสารผลและการกู้ระบบอย่างเป็นระบบสำคัญพอๆ กับความสามารถทางเทคนิค

หมายเหตุ

หลักสูตรนี้ไม่ใส่ตัวเลขเงินเดือน เพราะเงินเดือนต่างกันมากตามบริษัท ขนาดองค์กร อุตสาหกรรม ประสบการณ์ ทำเลที่ตั้ง ใบรับรองที่มี ทักษะภาษาอังกฤษ และช่วงเวลา ให้หาข้อมูลล่าสุดด้วยตัวเองดังนี้

  • ค้นหาชื่อตำแหน่ง เช่น "SOC Analyst" หรือ "Security Engineer" ใน JobsDB แล้วดูช่วงเงินเดือนในหลายประกาศ พร้อมจดทักษะและใบรับรองที่ประกาศต้องการบ่อยที่สุด
  • ค้นหาตำแหน่งเดียวกันใน LinkedIn Jobs และดูโปรไฟล์ของคนที่ทำตำแหน่งนั้นว่ามีประสบการณ์และใบรับรองอะไร
  • อ่านรายงานผลสำรวจเงินเดือนสาย IT ประจำปีของบริษัทจัดหางาน และสังเกตว่ารายงานสำรวจเมื่อไรและจากกลุ่มตัวอย่างใด
  • ถามคนที่ทำงานสายความปลอดภัยจริงในชุมชนหรือกลุ่มสายเทค เพราะได้ข้อมูลที่ใกล้ความจริงและเป็นปัจจุบันที่สุด

จบหัวข้อนี้แล้วไปต่อที่ไหน

หัวข้อนี้เป็นหัวข้อ Role สุดท้ายสายความปลอดภัยในเส้นทางที่แนะนำ เมื่อผ่าน Checkpoint ของ Step 12 และ Mini Project อยู่บน GitHub แล้ว ให้ต่อยอดดังนี้

  1. สอบใบรับรองใบแรก ISC2 CC หรือ CompTIA Security+ SY0-701 เพื่อยืนยันพื้นฐานและช่วยให้ Resume ผ่านการคัดกรอง
  2. ฝึกต่อเนื่องบน TryHackMe, Hack The Box และ picoCTF เพื่อสะสมชั่วโมงลงมือจริงและสร้างผลงานที่แสดงให้ผู้สัมภาษณ์เห็น
  3. เลือกสายที่สนใจแล้วเจาะลึก: สาย Blue Team ต่อด้วย CySA+ และ Detection Engineering ส่วนสายรุกต่อด้วย eJPT แล้ว OSCP+
  4. นำความปลอดภัยไปใช้กับหัวข้อที่สร้างระบบ เช่น ให้เขียน API ที่ปลอดภัยตั้งแต่ต้น และ ให้ดูแลความปลอดภัยของระบบ AI และ Secret ของ API Key
  5. ติดตามข่าวช่องโหว่และภัยคุกคามใหม่ทุกสัปดาห์ เพราะความปลอดภัยคือสายงานที่ต้องเรียนรู้ตลอดเวลา สิ่งที่จริงวันนี้อาจเปลี่ยนในเดือนหน้า
