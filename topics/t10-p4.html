เป้าหมาย

ฟิตเนสเครือข่ายสมมติชื่อ FitSomchai มีสาขาใน 5 จังหวัด ฝ่ายบริหารอยากรู้ล่วงหน้าว่าสมาชิกคนไหนกำลังจะยกเลิก (Churn) เพื่อให้ทีมดูแลลูกค้าโทรหาก่อน คุณจะสร้างโปรเจกต์ End-to-End ที่ครบทุกขั้นของงาน Data Science ได้แก่ ตั้งโจทย์ สร้างและโหลดข้อมูล สำรวจข้อมูล สร้าง Feature เทียบโมเดลกับ Baseline เลือก Threshold ตามต้นทุน ตรวจความเป็นธรรม ตีความโมเดล และเขียนรายงาน เกณฑ์ทางธุรกิจที่ตกลงกันคือ การพลาดสมาชิกที่จะยกเลิกเสียหาย 3 เท่าของการโทรหาสมาชิกที่ไม่ได้จะยกเลิก ใช้ ROC-AUC เทียบโมเดล และใช้ต้นทุนเลือก Threshold

ฟีเจอร์ของโปรเจกต์

  • สร้างข้อมูลสมาชิกจำลอง 2,000 คนที่รันกี่ครั้งก็ได้ไฟล์เดิม (Seed 42) บันทึกทั้ง CSV และ SQLite
  • โหลดข้อมูลจาก SQLite ด้วย Query ที่ใช้ params และตรวจ Schema ก่อนใช้งาน
  • EDA ที่พิมพ์อัตรายกเลิกแยกกลุ่ม และบันทึกกราฟ 4 รูปใน reports/figures/
  • Feature ใหม่ 2 ตัว และ ColumnTransformer ที่จัดการค่าว่าง ปรับสเกล และทำ One-hot ใน Pipeline
  • เทียบ 4 โมเดลด้วย 5-fold Cross-validation และปรับจูนตัวที่ชนะด้วย GridSearchCV
  • เลือก Threshold จากต้นทุนบนข้อมูลฝึก วัดผลบนข้อมูลทดสอบครั้งเดียว ตรวจ Recall รายจังหวัด และ Permutation importance แล้วบันทึกเป็น reports/metrics.json
  • ผู้ช่วย LLM ร่างบทสรุปผู้บริหารจากตัวเลขสรุปเท่านั้น และทำงานแบบจำลองอัตโนมัติเมื่อไม่มี ANTHROPIC_API_KEY
  • README ที่เป็นรายงานพร้อมข้อจำกัด และคำสั่งเดียว bash run_all.sh ที่รันซ้ำได้ทั้งโปรเจกต์

  2. Step 2: สร้างข้อมูลสมาชิกจำลองที่ทำซ้ำได้

    ข้อมูลจริงของสมาชิกฟิตเนสเป็นข้อมูลส่วนบุคคลตาม PDPA และบางส่วน เช่น ข้อมูลสุขภาพ เป็นข้อมูลอ่อนไหว จึงไม่ควรนำขึ้น Portfolio สาธารณะ Script นี้สร้างข้อมูลจำลองที่มีรูปแบบเหมือนจริง สมาชิกที่มาน้อย ร้องเรียนบ่อย อายุสมาชิกสั้น จ่ายเงินสด และใช้แพ็กเกจ basic มีโอกาสยกเลิกสูงกว่า และจงใจให้มีค่าว่าง 60 แถวในคอลัมน์ avg_session_min เหมือนเครื่องสแกนบัตรที่บันทึกพลาด เพราะใช้ Seed 42 ทุกคนจะได้ไฟล์เดียวกันทุกไบต์

    # สร้างข้อมูลสมาชิกฟิตเนสจำลอง (Synthetic) ด้วย Seed คงที่ รันกี่ครั้งก็ได้ไฟล์เหมือนเดิม
import sqlite3
from pathlib import Path

import numpy as np
import pandas as pd

SEED = 42
N = 2000
rng = np.random.default_rng(SEED)

provinces = np.array(["กรุงเทพมหานคร", "เชียงใหม่", "ขอนแก่น", "ชลบุรี", "ภูเก็ต"])
plans = np.array(["basic", "standard", "premium"])
fees = {"basic": 590, "standard": 990, "premium": 1590}

province = rng.choice(provinces, N, p=[0.45, 0.15, 0.12, 0.16, 0.12])
plan = rng.choice(plans, N, p=[0.5, 0.35, 0.15])
age = rng.integers(18, 66, N)
tenure_months = rng.integers(1, 49, N)
visits_last_30d = rng.poisson(np.select([plan == "basic", plan == "standard"], [6, 9], 12))
avg_session_min = rng.normal(55, 15, N).clip(15, 120).round(1)
classes_booked = rng.poisson(np.where(plan == "premium", 4, 1.5))
support_tickets = rng.poisson(0.6, N)
payment_method = rng.choice(["card", "qr", "cash"], N, p=[0.45, 0.4, 0.15])
has_trainer = (rng.random(N) < np.where(plan == "premium", 0.5, 0.15)).astype(int)
signup_date = pd.Timestamp("2026-10-01") - pd.to_timedelta(tenure_months * 30, unit="D")

# โอกาสยกเลิกสมาชิก: มาน้อย ร้องเรียนบ่อย อายุสมาชิกสั้น จ่ายเงินสด ยิ่งมีโอกาสยกเลิกสูง
logit = (
    0.2
    - 0.22 * visits_last_30d
    + 0.55 * support_tickets
    - 0.035 * tenure_months
    + 0.6 * (payment_method == "cash")
    + 0.35 * (plan == "basic")
    - 0.7 * has_trainer
    - 0.1 * classes_booked
)
churned = (rng.random(N) < 1 / (1 + np.exp(-logit))).astype(int)

df = pd.DataFrame({
    "member_id": [f"M{i:04d}" for i in range(1, N + 1)],
    "signup_date": signup_date.strftime("%Y-%m-%d"),
    "province": province,
    "plan": plan,
    "monthly_fee": [fees[p] for p in plan],
    "age": age,
    "tenure_months": tenure_months,
    "visits_last_30d": visits_last_30d,
    "avg_session_min": avg_session_min,
    "classes_booked": classes_booked,
    "support_tickets": support_tickets,
    "payment_method": payment_method,
    "has_trainer": has_trainer,
    "churned": churned,
})
# ทำให้ข้อมูลเหมือนของจริง: บางแถวไม่มีค่า avg_session_min (เครื่องสแกนบัตรไม่ได้บันทึก)
df.loc[rng.choice(N, 60, replace=False), "avg_session_min"] = np.nan

out = Path("data")
out.mkdir(exist_ok=True)
df.to_csv(out / "members.csv", index=False)
with sqlite3.connect(out / "members.db") as con:
    df.to_sql("members", con, if_exists="replace", index=False)

print("บันทึก", len(df), "แถว ลง data/members.csv และ data/members.db")
print("อัตรายกเลิกสมาชิก (churn rate):", f"{df['churned'].mean():.1%}")
print("ค่าว่างใน avg_session_min:", df["avg_session_min"].isna().sum())

  3. Step 3: โหลดข้อมูลจาก SQLite และตรวจ Schema

    ในงานจริง ข้อมูลอยู่ในฐานข้อมูล ไม่ใช่ CSV ฟังก์ชัน load_members ดึงข้อมูลด้วย SQL ที่ส่งค่าผ่าน params แปลงวันที่ตอนอ่าน และตรวจว่าคอลัมน์ครบและ churned มีแค่ 0 กับ 1 ก่อนส่งต่อ ถ้าวันหนึ่งทีมฐานข้อมูลเปลี่ยนชื่อคอลัมน์ โปรเจกต์จะหยุดพร้อมข้อความที่บอกปัญหาชัดเจน แทนที่จะฝึกโมเดลผิดแบบเงียบๆ ทุกไฟล์ต่อจากนี้เรียกฟังก์ชันนี้

    # โหลดข้อมูลสมาชิกจาก SQLite พร้อมตรวจ Schema ก่อนส่งต่อให้ขั้นอื่น
import sqlite3
from pathlib import Path

import pandas as pd

DB_PATH = Path("data/members.db")
EXPECTED_COLUMNS = [
    "member_id", "signup_date", "province", "plan", "monthly_fee", "age", "tenure_months",
    "visits_last_30d", "avg_session_min", "classes_booked", "support_tickets",
    "payment_method", "has_trainer", "churned",
]


def load_members(db_path: Path = DB_PATH, min_tenure: int = 0) -> pd.DataFrame:
    """อ่านตาราง members ที่ tenure_months >= min_tenure แล้วตรวจคอลัมน์และค่าของ churned"""
    if not db_path.exists():
        raise FileNotFoundError(f"ไม่พบ {db_path} ให้รัน python3 src/generate_members.py ก่อน")
    with sqlite3.connect(db_path) as con:
        df = pd.read_sql("SELECT * FROM members WHERE tenure_months >= ?", con,
                         params=(min_tenure,), parse_dates=["signup_date"])
    missing = set(EXPECTED_COLUMNS) - set(df.columns)
    if missing:
        raise ValueError(f"คอลัมน์หายไป: {sorted(missing)}")
    if not set(df["churned"].unique()) <= {0, 1}:
        raise ValueError("คอลัมน์ churned ต้องมีแค่ 0 และ 1")
    return df

import pandas as pd
from sklearn.compose import ColumnTransformer
from sklearn.impute import SimpleImputer
from sklearn.model_selection import train_test_split
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import OneHotEncoder, StandardScaler

NUM = ["age", "tenure_months", "visits_last_30d", "avg_session_min", "classes_booked",
       "support_tickets", "monthly_fee", "has_trainer", "fee_per_visit"]
CAT = ["province", "plan", "payment_method", "tenure_bucket"]
TARGET = "churned"


def add_features(df: pd.DataFrame) -> pd.DataFrame:
    """เพิ่มค่าสมาชิกต่อการเข้ายิม 1 ครั้ง และกลุ่มอายุสมาชิก โดยไม่แก้ DataFrame เดิม"""
    out = df.copy()
    out["fee_per_visit"] = (out["monthly_fee"] / (out["visits_last_30d"] + 1)).round(1)
    out["tenure_bucket"] = pd.cut(out["tenure_months"], bins=[0, 6, 12, 24, 48],
                                  labels=["0-6", "7-12", "13-24", "25-48"]).astype(str)
    return out


def split(df: pd.DataFrame):
    """แบ่ง 80/20 แบบ stratify ด้วย Seed คงที่ ทุกไฟล์จึงได้ข้อมูลทดสอบชุดเดียวกัน"""
    X, y = df[NUM + CAT], df[TARGET]
    return train_test_split(X, y, test_size=0.2, stratify=y, random_state=42)


def build_preprocessor() -> ColumnTransformer:
    """ตัวเลข: เติมค่าว่างด้วยมัธยฐานแล้วปรับสเกล | กลุ่ม: One-hot ที่ไม่พังเมื่อเจอค่าใหม่"""
    return ColumnTransformer([
        ("num", make_pipeline(SimpleImputer(strategy="median"), StandardScaler()), NUM),
        ("cat", OneHotEncoder(handle_unknown="ignore"), CAT),
    ])
    # ตรวจ Feature ใหม่และตัวเตรียมข้อมูลก่อนฝึกโมเดล

import json

import joblib
import numpy as np
import pandas as pd

COST_FN, COST_FP = 3, 1        # พลาดคนที่จะยกเลิก เสียหาย 3 เท่าของการโทรหาคนที่ไม่ได้จะยกเลิก
THRESHOLDS = np.round(np.arange(0.20, 0.81, 0.05), 2)


def cost(y_true, proba, t):
    pred = proba >= t
    return int(COST_FN * ((~pred) & (y_true == 1)).sum() + COST_FP * (pred & (y_true == 0)).sum())

def make_client():
    if os.environ.get("ANTHROPIC_API_KEY"):
        import anthropic
        return anthropic.Anthropic()
    return None                                         # โหมดจำลอง


def mock_summary(m: dict) -> str:
    """คำตอบจำลองที่สร้างจากตัวเลขจริงใน metrics.json ทำให้รันได้โดยไม่ต้องมี API Key"""
    cm = m["confusion_matrix"]
    worst = min(m["recall_by_province"], key=m["recall_by_province"].get)
    top = list(m["top_features"])[:2]
    return (f"[MOCK] โมเดลทำนายการยกเลิกสมาชิกได้ ROC-AUC {m['roc_auc']} บนข้อมูลทดสอบ {m['n_test']} คน "
            f"ที่ยกเลิกจริง {cm['tp'] + cm['fn']} คน "
            f"ที่ Threshold {m['threshold']} ระบบหาคนที่จะยกเลิกเจอ {cm['tp']} คน (Recall {m['recall']:.0%}) "
            f"แต่ในรายชื่อที่ให้ทีมโทรมีคนที่จะยกเลิกจริงเพียง {m['precision']:.0%} "
            f"ปัจจัยที่สำคัญที่สุดคือ {top[0]} และ {top[1]} "
            f"ควรเริ่มโทรหาสมาชิกกลุ่มนี้ก่อน และติดตาม {worst} ที่ Recall ต่ำสุด ({m['recall_by_province'][worst]:.0%}) "
            "ข้อจำกัด: ข้อมูลเป็นข้อมูลจำลอง ต้องทดสอบกับข้อมูลจริงก่อนใช้งาน")


def ask_llm(client, m: dict) -> str:
    import anthropic
    prompt = "สรุปผลโมเดลทำนายการยกเลิกสมาชิกจากตัวเลขนี้:\n" + json.dumps(m, ensure_ascii=False)
    try:
        response = client.messages.create(model=MODEL, max_tokens=4000, system=SYSTEM,
                                          messages=[{"role": "user", "content": prompt}])
    except anthropic.AuthenticationError:
        return "ERROR: API Key ไม่ถูกต้อง"
    except anthropic.RateLimitError:
        return "ERROR: เรียกบ่อยเกินไป ลองใหม่ภายหลัง"
    except anthropic.APIStatusError as e:
        return f"ERROR: API ตอบกลับสถานะ {e.status_code}"
    except anthropic.APIConnectionError:
        return "ERROR: เชื่อมต่อ API ไม่ได้"
    if response.stop_reason not in ("end_turn", "max_tokens"):
        return f"ERROR: โมเดลหยุดด้วยเหตุผล {response.stop_reason}"
    text = "".join(b.text for b in response.content if b.type == "text")
    return text + ("\n(คำตอบถูกตัดเพราะ max_tokens)" if response.stop_reason == "max_tokens" else "")

Interview Questions

คำถามเหล่านี้พบบ่อยในการสัมภาษณ์ตำแหน่ง Junior Data Scientist ถึง Data Scientist ระดับ Mid คำตอบตัวอย่างแสดงสิ่งที่ผู้สมัครที่ดีพูด ให้ฝึกตอบด้วยคำพูดของตัวเองภายใน 2–3 นาที และยกตัวอย่างจากโปรเจกต์ของคุณเสมอ

1. Precision กับ Recall ต่างกันอย่างไร และคุณเลือก Threshold อย่างไร (Junior)

แนวคำตอบ: Precision คือ ในบรรดาที่โมเดลทายว่าใช่ ถูกกี่เปอร์เซ็นต์ ส่วน Recall คือ ของจริงทั้งหมด โมเดลหาเจอกี่เปอร์เซ็นต์ สองค่านี้มักแลกกัน ลด Threshold แล้ว Recall เท่าเดิมหรือเพิ่ม แต่ Precision มักลดลง การเลือกจึงขึ้นกับต้นทุนของความผิดพลาดแต่ละแบบ ไม่ใช่ตัวเลข 0.5 ตายตัว

  • งานคัดกรองมะเร็งเน้น Recall เพราะพลาดผู้ป่วยเสียหายกว่าการตรวจซ้ำมาก ส่วนระบบแนะนำสินค้าเน้น Precision เพราะคำแนะนำที่ไม่ตรงทำให้ผู้ใช้เลิกเชื่อ
  • วิธีเลือกที่ถูก: กำหนดต้นทุนเป็นตัวเลขกับทีมธุรกิจ คำนวณต้นทุนรวมของแต่ละ Threshold จากผลทำนายแบบ Cross-validation บนข้อมูลฝึก แล้วยืนยันบนข้อมูลทดสอบครั้งเดียว
  • ตัวอย่างจากโปรเจกต์ Churn ML: พลาดคนที่จะยกเลิกเสีย 3 หน่วย โทรเสียเปล่าเสีย 1 หน่วย ได้ Threshold 0.65 ต้นทุนบนข้อมูลทดสอบ 138 หน่วย ถูกกว่า 0.5 (160) และถูกกว่าการไม่โทรเลย (162)
2. Data leakage คืออะไร ยกตัวอย่างและบอกวิธีป้องกัน (Junior–Mid)

แนวคำตอบ: Data leakage คือการที่ข้อมูลซึ่งโมเดลไม่ควรรู้ตอนใช้งานจริง หลุดเข้าไปตอนฝึกหรือตอนเลือกโมเดล ทำให้ผลวัดดีเกินจริงแล้วโมเดลพังเมื่อขึ้นระบบ เป็นสาเหตุอันดับต้นของโมเดลที่ "ดีแค่ในโน้ตบุ๊ก"

  • ตัวอย่าง 1: ปรับสเกลหรือเติมค่าว่างด้วยค่าเฉลี่ยของข้อมูลทั้งหมดก่อนแบ่ง Train / Test
  • ตัวอย่าง 2: ใช้ Feature ที่เกิดหลังเหตุการณ์ที่ทำนาย เช่น ใช้ "วันที่ขอคืนเงินค่าสมาชิก" ทำนายการยกเลิก ซึ่งข้อมูลนี้มีเฉพาะคนที่ยกเลิกไปแล้ว
  • ตัวอย่าง 3: เลือก Hyperparameter หรือ Threshold จากคะแนนบนข้อมูลทดสอบ
  • วิธีป้องกัน: ใส่ทุกขั้นเตรียมข้อมูลไว้ใน Pipeline แล้วส่ง Pipeline เข้า cross_val_score หรือ GridSearchCV ถามทุก Feature ว่า "ตอนทำนายจริงเรารู้ค่านี้แล้วหรือยัง" แยกฟังก์ชัน split() ไว้ที่เดียวให้ทุกไฟล์ใช้ร่วมกัน และแตะข้อมูลทดสอบครั้งเดียวตอนท้าย
  • สัญญาณเตือน: คะแนนดีผิดปกติ เช่น ROC-AUC 0.99 กับปัญหาธุรกิจที่ยาก หรือ Feature เดียวมีความสำคัญสูงกว่าตัวอื่นมาก ให้สงสัยไว้ก่อน
3. อธิบาย p-value และบอกข้อผิดพลาดที่พบบ่อยในการทำ A/B Test (Mid)

แนวคำตอบ: p-value คือโอกาสที่จะเห็นผลต่างอย่างน้อยเท่าที่เห็น ถ้าสมมติว่า H0 เป็นจริง คือไม่มีผลต่างจริง ไม่ใช่โอกาสที่ H0 จริง และไม่ได้บอกว่าผลต่างใหญ่แค่ไหน จึงต้องรายงานขนาดผลต่างพร้อม CI เสมอ เช่น "อัตราสมัครเพิ่มขึ้น 3.1 จุดเปอร์เซ็นต์ (CI 95%: 0.5 ถึง 5.7) p = 0.0237"

  • Peeking: ดูผลทุกวันแล้วหยุดทันทีที่ p < 0.05 ทำให้โอกาสสรุปผิดสูงกว่า 5% มาก ต้องกำหนดขนาดตัวอย่างและวันสิ้นสุดก่อนเริ่ม
  • เปลี่ยน Metric หลังเห็นผล: ดูหลายสิบ Metric แล้วรายงานตัวที่มีนัยสำคัญ ต้องกำหนด Metric หลักไว้ก่อน ถ้าทดสอบหลาย Metric ต้องปรับเกณฑ์ เช่น Bonferroni correction
  • การสุ่มแบ่งกลุ่มไม่ดี: เช่น ให้ผู้ใช้ iOS เห็นหน้าใหม่ทั้งหมด ผลต่างอาจมาจากชนิดอุปกรณ์ ไม่ใช่หน้าเว็บ
  • สับสนนัยสำคัญทางสถิติกับความคุ้มค่า: ข้อมูลหลายล้านคนทำให้ผลต่าง 0.05% มีนัยสำคัญได้ แต่อาจไม่คุ้มค่าการพัฒนา
  • เลือก Test ผิด: ข้อมูลนับจำนวนใช้ chi2_contingency ค่าเฉลี่ยสองกลุ่มอิสระใช้ Welch's t-test (equal_var=False) และข้อมูลจับคู่ใช้ ttest_rel
4. Overfitting คืออะไร ตรวจและแก้อย่างไร (Junior–Mid)

แนวคำตอบ: Overfitting คือโมเดลจำข้อมูลฝึกรวมถึง Noise จนทำนายข้อมูลใหม่ได้แย่ ตรวจได้จากช่องว่างระหว่างคะแนนข้อมูลฝึกกับคะแนน Cross-validation เช่น Decision Tree ที่ไม่จำกัดความลึกได้ Accuracy ข้อมูลฝึก 1.000 แต่ CV 0.916 ขณะที่ max_depth=3 ได้ CV 0.927 นี่คือ Bias-Variance trade-off โมเดลง่ายเกินมี Bias สูง โมเดลซับซ้อนเกินมี Variance สูง

  • ลดความซับซ้อน: จำกัด max_depth เพิ่ม min_samples_leaf หรือเพิ่ม Regularization เช่น Ridge, Lasso และ C ที่เล็กลงใน Logistic Regression (ในโปรเจกต์ Churn ML GridSearchCV เลือก C=0.01 แล้ว CV ดีขึ้น)
  • ใช้ Ensemble: Random Forest ลด Variance ด้วยการเฉลี่ยต้นไม้หลายต้น
  • เพิ่มข้อมูล: ดู learning_curve ว่าคะแนน CV ยังเพิ่มเมื่อข้อมูลเพิ่มหรือไม่
  • Early stopping: หยุดฝึก Neural Network หรือ Gradient Boosting เมื่อคะแนนบนข้อมูล Validation ไม่ดีขึ้น
  • ประเด็นที่ผู้สัมภาษณ์อยากได้ยิน: ต้องวัดด้วย Cross-validation ที่ไม่มี Data leakage และไม่ปรับจูนโดยดูข้อมูลทดสอบ ไม่อย่างนั้นจะ Overfit ข้อมูลทดสอบแทน
5. เล่าโปรเจกต์ Churn ML ของคุณ ทำไม Logistic Regression ชนะ และโปรเจกต์มีข้อจำกัดอะไร (Mid)

แนวคำตอบ: เล่าด้วยโครง โจทย์ วิธี ผล และข้อจำกัด ไม่เกิน 3 นาที

  • โจทย์: ทำนายสมาชิกฟิตเนสที่จะยกเลิกเพื่อให้ทีมโทรหาก่อน การพลาดคนที่จะยกเลิกเสียหาย 3 เท่าของการโทรเสียเปล่า ใช้ ROC-AUC เทียบโมเดลและใช้ต้นทุนเลือก Threshold
  • วิธี: ข้อมูลจำลอง 2,000 คนที่ทำซ้ำได้ด้วย Seed โหลดจาก SQLite ทำ EDA สร้าง Feature 2 ตัว ใช้ ColumnTransformer ใน Pipeline เทียบ 4 โมเดลด้วย 5-fold CV ปรับจูนตัวที่ชนะ เลือก Threshold จาก cross_val_predict และตรวจ Recall รายจังหวัด
  • ผล: ROC-AUC 0.754 บนข้อมูลทดสอบ Average precision 0.295 เทียบกับ Baseline 0.135 ที่ Threshold 0.65 หาคนที่จะยกเลิกเจอ 44% และลดต้นทุนจาก 160 เหลือ 138 หน่วย
  • ทำไม Logistic ชนะ: ข้อมูลถูกสร้างจากสูตรเชิงเส้น และมีเพียง 1,600 แถวฝึก โมเดลต้นไม้ที่ยืดหยุ่นกว่าจึงเรียน Noise ได้ง่ายกว่า ผลนี้สอนว่าต้องเทียบเสมอ ไม่ใช่เดาว่าโมเดลซับซ้อนดีกว่า
  • ข้อจำกัด: ข้อมูลจำลอง ไม่มีมิติเวลา Recall รายจังหวัดต่างกันมากแต่มาจากคนยกเลิกไม่กี่คนต่อจังหวัด และ Feature ที่สำคัญเป็นความสัมพันธ์ ไม่ใช่สาเหตุ ขั้นต่อไปคือทดลองกับข้อมูลจริง เพิ่ม Feature ตามเวลา และทำ A/B Test วัดว่าการโทรลดการยกเลิกได้จริง
