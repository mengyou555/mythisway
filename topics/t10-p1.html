10.1Learning Roadmap

ภาพรวมเส้นทาง

Data Science คือการใช้ข้อมูลตอบคำถามทางธุรกิจหรือทางวิทยาศาสตร์ เช่น "ลูกค้ากลุ่มไหนกำลังจะเลิกใช้บริการ" "โปรโมชันใหม่ทำให้ยอดขายเพิ่มขึ้นจริงหรือแค่บังเอิญ" หรือ "บ้านหลังนี้ควรตั้งราคาเท่าไร" นักวิทยาศาสตร์ข้อมูล (Data Scientist) ใช้สามอย่างร่วมกัน คือ การเขียนโปรแกรม เพื่อจัดการข้อมูลจำนวนมาก สถิติ เพื่อแยกสิ่งที่เกิดขึ้นจริงออกจากความบังเอิญ และ Machine Learning (ML) เพื่อสร้างโมเดลที่เรียนรู้รูปแบบจากข้อมูลในอดีตแล้วทำนายข้อมูลใหม่ได้ สิ่งที่สำคัญไม่แพ้กันคือการเล่าผลลัพธ์ให้คนที่ไม่ใช่สายเทคเข้าใจและนำไปตัดสินใจได้

หัวข้อนี้เป็นลำดับที่ 13 ของเส้นทางที่แนะนำ คุณเรียนจบ , , , และ มาแล้ว จึงมีเครื่องมือหลักครบ คือเขียน Python ได้ ดึงข้อมูลด้วย SQL ได้ ใช้ Terminal และ Git เป็น หัวข้อนี้จะต่อยอดสิ่งเหล่านั้นไปสู่การวิเคราะห์ข้อมูลและการสร้างโมเดล เส้นทางแบ่งเป็น 16 ขั้นใน 3 ระดับ ระดับ Beginner สอนเครื่องมือจัดการข้อมูล คือ NumPy, pandas และ matplotlib ระดับ Intermediate สอนสถิติที่ต้องใช้จริงและวิธีสร้างโมเดลด้วย scikit-learn อย่างถูกขั้นตอน ส่วนระดับ Advanced สอนโมเดลจำแนกประเภท การปรับจูนโมเดล การเรียนรู้แบบไม่มีผู้สอน Neural Network ด้วย PyTorch จริยธรรมของข้อมูลตาม PDPA และจบด้วย Mini Project End-to-End ML Project: ทำนายสมาชิกฟิตเนสที่จะยกเลิกสมาชิก ที่นำไปใส่ Portfolio ได้

ใช้เวลารวมประมาณ 162–248 ชั่วโมง (ตรงกับกรอบ 150–250 ชั่วโมงของหัวข้อนี้) ถ้าเรียนสัปดาห์ละ 7–10 ชั่วโมง (วันละ 1–1.5 ชั่วโมง สัปดาห์ละ 6 วัน) จะจบในราว 24 สัปดาห์ หรือประมาณ 6 เดือน หัวข้อนี้ยากที่สุดหัวข้อหนึ่งในหลักสูตร (ระดับความยาก 5 จาก 5) เพราะต้องใช้ทั้งโค้ดและคณิตศาสตร์ แต่ทุกขั้นมี Checkpoint ที่บอกชัดว่าต้องทำอะไรได้ก่อนไปต่อ และทุกตัวอย่างรันได้บนเครื่องของคุณเองโดยไม่ต้องใช้ GPU ไม่ต้องเสียเงิน และไม่ต้องต่ออินเทอร์เน็ตตอนรัน

  3. Beginner Step 3 · pandas พื้นฐาน: Series, DataFrame และการเลือกข้อมูล
  4. Beginner Step 4 · ทำความสะอาดและจัดรูปข้อมูล: Missing data, groupby, merge, pivot และ SQLite
  5. Beginner Step 5 · EDA และการทำกราฟด้วย matplotlib
  6. Intermediate Step 6 · สถิติเชิงพรรณนา ความน่าจะเป็น และการแจกแจง
  7. Intermediate Step 7 · สถิติเชิงอนุมาน: Confidence Interval, Hypothesis Test และ A/B Test
  8. Intermediate Step 8 · คณิตศาสตร์สำหรับ ML: Vector, Matrix และ Gradient Descent
  9. Intermediate Step 9 · ขั้นตอนการทำ ML ด้วย scikit-learn: Split, Pipeline และ Cross-validation
  10. Intermediate Step 10 · Regression และการวัดผล: MAE, RMSE, R²
  11. Advanced Step 11 · Classification และการวัดผล: Confusion Matrix, Precision, Recall, ROC-AUC
  12. Advanced Step 12 · Overfitting, Bias-Variance, Tree Ensemble และ GridSearchCV
  13. Advanced Step 13 · Unsupervised Learning (k-means, PCA) และการตีความโมเดล
  14. Advanced Step 14 · Neural Network เบื้องต้น: MLPClassifier และ PyTorch
  15. Advanced Step 15 · จริยธรรมข้อมูล PDPA, LLM เป็นผู้ช่วยวิเคราะห์ และการเล่าเรื่องด้วยข้อมูล
  16. Advanced Step 16 · Mini Project: End-to-End ML Project

เปรียบเทียบ

งาน Data Science เหมือนงานของหมอ ขั้นแรกหมอต้องเก็บข้อมูลคนไข้ให้ครบและถูกต้อง (เก็บและทำความสะอาดข้อมูล) จากนั้นตรวจร่างกายและดูผลแล็บ (EDA และสถิติ) แยกให้ออกว่าไข้ขึ้นเพราะติดเชื้อจริงหรือเพราะเพิ่งวิ่งมา (Hypothesis Test) แล้วจึงวินิจฉัยโดยอาศัยประสบการณ์จากคนไข้หลายพันคนก่อนหน้า (โมเดล ML ที่เรียนจากข้อมูลในอดีต) สุดท้ายหมอต้องอธิบายผลให้คนไข้เข้าใจด้วยภาษาง่ายๆ และรักษาความลับของคนไข้เสมอ (Storytelling และ PDPA) หมอที่เก่งเครื่องมือแต่อธิบายไม่เป็น หรือวินิจฉัยโดยไม่ตรวจก่อน ย่อมเป็นหมอที่อันตราย นักวิทยาศาสตร์ข้อมูลก็เช่นกัน

Data Science คืออะไร และทำงานเป็นวงจรอย่างไร

งาน Data Science ในบริษัทจริงไม่ได้เริ่มจากการเลือกโมเดล แต่เริ่มจากคำถาม และวนเป็นวงจรซ้ำหลายรอบ แต่ละรอบเข้าใจปัญหาลึกขึ้น วงจรที่ใช้กันแพร่หลายมีชื่อว่า CRISP-DM ซึ่งแบ่งงานเป็น 6 ช่วง หลักสูตรนี้ใช้วงจรเดียวกัน แต่เขียนเป็น 7 ขั้นให้เห็นงานชัดขึ้น

  1. ตั้งโจทย์ (Problem framing): แปลงคำถามธุรกิจให้เป็นคำถามที่ข้อมูลตอบได้ เช่น "ลดการยกเลิกสมาชิก" กลายเป็น "ทำนายว่าสมาชิกคนไหนมีโอกาสยกเลิกในเดือนหน้า เพื่อให้ทีมขายโทรหาก่อน" พร้อมกำหนดว่าวัดความสำเร็จด้วยอะไร
  2. เก็บและโหลดข้อมูล (Data collection): ดึงข้อมูลจากไฟล์ CSV ฐานข้อมูล SQL หรือ API แล้วตรวจว่าแต่ละคอลัมน์หมายถึงอะไรและบันทึกมาอย่างไร
  3. ทำความสะอาดข้อมูล (Data cleaning): จัดการค่าว่าง ค่าผิดรูปแบบ ข้อมูลซ้ำ และชนิดข้อมูลที่ผิด ขั้นนี้มักกินเวลามากที่สุดในงานจริง
  4. สำรวจข้อมูล (Exploratory Data Analysis, EDA): ใช้สถิติและกราฟดูการกระจาย ความสัมพันธ์ และสิ่งผิดปกติ เพื่อหาสมมติฐานที่น่าสนใจ
  5. สร้างโมเดล (Modeling): สร้าง Feature เริ่มจาก Baseline ง่ายๆ แล้วลองโมเดลที่ซับซ้อนขึ้น เปรียบเทียบอย่างยุติธรรมด้วย Cross-validation
  6. ประเมินผล (Evaluation): วัดผลด้วย Metric ที่ตรงกับเป้าหมายธุรกิจบนข้อมูลที่โมเดลไม่เคยเห็น และตรวจว่าโมเดลไม่ลำเอียงต่อกลุ่มใดกลุ่มหนึ่ง
  7. สื่อสารและนำไปใช้ (Communication & Deployment): เขียนรายงานที่บอกข้อสรุป ข้อจำกัด และสิ่งที่ควรทำต่อ หรือส่งโมเดลให้ทีมวิศวกรนำไปใช้ในระบบจริง แล้วติดตามผลต่อเนื่อง

คำศัพท์ 12 คำนี้จะเจอในทุกขั้นของหัวข้อนี้ ให้จำความหมายให้ได้ก่อนเริ่ม Step 1

คำศัพท์ความหมายตัวอย่างในหัวข้อนี้
Datasetชุดข้อมูลหนึ่งชุด มักเป็นตารางที่แต่ละแถวคือหนึ่งตัวอย่าง (Sample) และแต่ละคอลัมน์คือหนึ่งคุณสมบัติตารางสมาชิกฟิตเนส 2,000 แถวใน Mini Project
Featureคอลัมน์ที่ใช้เป็นข้อมูลนำเข้าของโมเดล เรียกอีกชื่อว่าตัวแปรต้น เขียนแทนด้วย Xจำนวนครั้งที่เข้ายิมใน 30 วัน อายุสมาชิก แพ็กเกจที่ใช้
Target / Labelคอลัมน์ที่อยากทำนาย เขียนแทนด้วย ychurned (1 = ยกเลิกสมาชิก, 0 = ยังอยู่)
Modelสูตรคณิตศาสตร์ที่รับ Feature แล้วให้ผลทำนายออกมา ค่าภายในสูตรได้มาจากการฝึกด้วยข้อมูลLogisticRegression, RandomForestClassifier
Trainingกระบวนการให้โมเดลปรับค่าภายในจนทำนายข้อมูลฝึกได้ดี ใน scikit-learn คือคำสั่ง .fit(X, y)model.fit(X_train, y_train)
Inference / Predictionการใช้โมเดลที่ฝึกแล้วทำนายข้อมูลใหม่ คือคำสั่ง .predict(X)ทำนายความเสี่ยงของสมาชิกที่เพิ่งสมัครเดือนนี้
Train / Test splitการแบ่งข้อมูลเป็นส่วนฝึกและส่วนทดสอบ ส่วนทดสอบต้องเก็บไว้วัดผลครั้งสุดท้ายเท่านั้น80% ฝึก 20% ทดสอบ ด้วย train_test_split
Baselineโมเดลที่ง่ายที่สุดที่ใช้เป็นเส้นเทียบ โมเดลจริงต้องดีกว่าเส้นนี้ ถึงจะมีประโยชน์DummyClassifier ที่ทายว่า "ไม่ยกเลิก" ทุกคน
Metricตัวเลขที่ใช้วัดว่าโมเดลดีแค่ไหน ต้องเลือกให้ตรงกับเป้าหมายRMSE สำหรับทำนายตัวเลข, Recall สำหรับหาคนที่จะยกเลิก
Overfittingโมเดลจำข้อมูลฝึกได้แม่นเกินไปจนทำนายข้อมูลใหม่ได้แย่ เหมือนนักเรียนท่องข้อสอบเก่าแต่ทำข้อสอบใหม่ไม่ได้Decision Tree ที่ลึกไม่จำกัดได้ Accuracy ข้อมูลฝึก 100% แต่ข้อมูลทดสอบต่ำกว่ามาก
Pipelineการต่อขั้นตอนเตรียมข้อมูลกับโมเดลเข้าด้วยกันเป็นชิ้นเดียว ป้องกันข้อมูลทดสอบรั่วเข้าไปตอนฝึกmake_pipeline(StandardScaler(), LogisticRegression())
Data leakageการที่ข้อมูลซึ่งโมเดลไม่ควรรู้ตอนทำนาย หลุดเข้าไปตอนฝึก ทำให้ผลวัดดีเกินจริงปรับสเกลด้วยค่าเฉลี่ยของข้อมูลทั้งหมดก่อนแบ่ง Train / Test

ในทีมข้อมูลมีหลายตำแหน่ง ซึ่งชื่อคล้ายกันจนมือใหม่สับสน ตารางนี้เทียบตำแหน่งที่พบบ่อยที่สุด เพื่อให้รู้ว่าหัวข้อนี้พาคุณไปทางไหน ส่วนรายละเอียดตำแหน่งงานและใบรับรองอยู่ท้ายหน้า

ตำแหน่งคำถามที่ตอบเครื่องมือหลักผลงานที่ส่ง
Data Analystเกิดอะไรขึ้นแล้ว และเพราะอะไร เช่น ยอดขายเดือนนี้ตกลงที่สาขาไหนSQL, Excel, Power BI หรือ Tableau, pandasDashboard, รายงานประจำสัปดาห์, ผลวิเคราะห์เฉพาะกิจ
Data Scientistอะไรจะเกิดขึ้น และควรทำอะไร เช่น ลูกค้าคนไหนจะยกเลิก ควรให้ส่วนลดใครPython, pandas, สถิติ, scikit-learn, SQLโมเดลทำนาย, ผล A/B Test, รายงานพร้อมข้อเสนอแนะ
ML Engineerทำอย่างไรให้โมเดลทำงานในระบบจริงได้เร็ว เสถียร และอัปเดตได้Python, Docker, Cloud, MLOps, APIบริการ API ของโมเดล, Pipeline ฝึกโมเดลอัตโนมัติ, ระบบติดตามโมเดล
AI Engineerทำอย่างไรให้แอปใช้ LLM และโมเดลสำเร็จรูปแก้ปัญหาได้Python หรือ TypeScript, LLM API, RAG, AgentChatbot, ระบบค้นเอกสาร, ระบบอัตโนมัติด้วย AI

print("ยอดขายแบบ NumPy:", (p * q).sum())

# Broadcasting: ขึ้นราคาทุกเมนู 10% แล้วปัดเป็นจำนวนเต็ม

STEP 6

สถิติเชิงพรรณนา ความน่าจะเป็น และการแจกแจง

1.5 สัปดาห์ · 10–16 ชม.
หัวข้อย่อย
  • ค่ากลาง: ค่าเฉลี่ย (Mean) ค่ามัธยฐาน (Median) และฐานนิยม (Mode) พร้อมเหตุผลว่าทำไมรายได้และราคาบ้านควรรายงานด้วยมัธยฐาน เพราะค่าเฉลี่ยถูกดึงด้วยค่าสุดโต่ง
  • การกระจาย: พิสัย (Range) ความแปรปรวน (Variance) ส่วนเบี่ยงเบนมาตรฐาน (Standard deviation) ควอร์ไทล์ และ IQR ที่ใช้หา Outlier ด้วยกฎ 1.5 × IQR
  • ความน่าจะเป็นพื้นฐาน: เหตุการณ์ กฎการบวกและการคูณ ความน่าจะเป็นแบบมีเงื่อนไข P(A|B) และแนวคิดของ Bayes' theorem ผ่านตัวอย่างผลตรวจโรคที่ผิดพลาดได้
  • การแจกแจงที่ต้องรู้จัก: Normal, Binomial, Poisson และ Uniform พร้อมตัวอย่างข้อมูลจริงของแต่ละแบบ เช่น จำนวนลูกค้าที่เข้าร้านต่อชั่วโมงมักเป็น Poisson
  • การสุ่มตัวอย่าง (Sampling): ประชากรกับกลุ่มตัวอย่าง การสุ่มแบบง่ายและแบบแบ่งชั้น (Stratified) และ Sampling bias เช่น สำรวจความพึงพอใจเฉพาะลูกค้าที่ยังไม่ยกเลิก
  • Central Limit Theorem (CLT) จากการจำลอง: สุ่มกลุ่มตัวอย่างซ้ำ 10,000 ครั้งด้วย NumPy แล้วดูว่าค่าเฉลี่ยของกลุ่มตัวอย่างกระจายเป็นรูประฆังแม้ข้อมูลต้นทางจะเบ้
  • Standard error คือส่วนเบี่ยงเบนมาตรฐานของค่าเฉลี่ยกลุ่มตัวอย่าง ซึ่งลดลงตามรากที่สองของขนาดตัวอย่าง
  • ใช้ scipy.stats สร้างการแจกแจง เช่น stats.norm(loc=0, scale=1) แล้วเรียก .cdf, .ppf และ .rvs(random_state=42)
ทำไมต้องเรียน
รายงานที่บอกว่า "ค่าเฉลี่ยเงินเดือนของพนักงานคือ 85,000 บาท" ทั้งที่คนส่วนใหญ่ได้ 25,000 บาทเพราะผู้บริหารไม่กี่คนได้หลักล้าน เป็นรายงานที่ถูกทางคณิตศาสตร์แต่ทำให้เข้าใจผิด การเลือกสถิติที่เหมาะกับรูปร่างข้อมูลจึงเป็นทักษะพื้นฐาน ส่วนความน่าจะเป็นและ CLT เป็นรากฐานของ Hypothesis Test ใน Step 7 และของการวัดความไม่แน่นอนของโมเดลทุกตัว

STEP 7

สถิติเชิงอนุมาน: Confidence Interval, Hypothesis Test และ A/B Test

1.5 สัปดาห์ · 10–16 ชม.
หัวข้อย่อย
  • ช่วงความเชื่อมั่น (Confidence Interval, CI) 95%: ความหมายที่ถูกต้องคือ "ถ้าเก็บข้อมูลซ้ำแบบนี้หลายครั้ง ช่วงที่คำนวณได้จะครอบค่าจริงประมาณ 95% ของครั้ง" ไม่ใช่ "ค่าจริงมีโอกาส 95% ที่จะอยู่ในช่วงนี้"
  • คำนวณ CI ของค่าเฉลี่ยด้วย stats.t.interval และด้วยวิธี Bootstrap ที่สุ่มข้อมูลซ้ำด้วย stats.bootstrap
  • ขั้นตอนของ Hypothesis Test: ตั้ง Null hypothesis (H0) และ Alternative hypothesis (H1) เลือกระดับนัยสำคัญ α = 0.05 ก่อนดูข้อมูล คำนวณ p-value แล้วตัดสินใจ
  • ความหมายที่ถูกต้องของ p-value: โอกาสที่จะเห็นผลต่างอย่างน้อยเท่านี้ ถ้า H0 เป็นจริง ไม่ใช่ความน่าจะเป็นที่ H0 เป็นจริง
  • เลือก Test ให้ตรงข้อมูล: ttest_ind เทียบค่าเฉลี่ยสองกลุ่ม (และ equal_var=False สำหรับ Welch's t-test), ttest_rel สำหรับข้อมูลจับคู่, chi2_contingency สำหรับข้อมูลกลุ่ม และ mannwhitneyu เมื่อข้อมูลไม่เป็น Normal
  • ความผิดพลาด 2 แบบ: Type I (สรุปว่ามีผลทั้งที่ไม่มี) และ Type II (มองไม่เห็นผลที่มีจริง) และ Statistical power ที่ขึ้นกับขนาดตัวอย่าง
  • A/B Test ตั้งแต่ออกแบบจนสรุป: สุ่มแบ่งกลุ่ม กำหนด Metric หลักและขนาดตัวอย่างก่อนเริ่ม ไม่หยุดการทดลองทันทีที่เห็น p-value ต่ำ (Peeking problem)
  • นัยสำคัญทางสถิติกับความสำคัญทางธุรกิจไม่เหมือนกัน: ผลต่าง 0.1% ที่มี p-value ต่ำมากอาจไม่คุ้มค่าที่จะลงทุน จึงต้องรายงานขนาดผลต่าง (Effect size) และ CI ประกอบเสมอ
ทำไมต้องเรียน
บริษัทเทคโนโลยีตัดสินใจเปลี่ยนหน้าเว็บ ราคา หรือโปรโมชันด้วย A/B Test ทุกวัน ถ้าอ่านผลผิด บริษัทจะลงทุนกับสิ่งที่ไม่ได้ผลจริง หรือทิ้งไอเดียที่ดี คำถามเรื่อง p-value และ A/B Test เป็นคำถามสัมภาษณ์ที่พบบ่อยที่สุดของตำแหน่ง Data Scientist และเป็นจุดที่ผู้สมัครตอบผิดบ่อยที่สุดด้วย

ตัวอย่างนี้จำลองผลการทดลองหน้าโปรโมชันของฟิตเนส กลุ่ม A เห็นหน้าเดิม กลุ่ม B เห็นหน้าใหม่ กลุ่มละ 1,000 คน แล้วใช้ Chi-square test ตรวจว่าอัตราการสมัครที่ต่างกันเป็นผลจริงหรือเป็นความบังเอิญ

# A/B Test: หน้าโปรโมชันแบบใหม่ (B) ทำให้คนสมัครสมาชิกมากกว่าแบบเดิม (A) จริงหรือไม่
from scipy import stats

visitors = {"A": 1000, "B": 1000}
signups = {"A": 82, "B": 113}

for g in "AB":
    print(f"กลุ่ม {g}: สมัคร {signups[g]} จาก {visitors[g]} คน = {signups[g] / visitors[g]:.1%}")

# ตาราง 2x2: [สมัคร, ไม่สมัคร] ของแต่ละกลุ่ม แล้วใช้ Chi-square test
table = [[signups[g], visitors[g] - signups[g]] for g in "AB"]
result = stats.chi2_contingency(table)
print(f"chi2 = {result.statistic:.3f}, p-value = {result.pvalue:.4f}")
print("ต่างกันอย่างมีนัยสำคัญที่ระดับ 0.05:", result.pvalue < 0.05)

p-value 0.0237 แปลว่า ถ้าหน้าใหม่ไม่ได้ช่วยอะไรเลยจริงๆ (H0 เป็นจริง) โอกาสที่จะเห็นผลต่างมากขนาดนี้จากความบังเอิญมีประมาณ 2.4% ซึ่งต่ำกว่าเกณฑ์ 0.05 ที่ตั้งไว้ก่อนทดลอง จึงปฏิเสธ H0 ได้ chi2_contingency ของตาราง 2×2 ใช้ Yates' correction เป็นค่าเริ่มต้น ผลจึงระมัดระวังกว่าการคำนวณด้วยมือเล็กน้อย ทั้งนี้ผลต่าง 3.1 จุดเปอร์เซ็นต์จะคุ้มค่ากับการเปลี่ยนหน้าเว็บหรือไม่ ยังต้องดู CI ของผลต่างและต้นทุนประกอบ ซึ่งจะฝึกใน Part 2

Checkpoint

ก่อนไปขั้นถัดไป คุณต้องทำสิ่งเหล่านี้ได้: อธิบายความหมายของ CI 95% และ p-value ได้ถูกต้องโดยไม่ใช้คำว่า "โอกาสที่ H0 จริง" เลือก Test ที่เหมาะกับข้อมูล 4 แบบได้ คำนวณ CI ทั้งแบบสูตรและแบบ Bootstrap ด้วย SciPy ออกแบบ A/B Test ที่บอก Metric หลัก ขนาดตัวอย่าง และเกณฑ์ตัดสินก่อนเริ่ม และอธิบายได้ว่าทำไมการหยุดทดลองทันทีที่ p-value ต่ำกว่า 0.05 ทำให้ผลผิด

คณิตศาสตร์สำหรับ ML: Vector, Matrix และ Gradient Descent

1 สัปดาห์ · 8–12 ชม.
หัวข้อย่อย
  • Vector คือรายการตัวเลขที่แทนหนึ่งตัวอย่าง เช่น สมาชิกหนึ่งคนคือ Vector ของอายุ จำนวนครั้งที่เข้ายิม และจำนวนเรื่องร้องเรียน และ Matrix คือตารางของ Vector หลายตัว
  • Dot product (a @ b) คือการคูณแล้วบวก ซึ่งเป็นหัวใจของ Linear Regression: ผลทำนาย = Feature แต่ละตัว × น้ำหนักของมัน แล้วบวกกัน
  • การคูณ Matrix กับ Vector (X @ w) คือการทำนายทุกแถวพร้อมกันในคำสั่งเดียว และกติกาว่า shape ต้องเข้ากันได้ เช่น (100, 3) @ (3,) ได้ (100,)
  • ระยะห่างระหว่างจุด (Euclidean distance) ที่ k-means และ k-Nearest Neighbors ใช้ และเหตุผลที่ต้องปรับสเกล Feature ก่อนวัดระยะ
  • Loss function คือตัวเลขที่บอกว่าโมเดลทำนายผิดมากแค่ไหน เช่น Mean Squared Error (MSE) และการเรียนรู้คือการหาน้ำหนักที่ทำให้ Loss ต่ำที่สุด
  • อนุพันธ์ (Derivative) ในความหมายเชิงภาพ: ความชันที่บอกว่าถ้าขยับน้ำหนักนิดหนึ่ง Loss จะขึ้นหรือลงเท่าไร
  • Gradient Descent: ขยับน้ำหนักสวนทางกับความชันทีละก้าว ขนาดก้าวคือ Learning rate ถ้าใหญ่ไปจะกระโดดข้ามจุดต่ำสุด ถ้าเล็กไปจะช้ามาก
  • เขียน Linear Regression ด้วย Gradient Descent เองด้วย NumPy ประมาณ 20 บรรทัด แล้วเทียบน้ำหนักที่ได้กับ LinearRegression ของ scikit-learn
ทำไมต้องเรียน
คุณใช้ scikit-learn ได้โดยไม่รู้คณิตศาสตร์เบื้องหลัง แต่จะติดทันทีที่โมเดลไม่ทำงานตามคาด เช่น ไม่รู้ว่าทำไม Logistic Regression ขึ้น ConvergenceWarning หรือทำไม k-means ให้ผลแย่เมื่อไม่ปรับสเกล การเข้าใจ Vector, Loss และ Gradient Descent ทำให้อ่านเอกสารของไลบรารีออก และเป็นพื้นฐานโดยตรงของ Neural Network ใน Step 14 ที่ทั้งหมดคือการคูณ Matrix และ Gradient Descent ซ้ำหลายชั้น

  • เขียน Gradient Descent หาค่า m และ c ของเส้นตรงจากข้อมูลจำลอง y = 3x + 5 + noise แล้วพิมพ์ Loss ทุก 100 รอบ

# โมเดลแรก: เทียบ Baseline กับ Logistic Regression บนข้อมูลมะเร็งเต้านมที่มากับ scikit-learn
from sklearn.datasets import load_breast_cancer
from sklearn.dummy import DummyClassifier
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import cross_val_score, train_test_split
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler

X, y = load_breast_cancer(return_X_y=True)
print("ข้อมูล:", X.shape[0], "แถว", X.shape[1], "Feature")

# แบ่งข้อมูล: 80% สำหรับฝึก 20% เก็บไว้ทดสอบครั้งสุดท้าย
X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.2, stratify=y, random_state=42
)

# Baseline: ทายคลาสที่พบบ่อยที่สุดเสมอ
baseline = DummyClassifier(strategy="most_frequent").fit(X_train, y_train)
print("Baseline accuracy (test):", round(baseline.score(X_test, y_test), 3))

# Pipeline: ปรับสเกลข้อมูลก่อน แล้วค่อยฝึก Logistic Regression
model = make_pipeline(StandardScaler(), LogisticRegression(max_iter=1000))
scores = cross_val_score(model, X_train, y_train, cv=5)
print("Cross-validation accuracy:", scores.round(3), "เฉลี่ย", round(scores.mean(), 3))

model.fit(X_train, y_train)
print("Logistic Regression accuracy (test):", round(model.score(X_test, y_test), 3))

1.5 สัปดาห์ · 10–16 ชม.
หัวข้อย่อย

  • Metric ของ Regression: MAE (ผิดเฉลี่ยกี่หน่วย อ่านง่าย), RMSE (ลงโทษความผิดพลาดใหญ่หนักกว่า) และ R² (อธิบายความแปรปรวนได้กี่เปอร์เซ็นต์ เทียบกับการทายค่าเฉลี่ย)

ก่อนไปขั้นถัดไป คุณต้องทำสิ่งเหล่านี้ได้: อธิบายความต่างของ MAE, RMSE และ R² และเลือก Metric ให้ตรงกับโจทย์ได้ อ่านค่าสัมประสิทธิ์ของโมเดลที่ปรับสเกลแล้วและอธิบายเป็นภาษาธุรกิจได้ ทำ Residual plot และบอกได้ว่าโมเดลพลาดอย่างเป็นระบบหรือไม่ เทียบ LinearRegression, Ridge และ Lasso กับ DummyRegressor ด้วย Cross-validation และอธิบายได้ว่า alpha ที่เพิ่มขึ้นทำให้โมเดลเปลี่ยนอย่างไร

STEP 11

Classification และการวัดผล: Confusion Matrix, Precision, Recall, ROC-AUC

2 สัปดาห์ · 12–18 ชม.
หัวข้อย่อย
  • Logistic Regression: แปลงผลรวมถ่วงน้ำหนักเป็นความน่าจะเป็น 0–1 ด้วยฟังก์ชัน Sigmoid ใช้ predict_proba เพื่อได้ความน่าจะเป็น และ predict ที่ตัดที่ 0.5
  • Decision Tree: แบ่งข้อมูลด้วยคำถามใช่หรือไม่ทีละขั้น อ่านง่ายและวาดเป็นแผนภาพได้ด้วย plot_tree แต่ Overfit ง่ายถ้าไม่จำกัด max_depth
  • Confusion Matrix: True Positive, False Positive, True Negative และ False Negative พร้อมวิธีอ่านผลของ confusion_matrix ที่แถวคือค่าจริงและคอลัมน์คือค่าทำนาย
  • Precision (ทายว่าใช่แล้วถูกกี่เปอร์เซ็นต์), Recall (ของจริงทั้งหมดหาเจอกี่เปอร์เซ็นต์) และ F1 ที่เป็นค่าเฉลี่ยแบบ Harmonic ของทั้งสอง และ classification_report ที่สรุปทุกค่าในตารางเดียว
  • ROC curve และ ROC-AUC ที่วัดความสามารถในการเรียงลำดับความเสี่ยงโดยไม่ขึ้นกับ Threshold และ Precision-Recall curve ที่เหมาะกว่าเมื่อคลาสที่สนใจมีน้อย
  • ข้อมูลไม่สมดุล (Class imbalance): ทำไม Accuracy 95% อาจไร้ค่าเมื่อมีผู้ฉ้อโกงแค่ 5% วิธีรับมือด้วย stratify, class_weight="balanced" และการเลือก Metric ที่เหมาะสม
  • การเลือก Threshold ตามต้นทุนธุรกิจ: ถ้าพลาดคนที่จะยกเลิกสมาชิกเสียเงินมากกว่าการโทรหาคนที่ไม่ยกเลิก ควรลด Threshold ลงเพื่อเพิ่ม Recall
  • Classification หลายคลาส (Multiclass) กับ load_wine และความหมายของ average="macro" กับ average="weighted"
ทำไมต้องเรียน
ปัญหาธุรกิจส่วนใหญ่เป็น Classification เช่น ลูกค้าจะยกเลิกหรือไม่ ธุรกรรมนี้ฉ้อโกงหรือไม่ อีเมลนี้เป็นสแปมหรือไม่ และเกือบทั้งหมดมีคลาสที่สนใจน้อยกว่าอีกคลาสมาก คนที่รายงานแค่ Accuracy จะพลาดประเด็นสำคัญทันที การอ่าน Confusion Matrix และเลือกระหว่าง Precision กับ Recall ตามต้นทุนของความผิดพลาดแต่ละแบบ เป็นคำถามสัมภาษณ์ที่แทบทุกบริษัทถาม
ลงมือทำ
  • ต่อยอด first_model.py ให้พิมพ์ confusion_matrix และ classification_report แล้วบอกว่าโมเดลพลาดเนื้องอกชนิดร้ายกี่ราย
  • สร้างข้อมูลไม่สมดุลด้วย make_classification(weights=[0.95], random_state=42) แล้วเทียบ Accuracy, Recall และ ROC-AUC ของ DummyClassifier กับ LogisticRegression ทั้งแบบมีและไม่มี class_weight="balanced"
  • ลอง Threshold 0.3, 0.5 และ 0.7 จาก predict_proba แล้วทำตาราง Precision และ Recall ของแต่ละค่า
ใช้เวลา
12–18 ชั่วโมง โมเดล Logistic Regression และ Decision Tree 3–5 ชั่วโมง Confusion Matrix และ Metric ทุกตัว 5–7 ชั่วโมง และข้อมูลไม่สมดุลกับ Threshold 4–6 ชั่วโมง
เปรียบเทียบ

Precision กับ Recall เหมือนตาข่ายจับปลา ตาข่ายตาถี่ผืนใหญ่จับปลาที่ต้องการได้เกือบหมด (Recall สูง) แต่ได้ขยะและปลาตัวเล็กติดมาด้วยเยอะ (Precision ต่ำ) ส่วนเบ็ดตกปลาที่เลือกเหยื่ออย่างดีได้ปลาที่ต้องการแทบทุกครั้งที่ติด (Precision สูง) แต่จับได้น้อยตัว (Recall ต่ำ) ไม่มีเครื่องมือไหนดีที่สุดเสมอ ขึ้นกับว่าการปล่อยปลาหลุดหรือการเก็บขยะขึ้นมา อย่างไหนเสียหายมากกว่ากัน

Checkpoint

ก่อนไปขั้นถัดไป คุณต้องทำสิ่งเหล่านี้ได้: วาด Confusion Matrix ด้วยมือจากผลทำนาย 10 ตัวอย่าง แล้วคำนวณ Precision, Recall และ F1 ให้ตรงกับ classification_report อธิบายได้ว่าทำไม Accuracy หลอกเราได้เมื่อคลาสไม่สมดุล เลือก Metric หลักให้โจทย์ "คัดกรองมะเร็ง" และ "แนะนำสินค้า" พร้อมเหตุผล ใช้ predict_proba เลือก Threshold ตามต้นทุนที่กำหนดได้ และอ่าน ROC-AUC 0.5 กับ 0.9 ได้ว่าหมายถึงอะไร

STEP 12

Overfitting, Bias-Variance, Tree Ensemble และ GridSearchCV

2 สัปดาห์ · 12–18 ชม.
หัวข้อย่อย
  • Underfitting (โมเดลง่ายเกินไป ผิดทั้งข้อมูลฝึกและข้อมูลทดสอบ) กับ Overfitting (คะแนนข้อมูลฝึกสูงมากแต่ข้อมูลทดสอบต่ำ) และวิธีดูจากช่องว่างของสองคะแนน
  • Bias-Variance trade-off: Bias คือความผิดพลาดจากสมมติฐานที่ง่ายเกินไป Variance คือความไวต่อข้อมูลฝึกชุดที่ได้มา และการปรับความซับซ้อนของโมเดลเพื่อหาจุดสมดุล
  • validation_curve ที่แสดงคะแนนเมื่อเปลี่ยน Hyperparameter หนึ่งตัว เช่น max_depth ของ Decision Tree และ learning_curve ที่บอกว่าการเก็บข้อมูลเพิ่มจะช่วยหรือไม่
  • Random Forest: รวม Decision Tree หลายร้อยต้นที่ฝึกด้วยข้อมูลสุ่มต่างกัน (Bagging) ลด Variance และ Hyperparameter สำคัญคือ n_estimators, max_depth และ min_samples_leaf
  • Gradient Boosting: สร้างต้นไม้ทีละต้นให้แก้ความผิดพลาดของต้นก่อนหน้า ใช้ HistGradientBoostingClassifier ที่เร็วและรองรับค่าว่างได้ในตัว พร้อม learning_rate, max_iter และ early_stopping
  • GridSearchCV ค้นหาทุกชุดค่าที่กำหนด และ RandomizedSearchCV สุ่มค้นหาเมื่อมีตัวเลือกมาก ตั้งชื่อพารามิเตอร์ใน Pipeline ด้วยรูปแบบ ชื่อขั้น__ชื่อพารามิเตอร์ เช่น model__max_depth
  • Nested evaluation: ใช้ Cross-validation เลือก Hyperparameter บนข้อมูลฝึก แล้ววัดผลครั้งสุดท้ายบนข้อมูลทดสอบที่ไม่เคยแตะเพียงครั้งเดียว
  • ตั้ง n_jobs=-1 ให้ใช้ทุก CPU และประมาณเวลาก่อนรัน เช่น 4 ค่า × 3 ค่า × 5 Fold = ฝึก 60 ครั้ง
ทำไมต้องเรียน
Overfitting คือเหตุผลอันดับต้นที่โมเดลดูดีในการทดลองแต่ใช้งานจริงไม่ได้ และเป็นแนวคิดที่ผู้สัมภาษณ์ถามแทบทุกครั้ง ส่วน Random Forest และ Gradient Boosting เป็นโมเดลที่ใช้มากที่สุดกับข้อมูลแบบตารางในงานจริง มักชนะ Neural Network บนข้อมูลแบบนี้ และการปรับจูนด้วย GridSearchCV อย่างถูกขั้นตอนทำให้ได้โมเดลที่ดีขึ้นโดยไม่โกงตัวเองด้วยข้อมูลทดสอบ
ลงมือทำ
  • ฝึก Decision Tree บน load_breast_cancer ด้วย max_depth ตั้งแต่ 1 ถึง 15 แล้วบันทึก validation_curve เป็นกราฟ ชี้จุดที่เริ่ม Overfit
  • เทียบ Logistic Regression, Random Forest และ HistGradientBoosting ด้วย Cross-validation 5 Fold บน ROC-AUC แล้วสร้างตารางพร้อมเวลาที่ใช้ฝึก
  • ใช้ GridSearchCV ปรับ max_depth และ min_samples_leaf ของ Random Forest แล้วพิมพ์ best_params_, best_score_ และคะแนนบนข้อมูลทดสอบ
ใช้เวลา
12–18 ชั่วโมง Overfitting และ Bias-Variance 3–5 ชั่วโมง Random Forest กับ Gradient Boosting 4–6 ชั่วโมง และการปรับจูนด้วย GridSearchCV 5–7 ชั่วโมง
Checkpoint

ก่อนไปขั้นถัดไป คุณต้องทำสิ่งเหล่านี้ได้: ดูคะแนนข้อมูลฝึกเทียบข้อมูลทดสอบแล้วบอกได้ว่าเป็น Underfit, Overfit หรือพอดี อธิบาย Bias-Variance trade-off ด้วยตัวอย่าง Decision Tree ที่ลึกต่างกัน อธิบายความต่างของ Bagging กับ Boosting เขียน GridSearchCV ที่ปรับพารามิเตอร์ในขั้นของ Pipeline ได้ถูกชื่อ และอธิบายได้ว่าทำไมห้ามใช้ข้อมูลทดสอบในการเลือก Hyperparameter

STEP 13

Unsupervised Learning (k-means, PCA) และการตีความโมเดล

1.5 สัปดาห์ · 10–14 ชม.
หัวข้อย่อย
  • Unsupervised Learning คือการหาโครงสร้างในข้อมูลที่ไม่มี Target เช่น แบ่งกลุ่มลูกค้าตามพฤติกรรมเพื่อทำการตลาดแยกกลุ่ม
  • k-means: เลือกจุดศูนย์กลาง k จุด จัดแต่ละตัวอย่างเข้ากลุ่มที่ใกล้ที่สุด แล้วขยับศูนย์กลางซ้ำจนนิ่ง ต้องปรับสเกลก่อนเสมอ และตั้ง random_state เพราะผลขึ้นกับจุดเริ่มต้น
  • เลือกจำนวนกลุ่มด้วย Elbow method (inertia_) และ silhouette_score แล้วตั้งชื่อกลุ่มด้วยการดูค่าเฉลี่ยของแต่ละกลุ่ม เช่น "กลุ่มมาบ่อยแต่จ่ายน้อย"
  • PCA (Principal Component Analysis): สร้างแกนใหม่ที่เก็บความแปรปรวนได้มากที่สุด ใช้ลดมิติจาก 13 Feature ของ load_wine เหลือ 2 แกนเพื่อวาด Scatter plot และอ่าน explained_variance_ratio_
  • ข้อจำกัด: k-means สมมติว่ากลุ่มเป็นก้อนกลมขนาดใกล้กัน และ PCA หาได้เฉพาะความสัมพันธ์เชิงเส้น จึงต้องตรวจผลด้วยกราฟและความรู้ธุรกิจเสมอ
  • การตีความโมเดล: coef_ ของโมเดลเชิงเส้น feature_importances_ ของโมเดลต้นไม้ และข้อเสียของ feature_importances_ ที่ให้น้ำหนักเกินจริงกับ Feature ที่มีค่าไม่ซ้ำกันเยอะ
  • Permutation Importance ด้วย sklearn.inspection.permutation_importance: สลับค่าของ Feature ทีละตัวบนข้อมูลทดสอบแล้วดูว่าคะแนนตกเท่าไร ใช้ได้กับทุกโมเดล
  • Partial Dependence ด้วย PartialDependenceDisplay ที่แสดงว่าผลทำนายเปลี่ยนอย่างไรเมื่อ Feature หนึ่งเปลี่ยน และคำเตือนว่าความสำคัญของ Feature ไม่ได้แปลว่าเป็นสาเหตุ
ทำไมต้องเรียน
ข้อมูลจำนวนมากในบริษัทไม่มี Label เช่น ประวัติการซื้อของลูกค้า การแบ่งกลุ่มด้วย k-means จึงเป็นงานที่ทีมการตลาดขอบ่อยมาก ส่วน PCA ช่วยมองข้อมูลหลายมิติให้เห็นเป็นภาพ และการตีความโมเดลคือสิ่งที่ทำให้ฝ่ายธุรกิจเชื่อและนำโมเดลไปใช้ ในหลายอุตสาหกรรม เช่น การเงินและประกัน การอธิบายเหตุผลของผลทำนายได้เป็นเงื่อนไขก่อนนำโมเดลขึ้นระบบจริง
ลงมือทำ
  • แบ่ง load_wine เป็นกลุ่มด้วย k-means โดยลอง k = 2 ถึง 8 บันทึกกราฟ Elbow และ Silhouette แล้วเลือก k พร้อมเหตุผล
  • ลดมิติด้วย PCA เหลือ 2 แกน วาด Scatter plot ระบายสีตามกลุ่มที่ได้ และบอกว่า 2 แกนแรกเก็บความแปรปรวนได้กี่เปอร์เซ็นต์
  • คำนวณ Permutation Importance ของ Random Forest จาก Step 12 แล้วเทียบอันดับกับ feature_importances_
ใช้เวลา
10–14 ชั่วโมง k-means และการเลือก k 3–4 ชั่วโมง PCA 3–4 ชั่วโมง และการตีความโมเดล 4–6 ชั่วโมง
Checkpoint

ก่อนไปขั้นถัดไป คุณต้องทำสิ่งเหล่านี้ได้: อธิบายขั้นตอนของ k-means ทีละรอบได้ เลือก k ด้วย Elbow และ Silhouette พร้อมเหตุผล ตั้งชื่อกลุ่มจากค่าเฉลี่ยของแต่ละกลุ่มให้ฝ่ายการตลาดเข้าใจ อ่าน explained_variance_ratio_ ของ PCA ได้ คำนวณ Permutation Importance และอธิบายได้ว่าทำไมผลอาจต่างจาก feature_importances_ และบอกได้ว่าทำไม Feature สำคัญไม่ได้แปลว่าเป็นสาเหตุ

Neural Network เบื้องต้น: MLPClassifier และ PyTorch

1.5 สัปดาห์ · 10–16 ชม.
หัวข้อย่อย
  • Neuron เทียมคือ Dot product ของ Input กับน้ำหนัก บวก Bias แล้วผ่าน Activation function เช่น ReLU และ Neural Network คือการต่อ Neuron หลายชั้น (Layer)

Best Practice

ทุกครั้งที่จบหนึ่งขั้น ให้ Commit งานใน ~/projects/ds-lab ด้วยข้อความที่บอกสิ่งที่ได้เรียนรู้ เช่น git commit -m "Step 11: เลือก threshold 0.3 เพื่อให้ recall ของคลาสมะเร็งเป็น 0.98" และจดตัวเลขสำคัญลง Learning Journal เมื่อครบ 24 สัปดาห์ Commit history กับ Journal นี้จะเป็นหลักฐานการเรียนที่ผู้สัมภาษณ์เห็นได้ทันที และช่วยให้คุณเล่าประสบการณ์ในการสัมภาษณ์ได้ละเอียด

Must-know Skills

ถ้าต้องสรุปหัวข้อนี้ให้เหลือทักษะที่งานจริงและผู้สัมภาษณ์คาดหวังจาก Data Scientist ระดับเริ่มต้น จะได้รายการนี้

  1. แปลงคำถามธุรกิจเป็นโจทย์ข้อมูลที่วัดผลได้ เพราะโมเดลที่แม่นยำแต่ตอบผิดคำถามไม่มีประโยชน์ และการตั้ง Metric ที่ถูกตั้งแต่แรกกำหนดความสำเร็จของทั้งโปรเจกต์
  2. จัดการข้อมูลด้วย pandas อย่างคล่องแคล่ว เพราะงานส่วนใหญ่ของ Data Scientist คือการโหลด ทำความสะอาด รวม และสรุปข้อมูล และผู้สัมภาษณ์มักให้เขียน pandas สด
  3. ดึงข้อมูลด้วย SQL แล้ววิเคราะห์ต่อใน Python เพราะข้อมูลจริงในบริษัทอยู่ในฐานข้อมูล และการรู้ว่างานไหนควรทำฝั่ง SQL ทำให้งานเร็วขึ้นหลายเท่า
  4. ทำ EDA และสื่อสารด้วยกราฟที่ถูกต้อง เพราะ EDA คือที่มาของปัญหาข้อมูลและไอเดีย Feature ส่วนกราฟคือภาษาที่ผู้ตัดสินใจเข้าใจเร็วที่สุด
  5. ใช้สถิติเชิงอนุมานและอ่านผล A/B Test ได้ถูกต้อง เพราะบริษัทตัดสินใจจากผลการทดลองทุกวัน และการตีความ p-value ผิดทำให้ลงทุนผิดทาง
  6. สร้างโมเดลด้วย Pipeline และวัดผลด้วย Cross-validation โดยไม่มี Data leakage เพราะผลวัดที่ดีเกินจริงคือเหตุผลอันดับต้นที่โมเดลพังเมื่อใช้งานจริง
  7. เลือก Metric และ Threshold ให้ตรงกับต้นทุนของความผิดพลาด เพราะปัญหาจริงส่วนใหญ่มีคลาสไม่สมดุล และ Accuracy อย่างเดียวหลอกได้ง่าย
  8. เข้าใจและแก้ Overfitting ด้วยการปรับความซับซ้อนและปรับจูนอย่างถูกขั้นตอน เพราะเป็นแนวคิดหลักที่ทุกการสัมภาษณ์ถาม และกำหนดว่าโมเดลจะใช้กับข้อมูลใหม่ได้หรือไม่
  9. ตีความโมเดลและอธิบายผลเป็นภาษาธุรกิจ เพราะโมเดลที่อธิบายไม่ได้มักไม่ถูกนำไปใช้ และหลายอุตสาหกรรมบังคับให้อธิบายเหตุผลของการตัดสินใจ
  10. ทำงานกับข้อมูลอย่างมีจริยธรรมตาม PDPA เพราะความผิดพลาดด้านข้อมูลส่วนบุคคลมีโทษตามกฎหมาย และโมเดลที่ลำเอียงสร้างความเสียหายจริงต่อผู้คน
  11. ทำโปรเจกต์ให้รันซ้ำได้ด้วย Seed, venv, requirements.txt และ Git เพราะผลที่คนอื่นทำซ้ำไม่ได้ไม่ถือเป็นผลทางวิทยาศาสตร์ และทีมไม่สามารถต่อยอดงานของคุณได้

Best Practice

Portfolio ที่ดีสำหรับสาย Data มี 3–4 โปรเจกต์ที่ต่างประเภทกัน เช่น Mini Project ของหัวข้อนี้ (Classification แบบ End-to-End) งานวิเคราะห์ A/B Test พร้อมรายงาน งานแบ่งกลุ่มลูกค้าด้วย k-means และงานที่ใช้ข้อมูลสาธารณะของไทยที่คุณสนใจ ทุกโปรเจกต์ต้องมี README ที่บอกโจทย์ ข้อสรุป และข้อจำกัดในย่อหน้าแรก เพราะผู้คัดเลือกส่วนใหญ่อ่านแค่ย่อหน้าแรกก่อนตัดสินใจว่าจะดูต่อหรือไม่

จบหัวข้อนี้แล้วไปต่อที่ไหน

เมื่อผ่าน Checkpoint ของ Step 16 และ Mini Project อยู่บน GitHub แล้ว คุณมีพื้นฐานของงานข้อมูลครบทั้งการจัดการข้อมูล สถิติ และ ML ลำดับที่แนะนำต่อจากนี้คือ

  1. หัวข้อถัดไปในเส้นทาง นำความรู้เรื่องการวัดผลโมเดล Overfitting และ Data leakage ไปใช้กับการสร้างแอปพลิเคชันที่ใช้ LLM โดยเฉพาะการประเมินคุณภาพคำตอบของ AI อย่างเป็นระบบ
  2. สร้าง Agent ที่ใช้เครื่องมือได้ เช่น Agent ที่เรียก pandas วิเคราะห์ไฟล์ CSV ให้ ต่อยอดจากผู้ช่วยวิเคราะห์ใน Step 15
  3. และ ที่เรียนมาแล้ว ใช้ทบทวนเมื่อต้องส่งโมเดลขึ้นเป็น API ให้ระบบอื่นเรียกใช้ ซึ่งเป็นงานหลักของ ML Engineer
  4. ทบทวน Window function และ CTE เพราะงาน Data Scientist ในบริษัทใช้ SQL ขั้นสูงทุกวัน และคำถามสัมภาษณ์สาย Data มักมีโจทย์ SQL ด้วย
  5. ถ้าสนใจใช้ ML ตรวจจับความผิดปกติใน Log หรือธุรกรรม ซึ่งเป็นงานที่สาย Data กับสาย Security ทำร่วมกัน
